## 每个模块目录必须有 README

六段必填：被测对象 / 测试文件 / 前置条件 / 运行方式 / 覆盖场景清单 / 已知限制
（模板见 [测试规范](../docs/04-测试/测试规范.md) §5）。

## 运行方式

| 诉求 | 命令（项目根执行） |
|---|---|
| 全量（推荐） | `run_tests.bat`（vet + test + 可选 race） |
| 全量（手动） | `go test ./test/... -count=1` |
| 单模块 | `go test ./test/store/ -v` |
| 单用例 | `go test ./test/event/ -run TestGhostOfflineAutoRemoveWhenEnabled -v` |
| 关键字过滤 | `go test ./test/... -run "Fixture" -v` |
| 竞态 | `go test ./test/... -race`（需 CGO/gcc） |

## 五条铁律（摘要，全文见测试规范 §3）

1. **先隔离后使用**：临时数据目录一律 `t.TempDir()`，不碰真实 `data/`、`logs/`（只读 `data/chains` 例外，缺失自动 skip）。
2. **副作用必须可控**：不拉起机器人进程、不连生产端口（控制通道 `Port=0`）。
3. **断言结果证据**：状态迁移 / 落盘数据 / 广播内容 / **机器人实收命令**；禁止只断言「调用了函数」。
4. **必须有真实数据支撑**：输入尽量取真实抓包夹具；构造数据必须 `real=false` 并说明依据；夹具元测试强制校验。
5. **模块级状态不跨用例泄漏**：全局缓存（位置合并器、批处理表）在用例内新建实例，不复用。
