# 与参考实现对照

> 参考实现：`F:\ZyBin\xm\2d-xiyou-server\robot\ctrlcenter`（Python 3.11 + FastAPI，业务完整）。
> 本项目是它的**骨架化 Go 重写**：保留基础设施与测试框架，业务模块留给使用方。

## 1. 定位差异

| | 参考实现（Python 版） | 本项目（Go 骨架） |
|---|---|---|
| 抓鬼对话收尾（2026-09-21） | 死等 30 秒 → 本地清 dialog_open → 空点 15 次 → 重登 | **8 秒内点服务端关闭项收尾**（非业务对话时）+ 判死阈值 8 次；中控侧自动重登 + 当日卡死 churn 防护 | `daily_ghost.py` / `internal/services/reghost` |
| 定位 | 生产用完整中控（含业务编排） | 骨架 + 测试框架（业务自行扩展） |
| 语言/依赖 | Python + FastAPI/uvicorn/pymysql | Go 标准库（**零第三方依赖**） |
| 端口 | 18082 / 17200 / 5173 | **28082 / 27200 / 5273** |
| 数据 | RDS + 本地 SQLite 账号库 | 无数据库（骨架不持久化业务数据） |
| 前端 | `F:\ZyBin\xm\robot-ctrl-web`（Vue3 完整面板） | `web/`（Vue3 简易四页签） |
| 文档 | 5 份单文件文档 | 分域多文档 + 索引（docs/README.md） |

## 5. 已修复的「参考实现踩过的坑」（本项目一并规避）

| 坑 | 本项目做法 |
|---|---|
| 单文件日志膨胀到 GB 级导致写入静默失败 | 日期级轮转 + 单文件熔断归档（`store.maybeRotateLocked`） |
| `readlines()` 全量读日志阻塞事件循环 | 尾部回读（`readTailLines`，耗时与文件大小无关） |
| robot 重启瞬间新连接被旧连接清理「清掉」 | 只在「当前持有的连接 == 自己」时清状态 |
| 位置事件逐条广播把前端压垮 | 100ms 合并 `robot_pos_batch` |
| 日志按 GB 写、文件句柄占用（Windows 清理失败） | 每条日志打开→写→关闭；Logger 由调用方显式 Close |
| 链数据字段被强类型吃掉 | `chainlib` 原样透传 + 真实形状夹具测试 |
