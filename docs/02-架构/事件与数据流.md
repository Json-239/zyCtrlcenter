# 事件与数据流

## 1. 一条事件的完整链路

```
robot_single_robot.exe（唯一一个进程）
   │  {"type":"task_progress","account":"robotA","done":4}
   ▼  TCP :27200（JSON + \n）
internal/ctrl.Server.handleConn        读行 → JSON 解析 → 打 "_zone"（当前区）标记 → 入 Events（容量 8192）
   ▼
internal/services/event.RunEventLoop   单协程顺序消费（避免状态竞争）
   ├─ HandleEvent(ev)   表驱动：handlers()[type] → 更新 state（含区归属）/ 写 store
   └─ AfterEvent(ev)    广播：WSHub.Broadcast → 各 WS 客户端（慢客户端断开）
   ▼
前端面板（Vue）
   ├─ WS 即时修补表格（快，事件自带 _zone）
   └─ 每 3 秒 /api/status 全量刷新（权威，含通道/进程/当前区）
```

反向（命令）：

```
面板按钮 → POST /api/start|stop|reset|robots/manage → api.Handler
   → event.SendCmd(cmd, action) → ctrl.Server.SendCmd
   → 写入唯一连接（5s 写超时；无连接返回 false，接口回 ok=false + 原因）
```

## 2. 事件处理表（骨架层的固定行为）

> 所有事件都带 `_zone`（控制通道打的区标记）；下表「状态动作」均在**该账号所属区**上生效。

| 事件 | 状态动作 | 落盘 | 备注 |
|---|---|---|---|
| `hello` / `pong` | — | — | 只记应用日志（含区） |
| `robot_online` | 记区归属、清已移除标记、建行置 `ONLINE`、写角色/等级/地图 | ✅ 一条 info log | |
| `robot_offline` | 置 `OFFLINE`、清握手标记 | — | |
| `status_reply` | 全量映射到状态表 + 记录游戏服地址 | ❌（每 3 秒一条，量太大） | 状态表唯一来源 |
| `robot_manage_reply` | — | ✅ | |
| `task_progress` | `done` / `task_index` 更新 | ✅ | |
| `robot_state` | 状态快照（含 `booth` 清残留） | ✅ | |
| `robot_pos` | 位置即时更新（像素 + **客户端格子**） | ❌ | 100ms 合并推 WS（`robot_pos_batch`，带 `gx/gy`） |
| `chain_done` | 置 `DONE` + `chain_done=true` | ✅ | `AutoRemoveOnDone` 且非 `already_done` → 下机 |
| `ghost_done` / `ghost_offline` | —（业务处置由使用方实现） | ✅ + 一条可读 warn/info | 同上受 `AutoRemoveOnDone` 控制 |
| `error` | `err_code` / `err_ts` / `err_repeat`（同码累计） | ✅ | 面板「任务失败待处理」数据源 |
| `log` | — | ✅ | `debug`/`trace` 不推 WS |
| 未知类型 | — | ✅ | fail-loud：新事件也能在日志里看到 |

> 完整字段与示例见 [控制通道协议](../03-协议/控制通道协议.md)。

## 3. 下机（移除账号）语义

`chain_done` / `ghost_done` / `ghost_offline` 在 `AutoRemoveOnDone=true` 时执行同一套动作：

1. `state.MarkRemoved(account)` —— 之后的 `status_reply` 心跳**不会**把它复活；
2. `state.Remove(account)` —— 面板立即消失；
3. 异步 `robot_manage / remove` 通知机器人端下线（`store` 记一条 `api` 事件）。

业务层需要「换号 / 冷却 / 补位」时，监听同样的三处状态变化自行实现（见 [扩展指南](扩展指南.md)）。

## 4. 日期级日志

| 日志 | 路径 | 切分 | 清理 | 熔断 |
|---|---|---|---|---|
| 运行历史（面板日志页） | `data/runs_YYYYMMDD.jsonl` | 按日 | 保留 30 天（`CTRL_RUNS_KEEP_DAYS`） | 单文件超 500MB 归档为 `.over_<ts>` 并只留最新一份（`CTRL_RUNS_MAX_MB`） |
| 单机器人 | `data/bot_logs/<账号>/runs_YYYYMMDD.log` | 按日 + 按账号 | 同上 | 同上 |
| 应用日志 | `logs/ctrlcenter_YYYYMMDD.log` | 按日 | 保留 30 天（`CTRL_LOG_KEEP_DAYS`） | — |

要点：
- **跨日自动切换**：写入时按当前日期取路径，不依赖进程重启；
- **尾部回读**：`ReadTail`/`ReadBotLogs` 从文件末尾分块回读，耗时与文件大小无关（面板轮询不阻塞）；
- **失败不静默**：写盘异常只影响日志，不影响事件处理（`LogEvent` 内部吞掉 IO 错误，业务继续）。

## 5. 位置推送合并（为什么需要）

行走中的机器人约 10Hz 上报位置；若逐条广播，几十上百个号会把 WS 与前端渲染压垮。
因此 `robot_pos` **不**逐条广播，而是攒 100ms 合并成一条：

```json
{"type":"robot_pos_batch","list":[{"account":"robotA","mapid":9,"x":100,"y":200}]}
```

同时状态表（`/api/status`）是即时更新的，所以轮询也拿得到最新位置。

## 6. 机器人连接接管与断线

- **单连接语义**：新连接接入立即接管（旧连接被关闭），适合「一个机器人进程 = 一条通道」。
- **接管竞态防护**：旧连接断开清理时，只在「当前持有的连接 == 自己」时才清状态，
  避免 robot 重启瞬间把新连接状态清掉（表现是面板所有操作失效）。
- **断线不影响面板**：控制通道断开只影响命令下发（接口返回原因「通道未连接」），
  状态表保留最后快照，超过 10 分钟无心跳的行由状态轮询清理。
