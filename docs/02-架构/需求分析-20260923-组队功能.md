# 需求分析：组队功能模块（队长 / 队员差异化）

> 2026-09-23 · 现状调研（机器人端+协议 / Go中控+前端）汇总后的需求分析底稿
> 结论一句话：**机器人端组队执行器已就绪（孤儿代码，从未线上跑过），Go 中控与前端零组队代码；所有现有编排都会拆队；第一优先级不是写代码，而是先实测服务端组队语义。**

---

## 1. 为什么要做（业务动机，均有实据）

| # | 动机 | 依据 |
|---|---|---|
| M1 | **半月岛/女儿国暗雷"空战斗"**：`base_s_20018/20002` 只配 2/3/4/5 人 compose，**单人踩雷建不出有效战斗**（进战斗没怪） | `config/fight/tailor/*.xml`；`docs/待办清单.md` 已记 |
| M2 | **捉鬼组队档**：3-5 人档 2019512/2019513（"队长有额外加成"，weight 500）；单人档 weight 1800 | `config/task/20195.xml` |
| M3 | **组队门槛任务**：普度众生 20025（队长加成）、守护训练 20037、修罗 20008、应梦贤臣 10022 | `config/task/*.xml` |
| M4 | **编排视角**：把"队长+队员"作为**可编排单元**（整队上线、整队派活、整队保活），避免三池/水位按单号操作 | 本次调研（编排耦合清单） |
| M5 | 带新手号：新手池（212 个可用 <31 级）可借组队被带上线做任务（**待验证收益**） | 新手池已启用 target=20（2026-09-23） |

### 反动机（要正视）
- 捉鬼**单人档 weight（1800）> 组队档（500）** → 从"接取效率"看组队不占优，组队价值主要在**队长加成与门槛任务/暗雷**；
- 组队要 3-5 人同图同点，**调度成本高**（跟随/归队/掉线重建），单人农场模式（当前）更省心。

## 2. 现状（事实底稿，两路只读调研）

### 2.1 机器人端（`deploy/zones/prod-240-2300/script/team_captain.py`，510 行）
- **已有**：建队(80104)、邀请(80078)、同意邀请(80153)、同意申请(80356)、退队/清队(80348)、解散(80385)、暂离归队(fast/waiting/nav 三态)、`next_action=start_ghost` 全员各自开抓；事件 `team_ready/team_disbanded/team_rejoined/team_return_nav` 上送（中控 Go 未处理）。
- **缺失/半成品**：
  - **队员跟随（`S2C_TEAM_FOLLOWER` 90067）完全未实现** ← 队员侧最大空洞；
  - 踢人(80208)/移交(80197)/拒绝邀请(80379)/拒绝申请(80008)/清空申请(80284)/队伍改名(80221)/召唤(80320/80201)/队长带路(80367/80206)/提醒(80114) 协议键**都在协议表**，只是未注册格式、未发消息；
  - 归队 nav 阶段依赖 `route_walk.py`，**该模块两副本均不存在** → 跨图暂离只能"快速归队（耗道具/元宝）"；
  - 无队伍全量查询协议 → `m_team` 纯内存，**重启失忆**；无 ACK/超时重传；邀请 10s 未确认即**乐观自动确认**（有误判风险）；
  - `daily_ghost.g.role`（solo/captain/member）**只存不用**（行为不分支）；
  - **心跳不上报队伍**（`client.py:624` 2026-08-25 起去掉 `m_team` 上报）→ 中控当前看不到队伍。

### 2.2 Go 中控 + 前端
- **`internal/`、`main.go`、`web/src/` 全量 grep "team" = 0 命中**；无队伍字段、无 `/api/team*`、无事件 handler、无 UI。
- 抓鬼命令 `role` 三处下发点**恒为 `"solo"`**（`autotask.go:914`、`handlers.go:270/646`、`restorer.go:374`）。
- **所有编排按单号操作、判据无队伍维度**（会拆队）：三池候选、水位压号/补号、游荡池回收/补位、恢复引擎补发、卡死重登、批量上线下线、暂停。逐项见 §4.2。
- 可复用前置：`state.Robot.RoleID`（组队载荷需要）、`newbieMaxLevel()=31`（与 py `LEVEL_MIN_TEAM=31` 同口径）、`paused`/`restoreCap` 的"独立表+Snapshot 填充"先例。

### 2.3 py 参考实现（可搬清单，事实对照）
- 接口 `routers/team.py`：`POST /api/team/setup | auto_setup | disband | disband_batch`、`GET /api/team/status`；
- 台账 `state.TEAMS` + `data/teams.json` 落盘；意图恢复（重连重建队、等队员 20s×10 后先用已在线队员组队）；
- 跟随调度 `services/team_follow.py`：FOLLOW_DISTANCE=300px、5s 检测、15s 导航节流；跨图/远距 → `route_walk` 把队员拉到队长旁；**组队抓鬼：全员到位才由队长 `ghost_start(role=captain)`**；
- 自动组队：按每组人数分组、`team_count=N` 只组 N 队、其余 solo 抓鬼；**排除游荡号**（30s 心跳 + role_id + 等级≥31）；
- 前端 `robot-ctrl-web/src/views/TeamView.vue`（394 行：自动/手动组队、解散、队伍状态表）+ `RobotTable.vue`（**队员折叠到队长行、树形展开**）+ 菜单「👥 组队控制」。
- 运行证据：py 2300 实例 **909 次 `GET /api/team/status`、0 次 `POST /api/team/*`**，`teams.json` 为空 → **py 侧组队功能在轮询但实际未使用**；其 README 写"已移除组队"属文档滞后（代码为准）。

## 3. 需求：队长 / 队员功能矩阵

等级：**P0=必须先有（否则不可用）｜P1=最小可用之后｜P2=进阶**

| 功能 | 队长 | 队员 | 优先级 | 现状（机器人端） |
|---|---|---|---|---|
| 建队（创建队伍） | ✅ 发起 | — | P1 | 有(80104) |
| 邀请 / 申请入队 | ✅ 邀请 | ✅ 申请 | P1 | 有 |
| 同意邀请 / 同意申请 | ✅ 同意申请 | ✅ 同意邀请 | P1 | 有（队员仅组队模式响应） |
| **跟随队长**（同图同点） | 走位即目标 | **跟随** | **P0'（若要做"整队行动"）** | **完全缺失**（90067 未实现） |
| 归队（暂离后回到队长旁） | — | ✅ | P1 | 半残（nav 依赖缺失的 route_walk） |
| 组队任务（同一任务/共享） | 带队接取 | 接取/同步 | P1 | 无（仅各自 start_ghost） |
| 队长召唤队员 | ✅ 召唤 | 响应 | P2 | 缺失（协议键在） |
| 踢人 / 移交队长 / 改名 | ✅ | — | P2 | 缺失（协议键在） |
| 拒绝邀请 / 拒绝申请 / 清空申请 | — | ✅ | P2 | 缺失（协议键在） |
| 主动退队 / 解散 | ✅ 解散 | ✅ 退队 | P1 | 有 |
| 队伍状态查询（服务端全量） | ✅ | ✅ | P0 | **无协议**（本地内存态，重启失忆） |
| 队伍聊天 / 提醒 | ✅ | ✅ | P3 | 无 |
| 队伍状态上报中控（心跳） | — | — | **P0（决策项）** | 已移除上报 |
| 中控：整队编排（不拆队） | — | — | **P0** | 完全没有 |
| 中控：队伍台账/落盘/展示 | — | — | P1 | 没有 |

> **P0' 的取舍见 §5 决策点 D2**：如果只做"组队容器 + 各自任务"，跟随可以先不做；要做"整队同图刷怪/暗雷"，跟随是硬前提。

## 4. 需求：中控侧（Go + 前端）

### 4.1 数据与接口
1. **队伍台账**（内存 + 落盘，仿 py `teams.json`）：`captain → {members[], mode(invite/apply), next_action(none/ghost/chain), all_present, since}`；
2. **队伍状态来源（决策项 D1）**：
   - 方案A：**中控自建台账**，只信机器人的 `team_ready/team_disbanded/team_rejoined` 事件（零机器人端改动，可热更/重启即生效）；
   - 方案B：**恢复机器人端 `m_team` 心跳上报**（数据更准，但属协议/上报层改动，不可热更、需重启验证）。
3. **命令下发**：`team_setup_captain/member/applicant`、`team_disband/clear/quit/status`（机器人端已支持，只差 Go 侧发）；
4. **HTTP 接口**：`POST /api/team/setup|auto_setup|disband|disband_batch`、`GET /api/team/status`（对照 py）；
5. **事件处理**：Go `event.go` 新增 `team_ready/team_disbanded/team_rejoined/team_return_nav` 四个 handler。

### 4.2 编排避让（**不拆队闸门**，逐项）
| 编排 | 需要的新行为 |
|---|---|
| 抓鬼/新手链候选 | `队长` 可派（带 `role=captain` + 策略）；**`队员` 一律跳过自动派发**（由队长的 next_action 驱动） |
| 手动「启动/自动分配」 | 按**队**成组下发；禁止只拉起半队 |
| 在线水位 | 压号**不压队长、不压队员**（或按整队计）；补号按"队"补 |
| 游荡池 | 组队号不进游荡候选；回收/补位排除队内号（对照 py：组队池排除游荡号） |
| 恢复引擎 | 队长重登 → **重建队**（等队员，超时先用已在线队员）；队员重登 → 等队长或重新入队；**不得单独补发 solo 抓鬼** |
| 卡死重登 | 同上；队长重登后触发队伍重建（否则整队失效） |
| 满额处理 | 队员满额是否继续跟随（决策项 D3）；队长满额 → 整队收工 or 换队长 |
| 暂停/停止 | 停队长 → 整队标记；停队员 → 询问是否踢/等 |
| 批量上下线 | 按队成组；队员下线不影响队长存活策略 |

### 4.3 前端
1. 主表：**队长/队员标记 + 队员折叠到队长行（树形）**（对照 `RobotTable.vue`）；
2. 筛选：新增"组队"桶（队长/队员/未组队）；
3. 组队控制页（对照 `TeamView.vue`：自动组队=每组人数/队伍数量/组队后任务/次数/模式；手动组队=队长下拉+队员多选；解散单队/批量/全部；队伍状态表）；
4. MapView：队伍维度（同队同色/同图提示）——P2。

## 5. 关键设计决策（**需要拍板**）

| # | 决策点 | 选项 | 我的建议 |
|---|---|---|---|
| **D1** | 队伍状态来源 | A 中控自建台账（信事件）｜B 恢复机器人心跳上报 | **先 A**（零协议改动、可快速验证）；B 作为后续增强 |
| **D2** | 功能边界 | ①"组队容器 + 各自任务"（不做跟随）｜②"整队同图行动"（含跟随） | **先 ①**（成本低、可先落"队员不拆队"闸门）；②另立一期 |
| **D3** | 队员满额/收工 | 继续跟随｜退出队伍转游荡｜整队收工 | 继续跟随（否则队伍随时残破）；由 `next_action` 决定 |
| **D4** | 组的粒度 | 固定小队（长期）｜临时组队（按任务组、用完即散） | 临时组队（对照 py：登记 intent，任务完即散） |
| **D5** | 拆队保护范围 | 全闸门（池+水位+游荡+恢复+重登）｜只做候选过滤 | **全闸门**（否则一出问题就拆队，前功尽弃） |

## 6. 分期落地建议

- **P0-验证（先做，不写代码）**：用 **py 参考侧（2300 实例，功能全、当前空闲）** 手工/半自动跑通 2-3 号组队，实测服务端语义：
  1. 组队后抓鬼是否**共享任务/加成**（队长/队员分别怎么走）；
  2. 半月岛暗雷组队**是否建出有效战斗**（对比单人空战斗）；
  3. 队员是否必须"同图同点"、跨图/离线如何处理；
  4. 快速归队的道具/元宝消耗口径。
  → **产出实测结论后再定 D2/D3/D4**；避免"代码写完发现服务端语义不是这样"。
- **P1-最小可用（Go + 前端 + 机器人缺口）**：
  - Go：队伍台账 + `/api/team/*` + 4 个事件 handler + **候选/水位/游荡/恢复的"不拆队"闸门**；
  - 前端：队伍列/筛选 + 组队控制页（对照 TeamView）；
  - 机器人端：补"队伍状态查询"（或明确接受内存态 + 重建逻辑）；修 `route_walk` 缺失（归队 nav）；
- **P2-期望增强**：跟随调度（对照 `team_follow.py`：300px/5s/15s 节流）、掉线重建、满额协调、召唤/踢人/移交/改名；
- **P3-业务编排**：组队抓鬼档（3-5 人，队长加成）、组队暗雷刷怪、组队门槛任务（普度众生/守护训练/修罗）、新手号带队。

## 7. 风险与不确定项（未证实，勿当结论）

1. **服务端组队语义未实测**：任务是否共享/加成是否生效/队长离线是否自动解散/队员要不要自己点钟馗 —— 目前只见于 py 注释与机器人端代码；
2. **组队抓鬼效率未知**（单人档 weight 1800 > 组队档 500；但队长加成与门槛任务另算）；
3. 机器人端邀请**10s 乐观自动确认**可能把"服务端没接上的队"当成已建队；
4. 队伍状态**重启失忆**（无全量查询协议）+ 心跳不上报 → 中控台账与真实队伍可能漂移；
5. `route_walk` 模块缺失 → 跨图归队实际不可用（只能快速归队，消耗道具/元宝）；
6. 三池编排拆队是**基于代码的推断**，未实测；组队上线前必须补齐 §4.2 闸门。
