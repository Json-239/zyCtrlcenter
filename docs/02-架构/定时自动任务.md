> 关联：[任务链路模块化设计](任务链路模块化设计.md) · [链数据](../05-运维/链数据.md) · [HTTP-API](../03-协议/HTTP-API.md)

## 1. 用户看到的是什么

面板「**任务**」页 = 三块：

| 区块 | 作用 |
|---|---|
| **定时自动任务** | 两套**互相独立**的策略：🆕 新手链 / 👻 抓鬼。各自：**保持在线数**（每轮只补差额）、间隔 + 随机抖动、每轮最多补几个、硬上限、没号时自动注册 |
| **号池分区** | 把号划成 **新手号池**（未毕业：等级<31 且未 `chain_done`）/ **抓鬼号池**（已毕业：≥31 或 `chain_done`）/ 未知（等级未上报）。**新手链只从新手池拉、抓鬼只从抓鬼池拉**（账号池页可筛选、每行带池标签） |
| **手动启动（固定任务）** | 一个按钮「按意图启动」：新手链号发 `start_chain`、抓鬼号发 `ghost_start`（带组装载荷）；低于抓鬼门槛的号跳过并给出原因 |
| **待恢复** | 钟馗对话卡死的号在这里排队等"自动重登 + 补发"，也可手动「取消恢复」 |
| （折叠）链数据 / 链路工具 | **高级**：链文件列表、模块视图、落点/网格检查 —— 排障用，平时不用看 |

> 固定任务只有两条（新手链、抓鬼），链数据是"提示表"由中控搬运/组装，**用户不需要理解文件**。
> 以后新增任务类型时，在 `internal/services/autotask` 加一个 `Kind` + 面板加一块即可。

## 2. 定时任务的运行口径

一轮（`Tick`，每 5 秒检查一次）：

```
到点（next_at）
  → 硬上限（MaxOnline）到了？      → 记一行"已达上限"，15 秒后再看（不硬拉）
  → **保持数达标了？（在跑 >= TargetOnline）** → 记"已达标，暂不补"，等下一轮
  → 差额 = TargetOnline - 在跑；从"该做但没在做"的候选里随机挑 N 个
       （N = BatchMin..BatchMax，且不超过差额；例：在跑 47 / 目标 50 → 本轮最多补 3）
      · 在线的号 → 直接下发任务
      · 离线的号 → 先 robot_manage add 上线，**等 8 秒**（等角色数据就绪）再下发
        （参考实现同款：太早发会被当"未登录缓冲"丢掉）
  → 没号可挑？
      · 开了"自动注册" → 按前缀/序号/后缀生成新号并注册（后台跑，下一轮自然被挑到）
      · 没开 → 记一行"没号可拉"，什么都不做
  → next_at = now + IntervalSec + rand(JitterSec)   // "5 分钟之内随机" = 基础 0 + 抖动 300
```

> **"在跑"的口径（2026-09-21 修正）**：抓鬼按**活跃抓鬼会话**计（机器人上报的 `ghost` 字段非空），
> 不是"在线 + 意图=ghost"。旧口径把"在线但没会话"的号（重连后命令没补发、卡在对话里的）
> 也算在跑 → 保持数虚高（实测 127 vs 真实 41），判定"已达标"不再补号，那批号永久空转。
> 新手链没有会话字段，仍按"在线 + 意图"计。

> **参数落盘（2026-09-21）**：每次 `start`/`stop` 把两套策略的配置与启用状态写
> `<DataDir>/autotask.json`；中控启动时自动读回，**只重新启用"上次是启用"的策略**
> （用户主动停过的保持停止）。没有这个的话重启后 `target_online` 全变 0、保持数失效。

**候选判定**（`internal/api/autotask.go`，与手动「启动」共用同一套判据）：

| 策略 | 候选条件（简化） |
|---|---|
| 新手链 | 该区**可用**、未被手动移除、没在跑、`同错<3`、**未毕业**（等级<31 且未 `chain_done`）、意图不是抓鬼 |
| 抓鬼 | 同上 + **已毕业**（≥31 级或 `chain_done`）**且过等级门槛**（`max(31, 服务端 required_level)`）+ 今日未抓满 |

## 2.1 号池分区（新手池 / 抓鬼池）

| 分区 | 判据 | 用在哪 |
|---|---|---|
| **新手池** | 等级 < 新手链阈值（默认 31）**且**未 `chain_done` | 新手链策略的候选；面板「账号池」可筛选 |
| **抓鬼池** | ≥ 阈值 **或** `chain_done` | 抓鬼策略的候选（再过等级门槛） |
| 未知 | 等级未上报且无记录 | 不参与（先把号上线跑一次，机器人报等级后自动归位） |

- **不额外落盘**：分区由"本地库 + 运行时状态"实时算（口径与意图判定同源），避免"库里标了新手、实际已毕业"的漂移。
- 面板两处可见：「任务」页每套策略下方（池标签 + 可用/在跑/目标）；「账号池」页的 `池分区` 下拉筛选与每行「新手/抓鬼」标签。
- **每轮只往对应池里拉号**：新手链只挑新手池、抓鬼只挑抓鬼池（含"离线待上线"与"在线空闲"两种）。

## 3. 抓鬼等级门槛（ghost_fit 最小版）

- **硬门槛**：等级已知且 `< max(31, 该号登记的服务端要求等级)` → **不派抓鬼**（即使 `chain_done`）。
  依据：参考实现生产实测 42 个 <31 级号被"链完成 → 直接抓鬼"派去点钟馗，服务端按等级门槛不理 →
  连点 15 次无对话 → 重登风暴（`services/ghost_fit.py` 的 `GHOST_LEVEL_FLOOR=31`）。
- **学到的门槛**：`ghost_offline.required_level` 登记进 `state.Robot.GhostRequiredLevel`，低于它的号不派
  （等级当天不会变，故不做当日失效）。
- **不静默**：被门槛拦下的号在 `/api/start` 的 `skipped[]`、定时任务候选数与日志里都看得见。

## 4. 卡死自动重登恢复（reghost）

机器人遇到钟馗对话卡死会**自己停止抓鬼**并在事件里说明"等中控重登后重新下发"
（`daily_ghost.py:441`）。中控侧补上这条链路（`internal/services/reghost`）：

```
error{code=GHOST_DIALOG_STUCK}  → Request(account)
   → 下线（robot_manage remove）→ 等机器人摘掉（或超时）
   → 重登（robot_manage add，密码只从池里取）→ 等上线
   → 上线后 8 秒 → 按意图补发（抓鬼：带组装载荷的 ghost_start）
   → done（保留 10 分钟供面板确认）；连续失败 3 次 → failed（交人工）
```

- **手动停止/下机时清除**（`POST /api/stop`、`robot_manage remove`、面板「取消恢复」）——
  否则会出现"我明明停了，它又被自动拉起来"（参考实现 `routers/ghost.py` 同款 `_PENDING_REGHOST.pop`）。
- 同一号在冷却期（300s）内重复报错只登记一次。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/autotask` | 两套策略的状态（配置/是否启用/**在跑·目标·缺口**/下一轮/最近 12 轮）+ 候选数 + **`pools`（两池可用数/在跑数/目标/缺口）** + 待恢复名单 |
| POST | `/api/autotask/start` | `{kind, target_online, interval_sec, jitter_sec, batch_min, batch_max, max_online, register_enabled, register_count, launch_delay_sec}`（可选鉴权）。`target_online` = **保持在线数**（0=不限，不按目标补） |
| POST | `/api/autotask/stop` | `{kind}`（可选鉴权） |
| POST | `/api/autotask/run` | `{kind}` 立即跑一轮（可选鉴权） |
| POST | `/api/reghost/cancel` | `{account}` 取消该号的自动重登恢复（可选鉴权） |

配置项（`CTRL_*`）：`CTRL_AUTO_REGISTER_PREFIX`（默认 `robot`）、`CTRL_AUTO_REGISTER_SUFFIX`（默认 `@xy3.com`）、
`CTRL_AUTO_REGISTER_PAD`（默认 7 位）；抓鬼门槛复用 `CTRL_NEWBIE_MAX_LEVEL`（默认 31）。

## 6. 与其它机制的关系

| 机制 | 管什么 | 什么时候动手 |
|---|---|---|
| 定时自动任务（本页） | **主动扩量**：按节奏拉起该跑的号 | 到点 |
| 恢复引擎（`restorer`） | **被动补发**：在线但没在跑的号，按意图补发（冷却/熔断） | 每 5 秒 |
| 卡死重登恢复（`reghost`） | **卡死自救**：钟馗对话卡死 → 重登 → 补发 | 收到卡死事件 |
| 意图判定（`intent`） | 该跑哪条链（等级/`chain_done`） | 心跳/上线/链完成 |

三者共用同一套判据与下发口径（`LaunchTask`），避免"两条链路各写一套"。

## 7. 已知限制

- 策略配置**不落盘**：中控重启后需重新启动定时任务（与参考实现一致；面板一眼能看到"已停止"）。
- 自动注册按"前缀 + 递增序号 + 后缀"生成；不做每日上限（按使用方要求），但受 `TestReport` 的
  建号批次上限（`createMaxBatch=20`/次）约束，注册在后台跑、失败逐个记日志。
- `done`/`failed` 的恢复记录保留 10 分钟后自动清理（面板确认窗口）。
