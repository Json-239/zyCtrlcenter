## 2. 决策记录（落地口径）

| # | 决策 | 理由 |
|---|---|---|
| 1 | 抓鬼导航数据缺失 → **硬失败**（不发任何命令） | 宁可明确报错，也不要"点一次没反应"（机器人端 8MB 行上限内，2.2MB 载荷可下发） |
| 2 | 「任务链」页的 nav 数据**保留可选**，只禁用「启动链」按钮 | 同一个下拉同时驱动"启动"和"看详情"；禁掉就再也打不开 `ghost_map_pos` 排障 |
| 3 | 测试数字**只有一处来源**：`go test -json` 实测 | 覆盖现状.md 曾出现"逐行相加 210、合计写 217"的漂移 |
| 3.1 | 抓鬼载荷**组装**（基座链 + 抓鬼专属），不要求一份 2.2MB 大文件 | 口径对齐参考实现 `services/chain.py:ghost_nav_payload()`：坐标/网格/路由复用新手链，抓鬼专属只需 `ghost_maps`/`ghost_map_pos`/`maps`（≈1.7KB）；链数据更新后抓鬼自动跟随，且**发送前硬校验地址齐不齐**（刷鬼图有网格、有落点） |
| 3.2 | `ghost_start` 补齐 `daily_limit` 与 `done`（有才带） | 与参考实现 `routers/ghost.py`/`intent_restore.py` 一致；`done` 让"重新下发不丢进度" |
| 4 | 补发命令**同命令 + 同链合并成一条** | 抓鬼载荷 2MB 级，逐号一条 = N×2MB 灌同一条控制通道 |
| 5 | 控制通道写失败 → **断开连接**（机器人重连） | 半行会与下一条命令粘连成非法行，机器人会把两条都丢掉（静默丢命令） |

## 4. 与首版计划的差异（审查修正）

首版计划有 4 处硬伤，落地时按下面口径修正（详见 §2 决策表）：

1. **模块口径唯一**：首版"`/api/modules` 全集 == `ModuleNames()`"与"页面 12 个模块"互相矛盾（`ModuleNames()` 只有 9 个动作模块）。现口径：动作层严格 == `ModuleNames()`；另外 3 项（chainlib/chainplan/编排）单独分层，总数 12。报告里的"19 个测试包"是**测试包**，与"模块"不是一回事。
2. **nav 数据可查看不可启动**：首版要在下拉里 disabled，会连带把"看详情"一起禁掉。
3. **载荷不放大 + 写失败不粘连**：首版只考虑了机器人端 8MB 单行上限；补发逐号一条 = N×2MB，且中控 5s 写超时留下半行会让后续命令静默丢失。现已合并下发 + 按载荷放宽写超时 + 写失败断连。
4. **非 auto 路径有落点**：首版 A3 要求"手选 `newbie_full` 给 ≥31 的号要提示"，但任务链页不传 auto、后端当时也不判断 —— 现在后端回 `warnings`，前端内联显示。

## 5. 复现方式

```bat
run_tests.bat                      :: 全量（vet + test + 竞态）——退出码汇总三者
go run ./tools/test_report         :: 生成报告 + 校验覆盖现状数字（不一致 → 非零退出）
go run ./tools/test_report -write  :: 把「用例数」列与合计回写进 覆盖现状.md
```

产物：`docs/04-测试/报告-YYYYMMDD.md`（人看）+ `data/test_report.json`（模块地图页读；`data/*` 不入库 → 新克隆显示"—"）。
客观闸门需要游戏服配置目录：`set ZY_GAME_CONFIG=<游戏服 config>`（默认 `F:\ZyBin\xm\2d-xiyou-server\config`）。

## 6. 未做项（记入待办）

- **`done`（抓鬼当日已完成次数）不下发**：机器人读 `cmd.get("done", 0)`，不带时走"服务端 task_limited 校准"分支；中控已有该状态（`state.Robot.Ghost`），需要时用 dict 形式下发（`{"账号": 次数}`）可减少一次校准往返。
- **`daily_limit` 不下发**：机器人默认 50，与产线口径一致；要改再加配置项。
- 大载荷 HTTP 拉取模式（`chain_id` + 机器人按 `GET /api/chains?id=` 拉）暂不做：当前 2.2MB 在 8MB 行上限内，且已合并下发。
