# 项目简介

## 这是什么

`zyCtrlcenter` 是**机器人中控骨架**：一个 Go 单二进制服务，负责

1. 通过 **TCP 控制通道**（默认 `:27200`，JSON-lines）接收机器人上报的事件、下发命令；
2. 通过 **HTTP API + WebSocket**（默认 `:28082`）把状态与日志提供给前端面板；
3. 把运行数据**按日期**落盘（运行历史 / 单机器人日志 / 应用日志）；
4. 可选地管理机器人进程（默认不接管）。

配套一个 Vue 3 简易面板（`web/`）和一个**完整的测试框架**（`test/`）。

## 边界：骨架层 vs 业务层

本项目的定位是「**能跑的骨架 + 可复刻的测试框架**」，不做业务决策：

| 层 | 本项目提供 | 由使用方实现 |
|---|---|---|
| 通道 | TCP 单连接接管、JSON-lines 收发、命令透传 | — |
| 事件 | 表驱动分发、状态映射、错误记账、落盘、WS 推送 | 业务动作（换号、冷却、资格判定、补位） |
| 状态 | 机器人状态容器（并发安全） | 业务状态（定时编排、游荡池、任务意图） |
| 数据 | 日期级日志（历史/单 bot/应用） | 账号库、数据库、链数据内容 |
| 链数据 | 文件驱动加载 + **原样透传** | 链数据文件本身（见 [链数据](../05-运维/链数据.md)） |
| 进程 | 拉起/停止/重启（默认不动外部进程） | 多开部署策略 |
| 接口 | 通用控制接口（status/logs/chains/start/stop/reset/robots/restart/ws） | 业务接口（账号、抓鬼、游荡、配置页…） |

> 设计原则：**中控只做搬运与记账，不做游戏逻辑决策**。机器人的执行由游戏服务端推送驱动，
> 中控下发的链数据只是「提示表」，不是指令序列。

## 关键特性

- **多区配置（服 → 区，单进程切换式）**：维护多个候选区（如同一 IP 的 2400/2300），
  面板可增删改与切换；「应用到机器人」把该区 `ip/port/编码` 写进机器人 `config.py`（只改三个键、写前备份），
  重启机器人即完成切区。运行时保持**一个机器人进程 + 一条控制通道**。见 [多区配置](../05-运维/多区配置.md)。
- **零第三方依赖**：只用 Go 标准库（含自研最小 WebSocket 实现 `internal/wsutil`），内网/离线可编译部署。
- **日期级日志**：`data/runs_YYYYMMDD.jsonl`、`data/bot_logs/<账号>/runs_YYYYMMDD.log`、`logs/ctrlcenter_YYYYMMDD.log`，
  带保留窗口清理与单文件熔断归档。
- **默认不接管环境**：不自动拉起、不杀机器人进程（`--auto-robot` / `--kill-robots` 显式开启）。
- **可选鉴权**：高危写接口支持 token，默认关闭（不破坏前端）。
- **测试框架**：`test/` 目录约定 + 共享基座 + 真实报文夹具（provenance 强制校验）+ 每模块 README + 一键运行。
