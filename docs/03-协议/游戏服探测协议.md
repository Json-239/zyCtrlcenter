# 游戏服探测协议（中控 ↔ 游戏服）

> 用途：面板「账号池」页的**可用性验证**——回答"这个号在某区到底存不存在、能不能用"。
> 中控**直接连游戏服**跑一遍登录协议，不经过机器人进程、不真正进入游戏（**无副作用**）。
> 相关：账号池与检索见 [账号库](../05-运维/账号库.md)，接口见 [HTTP-API](HTTP-API.md)。

- 通道：中控 → 游戏服 TCP，地址 = 区地址（`<host>:<port>`）
- 帧格式：`[type int32 LE][pblen int32 LE][body(pblen 字节)]`（**无加密**）
- 字段编码：`1/2/4/8` = 有符号整数 LE；字符串 = `[len int32 LE][编码后的字节]`
- 字符串编码：**跟随区编码**（`PROTOCOL_CODING`，见 §5）
- 单账号一条独立连接（互不影响）；批量时按并发上限并行
- 实现：`internal/gameproto`（帧编解码）、`internal/accountverify`（探测流程）、`internal/api/handlers_verify.go`（接口）
- 测试：`test/gameproto`（字节与参考实现逐字节对齐）、`test/accountverify`（假游戏服回放全链路）、`test/api`（HTTP 链路 + 写回账号池）

## 1. 时序

```
中控                                                 游戏服
 │── 100 MC_CONNECT（空体） ─────────────────────────▶│
 │◀─ 200 S2C_CONNECT_QUERY（空体）───────────────────│  服务端问"你在吗"
 │── 255 MS_CONNECT_BACK [200] ─────────────────────▶│  回 200 = 握手确认
 │◀─ 255 MS_CONNECT_BACK [200] ──────────────────────│  （双向，两端各发一次）
 │── 101 MC_VER [版本号] ───────────────────────────▶│  版本验证
 │◀─ 400 S2C_VER [retcode, msg] ─────────────────────│  retcode=0 才继续
 │── 102 MC_LOGIN_LANGQI [账号, md5(明文密码)] ──────▶│  登录（密码先 md5，小写 hex）
 │◀─ 300 S2C_ACK_ACCOUNT [retcode, msg] ─────────────│  登录验证结果（见 §3）
 │     仅当 retcode=0 且 query_role=true：
 │── 1000 C2S_QUERY_ROLE [0] ───────────────────────▶│  查角色（不选角色，不算进入游戏）
 │◀─ 90132 S2C_QUERY_ROLE [数量, (角色…)] ───────────│  拿角色名/等级/转生
```

> 实现是"收到就回、无关帧忽略"的循环（不依赖严格先后），并受**总超时**与 `context` 双重约束。

## 2. 消息表

| 消息号 | 名称 | 方向 | 字段 | 说明 |
|---|---|---|---|---|
| 100 | `MC_CONNECT` | C2S | — | 握手（空体） |
| 200 | `S2C_CONNECT_QUERY` | S2C | — | 服务端连接查询 → 客户端回 `255 [200]` |
| 255 | `MS_CONNECT_BACK` | 双向 | `[4]` | 握手回包；收到后客户端发 `101 [版本号]` |
| 101 | `MC_VER` | C2S | `[""]` | 版本验证（版本号字符串，默认 `58740022`） |
| 400 | `S2C_VER` | S2C | `[4, ""]` | 版本返回；`retcode=0` 通过，否则中止 |
| 102 | `MC_LOGIN_LANGQI` | C2S | `["", ""]` | 登录 `[账号, md5(明文密码)]`（md5 小写 hex） |
| 300 | `S2C_ACK_ACCOUNT` | S2C | `[4, ""]` | 登录验证返回（见 §3） |
| 1000 | `C2S_QUERY_ROLE` | C2S | `[4]` | 查角色 `[0]`；仅登录成功后发 |
| 90132 | `S2C_QUERY_ROLE` | S2C | 变长 | 角色列表（见 §4） |

## 3. 登录返回码（`300` 的 `retcode`）与判定

| retcode | 含义 | `exists` | `usable` | 说明 |
|---|---|---|---|---|
| `0` | 登录成功 | ✔ | ✔ | 该区可用；可继续查角色拿角色名/等级 |
| `100` | 账号不存在 | ✘ | ✘ | 该区没有这个号（面板显示「不存在」） |
| `200` | 密码错误 | ✔ | ✘ | 号存在但密码不对——**不能算可用**，否则会被定时上线反复拉起 |
| `300` | 账号被冻结 | ✔ | ✘ | 同上 |
| 其它 | 未预期 | ✔ | ✘ | 说明里带上原始 `retcode`，便于对协议 |

判定规则（`internal/accountverify`）：

- `exists` = 服务端明确表示号存在（`0/200/300/其它非 100`）
- `usable` = **仅 `retcode=0`**（真正能登录进去）
- 网络/超时/编码/解析错误 → `Err` 非空，**两者都不置真**，且**不写回账号池的可用性结论**（只记一条 `验证失败：…`）

## 4. 角色列表 `90132` 的字节布局

```
数量 int32
└ 每个角色（按顺序重复"数量"次）：
    role_id     int32
    role_index  int16
    role_name   字符串（[len int32][编码字节]）
    role_level  int16
    role_turn   int8
    外观        int32 × 4   （发型/发色/脸型/脸纹，中控不关心但必须跳过）
    contour     int32 数量 + 数量 × int32
```

- `数量 <= 0` → 无角色（**不算错误**，面板显示「无角色」）
- 中控只取**第一个**角色（角色名 + 等级 + 转生）用于展示与选号
- 字段不足/长度越界 → 报错（不返回半条数据）

## 5. 编码与版本号

| 项 | 规则 |
|---|---|
| 字符串编码 | 跟随**区编码**（`zones.json` 里服/区的 `coding`，默认 `UTF-8`）。编码不一致 → 中文乱码，账号判断可能全错 |
| `GBK` | **明确报错**（`ErrUnsupportedCoding`）而不是静默乱码：本实现为零第三方依赖（纯标准库），未内置 GBK 表。该区需要 GBK 时先把区编码改成 `UTF-8`，或按 `internal/gameproto/gameproto.go` 的 `encodeStr/decodeStr` 接入编码表 |
| 版本号 | `101` 里发的是**客户端协议版本**，默认 `58740022`；可用环境变量 `CTRL_GAME_VERSION` 或接口参数 `version` 覆盖 |
| 密码 | 请求里没给 → 取账号池里该账号的密码 → 再退到默认密码（`123456`）；下发前一律 `md5(明文)` 小写 hex |

## 6. 批量与资源约束

| 项 | 默认 | 上限 | 说明 |
|---|---|---|---|
| 并发 `concurrency` | 2 | 16 | 每个账号一条独立连接 |
| 单账号超时 `timeout_sec` | 8s | 30s | 握手/登录/查角色共享这条总超时 |
| 单次账号数 | — | 200 | 超过直接拒绝（提示分批） |
| `query_role` | `true` | — | 关掉可少一轮交互（只判可用性） |
| `persist` | `true` | — | 结果写回账号池（**只对池内账号生效**，池外不凭空建档） |

### 6.1 两种验证模式（接口层）

| 模式 | 触发 | 行为 |
|---|---|---|
| **同步** | 请求带 `accounts`（1 个或几个） | 当场返回 `results`（面板"手输账号单独验"走这条） |
| **批量任务**（默认） | 请求**不带** `accounts` | 从**账号池**按 `zone` 选号 → 后台跑 → `job` 进度可查、可停 → 结果**逐条同步回池** |

批量选号范围（`scope`，都是"池里该区该状态"的号）：

| scope | 含义 | 典型用途 |
|---|---|---|
| `unverified`（默认） | 该区**有记录**、但还没验证过 | 日常补验（新导入/新增到该区的号） |
| `unusable` | 该区已验证但"存在却不可用" | 重验看是否恢复（例：密码改过、解冻） |
| `unknown` | 该区**没有任何记录**的号 | 探明"这个区到底有没有它"（量大，按 `limit` 分批） |
| `all` | 池内全部 | 兜底 |

> 口径要点：**"该区的账号" = 池里有该区状态记录的号**。没记录的号不会混进默认范围——
> 否则一次点击就会把整池（几千个）卷进去。数量预览见 `GET /api/accounts/stats` 的 `pending`。
> 正在线跑着的号默认跳过（`skip_online=true`，它们已经证明能登录），跳过了谁会在 `skipped_online` 里列出来。
> 任务相关接口（进度/停止）见 [HTTP-API](HTTP-API.md) §1。

## 7. 错误语义（写回账号池时）

| 情况 | 结果 | 账号池里写什么 |
|---|---|---|
| 正常返回（含 100/200/300） | `Err=""` | `verified=true`、`usable`=判定值、`msg`=说明（含角色/等级）、`verified_at`=本次时间 |
| 连接失败 / 超时 / 版本失败 / 编码不支持 / 解析失败 | `Err` 非空 | 只写 `msg="验证失败：<原因>"`，**不动** `usable`（避免一次网络抖动把好号标坏） |

## 9. 注册协议（建号）

用途：**新建账号**（面板「账号池 → 建号」）。握手/版本同上，之后：

| 消息号 | 名称 | 方向 | 字段 | 说明 |
|---|---|---|---|---|
| 106 | `C2S_GET_REGISTER_IDENTIFYING_CODE` | C2S | — | 取注册验证码 |
| 702 | `S2C_GET_REGISTER_IDENTIFYING_CODE` | S2C | `[""]` | 验证码（汉字串，**原样回传**） |
| 104 | `C2S_REGISTER_ACCOUNT` | C2S | 8×字符串 | `[验证码, 账号, 密码, 确认密码, 激活码, 姓名, 身份证, QQ]` |
| 700 | `S2C_REGISTER_ACCOUNT` | S2C | `[4,4,4]` | `[db_ret, err_item, errid]`；`db_ret=0` = 成功 |

**流程（先验证、再注册）**：先定密码（请求给的 → 库里该服的 → 随机生成），再跑一次**登录探测**：

| 探测结果 | 动作 |
|---|---|
| `ret=0` | 账号已存在且密码可用 → **跳过注册**，写回池（可用 + 角色/等级） |
| `200/300` | 账号存在但密码不符/冻结 → **不注册**（注册必回 111），标"存在但不可用"并提示改密码/删号重建 |
| `100` | 该服没有这个号 → 走下面的注册流程（106 → 104） |
| 出错（网络/超时/编码） | **不注册**（避免重复建号），也不改动库里的可用性结论 |

**账号名怎么来（按编号，同 py 中控的用法）**：`前缀 + 序号(补零) + 邮箱后缀`，
如 `robot000` + `3004` + `@xy3.com` → `robot0003004@xy3.com`；补零宽度默认按最大序号位数自动算，
也可显式指定；`auto_start=true` 时起始序号 = **池内同前缀最大序号 +1**（不撞已有账号）。
一次最多 200 个，按 `batch_size`（每批）+ `concurrency`（批内并发）跑。

**脏密码**：库里若是 py 时代的老密码（长度不合服务端 6~20 规则）→ 建号时**改用新的随机密码**
并把新密码写回库（否则拿它去注册必然失败，还说不清原因）。

| errid | 含义 | 处理 |
|---|---|---|
| 110 | 注册成功 | 把该号与**随机密码**写进账号库（该区） |
| 111 | 用户名已存在 | 不写库，提示换名 |
| 112 | 服务端处理失败（多为同 IP 注册过频=风控） | **退避重试**（`retryable=true`） |
| 116 | 验证码出错 | 重新取码再来 |

**密码规则**：没有"统一密码"，且**同一个服内通用**（`zones` 里同 host 的区共享一个密码），
查找顺序：精确区 → 同服其它区 → 账号级（老数据）；其余情况按 §9 的流程生成 **16 位随机密码**
（剔除 `0/O/1/l/I` 等易混字符），注册成功后写进账号库该区 `zones["<host:port>"].password`；
此后**验证 / 登录 / 批量上线一律用库里这个密码**（取不到就明确报错，绝不拿默认密码去试）。
实现：`internal/accountcreate`（`Register` / `NewPassword`）。
