# 协议总则

> 本目录是**事实协议（单一事实源）**：新增/修改任何命令、事件、API 必须先改这里的表，再改代码。
> 面板「协议映射」页（`GET /api/protocols`，数据在 `internal/api/protocols.go`）是本目录的同步副本。

## 1. 三套协议

| 协议 | 通道 | 帧格式 | 文档 |
|---|---|---|---|
| **控制通道**（中控 ↔ 机器人） | TCP `127.0.0.1:27200`（可配） | UTF-8 JSON + `\n`；**上行**单行 ≤64KB、**下行**可带 2MB 级链数据载荷；**单连接**（新连接接管旧的） | [控制通道协议](控制通道协议.md) |
| **前端协议**（中控 ↔ 面板） | HTTP `127.0.0.1:28082` + WebSocket `/ws` | HTTP JSON（UTF-8）+ WS 文本帧 | [HTTP-API](HTTP-API.md) |
| **游戏服探测协议**（中控 ↔ 游戏服） | TCP 到游戏服 `IP:端口`（按区） | 二进制 `[type int32][pblen int32][body]`；字符串 = 长度前缀 + 编码字节 | [游戏服探测协议](游戏服探测协议.md) |

方向约定：
- 控制通道：中控 → 机器人是**命令**（`cmd` 字段）；机器人 → 中控是**事件**（`type` 字段）。
- 中控对命令与链数据**只做透传**，不做业务改写（保证机器人端协议演进不被中控卡住）。

## 2. 设计约束

1. **单连接语义**：同一时刻只服务一个活跃机器人连接（多进程部署时，一个机器人进程连一个中控实例）。
2. **读写不互相阻塞**：读侧只做「解析 + 入队」（容量 8192）；写侧超时按载荷放宽（5s + 每 256KB 1s，上限 60s），**写失败断开连接**（避免半行把后续命令粘成非法行）。
3. **非法输入不致命**：非法行/超长行直接忽略；处理事件 panic 被兜底捕获并记日志。
4. **失败必须可解释**：下发失败时接口返回 `ok=false` + 原因（通道未连接 / 进程缺失）。
5. **未知事件 fail-loud**：未注册的事件类型也会写运行历史，便于排查机器人端新增事件。

### 骨架版的取舍（相比参考实现 Python 版）

- **保留**：`start_chain` / `stop` / `reset` / `status` / `robot_manage` / **`ghost_start`（抓鬼带导航数据，2026-09-21 起）**；全部事件类型（表驱动全覆盖）。
- **暂不提供**：`ghost_stop`（机器人端 `stop` 内部会兜底停抓鬼）、`random_walk(_stop)`、`fpp_sync`、`ping` 等业务/可选命令——
  使用方需要时按 [扩展指南](../02-架构/扩展指南.md) 自行新增（命令就是 `SendCmd(map)`，一行的事）。
- 事件处理只保留**通用语义**（状态映射/记账/下机），业务动作（换号/冷却/资格）由使用方实现；
  详见 [事件与数据流](../02-架构/事件与数据流.md) §2-§3。
