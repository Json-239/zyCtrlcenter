# 控制通道协议（中控 ↔ 机器人）

- 通道：TCP **一条**（默认 `127.0.0.1:27200`，`--ctrl-port` / `CTRL_CTRL_PORT` 可改）
- 帧格式：UTF-8 JSON + `\n` 结尾；**上行**（机器人→中控）每行 ≤64KB，**下行**（中控→机器人）命令可带 2MB 级链数据载荷（如抓鬼导航数据 2.2MB）
- 连接：**单连接**（新连接接管旧连接）；断线不影响面板（状态保留最后快照）
- 区标记：通道在事件入队时打 `_zone` = **当前区**（`"<服key>/<区key>"`，切区时由接口更新）
- 实现：`internal/ctrl/server.go`、`internal/services/event/event.go`
- 配置：`data/zones.json`（服/区定义），接口 `/api/config*`，详见 [多区配置](../05-运维/多区配置.md)

## 1. 命令（中控 → 机器人）

| 命令 | 关键载荷 | 说明 |
|---|---|---|
| `start_chain` | `chain_id` + `chain?{…}` + `accounts?` | 启动/续跑链。`chain` 可省略——中控没找到链数据文件时只下发 `chain_id`，由机器人端决定怎么跑 |
| `ghost_start` | `chain_id` + `chain{…}` + `role:"solo"` + `daily_limit` + `done?{账号:已抓次数}` + `accounts` | 钟馗抓鬼日常：**必须带导航数据**（`npcs`/`map_grids`/`dijkstra`/`ghost_maps`/`ghost_map_pos`），不带 = 机器人拿不到刷鬼图与落点 → 原地不动。中控侧载荷是**组装**出来的（基座链的坐标/网格/路由 + 抓鬼专属的刷鬼图/落点，口径同参考实现 `ghost_nav_payload`），缺失或地址不全即**硬失败**（`ok:false`，一条命令都不发） |
| `share_daily_start` | `share_key` + `chain_id` + `chain{…}` + `daily_limit` + `done?{账号:已做次数}` + `accounts` | **分享日常**（2026-09-23 接入，P0 = 大唐神捕 `share_daily_大唐神捕`）：与 `ghost_start` 同构；载荷同样由中控**组装**（基座链 `newbie_full` 的坐标/网格/路由 + 声明文件 `shenbu_nav` 的 `task_order` 等），`task_order` 必须列全分支任务号（少列会让后续环节被当"链外任务"静默忽略）；缺失/形状不对即硬失败 |
| `share_daily_stop` | `accounts` | 停止分享日常（停策略时中控给在跑的号收工；否则号会一直跑到日限） |
| `stop` | `accounts?` | 停链（机器人保持在线） |
| `reset` | `accounts?` | 重置重跑 |
| `status` | — | 心跳，中控每 3 秒下发，机器人回 `status_reply` |
| `robot_manage` | `action:"add"｜"remove"` + `accounts` | add：`accounts=[[账号,密码],…]`；remove：`accounts=[账号,…]` |
| `reload_scripts` | `modules?["quest_engine",…]` | 脚本热更（2026-09-21）：机器人进程内 `importlib.reload` 指定模块，**免重启**就能把脚本补丁铺到现场（`POST /api/robot/reload_scripts`）。注意会重置模块级缓存（导航链/网格，下次收到带 `chain` 的命令会重新填充）；建议任务间隙触发 |

命令由 `event.SendCmd(cmd, action)` 统一发送：JSON 序列化 → 写入唯一连接（写超时按载荷放宽：基础 5s + 每 256KB 加 1s，上限 60s；**写失败断开连接**等机器人重连，避免半行与下一条命令粘连成非法行）→ 返回布尔。
失败时接口返回 `ok=false` 并给出原因，同时写一条应用日志。**中控不改写命令内容**（原样透传）。

**单进程语义**：同一时刻只服务一个机器人进程；要切到另一个区，走
「切换当前区 → 应用到机器人（改 config.py）→ 重启机器人」（见 [多区配置](../05-运维/多区配置.md)）。

### 链数据的三条来源（`POST /api/start`）

| 优先级 | 来源 | 行为 |
|---|---|---|
| 1 | 请求体带 `chain` | 原样下发（`chain_source=request`） |
| 2 | `data/chains/<chain_id>.json` | 加载 + 缺省补齐后下发（`chain_source=file`） |
| 3 | 都没有 | 只下发 `chain_id`（`chain_source=none`） |

> **导航数据不是链**：`task_order` 为空的文件（如 `zhongkui_nav.json`，抓鬼用）在面板里标 `nav_only`，
> 手选它启动会被接口层直接拒绝（`ok:false, nav_only:true`）——它只能由「启动」自动分配随 `ghost_start` 下发。

> 链数据文件的内容（含 `ghost_map_pos` 之类中控不认识的字段、以及不同形状的 `npcs`/`dijkstra`）
> 会**原样透传**，实现见 `internal/chainlib/passthrough.go`。

## 2. 事件（机器人 → 中控）

> 「处理」列对应 `internal/services/event/event.go` 的 `handlers()` 表；
> `TestEventTableCoversProtocolSpec` 强制要求下表每个事件都有分支。

| 事件 | 关键字段 | 处理 |
|---|---|---|
| `hello` | `robot_version`、`pid` | 记应用日志（握手） |
| `robot_online` | `account`、`role_name`、`level`、`mapid` | 清已移除标记 → 建行置 `ONLINE` → 落历史 |
| `robot_offline` | `account` | 置 `OFFLINE`、清握手标记 |
| `status_reply` | `server`、`robots:[{account,state,task_index,done,chain_done,role_name,level,mapid,fight,online,pos,fpp,role_id,ghost,ghost_target,hp,mp,bag,equip,summons,booth,walk,route,daily,hs,err_code,err_ts}]` | 全量映射状态表 + 记录游戏服地址；**不落历史**（每 3 秒一条，量太大）。`daily` = 分享日常进度 `{share_key,done,limit,state}`（或数组，多日常）；老版机器人不带 → 判据按"未知"保守处理（不判新日常） |
| `robot_manage_reply` | `result:{added:[],removed:[]}` | 落历史 |
| `task_progress` | `account`、`done`、`task_index` | 更新进度 + 落历史 |
| `robot_state` | `account`、`state`、`task_index`、`done`、`mapid`、`pos`、`hp`、`mp`、`bag`、`equip`、`booth` | 更新快照（未带 `booth` = 已不摆摊，清残留）+ 落历史 |
| `robot_pos` | `account`、`mapid`、`x`、`y`（像素） | 即时更新状态（含格子坐标）；100ms 合并为 `robot_pos_batch` 推 WS（不逐条广播、不落历史） |
| `chain_done` | `account`、`chain_id`、`already_done?`、`done?` | 置 `DONE` + `chain_done=true`；`AutoRemoveOnDone` 且非 `already_done` → 下机 |
| `ghost_done` | `account`、`done`、`limit`、`reason` | 落历史 + 可读日志；`AutoRemoveOnDone` → 下机（业务处置由使用方实现） |
| `ghost_offline` | `account`、`code`、`reason`、`required_level?` | 同上 |
| `error` | `account`、`code`、`msg`、`task_index?` | 记 `err_code`/`err_ts`/`err_repeat`（同码累计）+ 落历史 |
| `log` | `account?`、`level`、`msg` | 落历史；`level=debug/trace` 不推 WS |
| `pong` | — | 无处理 |

**下机语义**（`AutoRemoveOnDone=true`，默认开启）：标记已移除（心跳不复活）→ 删行 →
异步通知 `robot_manage/remove`。详见 [事件与数据流](../02-架构/事件与数据流.md) §3。

## 3. JSON 示例

```json
// 命令：启动链（链数据来自文件）
{"cmd": "start_chain", "chain_id": "newbie_full",
 "chain": {"chain_id": "newbie_full", "name": "新手链", "start_task": 7001001, "end_task": 5010105,
           "npcs": {"13035": [[12, 3931, 882]]},
           "task_hints": {"7001115": {"executor": "shop_purchase"}},
           "task_order": [{"task_index": 7001001, "name": "天命所归", "catcher_npc": "10103", "next": [7001002]}],
           "grid_cell": 16, "map_grids": {}, "dijkstra": {}},
 "accounts": ["robotA"]}

// 命令：动态添加机器人
{"cmd": "robot_manage", "action": "add", "accounts": [["robotA", "123456"]]}

// 事件：状态心跳（status_reply 不落历史）
{"type": "status_reply", "server": "1.2.3.4:2300",
 "robots": [{"account": "robotA", "state": "DIALOG", "task_index": 7001005, "done": 3,
             "chain_done": false, "role_name": "测试", "level": 21, "mapid": 5,
             "online": true, "pos": [1200, 800], "hp": 2400, "hs": true}]}

// 事件：任务出错（面板「任务失败待处理」数据源）
{"type": "error", "code": "TASK_STUCK", "msg": "任务 7001130 商店购买重复 4 次未入包",
 "task_index": 7001130, "account": "robotA"}

// 前端实时推送：位置合并
{"type": "robot_pos_batch", "list": [{"account": "robotA", "mapid": 9, "x": 100, "y": 200}]}
```

## 4. 状态字段（`/api/status` 的 `robots[]`）

`account / online / state / task_index / done / chain_done / role_name / level / mapid / fight / pos / fpp /
role_id / ghost / ghost_target / hp / mp / bag / equip / summons / booth / walk / route / hs / err_code /
err_ts / err_repeat / err_msg / last_task / last_seen`

- `hs` = 游戏服握手完成（≠ 登录成功）；下线即清位。
- `err_code` / `err_repeat` = 最近一次「任务做不下去」的原因与重复次数（面板据此提示待处理）。
- 状态枚举（机器人上报原样透传）：`WAIT_TASK`/`NAV`/`CLICK`/`DIALOG`/`FIGHT`/`SHOP`/`ALLOC`/`WAIT_NEXT`/`DONE`/`ERROR`/`IDLE`/`ONLINE`/`OFFLINE`。
- **坐标口径**：`pos` = 服务端**像素**（机器人上报原值）；`pos_grid` = **客户端格子坐标** = `pos / grid_cell`（默认 16，向下取整）。
  面板显示格子，像素放在 title；地图名靠 `GET /api/maps`（mapid → 中文名），详见 [坐标与地图](../05-运维/坐标与地图.md)。
