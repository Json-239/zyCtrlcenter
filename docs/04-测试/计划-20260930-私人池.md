# 计划-20260930 私人池（个人号独立池 + 手动执行）

> 需求方：用户；勘查：pool-fix-go（报告 `分析-20260930-私人池实施前勘查.md`，commit 722d8f3）
> 状态：**待用户过目确认**（3 个待拍板项见 §6），确认后进入实施批

## 1. 需求与口径（用户已拍板）

1. **私人池 = 显式标记**：用户在面板"添加账号"时勾选"私人池"；支持对已有号移入/移出。
2. **编排隔离（硬约束）**：私号不参与一切自动编排——水位器（选号/压号）、自动任务（抓鬼/新手/神捕/烽火/孵化）、游荡池、恢复器（意图补发+离线定向补拉）、重登恢复、组队派发、重启补号、自动下机等**全部不碰**。
3. **上/下线手动**：中控不为私号保持在线（不保活、不回收、不压号、满额也不自动下机）。
4. **任务手动单独执行**：覆盖 **抓鬼 / 神捕 / 烽火 / 新手链** 的单独启动与停止；**游荡不做**手动入口。
5. **同机器人进程**跑（只做编排隔离，不做物理隔离）。
6. **链路去掉"整理背包与物品使用"**：用户认为现有物品使用逻辑不成熟；私号默认关"整理/使用/丢弃/穿装备/扩容"，**自动吃药保留（用户拍板："自动吃药肯定是要的"）**——细节见 §4。
7. **空闲处置（用户拍板）**：私号空闲时**只摆摊**（不游荡）——禁止机器人端自动游荡，空闲→自动摆摊（复用现有 booth 链路）。
8. 在线统计口径：私号在线**显示但无作用**（不计入水位目标/本地读数/池统计）。
9. 首个私号已定：`zhihe239`（角色"帅是入场卷"，65 级）；背包/装备解读已完成（见分析小节/对话记录），作为"关哪些"的依据。

## 2. 现状差距（为什么需要这组闸）

- 现在号池（新手池/抓鬼池）是**按等级推导**的（`handlers_accounts.go:528 poolOf`），没有"来源/归属"维度——手动加的号一上线即被自动机制当候选抓走（勘查含 6 条典型链路复述）。
- 账号库 `accounts.json` 会被 `tools/import_accounts.py` **全量重建**——故私人标记**不能**放 Account 字段（每次导入被清），须独立注册表。

## 3. 设计方案（MVP）

### 3.1 注册表与判据
- 新增 `data/personal_pool.json`（账号名列表；原子写；启动加载；删号时清标记）。
- `IsPersonal(name)`；`poolOf` 首行加 `personal` 分支（覆盖推导）；`poolUsable` 自动排除。
- 新接口：`POST /api/personal/add|remove {accounts}`（移入/移出）；`GET /api/personal`（列表）。
- 面板"添加账号"透传勾选 → 添加成功后自动入私人池；删除账号同步清标记。

### 3.2 排除闸口（14 条，逐条 file:function:line 见勘查报告 §2）
水位候选/压号视野/本地读数；autotask 全 kind 候选（一行加在候选循环首部）；restorer Skip（同时挡住新上的离线定向补拉）；reghost 三处；游荡池视野；组队 drop；A+C 重启补号；自动下机 removeAccount；意图作废（event 侧，main 注入 `SetPersonalPool`，模式同 SetLevelSync）；startAuto 手动分配同点剔除。

### 3.3 手动执行（薄端点，不写台账/配额）
- 新增 `POST /api/personal/task {accounts, task(ghost|shenbu|fenghuo|newbie), action: start|stop, ensure_online?}`：
  - start：复用既有命令构造（抓鬼 `ghostStartCmdOf`；神捕/烽火抽 `shareDailyStartCmdOf`；新手链 `start_chain`）**直发机器人**；`ensure_online=true` 时先走 robots/manage add（手动语义，绕配额）。
  - stop：用机器人现成 `ghost_stop` / `share_daily_stop` / quest `stop`。
  - 全程**不写**在途/配额/台账；但走标准 SendCmd 通道（不绕机器人协议）。
- 上/下线复用现成 `/api/robots/batch(force)` 与 `/api/robots/manage`。

### 3.4 前端
- `AccountsView`：添加表单加"私人池"勾选并透传；`POOL_LABEL` 与主表标签加"私人"；行操作加"移入/移出私人池"。
- 新增**「私人池」操作卡**（参照 Dashboard 组队卡先例）：私号列表（在线/状态）+ 行内上/下线 + 任务下拉（抓鬼/神捕/烽火/新手链 启停）。
- `TasksView` 私号明细加标注（小改）。

## 4. 背包/物品行为（口径已定稿）

- 目标：私号链路**不整理背包、不使用物品、不丢弃、不穿装备、不自动扩容**（默认全关）；**自动吃药保留**（heal 链 + 金创药/昙花霜，用户拍板）。
- 机器人端行为点（关闸位置）：`daily_ghost.__tidy_bag`（整理/使用）、`auto_summon._try_bag_cleanup`（buff 使用+低等级装备丢弃）、`bag_ops.auto_use_bag_expanders`/`auto_equip_best_items`（扩容/穿装备）、`share_daily` BAG_FULL 清理、新手链内背包动作；heal 链保留。
- **私号标记投递机制**（机器人端如何得知）：建议 ctrl 在启动/添加命令里携带 `personal` 标记 → 机器人按号记 flag（拿不到标记时按"机器人模式"兜底）；备选=私号名单随心跳通道下发。待勘查追加块定稿。
- 已知关闭后果：背包满时任务可能停摆（私号由用户手动管理）、装备不自动穿——均属预期，写入操作卡提示文案。
- **首号解读（zhihe239）实证了用户判断**：现有 tidy/整理逻辑会"使用"药品类（雪参丸/百合散/玉藕膏/凝血丹/御赐护命丹等会被当可消耗品吃掉）、会有低等级装备丢弃与自动换装面——私人模式全关正确。
