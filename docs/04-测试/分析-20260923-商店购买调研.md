### 3.4 关键约束

1. **会话货架全局唯一**（`role_session.sale_index`，点任何商店选项都会被改/覆盖）
   → 买药、领助战令、任务购买**不能并发**，否则 `sale_entry/get_goods_object` 取不到 → **静默失败**。
2. `goods_index` 是**页面内索引**（不是 item_index），每次 `SALE_GOODS` 到达都必须重新查找（旧实现坑已修）。
3. 储备金字段：`COOKIE_SCHOOL_CONTRIBUTION(9617)`，机器人心跳上报为 `reserve`（`internal/state/state.go:46`），
   机器人脚本已解析到 `robot_object.m_reserve`（msghandle.py L1394-1428，2026-09-23 落地）→ **买前可判余额**。

`GET http://127.0.0.1:28082/api/status`（机器人端 90353/90073 同步的实时值，2026-09-23 实测）：

- robot0001023 事发时 reserve=**449,652**（买 20 个金创药只需 4,220）→ **钱绝对不是失败原因**。

### 6.2 流程 / 状态机（串行 + 可观测）

```
IDLE
 └(需要物品 & m_reserve >= 预算)→ LOCK_SHOP（全局商店会话锁，与领令/任务购买互斥）
    → NAV(npc 候选) → CLICK_NPC(等待 SHOW_DIALOG) → CLICK_OPTION("储备金购买")
    → WAIT_SALE_GOODS(90099) → 重查 goods_index（找不到→上报 GOODS_NOT_FOUND）
    → BUY(80108 [npc, goods_index, count])
    → WAIT_ACK：成功判据（任一） ① 通知 1110 金额 == 单价×数量
                                 ② 通知 1276 且 item 匹配
                                 ③ 背包数量增量 >= count（90398 或轮询 m_bag_cache）
      失败判据：通知 552/63/1248/1255/1278/1290/1295 → 记原因 + 退避(180s) + 上报中控
      超时：关对话 → 重开商店（上限 3 轮）→ 仍失败上报 STUCK
    → UNLOCK_SHOP → 使用/继续任务
```

### 6.3 必须写进实现的约束

1. **串行化**：同一号同一时刻只允许一个商店流程（重写后把 daily_ghost 买药、助战令、任务购买统一到一条"商店会话"管线）。
2. **买前判余额**：读 `robot_object.m_reserve`（9617 同步）≥ 单价×数量，否则等每日福利/放弃。
3. **数量分批**：单次建议 ≤10（首单可 1 个探活）；凑数用多次购买累计，避免一次被 1278/1290 拒。
4. **通知识别全覆盖**：1110（受理）、1276（到货）、552/63/1248/1255/1278/1290/1295（拒绝原因）+ 中控上报。
5. **失败可见**：当前 daily_ghost 完全不看通知（"商店流程收到未识别通知"本身就是缺口），重写必须映射原因。
6. **NPC 兜底顺序**：药品 13011（616/11）→ 13222 阿迪亚（37）；杂货 13021（612/11）→ 13008（5）→ 13220（37）；
   **移除 13031（不卖货）**。
7. `goods_index` 每次页面重查；点选项用"关键词匹配 + 非关闭项"双保险（不要写死 index，虽然实测=0）。

| 风险 | 触发场景 | 处置 |
