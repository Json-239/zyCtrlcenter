## 一、为什么要改（用户原话）

> 我感觉当前的大屏并不能让我直观的知道当前机器人再做什么，比如：**完成 / 这一轮跑完了 / -- · 52跑完** —— 做个跑完是什么跑完了，**新手链路跑完还是抓鬼上限跑完了**，**新手/抓鬼都看不见进度**

三个痛点一一对应：

| 用户看到的 | 屏幕上的真相（改前） | 为什么看不懂 |
|---|---|---|
| `-- · 52 跑完` | `task_index=0 → "--"`、`done=52`、`chain_done → "跑完"` | 任务列只显示**裸数字 + 一个没主语的"跑完"**，看不出是"新手链 52 个任务全跑完"，还是"抓鬼抓了 52 次" |
| `这一轮跑完了` | 状态列 `DONE` 的短语（`STATE_PHRASES.DONE`） | 抓鬼满额与新手链完成**共用同一句话**，两种终态无法区分 |
| `看不见进度` | 抓鬼只有裸 `done`；新手链连数字都没有 | 没有分子/分母，也看不出"离收工还有多远" |

## 二、先搞清口径：`done` 字段**随会话切换**（本次最关键的一处纠正）

主控给的字段表写的是 `r.done = 今日抓鬼完成次数`。实测（只读 `/api/status` + 读机器人端 `client.py`/`quest_engine.py`）口径是**分叉**的：

| 会话 | `st["done"]` 的来源 | 含义 | 分母 |
|---|---|---|---|
| 抓鬼会话活跃 `ghost.enabled=true` | `client.py`：`st["done"] = g.done_count` | 今日抓鬼次数 | `ghost.limit`（默认 50） |
| 其余（新手链 / 捉鬼链） | `quest_engine.py`：`done = done_base + len(done_tasks)` | **当前链已完成的任务节点数** | 链文件的 `task_order` 长度（`newbie_full` = 52） |

证据（实时只读采样，2026-09-21 19:0x）：

```
chain_done=true 的 5 个号：state=DONE, task_index=0, done=52, ghost={done:0, enabled:false, state:IDLE}
  → 52 = newbie_full 链的节点数（/api/chains 里 newbie_full.task_count=52），不是抓鬼次数
抓鬼中的号：done=2, ghost={done:2, limit:50, enabled:true}  → 两边同源
```

所以用户看到的 `-- · 52 跑完` 就是**一个刚跑完整条新手链（52/52）的号**：
`task_index=0`（没有"当前任务"）→ `--`；`done=52`（链跑完 52 个节点）；`chain_done` → `跑完`。
**判定"哪条链、跑到哪一步"必须 `ghost.enabled` / `chain_done` / `level` 一起看**，裸数字看不出来。

## 四、改动文件与关键 diff

### 4.1 `web/src/components/Dashboard.vue`

**(a) 脚本新增「任务列」段（311-445 行）**——判定集中在一个函数里：

```js
// 链节点总数（进度的分母）：按意图表给的链 id 去 /api/chains 列表里取 task_count
const chainTotals = computed(() => {
  const byId = {}
  for (const c of chains.list) byId[c.id] = c
  const total = (id) => { const c = byId[id]; return c && !c.error && c.task_count > 0 ? c.task_count : 0 }
  return { newbie: total(intents.data?.newbie_chain_id || ''),
           zhuaogui: total(intents.data?.zhuaogui_chain_id || '') }
})

// 任务列内容，判定优先级：
//   抓鬼中 > 抓鬼已满 > 新手链完成 > 抓鬼已停 > 捉鬼链 > 新手链进行中 > 只剩任务号
function taskCell(r) {
  const g = r.ghost || null
  const gDone = g ? (Number(g.done) || 0) : 0
  const gLimit = g && Number(g.limit) > 0 ? Number(g.limit) : 50
  const ghostOn = !!(g && g.enabled === true)   // 真在抓鬼（enabled=false 的历史会话不算）
  const ghostFull = !!g && gDone >= gLimit      // 今日抓鬼已满额
  const done = Number(r.done) || 0
  const kind = chainKindOf(r)
  const subTask = r.task_index ? taskLabel(r.task_index) : ''

  if (ghostOn && !ghostFull) return { tag: 'info', bar: 'live', pct: ..., text: `👻 抓鬼 ${gDone}/${gLimit}`, sub: subTask || '在钟馗抓鬼' }
  if (g && (ghostFull || (ghostOn && r.state === 'DONE'))) return { tag: 'ok', text: `👻 抓鬼 已满 ${gDone}/${gLimit}`, ... }
  if (r.chain_done) return { tag: 'ok', text: `🆕✅ 新手链完成 ${frac(done, total)}`, sub: `整条链 ${total} 个任务跑完`, ... }
  if (kind === 'ghost') return { tag: 'dim', text: `👻 抓鬼 ${gDone}/${gLimit}`, sub: subTask || '没在抓鬼（会话已停）' }
  if (kind === 'zhuaogui') return { tag: 'info', text: `⛓ 捉鬼链 ${frac(done, total)}`, ... }
  if (kind === 'newbie') return { tag: 'info', text: `🆕 新手链 ${frac(done, total)}`, sub: subTask || '还没接任务' }
  if (r.task_index || done > 0) return { tag: 'dim', text: subTask || `${done} 个任务`, sub: ... }
  return { tag: 'dim', text: '--', sub: '' }     // 无任务无会话：保持原样的 `--`
}
```

链身份 `chainKindOf(r)`：优先意图表（与「🆕新手」筛选同一份数据，`newbie`/`zhuaogui`/`ghost`）；
意图表里没有该号时按机器人上报的等级兜底（`0 < level < newbie_max_level` → 新手链，与意图判定同口径）；
再不行返回 `''` → 走兜底分支，**不猜链**。

## 六、未做 / 风险

**未做**
- 状态列 `stateLabel/statePhrase` 未改（按要求"不要大改"）。`DONE` 仍是「完成 / 这一轮跑完了」，靠任务列补足"是哪条链"。
- 地图页弹窗里的 `任务 … · 进度 {{ done }}`（`MapView.vue:269`）没动——用户只反馈大屏；同一份口径若要在弹窗复用，需要把 `taskCell` 抽到 `store.js`（本次刻意留在组件里，减少对其它视图的连带影响）。
- 摆摊（`booth`）模式未单独分支：摆摊号会落到"重新派活/捉鬼链"分支显示。实测当前 0 个摆摊号，先不做。
- 新手链"第几步"用的是 `done/52`（机器人上报的链内完成节点数），**不是**"第 N 个节点叫 初到渔村"的精确映射；如需精确到节点，要读链文件 `task_order` 做 `task_index → 序号` 映射（本次未做）。

**风险 / 注意**
- 分母来自 `/api/chains` 的 `task_count` + 意图表给的 `newbie_chain_id`。链文件缺失/改名时（`task_count=0`）**不会硬编 52**，而是退化成 `52 个任务`——宁可少显示，不显示错的。
- 链身份依赖意图表（每 5 秒刷新，且仅在"意图面板打开 / 筛选中🆕新手"时轮询；开屏会拉一次）。意图表拿不到时按 `level < 31` 兜底，仍拿不到就走"不猜链"的兜底分支。
- 抓鬼"已满"的判定同时接受 `ghost.done >= ghost.limit` 与 `ghost.state == 'DONE'`（后者只在满额路径上出现）。
- 抓鬼满额后机器人会 `enabled=false` + `reset()`，但 `done/limit` 留着——所以"已满"不依赖 `enabled`；反过来 `enabled=false` 且未满的号显示"已停"，不会误判成已满。
- 部署仍需主控执行：本次只刷新了 `web/dist/` 构建产物；中控 API 进程（28082/27200）未重启也未热更（核对过当前没有进程在服务 `web/dist`，只有 API 在跑）。
