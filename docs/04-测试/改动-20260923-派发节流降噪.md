根因两条（缺一不可）：
1. **机器人端误判**（已由 team-lead 修）：排除图闸把"没带 `maps` 的定向派发（mapid=N）"当成
   "给定选图全被排除"直接拒收 —— keeper 的派发**一律不带 maps**，于是 100% 无效、游荡名额实际
   靠机器人 `auto_roam` 撑着。
2. **中控 keeper 无在途/失败记账**：只把 `walk.enabled=true` 算"在游荡"，命令发出后不记账 →
   派发不生效的号每轮仍算空闲被重挑（且 `BalanceAssign` 总挑人最少的图 → 连目标图都重复）。

## 二、改动

### P0-a 定向派发显式带 `maps=[目标图]`（`internal/api/randomwalk.go:DispatchRoamEx`）
- 定向派发（`mapid=N` 且调用方没给白名单）→ 命令里补 `maps=[N]`（等价声明："指定图必须含于
  白名单"本就成立；面板「分配到所选图」路径也带 maps → 两条路径同构，机器人端不再误判）。
- 调用方显式给了白名单 → **原样保留**；随机图不受影响。

### P1 keeper 在途记账 + 退避（`internal/services/roampool/roampool.go`）
- `inflight{account → {mapid, at, fails, until}}`；**生效判据 = `Roaming(r)`（walk.enabled=true）
  → 立刻清除**（机器人收到命令即置 true，实测秒级）；离线/状态行被清理 → 清除。
- `until` 之前不再派该号；连续未生效每次重派 **+1 档**：`backoff_sec` 默认 **60 → 120 → 300s**
  （末档 = 上限）；真正生效后再派从第 1 档重新起算。
- **在途占位** `pending = until 未到 且 距上次派发 < inflight_ttl_sec(120s)` → 计入目标缺口
  （`running + pending >= target` 即达标），避免"上一批还在路上又派一批"；占位取两者小者
  （300s 档位最多占 120s，结果已知就释放目标缺口）。
- 参数落 `data/roampool.json`（可热改）：`inflight_ttl_sec`、`backoff_sec`（POST /api/roampool
  同样接受，非法值拒绝且不生效）；`Status`/`/api/roampool` 暴露 `inflight`/`inflight_pending`/`idle_streak`。
- 两条既有通道**不受影响**：回收（`PickReclaim`）照常；超编收敛（`PickExcess`）照常 —— 在途号只是
  从"补位候选池"里剔除，不会被重复派。

### 日志降噪（同文件，纯日志、不改行为；`lastAct` 每轮照常更新 → 面板状态不丢）
| 行类 | 现状（平稳窗 16:00~17:00） | 节流口径 | 推演 |
|---|---|---|---|
| 达标 | 36/h（每轮重复） | 状态翻转立刻打 + `goalLogSec=600` 心跳 | ~6/h |
| 空转 no-op | 65/h | 同「类型+缺口档+空闲档」键 `noopLogSec=300` | ~13/h |
| 动作（补位/回收） | 259/h | `actionLogSec=60` 聚合（首条原样；下一条带"近60s 另：补位 x 次/y 个、回收 z 次/w 个"前缀） | ~60/h |
| 合计 | **358/h** | — | **≈79/h（≤100 目标）** |

- 空转退避（B1）：连续"无动作且无活可干" → 轮询间隔 ×2 拉长到 `idleBackoffMax=60s`；
  **actionable = 有可回收候选 或 有可补位候选**（两者都算）→ 立刻回到 `interval_sec`，
  任务池缺人时的回收（含领双号）**不延迟**。
