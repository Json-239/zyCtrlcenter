## 一、现象与量化

### 1.1 表征
生产日志（`data/bot_logs/*/runs_20260922.log`）高频出现：

- `对话超 30 秒未关闭, 强制关闭回 READY 重新接取(第 N 轮)`
- `抓鬼需重登恢复: 钟馗对话 7 轮超 30 秒未关闭(服务端对话状态卡死)`（= 下线换号）

### 1.2 关键反证：文案说"30 秒"，实测根本不到 30 秒

全量统计 5412 条"第 N 轮"事件：

| 相邻轮次间隔 | 占比 |
|---|---|
| ≤ 2 秒 | 46.8% |
| < 10 秒 | 46.8% |
| < 30 秒 | 47.0% |

**467 个"第 1 轮 → 第 7 轮（重登）"完整样本，耗时全部 7~16 秒（p50=8 秒）**。
若判据真是"对话打开超 30 秒"，7 轮至少 210 秒 —— 实测直接排除该可能。

现场样本 `robot0005301@xy3.com`（20:20:00~20:20:09）：**9 秒内连发 7 轮**并触发重登；
同一时段日志显示该 NPC 是 **13255（跳转NPC，花钱传送"请送我去幽冥界（5银）"）**，
而不是钟馗（10146）—— 报错文案"钟馗对话"也不成立。

### 1.3 触发时点
"领双前置"（`pre_daily`）首次上线 **15:53:14**，误判随即暴涨：

| 小时 | 强制关闭 | 重登 |

## 二、根因（三个缺陷叠加）

### 缺陷 A：看门狗计时基准错误（`daily_ghost.py`）

```python
# 修复前（截取）
if (now_ms - g.state_since_ms > DIALOG_CLOSE_AFTER_MS ...)   # 8 秒 分支
if now_ms - g.state_since_ms > 30000:                        # 30 秒 分支
    g.rounds += 1
```

`g.state_since_ms` 是**进入 STATE 的时刻**，被当成"对话已打开时长"：

1. 号在 READY 停留早已超过 30 秒（例如现场"READY 前往钟馗空转 78 秒"）；此时对话一打开，
   `now_ms - g.state_since_ms` **立即 > 30 秒** → 立刻判超时；
2. 更糟的是 `__set_state()` 只在**状态发生变化**时刷新时间戳：

```python
def __set_state(g, state, now_ms=None):
    if g.state != state:          # ← 已是 READY 时，强制关闭回 READY 不会刷新
        g.state = state
        g.state_since_ms = ...
```

   因此"超时 → 强制关闭 → 回 READY"这一步不会重置计时，**每个 tick 都继续判超时**，
   `g.rounds` 以 tick 频率（约 1 次/秒）累加 → 7~8 秒攒满 7 轮 → 触发重登。

> 注释里写的"对话打开超 30 秒未关闭"与实现（状态持续时长）**语义不一致**，这是最根本的一条。

### 缺陷 B：`show_dialog` 守卫整段吞掉对话（`quest_engine.py`）

```python
# 修复前
if quest.pending == None:
    __handle_dialog(robot_object, quest, data)     # 只有 pending 空时才处理
```

点击/走路动作在途（`quest.pending` 非空）时，服务端推来的对话**不会被点任何选项**；
而 `show_dialog` 事件是一次性的 —— pending 清空后没有任何补偿路径 →
**对话永久挂着**（服务端对话态不关，还会拒绝移动）。

### 缺陷 C：READY 空档期重复走同一跳，把 pending 又填上（`daily_ghost.py`）

```python
_has_progress = (quest.dijkstra_waiting and quest.dijkstra_route) or \
    quest.pending is not None or quest.walk_target is not None
if _has_progress:
    ...
    return 0
# 无任何推进：累计空转超 5 秒则强制重置；否则
quest_engine.__start_next_hop(robot_object, quest, 300)   # ← 每个 tick 都重规划
```

"点完跳转NPC、服务端对话还在路上"的空档期里，`pending/walk_target` 恰好都已清空 →
`_has_progress=False` → **每 tick 都 `__start_next_hop`** 重新走同一跳（重复点击同一 NPC、
重开对话），并把 `pending` 再次填非空 → **正好触发缺陷 B**。

三者闭环（现场 robot0005301 完整复现）：

```
点跳转NPC 13255 → 服务端推对话
  → pending 被空档重规划填上 → __handle_dialog 被跳过（B）→ 选项永不点
  → 看门狗旧基准每 tick 判超时（A）→ rounds 1..7（8 秒）
  → 重登 → 回来重复（C 继续制造空档）
```

## 三、修复

### 3.1 `quest_engine.py`

| 位置 | 改动 |
|---|---|
| `show_dialog` | 新增 `quest.dialog_open_ms = __now_ms()`（对话打开时刻，看门狗新基准） |
| `show_dialog` 守卫 | `pending` 非空且类型为 `walk`/`click` 时记 `quest.dialog_deferred = True`（`dialog_click` 除外：那本来就是"即将点选项"） |
| `close_dialog` | `dialog_open_ms = 0`、`dialog_deferred = False` 复位 |
| `tick` pending 消费处 | 消费完若 `dialog_deferred` 且对话仍在 → 补调 `__handle_dialog`（并打日志"对话补处理"），随后 `return 0` |

### 3.2 `daily_ghost.py`

| 位置 | 改动 |
|---|---|
| 常量 | 新增 `DIALOG_STUCK_MS = 30000`、`NAV_IDLE_GRACE_MS = 1500` |
| 看门狗 | 计时基准改 `quest.dialog_open_ms`（`getattr` 兜底 `state_since_ms`，兼容热更旧实例）；8 秒关闭项分支同步改用 `_dlg_elapsed`，重计时改 `quest.dialog_open_ms = now_ms` |
| 30 秒分支 | 新增"同段对话只计一轮"守卫 `g.dlg_count_ms == _dlg_ms`；真实卡死判据 = 连续 7 段对话各自开满 30 秒（≥210 秒）才重登 |
| `__consume_nav` pending 消费处 | 与 `quest_engine.tick` 同款补处理 |
| READY 空档 | `_has_progress` 分支打点 `g.nav_last_progress_ms`；无推进时若距上次推进 < `NAV_IDLE_GRACE_MS`（1.5 秒）先等，让服务端对话/换图推送到达，不再立即重走同一跳 |

> 兼容性：全部新字段走 `getattr` 兜底，热更后的旧 `QuestState` 实例不会报错；
> `dialog_open_ms=0` 时退回旧基准（仅影响热更瞬间已打开的对话，一次性）。

## 四、单元测试（`tools/dialog_stuck_selftest.py`，24 项）

源码级提取 + fake 注入直接执行真实代码块（沿用 `quest_dialog_pending_selftest.py` 的模式）：

**静态 8 项**：新基准存在且旧表达式已从看门狗消失；同段只计一轮；常量与复位；
守卫 deferred 标记（仅 walk/click）；tick 与 `__consume_nav` 两处补处理且位于 `pending` 清空之后；空档宽限位于 `__start_next_hop` 之前。

**动态 16 项（含 3 条反例）**：

| 用例 | 断言 |
|---|---|
| A1 | 进 READY 已 100 秒 + 对话刚打开 → **不误判**（rounds=0，无重登） |
| A1-反例 | 旧基准表达式在同样输入下立即判超时 → 证明修复有效 |
| A2 | 对话真实时长 31 秒 → 计 1 轮 + 关对话回 READY，不重登 |
| A3 | 同段对话连续 7 tick → rounds 仍 =1（修复前 =7 轮重登） |
| A3-反例 | 旧实现同样 7 tick 累加 7 轮 → 证明修复有效 |
| A4 | 7 段不同对话各开满 30 秒 → 第 7 段仍触发重登（**真实卡死兜底保留**） |
| A5 | 对话开 9 秒 + 有"离开"项 → 点关闭项收尾 + 对话计时重计 |
| B1/B1b/B1c | walk→deferred；dialog_click→不标记；pending=None→直接处理 |
| B2/B2b | pending 消费后补处理（1 次）且不误补 |
| B3 | `__consume_nav` 同款补处理 |
| C1/C2/C3 | 空档 0.5s→不重走；3s→正常推进；首次进入→不拖延 |
