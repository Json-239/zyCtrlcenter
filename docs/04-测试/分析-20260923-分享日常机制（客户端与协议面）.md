# 分析-20260923-分享日常机制（客户端与协议面）

> 调研范围：只读。游戏客户端 `F:\ZyBin\xm\xiyou3-client\`、服务端 `F:\ZyBin\xm\2d-xiyou-server\`（均**未做任何修改**），
> 对照机器人端 `F:\ZyBin\zyCtrlcenter\deploy\zones\prod-240-2300\script\`。
> 结论用途：为"大唐神捕""烽火大唐"两条日常的机器人侧复刻提供权威参考。

## 一句话结论

"分享日常"（客户端 `auto_task` / 服务端术语 `share_daily`）是**纯客户端驱动的状态机**，除接取与交付需要点击 NPC 对话外，**没有任何"自动任务"专属协议**——它完全复用现有的任务/对话/移动/商店/物品回收协议：客户端按本地 `config/auto_task.csv` 的 `share_daily_key` 行，从**客户端本地算出的可接票据列表**里找 `ticket_broker`，寻路过去点 NPC → 点接受选项（`C2S_CLICK_DIALOG`）→ 服务端按票据 step 的 `action_pick_task` **加权随机**下发任务（`S2C_ADD_TASK`）→ 状态机按任务的 `demand_counter_list`（杀怪/收集/购买）+ 服务端下发坐标（attr `12054`）/需求地点（`12053`）执行寻路、巡逻遇怪、购买、回收提交 → 到 `catcher` 交付 → 按 `daily_limit` + `share_daily_key` 判定"今日 X/N"，做满即停。

## 机制总览（步骤化流程）

### A. 面板行与启动入口

1. **面板行来自服务端配置**：`2d-xiyou-server\config\activity_notice.xml` 的 `<activity_entry>`，每行带 `activity_share_daily_key` 与 `activity_finish_times`（= 面板显示的上限）：
   - 捉鬼 `activity_index=31`，`finish_times=50`，`share_daily_捉鬼`，等级 ≥20，`activity_type=个人`（第 630-686 行区段）
   - 大唐神捕 `activity_index=15`，`finish_times=10`，`share_daily_大唐神捕`，等级 ≥40，个人（第 194 行起）
   - 烽火大唐 `activity_index=25`，`finish_times=20`，`share_daily_宫廷10`，等级 ≥40，个人（第 581 行起）
   - 伏魔 `activity_index=44`，`finish_times=50`，`share_daily_伏魔`，等级 ≥60，**组队（3 人以上）**（第 687 行起）
2. **按钮显隐**：`xiyou3-client\script\activity\daily_layout.py:268-289`，用 `auto_task.config.is_auto_executable(0, share_key)` 决定是否显示"自动任务"按钮；次数做满时置灰（`:285-286`、`:320-321`）。
3. **点击按钮**：`daily_layout.py:330-357` → `auto_task.manager.start_by_share_key(share_key)`
   （`auto_task\auto_task_manager.py:536-578`）：
   - 名下已有同 playthrough 任务 → 直接 `start(task_index)` 执行；
   - 有可接票据 → 寻路到 `task_ticket.get_ticket_broker()`；
   - 二者都没有 → 进 accept 模式（`__waiting_next_round = True`），等票据刷新。
4. **主循环驱动**：`script\xygame.py:100-101` 每帧调用 `auto_task.manager.update(cal.get_global_time())`。
5. **停止**：Esc 走 `script\inputctl2\keyevent.py:319-321`；队员身份下按钮置灰（`daily_layout.py:277-280`）；队长转移时自动停（`auto_task_manager.py:1124-1145`）。

### B. 接取（ticket → broker → dialog option → ADD_TASK）

6. **`__try_click_accept_npc`**（`auto_task_manager.py:713-813`）：
   - 若对话框已开：只用本 run 的关键词点选项（`auto_select_dialog_option_by_keywords(get_keywords(share_key))`，`auto_task_action.py:145-217`）；不命中就"安全关闭"（只点"离开/取消/关闭"类，`auto_task_action.py:55-142`），**绝不点第一项**以免误接无关日常；
   - 必须走到 NPC 身边才点（`player.is_npc_nearby`，`:774`）——`click_npc_model()` 在远处只会"开始寻路"而不真点击（`click\click_manager.py:46-66`）；
   - 点击 → `click.manager.click_npc_model(npc_id)` → 发 `C2S_CLICKNPC`（`click\click_operator.py:48,55,69`）；
   - 服务端推送 `S2C_SHOW_DIALOG` → 客户端 `dialog\*_dialog.py` 发 `C2S_CLICK_DIALOG = [dialog_index, option_index]`（`dialog\screen_dialog.py:319,326`、`simple_dialog.py:495`、`window_dialog.py:373`）；
   - 服务端 `dialog\dialog_dispatcher.py:dispatch_click_dialog` → `dialog_ruler.click_dialog(option_index)` → 执行该 step 的动作。
7. **服务端票据动作**：`2d-xiyou-server\script\task\ticket_action.py`
   - `DialogTicketAction`（`:43-80`）下发对话；
   - `PickTaskTicketAction`（`:96-116`）→ `task_group.get_random_task(role_object)`（`task\task_group.py:25-55`：按 `task_weight` 加权随机，`can_accept_task()` 过滤，**上次接过的任务权重降为 1**）→ `add_task_object()`。
8. **接取条件（服务端权威）**：ticket 的 `<ticket_condition>` 由 `condition\role_condition.py` 求值；本两条日常用到：
   - `condition_role_level`（`role_lower_level` 40）→ `RoleLevelCondition`（`role_condition.py:259`）
   - `condition_role_task / not_accept_task_share_daily_key` → `RoleTaskCondition`（`role_condition.py:561-614`，命中即拒绝并回通知 60）
   - `condition_role_buff condition_result="相反"` → `RoleBuffCondition`（`:1367`；用于"刚放弃，需 N 秒后才可再接"的冷却）
9. **接取结果**：
   - 成功 → `S2C_ADD_TASK`（`sender\sender_task_.py:7-10`）+ 通知 `NOTICE_ADD_TASK=21`
   - 失败 → `S2C_NOTICE_MESSAGE` 带失败码（客户端 `keys\notice.py`：`58/59` 任务条件、`70/71` 等级、`715` 今日次数上限、`716` 本周上限、`776` 任务栏满、包裹满类 `360/528/1295` 等）
   - 客户端路由：`task\task_dispatcher.py:17`（ADD_TASK 回调）→ `task\task_observer.py:25` → `auto_task.manager.on_task_added`（`auto_task_manager.py:958-987`）新建状态机；失败码走 `notice\notice_dispatcher.py:13-27` → `on_accept_notice`（`auto_task_manager.py:1024-1047`，致命码表见 `:65-87`、`:123-147`）
10. **静默拒绝的处理**（很关键，机器人也会踩）：冷却/次数上限时服务端**既不回通知也不发任务**，还把该 ticket 从可接列表撤下。客户端分三段判定（`auto_task_manager.py:773-812`）：
    - **先判"走到没"**：`ACCEPT_ARRIVE_TIMEOUT = 20s`（`:37`、`:775-781`），走不到 broker → stop「无法到达接取NPC」；
    - **再判"点了没判决"**：以**第一次点击接取 NPC** 为起点计时（`:787-788`，跨图寻路不消耗该计时），`ACCEPT_TRY_TIMEOUT = 3.0s`（`:17`）内既无任务也无拒绝通知 →
      - 若 15s 内有包满通知（`is_bag_full_recently`）→ stop「包裹已满，请先清理包裹」（`:790-795`）
      - 若票据**仍可接**（`__accept_ticket_acceptable()` 读 `task_ticket.can_accept_task()`，含 buff 条件）→ 进冷却等待，最多 `ACCEPT_COOLDOWN_MAX_WAIT = 900s`（`:21`，`__enter_accept_cooldown`/`__check_accept_cooldown`:687-711，每 30s 一条日志）
      - 否则 → stop（接取失败）
    - 包满通知窗口 `BAG_FULL_NOTICE_WINDOW = 15s`（`:33`）；包满码共 5 个：`NOTICE_NO_SPACE_TO_GIVE=360`、`NOTICE_CAN_NOT_GET_BY_FULL_BAG=415`、`NOTICE_HAVE_NO_SPACE_IN_BAG=418`、`NOTICE_BAG_HAS_NO_SPACE_TO_OPERATOR=528`、`NOTICE_ITEM_NOFREEPOINT=1295`（`:25-31`）

### C. 执行（AutoTaskStateMachine，`auto_task_state.py`）

状态与常量：`STATE_IDLE / WAIT_ARRIVE / HANDLE_DIALOG / BUY_ITEM / BUY_WAIT / USE_ITEM / PATROL / WAIT_FIGHT / WAIT_NEXT_ROUND / STOPPED`（`:11-24`），决策间隔 `UPDATE_INTERVAL = 1s`（`:27`）。

11. **IDLE 决策**（`__on_idle`，`:251-351`）：
    1) `use_item` 列 → `__check_use_item`（`:387-399`，发 `C2S_USE_ITEM`）
    2) `can_finish_task()` → `__goto_finish_npc`（`:452-494`，`submit_npc` 列优先，否则 `finish_npc_index`，再否则 `finish_npcid`）
    3) 遍历未完成 demand：`KILLING→__goto_kill_area`（`:643-701`）、`COLLECTION→__goto_collect`（`:777-822`）、`PURCHASE→__handle_purchase_demand`（`:401-432`）
    4) `buy` 列兜底 → `__check_config_buy`（`:434-450`）
    5) 无 demand 的纯对话任务 → 去交付 NPC
12. **杀怪**：`__goto_server_target_location`（`:549-579`）优先用服务端下发的 `TASK_TARGET_LOCATION_LIST = 12054`（由 `task\task_object.py:230-241` 打包进任务 attr；`task\task_action.py:430,499,507` 逐点追加）——同图优先、已去过的点跳过、全去过则清空重来；到点后 `__on_handle_dialog` 用 `npc.manager.get_clickable_npc_object()` 点怪（`:1242`，避免点到别人的怪），无归属怪时换 `kill_npc` 列里的另一只（`__find_clickable_kill_npc`:620-641）。
13. **走路遇怪（暗雷巡逻）**：`__on_patrol`（`:1404-1456`）+ `__wander_around_patrol_center`（`:1535-1604`）：
    - 先 `finding.switch_auto_patrol(False)`（非 VIP 静默跳过，"自动寻怪"开关）；
    - 以**角色当前位置**为中心在 `PATROL_RANGE = 400px` 内随机取点走（不以固定 `DEMAND_LOCATION` 为中心，防被战斗拉偏后朝远处跑）；
    - 游走点与路径都要避开地图传送点（`__is_near_map_skip`:1508、`__path_cross_map_skip`:1521），点还要离地图边缘 `PATROL_EDGE_MARGIN = 300px`；
    - 服务端每次开启巡逻会随机重选一张图作为 `DEMAND_LOCATION`（`task_action.py:1169-1177`），客户端检测到换图就改去新图（`__check_patrol_map_rotated`:1459-1484）。
14. **收集**：`__goto_collect`（`:777-822`）按 demand 数据分三支——`task_npc_index` 有值→去找 NPC；有坐标→去坐标并按 `DEMAND_LOCATION` 巡逻掉落（军机情报 110185 类）；两者都没有→`__handle_carried_collection`（`:879-930`）：背包已够→直接去交付；不够→`fetch_npc` 列找 NPC 领取（`__goto_fetch_npc`:932-960）或 `shop` 列找商店购买（`__goto_shop_for_item`:962-984）。
15. **购买**：`__on_buy_item`（`:1294-1369`）→ `auto_buy_items`（`auto_task_action.py:621-683`，`salenpc_layout.find_goods_by_item_index` / `buy_goods_object` / 翻页 `request_shop_page`；包满立即停并提示）→ `__on_buy_wait`（`:1371-1398`，轮询背包数量，`BUY_WAIT_TIMEOUT = 3s` 到账才算成功）。
    - **两段式货币**：商店优先用 `shop` 列的 `@keyword`（如 `@金币`）；储备金阶段选"储备金"选项，失败切金币重试一次，仍失败才停（`:905-926`、`:1347-1357`）。
16. **交付**：`__on_handle_dialog`（`:1163-1292`）：
    - 先试**物品回收窗口** ITEM_RECYCLE_LAYOUT（`auto_confirm_item_recycle`，`auto_task_action.py:271-304`；服务端由 `action_item_recycle`（`task_action.py:2198-2222`）/`action_demand_item_recycle`（`:2224-2252`）下发 `S2C_ITEM_RECYCLE`，`trade\trade_recycle.py:33`）；提交用 `submit_item_object`，提交次数上限 `MAX_RECYCLE_SUBMITS = 3`（`:47`、`:1175-1200`）
    - 否则 `auto_select_dialog_option(dialog 列关键词)`（`:1201-1202`）→ 点 NPC → 交付；交付上限 `MAX_FINISH_TRIES = 12`（`:52`）
17. **战斗**：`__on_wait_fight`（`:1687-1701`）+ manager 每帧 `auto_start_fight()`（`auto_task_action.py:338-345`）；特殊战斗（必须对指定怪用指定道具）由 `fight_item` 列驱动（`auto_use_fight_item`，`auto_task_action.py:470-568`）。

### D. 循环、每日次数与收尾

18. **`on_task_finished`**（`auto_task_manager.py:911-955`）：若该 playthrough 还有后续（`chain` 列 / `chain_task` 列 / 关键词匹配的在身后续 / 手头仍有 pending 任务）→ 进"等下一轮"，否则查次数，做满即 `stop("：今日次数已用完")`。
19. **下一轮**：`__try_accept_next_round`（`:815-908`，先等 `WAIT_NEXT_ROUND_ACCEPT = 3s` 让服务端自动下发链的下一环）；票据被动刷新走 `on_acceptable_ticket_added`（`:991-1022`，由 `S2C_UPDATE_ACCEPTABLE_TICKET = 90281` 触发，`task\task_dispatcher.py:179-186`）。
20. **次数判定（客户端口径 = 面板口径）**：
    - `is_daily_limit_reached(share_key)`（`:1199-1207`）→ `activity\activity_operator.py:44-65` `get_finish_times_value()`：`finished = task.ruler.get_task_limited(share_key).get_today_finish_count()`，`total = task_entry.get_daily_limit() + task.task_operator.get_increase_limit(share_key)`
    - 数据来源：登录 `S2C_LOAD_TASK_LIMITED`（90152，全量）/ 完成时 `S2C_UPDATE_TASK_LIMITED`（90300，单条增量）——`sender\sender_task_.py:34-44`，调用点 `task\task_ruler.py:159`、`:628`
    - **计数时机**：只有 `task_index == episode_root` 的任务完成时才 +1（`task\task_ruler.py:184-188` → `__update_finish_task_limited`:307-329），即"主任务完成即扣次数"，后续交付环节（`daily_limit=-1`）不额外扣。
    - **次数满 ≠ 立刻收工（最重要的口径）**：计数在主任务完成时就已经到顶，而收尾任务此时还在身上（捉鬼 `2019512/2019513` → `2019511 交付捉鬼任务`；大唐神捕 `2028302` → `2028311` → `2028399 回复张忍慎`，见 `:1071-1072` 原文）。`__stop_if_daily_limit_reached`（`:1061-1110`）规定：**本 playthrough 还有未完成在身任务时绝不停止**，改为 `start(pending)` 先把它跑完（收尾不占额外次数）；确实没有后继时才等 `DAILY_LIMIT_DELIVERY_WAIT = 2s`（`:313`）让服务端补发后继，仍没有才 `stop("：今日次数已用完")`。服务端下发后继比主任务完成晚约 1 tick（~60ms）。
    - **跨 share_key 执行时保留原 key**：`__keep_playthrough_key`（`:462-476`）——切到"只属于本链的后续任务"（如大唐神捕执行 `share_daily_shenbu_reply` 的 2028399）时仍用启动时的 `share_daily_大唐神捕` 计数与匹配，否则次数查询与面板按钮归属一起失效。
    - **上限加成**：`buff_ruler.get_buff_increase_limit(share_daily_key)`（`task\task_operator.py:95-98`）+ `S2C_UPDATE_TASK_LIMIT`（90068，`buff\buff_ruler.py:107`、`buff\buff_action.py:674`）
    - **客户端本地也复算一遍**：`task\task_operator.py:45-78` `is_task_undone()`（票据 `can_accept_task` 会调它，`task\task_ticket.py:101`）——所以"次数用完"是客户端可判的，不必等服务端拒绝。
21. **掉线/重登自愈**：`cleanup()`（`:191-198`）；暂停/恢复保留上下文（`pause`:282-325 / `resume`:327-367，含"接管玩家手动接的任务" `__find_running_task_to_adopt`:503-524）。
