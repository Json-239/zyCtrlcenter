# 分析-20261014-多实例可行性校核（独立只读侦察）

> 性质：可行性校核（与《分析-20261014-实例管理页方案.md》互补，口径互见）。全程只读：未改任何文件/未启停任何进程/未发 POST。实测时间 2026-10-14 上午（运行态：中控 PID 45444 @09:06，机器人 PID 37204 @10-12 15:57）。
> 总判定：**同一 exe 多实例并行 = 可行（有条件，见 §6 条件清单）**；"实例管理页"底层操作 = 重启机器人/切区已成熟，创建/删除/中控自身重启需 MVP 新写（§6.2）。

## 1. 同一 exe 多实例的参数隔离审计

### 1.1 隔离参数（CLI/env，全部实测存在）
- `--web-port`/`--ctrl-port`（config.go:320-321,441-446）；`--deploy`（:447-449→RobotExe/RobotConfigPy :494-495）；`--data-dir`（:450-452→DataDir/ChainDir/MapsFile/AccountsFile :473-478）；`--base-dir`（:322,332-334；影响 DataDir 默认、LogsDir、WebDistDir、config.local.json、defaultDeployDir/GameConfigDir :519-551）。env 兜底 `CTRL_WEB_PORT/CTRL_CTRL_PORT/CTRL_DEPLOY_DIR/CTRL_DATA_DIR/CTRL_WEB_DIST` 全套（:4-14 注释清单）。
- 端口预检：main.go:212-216 先 `net.Listen`，占用即 FATAL 退出（且先于 EnsureRunning，10-10 事故修复保留）→ 第二实例碰端口不会留僵尸。
- 进程内 sync.Once（api.go:139 payloadOnce、hub.go:41、event.go:64）都是**单进程内单例**，非跨进程资源，无影响。

### 1.2 每实例状态（DataDir 文件清单：代码+实测 ls 交叉）
- 读写自建：zones.json(main.go:93)、accounts.json(config.go:478)、waterline.json(main.go:279)、roampool.json(main.go:287)、rotation.json(rotation.go:53)、personal_pool.json(main.go:237)、share_daily_assign.json(main.go:74)、share_daily_full.json(main.go:81)、autotask.json(autotask_persist.go:38)、booth_config.json(booth.go:90)、skill_config.json(skillconfig.go:57)、runs_YYYYMMDD.jsonl(store.go:50)、bot_logs/<账号>/runs_*.log(store.go:99-103)。

- Load 缺省语义：文件缺失=默认值运行（roampool/waterline 等运行期自建），**B 的 DataDir 空目录冷启动可行**。

### 1.3 全局/单例/硬编码发现（逐项：file:line + 影响）
- **F1 LogsDir 固定 `base/logs`**（config.go:485，无 CLI/env）→ 两实例同 base 时 `ctrlcenter_*.log`、`logs/watchdog.log` 混写。影响：中（日志混排/审计困难；cleanup 只删超期旧文件，不伤当日）。规避：B 用独立 base 目录或等 `CTRL_LOG_DIR` 参数化（P1）。
- **F2 默认端口常量 28082/27200**（config.go:38-39）→ 仅缺省值，覆盖即可；run_ctrlcenter.bat 的占用预检只查这两端口，B 不复用该 bat 无碍。
- **F3 watchdog 单实例假设**：探活端口缺省 28082（ctrlcenter_watchdog.py:99）、`_proc_count()` 全机统计 zyctrlcenter.exe（:65-79）、拉起固定 `_start_detached.bat`（:82-93）、ROOT 固定（:35）。影响：B 无看护；且多实例常态后 `>1 告警`（:120-128）会每 60s 误报"疑似误拉孤儿"。扩多实例改动点：①--port→(port,bat) 列表；②_proc_count 期望值参数化/按命令行归属过滤；③_start 按实例 bat。
- **F4 run_ctrlcenter.bat / start.bat 的 `--restart` = `taskkill /IM zyctrlcenter.exe /F`（按镜像名全杀）** → **管理页"重启中控"绝不能复用**：会连另一实例一起杀。必须按命令行（含 `--data-dir`/`--web-port`）或端口归属定位 PID 后杀。
- **F5 process.RunningAny 用 tasklist 镜像名全机匹配**（process.go:81-106）→ 当前**无调用者**（全仓 grep 仅定义处）；将来管理页若复用它判"机器人是否在跑"，A 会看到 B 的机器人（同名 robot_single_robot.exe）而误判。建议改造或弃用（P2）。
- **F6 booth 兜底副本半绝对路径**：booth.go:104-105 硬编码 `<BaseDir>/deploy/zones/prod-240-2300/script/…` 与 `<BaseDir>/../xm/…/single_robot_zy/script/…`；同步时"存在的候选全写"（booth.go:177-207）。A/B 同 base 时 B 的摆摊配置会写进 A 的 deploy 副本（低危互踩）；B 独立 base 时仅写自身+不存在则跳过。建议收敛为"只写本实例 DeployDir"（P1）。
- **F7 killOrphansInDeployDir 按 ExecutablePath 前缀 `dir\*`**（orphans.go:25-29，Taskkill /PID /F :58-69）→ 独立验证：`…\single_robot_zy\*` 与 `…\single_robot_zy_2300\*` 互不匹配（分隔符边界），**两副本不误杀**；红线：不得把一个 deploy 副本放到另一 deploy 目录内部（前缀会命中）。
- **F8 前端 fetch 全相对路径**（方案 §1.3 已核）→ 两实例共享同一 `web/dist` 只读安全；static.go:61-88 仅 ServeFile，无写。
- **F9 import_accounts.py 默认输出 `<项目根>/data/accounts.json`**（import_accounts.py:42，可 argv[2]/--out 覆盖）→ 工具级默认指 A；B 的账号分片需显式 --out。
- **F10 shop_probe.py:29 硬编码 `F:/ZyBin/zyCtrlcenter/data/chains/newbie_full.json`**（2300 副本内；_DEFAULT_CFG，需触发文件才生效）→ 工具级、非热路径，低危。
- **F11 计划任务**（实测 Get-ScheduledTask）：`ZyCtrlCenter`(Ready)→`_start_detached.bat`；`ZyCtrlCenterWatchdog`(Running)→`_start_watchdog.bat`。均 A 专属；B 上线需并行加一套（或在管理页内建等价守护）。
- **F12 main.go 只注入 `ROBOT_ZONE_IP/PORT`**（main.go:151-156）；`ROBOT_CTRL_HOST/PORT` 靠启动脚本环境继承（process.go:119-127 os.Environ()+extra）→ **B 启动脚本必须自行 set ROBOT_CTRL_PORT=27201**（P0，见 §6）。

## 2. 机器人副本独立性核验（single_robot_zy_2300）

- **副本质量**：21MB / 626 文件（生产副本 2966 含 709 .bak/quest_progress/diag 运行态）；无 state/、无 quest_progress_*.json、无 diag.log、无 .bak（干净）。16 个关键脚本 sha1 与生产副本**逐一相同**（config/client/msghandle/daily_ghost/quest_engine=34f25d69（含今日 C 型修复）/share_daily/map_rescue/booth/main_tester/ctrl_client/cnet/random_walk/bag_ops/auto_roam/pre_daily/encourage_claim）；两 config.py `diff` 零差异。
- **区参数**（两副本同款）：config.py:28-29 `ip = env ROBOT_ZONE_IP or "47.96.8.240"`、`port = env ROBOT_ZONE_PORT or 2300`；zone_key(:32)。ctrl：config.py:341-344 `ctrl_server_ip = env ROBOT_CTRL_HOST or 127.0.0.1`、`ctrl_server_port = env ROBOT_CTRL_PORT or 17200`；连接点 ctrl_client.py:86 `sock.connect((config.ctrl_server_ip, config.ctrl_server_port))`。
- **两实例并存读法**：A 中控（env ROBOT_CTRL_PORT=27200，_restart_warm_20261014.bat 实配）拉起 A 副本→连 27200；B 中控（必须 env=27201）拉起 B 副本→连 27201；区地址由各中控按各自 zones.json current 注入。**风险**：B 若漏设 ROBOT_CTRL_PORT → 默认 17200（py 参考中控）或误配 27200（串到 A）→ B 面板全空/A 出现幽灵连接。

- 机器人进程相对路径落点：中控拉起时 `cmd.Dir = deployDir`（process.go:120）→ 机器人若有相对写盘也落在自己副本内。

## 3. 进程管理机制盘点（供实例管理页复用）

- `EnsureRunning`（process.go:109-151）：先 `killOrphansInDeployDir` 再 `exec.Command(exe).Dir=deployDir`+HideWindow 启动（detach=系统 detached 子进程；中控自身由 bat `start /min` 独立弹出）；`Stop(killOrphans)`（:158-184）=按目录清孤儿+杀自拉 cmd；`Restart`（:187-191）。存活检测：Running=句柄（:72-77）；RunningAny=tasklist 镜像名（F5，未用）。
- 孤儿判据=EcecutablePath 前缀（orphans.go），**已具备跨实例隔离粒度**，可直接被管理页复用为"停机器人"。
- watchdog（tools/ctrlcenter_watchdog.py）：HTTP `/api/status` 探活（:55-62，8s 超时）+ tasklist 计数（:65-79）+ bat 拉起（:82-93）+ 退避 60/120/300s + 观察 3 周期。多实例化改动点见 F3（只列不改）。
- Windows 启动方式：schtasks→bat→`start /min`；温启族 `_restart_warm_*.bat` 无 `--auto-robot`（保住机器人）；冷启 `_start_detached.bat` 带 `--auto-robot`。Go 直接 CreateProcess/杀进程树可行（process.go 已用 os/exec + taskkill /PID 先例）；**实例定位需新写**（CommandLine 匹配 `--data-dir/--web-port`，py 参考 `stop_robot` 只按 PID 不全局 taskkill 的先例可信）。

## 6. 结论

### 6.1 可行性判定：可行（有条件）
条件（P0，缺一不可）：
1. **B 启动脚本 set `ROBOT_CTRL_HOST=127.0.0.1` `ROBOT_CTRL_PORT=27201`**（F12：中控不注入该值，机器人默认 17200）。
2. **B 的 zones.json 初始化 current=2300**：默认种子 current=servers[0].Zones[0]=**2400**（zones.go:124）——不处理则 B 登录错区。
3. **账号池硬分片**：B 独立 accounts.json（import_accounts.py --out），与 A 号段/名单不重叠（防双开互踢；仅按 zone 过滤不保证无重叠）。
4. **B 不复用 run_ctrlcenter.bat/start.bat --restart**（taskkill /IM 全杀，F4）；管理页/脚本的"重启中控"必须按命令行/PID 定位。
5. B 用独立 `--data-dir`（建议 `data_2300`，或独立 base 目录顺带解决 F1 logs 混写）。

### 6.2 管理页底层操作成熟度分级
| 操作 | 成熟度 | 现成资产 / 缺口 |
|---|---|---|
| 重启机器人 | **成熟** | `POST /api/robot/restart`→Manager.Restart（process.go:187）；按 deploy 目录隔离已具备 |
| 切区（栈内） | **成熟** | /api/config/switch+apply+重启机器人；B 走 env 注入路径（config.py 是表达式→apply 会 Skipped 不写反而不破坏） |
| 实例切换（页面） | **零风险** | location.href 跳转（各实例自托管 dist，同源相对路径） |
| 状态检测 | 半成熟 | HTTP /api/status+gzip 现成；进程层需新写（CommandLine/端口归属） |
| 重启中控（温/冷） | 流程成熟、自动化缺 | bat 族可手工复刻；自动执行需新写"按命令行定位 PID 杀+重拉"（禁止 /IM 全杀） |
| 创建实例 | **需新写** | 目录复制（robocopy 级）+ data 初始化（F9）+ 端口预检 + 脚本生成模板 |
| 删除实例 | **需新写** | 停进程（走 F7 判据）→ rename 归档；红线=先停后档、永不先删 |

### 6.3 防坑清单
- P0：①ROBOT_CTRL_PORT 漏设（串 17200/27200）；②B 默认区 2400（启动错区）；③账号池重叠（双开）；④/IM 全杀（F4）；⑤启动前探活+端口试绑（10-10 误拉事故模式：误拉第二实例→多拉 robot→抢单通道）。
- P1：⑥LogsDir 参数化或独立 base（F1）；⑦watchdog 多实例化（F3，含消 >1 误报）；⑧booth 兜底副本收敛（F6）；⑨机器人副本热更同步纪律（当前零 drift，今后每批热更要反向同步并复跑 cold_start_selftest）。
- P2：⑩RunningAny 改造/弃用（F5）；⑪import_accounts.py --out 流程化（F9）；⑫instances.json 文件锁/单写者。
