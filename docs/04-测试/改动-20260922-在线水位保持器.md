## 一、口径（用户已拍板，勿改）

| 项 | 口径 | 说明 |
|---|---|---|
| 人数来源 | **服务端全服在线（含真实玩家）** | 机器人定时发 `@online` 管理命令 → 服务端回执解析成 `svr_online{count,ts}` 随心跳上报；中控取最新一条（`state.SvrOnlineLatest`） |
| 兜底 | 服务端读数**缺失**或**超过 180 秒**未更新 → 用**本地握手数**（`counts.handshake`，即我们自己的号） | 生产服还没授权时 `svr_online` 为空，只能兜底 |
| 标注 | 状态里带 `source: svr\|local` 与 `fresh: true/false`；面板「数据来源」必须显示 | **别把兜底当真值**：本地口径只数我们的号，会偏低（真实玩家没算）；反之服务端读数含真人，压号时别把自己压空（见 `min_keep`） |
| 生效范围 | 只对**当前区**（`/api/status` 的 `current`） | 机器人快照按 `robot.zone == 当前区` 过滤；本地兜底也只数当前区握手数 |
| 数据新鲜度 | `svr_online.age_sec ≤ 180` 视为新鲜 | 面板把过期的服务端读数也展示出来（`svr` / `svr_age_sec`），便于排查"是不是没授权" |

## 二、调节规则

| 参数 | 默认 | 含义 |
|---|---|---|
| `interval_sec` | **60** | 每 60 秒检查一轮（1 秒粒度轮询，改小下一轮立刻生效） |
| `dead_zone` | **3** | `\|target - cur\| < 3` → 不动（抖动不折腾） |
| `max_step` | **5** | 每轮最多调整 ±5 个（含"待下线收工后断开"的，避免一次砸太多命令） |
| `target` | **100** | 目标在线人数 |
| `prefer_idle` | true | 压号优先断空闲号 |
| `random_fallback` | true | 空闲号不够时随机补选（避免每轮盯同一小批号） |
| `min_keep` | 0 | 保底：**我们自己的号**不低于这个数（0 = 不保底） |
| `enabled` | **false** | 总开关；`false` 时循环什么都不做（默认必须人工开，不会自己动生产） |

一轮的判决（`Keeper.Tick`）：

```
cur, source = 服务端新鲜读数 ? svr : 本地握手数
raw = ComputeAdjust(cur, target, dead_zone, max_step)     # 正=补号，负=压号，限幅 ±max_step
raw<0 且 本地号数+raw < min_keep  →  raw 收窄（保底，绝不让自己的号被压空）
raw>0 → 撤销"待下线"；要补的量 = raw - 在途数（在途=已下发上线还没登录的号，防重复补）
raw<0 → ① 先把"待下线"里已收工的号断掉 ② 还差就新挑（空闲的直接断，在忙的进待下线）
raw=0 → 撤销"待下线"（读数已回目标附近，别再多断号）
```

**为什么要在途/待下线的记账**：不记账会"重复补号"（下发后要几十秒才登录，下一轮看读数没涨 → 又补一批）或
"重复压号"（已标了待下线还在算差额）。在途超过 300 秒自动作废（允许重新补），队列里已离线的号自动摘掉。

## 三、断谁（空闲优先，不硬打断）

- **空闲** = 无任务、无活跃抓鬼会话、非战斗、非游荡/孵化（`waterline.Busy`，与 `api.isTasking`、
  restorer 的「不打扰」口径一致：`NAV/CLICK/DIALOG/FIGHT/SHOP/ALLOC/WAIT_NEXT`，以及 `WAIT_TASK` 且任务索引非 0）；
- 空闲号 → **立刻**下发 `robot_manage remove`（本地同时标记移除，防心跳复活）；
- **正在干活的号绝不硬断** → 只标记「待下线」（面板显示"待下线 N 个"），等它回到空闲态由下一轮断掉；
- 空闲号不够且 `random_fallback=true` → 在剩余号里**随机**补选（仍是"忙号只进待下线"）；
- 号池没有可用号（或库里没密码）→ 记 `last_err`、不报错、下一轮继续；
- 一轮内任何异常只记日志：`Tick` 的 panic 被 `Start` 兜住，单轮失败不影响下一轮。

## 四、API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/waterline` | `{ok, enabled, target, dead_zone, max_step, interval_sec, prefer_idle, random_fallback, min_keep, cur, source, fresh, local, svr, svr_age_sec, diff, pending[], inflight[], last_action, last_run_ts, last_err}` |
| GET | `/api/status` | 顺带带 `waterline`（同一份摘要，面板少一次请求） |
| POST | `/api/waterline` | 设置 `{enabled?, target?, dead_zone?, max_step?, interval_sec?, min_keep?, prefer_idle?, random_fallback?}`（未给的字段保持原值）；校验：`target 0~10000`、`dead_zone ≥0`、`max_step 1~50`、`interval_sec 10~3600`；越界**不落盘、不生效**并返回原因 |

```
curl -X POST http://127.0.0.1:28082/api/waterline \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"target":100,"dead_zone":3,"max_step":5,"interval_sec":60}'
```

参数落盘 `data/waterline.json`（原子写：tmp + rename），重启后原样恢复；文件缺失/字段残缺时用默认值补齐
（**不会**把 `target` 缺省成 0 = 把号全断）。

## 七、风险与注意

| 风险 | 说明 | 缓解 |
|---|---|---|
| 服务端读数未授权/过期 → 用本地口径 | 本地口径**只含我们的号**（不含真实玩家）→ 在"目标=全服在线"的前提下会**偏低**，保持器会一直补号直到本地握手数达标（把号池拉空、并在游戏服上堆号） | 面板强制显示来源；`local` 时建议运维按"只算我们的号"重设 `target`；`min_keep`/`max_step` 限幅；号池不够时只记错误不乱来 |
| 服务端读数含真人（口径正确时） | 真人涌入会让 `cur` 超过目标 → 保持器**压我们的号**（真人不可控） | 死区 3 + 单轮 ±5 + `min_keep` 保底，避免把号压空；需要"只保底量"时把 `min_keep` 设成希望保有的机器人数 |
| 批量上下线的频控 | 每轮最多 ±5，但每 60 秒一轮会**持续**下发；`robot_manage add/remove` 每批 10 个、批间隔 300ms，批量过大可能触发游戏服风控/登录风暴 | 保持 `max_step` 小（默认 5）、`interval_sec` 不要调太小（下限 10s）；`enabled` 可随时关；下线顺序优先空闲号、忙号等收工 |
| 与其它引擎抢号 | 「定时自动任务」（保持数）、恢复引擎（补发）也会拉号，可能在压号后又把号拉起来 | 压号时**本地标记移除**（`MarkRemoved`），`autotask` 候选会跳过被移除的号；我们自己压下去的号（`SelfOfflined`）在目标上调时仍可被水位保持器重新拉起 |
| 卡在忙态的号永久"待下线" | 一直卡死/长期做任务的号不会被断（这是刻意：不硬打断），`pending` 可能长期非空、人数压不下来 | 面板可见"待下线 N 个"；需要强压时人工处理卡死号（卡死恢复/重登链路已有），或临时调大 `max_step` 配合人工 |
