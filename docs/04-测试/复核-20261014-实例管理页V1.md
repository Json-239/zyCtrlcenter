## 3. 发现清单

**P0：无。**

**P1-1（配置级，部署条件）**：A 的 `start_script` 语义不闭环。
`instances.json:13`（a.start_script=`_restart_warm_20261014.bat`）该脚本：无 kill、明确注释
`NO --auto-robot on purpose: keep the running robot process (pid 37204) untouched`。
而 `service.go:193-211` Stop 会杀中控**和机器人**。→ 管理页对 A「停止」后点「启动」：
中控回来、**机器人不会回来**（前端确认文案"可用「启动」重新拉起"对 A 不成立）。
watchdog 对"整栈全死"的 A 同样只恢复中控。复现：A 行停止 → 启动 → `robot_alive=false` 不变。
处置：换完整启动脚本（参照 `_start_2300.bat`/向导产物，含 `--auto-robot`）或写明口径。

**P2-1（API 暴露面）**：`Start` 无 IsSelf 闸（`service.go:114-135`；Z8 实证会执行脚本）。
前端用 `ctrl_alive=false` 隐藏自身"启动"按钮，但 `POST /api/instances/p28082/start` 直调可执行
A 的启动脚本（现行脚本无 kill → 旧 A 活着时会短暂双起、端口冲突自退；若将来 A 换含 kill 的完整
脚本，则等同"无确认的自杀式重启"，绕过了 controller 的 ErrSelfOperation 保护）。
建议：部署换 A 脚本时**同步对自身加 start 闸**（或文档化）。

**P2-2（文档/实现不符）**：`api.go:131` 注释与作者声称"注册表加载失败时接口回 503"**不成立**。
`api/instances.go:45-48` 先 `a.Instances = NewInstancesService(...)` 再 `Load`，Load 失败时
Instances 非 nil（空表）→ 实测 GET /api/instances = **200 + ok:true + instances:[]**（Z3）；
503 只在对象从未装配（nil）时。影响：`instances.json` 被写坏时管理页显示"还没有实例记录"
（运维可能误读为实例丢失；页内"新建实例"可用但 Create 会报"找不到模板 deploy"）。
watchdog 侧不受影响（坏文件→退化单实例，保守）。建议：Load 失败时清 nil 或加不可用标志。

**P2-3（环境依赖）**：`proxyRobotRestart`（`service.go:275-292`）向目标实例发 POST **不带 token**；
`requireToken` 在 `APIToken != ""` 时强制（api.go:323-334）。当前 `config.local.json` 是占位符
CHANGE_ME→视为未配置（config.go:559-565）→ 代理正常（已实测通）。**若将来配置了 token，
robot 代理与整个实例管理页前端都会 401**。部署保持 token 为空；或在启用 token 时同步改代理带
token+前端带 token。

**P3（体验/健壮，不阻断）**：
- P3-1：自身实例行的重启菜单仍显示 controller/cold（点击必被后端拒"不能重启自身实例"）
  （vue:378-395）；robot 项对自身可用（设计允许）。
- P3-2：robot 透传响应若为 200 非 JSON → 前端 `resp.json().catch(()=>({}))`（vue:142）得 `{}` →
  `res.ok===undefined` → 误报成功 toast（正常中控不会 200 非 JSON）。
- P3-3：GET /api/instances 每 5s 轮询会触发 a+b 各 2 次 PowerShell（4 次/5s）；低频场景可接受，
  将来可加 TTL 缓存。
- P3-4：`startDetached`/watchdog `_start_instance` 用 `cmd /c start "" /min <path>`——路径含空格时
  `start` 的 title 歧义可能启动失败（当前所有路径无空格；非注入面，参数走数组不经 shell）。
- P3-5：`logs/watchdog.log` 现存 45 条旧版误报（11:16-11:36"检测到 2 个中控实例"）与
  11:25:42 自检输出污染（t1-t5 行，无实际进程动作，现场进程仍为 45444/67428 两个）；
  新 watchdog 就位后停止，建议人工标注该批次。

## 4. 风险专查 a-f 结论

- **a) start 注入面**：id/name 不进命令；脚本执行走 `exec.Command("cmd","/c","start","","/min",path)`
  参数数组（无 shell 拼接）；bat 内容由 zone_key/端口/路径拼接，而 zone_key 经 `lookupZone`
  强校验（SeedServers/zones 注册表）→ 不可注入。低风险（P3-4 空格路径仅功能问题）。
- **b) proxyRobotRestart URL**：`fmt.Sprintf("http://127.0.0.1:%d/...")`，WebPort 为 int；
  -1/0/70000 实测返回 error 不 panic（Z8）。web_port 若被恶意改成 80 只会代理到本机 80 的
  同一路径——暴露面有限。
- **c) 并发**：写操作（start/stop/restart/delete/create）共用单 mutex（Z6 重叠检测为 0）；
  GET 列表的并行探测只读（List 快照），无锁竞争。
- **d) /api/ping 暴露面**：**恰好 2 键**（ok/ts），无版本/计数/路径信息（Z3 强断言）；localOnly
  护住非回环（403 实测）。不挂 token 的理由（watchdog 读不到 token→误判误拉）成立。
- **e) instances.json 坏文件**：Load 报错不 panic、内存保持空表（Z7）；watchdog 读坏→退化单实例
  （坏版实测）；运行中进程不受外部改文件影响（内存快照）。唯一问题是 P2-2 的接口语义。
- **f) B 不可达时前端渲染**：后端 status 无 omitempty 全字段输出（false/0/-1）→ 前端
  `stOf(inst)` 兜底 `{}`，渲染"未运行/HTTP不通/在线 --"，启动按钮可见（可拉起）✓。

## 6. 部署顺序建议（重要）

1. **先重启常驻 watchdog**（用新代码，**不要动 A/B 进程**）：
   `taskkill /PID 56484 /F`（或按运维既有流程停 task scheduler 任务）→ 用
   `_start_watchdog.bat`（或 task scheduler 既有任务）重拉。生效后误报立即停止；
   新 watchdog 对旧版 A/B 友好（无 /api/ping 自动回退 /api/status，已实测）。
2. **再重建并温重启 A 中控**：
   - 先 `go build -o zyctrlcenter_new.exe .`（避免直接覆盖被运行中 exe 锁定）；
   - `taskkill /PID 45444 /F`（或走既有温重启流程的杀进程步）→ 覆盖
     `move /y zyctrlcenter_new.exe zyctrlcenter.exe` → 跑 A 启动脚本；
   - **注意**：新 watchdog 若在"kill 后、start 前"的 tick 看到 A 计数=0 会**立即代拉**
     （跑 a.start_script）——与手动 start 双跑时端口冲突自退（无害但留一条 FATAL）。
     推荐直接依赖 watchdog 代拉（10s 内）或手动一气呵成；
   - 机器人 37204 不受影响（脚本无 --auto-robot）——**但请先处理 P1-1 的脚本口径**。
3. **B（可选）**：B 的实例管理只需 A 侧能定位+探活（ctrl_match 定位与 /api/status 回退均不要求
   B 有新接口），**可以暂不重启**。若升级 B：**不要直接跑 `_start_2300.bat`（带 --auto-robot
   会再起一个机器人）**——应 kill B 中控后以"不带 --auto-robot"的命令行手工拉起（保 robot 40592）。
4. **前端**：无需动作。dist 已含新文案（`此后端版本不支持实例管理…`/`归档实例（危险操作）`），
   中控读盘服务（index no-cache、assets 名带哈希）——刷新即见；复核期 `npm run build` 复跑产物
   sha256 与现 dist **完全一致**（确定性构建）。
5. 部署后验收：`curl 127.0.0.1:28082/api/ping` → `{"ok":true,"ts":…}`；
   `GET /api/instances` → a/b 两行 status 全字段；管理页刷新出卡片；`--once` 两实例 alive=True。
