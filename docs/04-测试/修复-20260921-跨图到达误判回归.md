## 2. 根因：两种"route 空 + final None"被混为一谈

今天为修"跨图中转点静默停住"（robot0001028 长安东市集案例，见
`修复-20260921-跨图中转点堆积.md`）给 `__start_next_hop` 加了兜底：`dijkstra_route`
为空且 `dijkstra_final == None` 时，按 `dijkstra_plan` 重规划（限 3 次/60s，用尽报
`NAV_NO_FINAL`）。**该兜底把两种语义不同的场景混为一谈：**

| 场景 | 语义 | 正确处理 |
|---|---|---|
| (a) 路由丢失（route 被意外清空/走丢） | 异常 | 重规划 → 用尽报错 |
| (b) **已正常到达目标图**（跨图完成、route 刚好走空、没有额外 final 点） | 正常态 | **不重规划**，清状态交回上层状态机（抓鬼 WAIT_GHOST 找鬼等） |

### 现场为什么踩中 (b)

1. 抓鬼去钟馗时 `__goto` → `__teleport_click` 设 `dijkstra_plan = {npc_id: 10146(钟馗)}`；
2. 接到捉鬼任务后去图25，走 daily_ghost `__goto_xy`（daily_ghost.py:1145）——它**只重建
   `dijkstra_route`、显式 `dijkstra_final = None`，不清 `dijkstra_plan`**；
3. 最后一跳（destination 47）成功 → 回执处理 pop 掉 route（变空）→ 本地 `m_mapid = 25`
   → 调用 `__start_next_hop`（quest_engine.py:1402 附近）；
4. `final == None` 且 `dijkstra_plan` **残留非空**（钟馗 10146）→ 被当成 (a) → 重规划回钟馗。

结论：**只要"到达目标图"发生在 `__start_next_hop` 的 `final==None` 分支，且 plan 有
残留（daily_ghost 模式必经），就必然被弹回**——所以是 5+ 号反复的回归，不是偶发。

### ② `__start_next_hop`：route 非空分支兜底记录（覆盖 `__goto_xy` 入口）

```python

if _goal:
    quest.dijkstra_goal_map = _goal
```

### ③ `__start_next_hop`：`final==None` 分支**先判"是否已到达"**，再走原分流

```python
_goal_map = int(getattr(quest, "dijkstra_goal_map", 0) or 0)
if _goal_map and int(robot_object.m_mapid or 0) == _goal_map:
    __emit(robot_object, {"type": "log", "level": "debug",
        "msg": "跨图已到达目标图 %d, 跨图结束(交回上层)" % _goal_map})
    quest.dijkstra_route = []
    quest.dijkstra_waiting = False
    quest.dijkstra_jumper = None
    quest.dijkstra_goal_map = 0
    return
# ↓ 未到达才继续今天加的"重规划(限 NAV_REPLAN_MAX 次) → NAV_NO_FINAL"
```

- 未引入新字段到 `QuestState`（约束"只改 quest_engine.py"；沿用本文件动态字段惯例，
  读取一律 `getattr` 兜底，热更 reload 对旧实例兼容）。
