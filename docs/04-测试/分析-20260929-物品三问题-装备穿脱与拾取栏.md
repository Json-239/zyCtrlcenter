## 2. 根因（三问题）

### 2.1 问题1：装备被"当消耗品使用" → 穿脱震荡（主因）

**机器人端 xml 的装备条目没有 `item_handler`**（实测 220602 兽牙坠/223504 凌燕履/223604 如意金锁/213604 螺旋枪，handler 全空；只有 `<related_element_index>element_neck_a_lv1</related_element_index>`）。
旧 `__tidy_bag` 的判定链：
```python
handler = mi.get("handler", "")          # 装备 → ""
if handler == "任务物品": continue
if handler == "装备物品": ...to_drop/to_wear...   # ← 永不命中
else: to_use.append(...)                 # ← 装备全落这里 → 发 C2S_USE_ITEM
```
且 `__tidy_bag` 遍历 `quest.bag`（`{item_index:[item_id,count]}`，**无位置**、含装备栏物品）→ 对**装备栏里已穿的装备**也发 `C2S_USE_ITEM`。

**服务端语义**（SV/item/item_operator.py `dispatch_use_on_role`）：
- 装备栏(`POCKET_TYPE_EQUIP`)里的物品：**跳过条件检查直接 `use_on_role` = 解下**；
- 背包里的装备：`is_qualified_role` 通过 → 穿上（`WeaponItemHandler.put_on_weapon_item` 等）。

**结果**：每轮 tidy（福利 30 分钟/买令前）把装备的"穿/脱"翻转一次；真正的穿戴链 `bag_ops.auto_equip_best_items` 只在**稀疏的背包快照**（现场 ~1 次/小时，"背包整理: lv=" 23 条/天）跑一拍。两者叠加 → 装备长期随机停在"脱下相"（现场 65% 号装备栏空）。

**次要因素**：异性/条件不符的装备（head_m/chest_m 等）被服务端 `is_qualified_role` 静默拒绝，装备栏空后永远穿不上、躺在背包（用户"剩项链/鞋"的另一半来源）。

### 2.2 问题2：粗布包"只使用了一个"

`bag_ops.auto_use_bag_expanders`（旧）：
- 只在**登录首次**跑（msghandle 的 `bag_opened` 一次性）；
- 发一条 `C2S_USEITEM` 后**立即 `bag.pop(item_index)`**，永不再试；
- `m_bag_cache`/心跳按 item_index 覆盖（同款第二个实例只留 1 条），若显示的是"包裹栏那条"（`_is_in_bag_pos=False`）则背包里那个**永不被尝试**；
- 登录后新获得的粗布包（任务/商店）没有任何重试机会。

**现场**：41 个号背包区还有粗布包未装（其余 187 号已装到 25617）。服务端 `put_on_trough_item`（SV/item/pocket_operator.py:460）只校验槽位（`MAX_TROUGH_COUNT`）与包裹归属，**无同款限制 → 支持装多个**（用户预期正确）。

### 2.3 问题3：临时拾取栏未取出

- 服务端：`POCKET_TYPE_PICK=5167`，位置 `0x6450-0x64ff`（SV/item/item_param.py:69-70），物品带 `PICK_EXIST_TIME`（默认 **5 分钟**）过期销毁；`dispatch_pick_all_item`（SV/item/item_dispatcher.py:79）处理 `C2S_PICK_ALL_ITEM` → 逐件移回背包（背包满即停，回 notice 840 成功 / 841 失败）。
- 机器人端：`C2S_PICK_ALL_ITEM(80125)` **只有 `protocol2/c2s_key.py:128` 的 key 定义**——protocol3 无别名、无 FORMAT 注册、**0 调用点** → 掉落/包满转移进 PICK 区的物品全部吃满 5 分钟过期。
- 现场：多号 PICK 区有天命宝箱×4、铁布衫、追捕令等（尚未过期的）。
- 附带：`tidy` 对 PICK 区物品也会发 USE（同为"无位置过滤"受害者）；`encourage_claim._use_boxes` 用 `quest.bag` 无位置过滤（改造顺手加）。

## 3. 修复方案（已落盘，未部署）

原则：**所有"使用/丢弃"动作只对背包区物品**；装备/扩容包/拾取栏各交专链；新链路"能重试、能退避、不乱发包"。

| 文件 | 改动 |
|---|---|
| `daily_ghost.py` | ① `__tidy_bag` 重写收集阶段：**只处理背包区**（`0x2000<=pos<0x3000`，非背包区/无 pos 一律跳过）；**装备跳过**（双判据 `bag_ops._get_equip_slot` + 新增的 `meta["rel"]` 以 `element_` 开头，后者不依赖 client 表加载——`__load_item_meta` 已补解析 `related_element_index`）；**扩容包跳过**（交 auto_use_bag_expanders）；原 `to_drop/to_wear` 装备分支**废弃**（装备穿/丢统一交 `bag_ops.auto_equip_best_items` + `auto_summon._try_bag_cleanup` 的既有一套判据+防重闸）；数据源优先 `m_bag_cache`（带 pos）。② 新增 `tick_pick_pocket_cleanup`：缓存里有 PICK 区物品**或近 10 分钟有 839"包裹满转拾取栏"信号**（单条入包不更新缓存+全量快照稀疏，故补第二信号）→ 发 `C2S_PICK_ALL_ITEM`（节流 60s；战斗中/摆摊中跳过；连续 5 次无进展退避 10 分钟；空 PICK 时服务端回 840 无副作用） |
| `bag_ops.py` | ① 新增 `POS_TROUGH/POS_PICK` 常量（服务端权威区段）。② `auto_use_bag_expanders` 重写：**每次背包快照尝试**（幂等），**不再 pop**，按号节流 60s + 每会话上限 8 次 + 单轮上限 2 个；新增 `extra_ids` 参数（接收 msghandle 从**原始快照列表**收集的背包区扩容包实例，**绕开同 item_index 覆盖**） |
| `msghandle.py` | `role_item_handle`：解析循环里收集 `_bagx_raw`（原始列表里的背包区扩容包实例）；`auto_use_bag_expanders` 调用**移出"登录一次性"**，改为每次快照调用（内部自带节流/上限） |
| `main_tester.py` | 挂 `daily_ghost.tick_pick_pocket_cleanup(robot_object, now)`（与追捕令兜底清理并列） |
| `protocol3.py` | 注册 `C2S_PICK_ALL_ITEM = protocol2.c2s_key.C2S_PICK_ALL_ITEM`（80125）+ `FORMAT_MC[...]`（协议层） |
| `encourage_claim.py` | `_use_boxes` 加背包区 pos 过滤（拿 `m_bag_cache`；包满时奖励箱会进 PICK 区，对 PICK 区发 USE 无效）；`m_bag_cache` 空时回退旧行为 |
| `tools/item_pouch_fix_selftest.py`（新增） | 38 项断言：源码形状（含"不得再有 to_drop/to_wear/C2S_DROP_ITEM"反向断言）+ `tick_pick_pocket_cleanup` 与 `auto_use_bag_expanders` 的 mock 行为测试（发现即发/节流/战斗跳过/退避/不 pop/extra_ids/会话上限）+ 4 组坏版灵敏度 |
| `tools/item_use_selftest.py`（微调） | 蛋跳过敏感度断言的替换串适配新变量名（`_bo_egg`→`_bo`），兼容新旧写法 |

**明确不做**（防过度）：不改 Go；不给"异性装备穿不上"做特判（P2，缺服务端回执难判定）；不动 `auto_equip_best_items`/`should_drop_equip` 主体判据（09-21 已统一）。

## 6. 遗留 / P2 建议

1. **异性/条件不符装备永远穿不上**（服务端静默拒绝）：可后续在 `auto_equip_best_items` 用物品表性别/等级条件做"不再重复尝试"（需先把 `item_element` 的 condition 数据引入机器人端）。本次不动。
2. **背包快照稀疏（~1 次/小时）**：装备"脱下→穿回"的最坏延迟=快照周期。tidy 修复后不再主动脱下，仅"新获得装备"等快照穿上；如要加强，可把 `auto_equip_best_items` 挂一个低频 tick 兜底（P2，改动面小）。
3. **心跳 bag 缺 item_index**：面板"点击物品看实现"（清单任务）需要 `idx` 字段；本次未动（与三问题无关，避免混批）。
4. **PICK 清理的"背包满"死结**：背包满时 `PICK_ALL` 移不进去（notice 841），本实现最多重试 5 次后退避——根治要靠"先清背包"（tidy/丢弃链正常时自然缓解）。
