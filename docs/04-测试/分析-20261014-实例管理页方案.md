# 分析-20261014-实例管理页方案（多区形态 A：每区一套栈的统一管理）

> 状态：**只读侦察 + 方案设计**（未改任何代码/未启停任何进程）。目标：一个前端页面统一 创建/删除/重启/切换 多套栈（每套 = 1 Go 中控 + 1 机器人进程 + 1 data-dir + 1 robot 部署目录 + 一对端口）。
> 结论速览：**可行性高**。Go 中控已把状态几乎全部参数化到 `--data-dir/--deploy/--web-port/--ctrl-port`（main.go:93/122、config.go:474-494），现状唯一两个"拦路缺口"= ①`LogsDir` 硬编码 `base/logs`（config.go:485，无 CLI/env）②Go 侧不注入 `ROBOT_CTRL_PORT`（process.go 仅注入 ROBOT_ZONE_*，main.go:151-156）。推荐管理器**长在主中控**（新包 `internal/services/instances` + 独立 `instances.json`，所有实例同 exe 故人人都可当管理器）。

## 3. 生命周期操作分解

### 3.1 创建（向导；MVP 只生成脚本不自动执行）
1) **preflight**：端口空闲（试绑 2808x/2720x）、data-dir/deploy-dir/exe 唯一且存在、与既有实例的 zone/账号范围无交集。
2) **复制机器人目录**：源=干净模板（建议先固化一份 `_template/`，当前可直接用 `single_robot_zy_2300`）；排除清单（实测）：`*.bak_*`、`*.snap_*`、`__pycache__/`、`*.pyc`、`quest_progress_*.json`、`diag.log*`、`console*.log`。
3) **初始化 data-dir**：复制只读件 `chains/ maps.json item_usage_catalog.json`；生成 `zones.json`（单区+current）；生成 `accounts.json` 分片（§1.6）；其余（autotask/waterline/roampool/rotation/booth_config/personal_pool/share_daily_*）**运行时自生成、不存在=默认**（Load 语义已核：roampool.go:461-472 等）。
4) **端口分配**：web 从 28083 起 +1、ctrl 从 27201 起 +1（28082/27200 已占；py 18083/17201 不冲突）。
5) **生成启动脚本** `instances/<id>/start.bat`：模板=_start_detached 族；必须含 `set ROBOT_CTRL_PORT=<本实例ctrl>`（缺口 #2 的规避）、`--deploy/--data-dir/--web-port/--ctrl-port`、业务 env；**不要**带 `--kill-robots`（unless 显式）。
6) 首启（V2 再自动化）＝ `cmd /c start.bat`（detached）。
- 复用：目录复制/排除=新写小工具；端口试绑=net.Listen；脚本生成=模板字符串。风险：复制半途失败留脏目录（先写 `<id>.tmp` 再 rename）。

### 3.2 删除（归档不真删）
1) 停机器人：按 exe 路径前缀定位（orphans.go 模式）`taskkill /PID`；2) 停中控：按"命令行含 `--data-dir=<本实例>`/exe+启动时间"定位 PID 杀树；3) `rename data-dir → _archived/<id>_<ts>/data`（deploy-dir 可选一并归档）；4) instances.json 移除。防误删：二次确认 + 要求输入实例 id + 默认只归档。

### 3.3 重启（三种语义，UI 下拉）
- **温启**（中控重启、机器人不动）：复刻 `_restart_warm_*.bat`（无 `--auto-robot`）。
- **冷启**（中控+机器人，`--auto-robot`）：复刻 `_start_detached.bat`；注意 10-10 事故教训=先 Listen 端口再拉机器人（main.go:208-216 已修）。
- **仅机器人**：**走目标实例现成 API** `POST /api/robot/restart`（api.go:243 附近路由），不要外部杀进程（防止和实例内 Manager 互抢）。
- 幂等：操作前探活；已运行则 start 直接返回 ok。

### 3.4 切换（明确=页面视角切换）
- MVP=**跳转式**：`location.href = http://<host>:<web_port>/`（每个实例自托管同一份 dist；零 CORS、零 store.js 改动）。localStorage 记住常用实例列表。
- 进阶（V3）=同页聚合：由管理端后端**代发**跨实例 HTTP（server-side，无 CORS），前端只调本实例 API。
- **不影响任何进程**；与顶栏"区选择器"（实例内 current 指针）并用，文案区分"实例=哪套栈 / 区=栈内连哪个服"。

### 3.5 状态检测
- 进程存活：PowerShell 按 `ExecutablePath` 前缀扫 robot（复用 orphans.go:25-29 手法）+ 中控按命令行参数/端口归属（`Get-CimInstance Win32_Process` CommandLine 匹配 `--web-port`）。
- HTTP 探活：`GET /api/status`（现约 228KB/gzip 31KB；建议新增超轻 `GET /api/ping`，1 个 handler，返回 version/uptime）。频率：管理页 10s/实例；在线数低频 30-60s 或点击拉取。
- 快照写回 `status_cache`（instances.json），管理页即使某些实例挂也不空白。

## 4. 管理器放置方案对比与推荐

| 方案 | 优点 | 缺点 |
|---|---|---|
| a) 长在主中控（新包+独立 instances.json） | 复用面板/API/requireToken/WS；落地最快；**所有实例同 exe → 每个人口都能当管理器**（主栈挂可从 2 区栈操作） | 主栈与"被管对象的代理"耦合；watchdog 需配套改造 |
| b) 独立轻管理器（小 Go 服务/脚本） | 与实例解耦；实例全挂仍可管 | 多一个进程要守护；前端/鉴权/页面全要另做 |
| c) 纯脚本+手工 | 零开发 | 不满足"统一管理"需求 |

**推荐 a**：核心逻辑做成独立包（`internal/services/instances`）保持未来可平移；实例管理页在每个实例的面板上都在（读同一份 instances.json）；b 作为三期选项（实例数≥4 或需要"全挂可管"时）。c 仅作兜底 runbook。

## 5. API 设计（挂主中控路由表 api.go:196-243 同款）

- `GET  /api/instances`（列表+status_cache+实时探活摘要；只读）
- `POST /api/instances`（创建向导：validate→preflight→落盘+生成脚本；**requireToken**）
- `GET  /api/instances/{id}/status`（聚合探活+可选在线数）
- `POST /api/instances/{id}/start|stop`（进程旁路；requireToken）
- `POST /api/instances/{id}/restart`（`mode=warm|cold|robot`；robot 转目标实例 API；requireToken）
- `DELETE /api/instances/{id}`（归档；requireToken）
- 鉴权：复用 `requireToken`（api.go:310-330，Bearer / X-API-Token）；调目标实例时带目标实例自己的 token（读其 config.local.json）。
- 并发锁：`map[id]*sync.Mutex` + 操作幂等（进行中重复请求返回 409/ok:false"进行中"）；启动前必探活（防 10-10 式重复拉起事故）。

## 7. MVP 分期

- **V1（建议先做）**：只读实例列表（进程扫描+探活）+ 启/停/重启（warm/cold/robot）+ 跳转式切换器 + 创建向导（预检+生成脚本/不自动执行）。配套小改：`GET /api/ping`；watchdog 改"按端口逐实例探测"（消 >1 误报）。
- **V2**：自动创建（目录复制+data 初始化+账号分片工具）/删除归档/机器人目录升级（版本同步）；`LogsDir` 参数化（`CTRL_LOG_DIR`，config.go:485 小改）。
- **V3**：聚合视图（所有实例在线数/任务并列）、跨实例只读总览、可选独立轻管理器。

## 8. 风险与安全清单

1) **高权限 API**：杀进程/写目录接口务必 `requireToken` + 仅 127.0.0.1（现状 WebHost 默认，config.go:363）；管理页动作全部记 `Store.LogEvent`（审计）。
2) **误拉实例**（2026-10-10 事故）：start 前先探活+端口试绑；脚本单实例一份、不共享 bat。
3) **端口/目录冲突**：创建预检硬拦；ctrl_port 与 web_port 同实例内也校验不同值。
4) **删除缓冲**：rename 归档，永不先删。
5) **版本漂移**：2300 副本当前与生产零差异（10-14），但生产热更后会漂。建议：实例记录 `script_sha_snapshot`（创建时全量 sha1 清单落盘 instances/<id>/version.json）+ 一个 `sync_scripts`（白名单 diff→复制）工具；升级纪律=从主副本反向同步并复跑 cold_start_selftest。
6) **`LogsDir` 混写**（缺口 #1）：V2 前两实例共用目录可容忍（仅日志混排），禁用同一 `watchdog.log` 的双兜底（watchdog 只服务 1 号栈）。
7) **`ROBOT_CTRL_PORT` 注入**（缺口 #2）：向导生成的 bat 必 `set`；未来可在 Go 侧补注入（process.go extraEnv 追加 = 一行级改动）。
8) **账号双开**：分片按号段（§1.6），管理页在创建向导里校验与既有实例范围交集。
9) **资源预算**：每栈 ≈ robot 1.5GB 内存（280 号）+ 中控 ~70MB + 端口×2 + 磁盘（deploy 21MB、data 按 runs/bot_logs 30 天增长）；扩容前先看内存余量。
10) 当前 git 工作区非干净（rotation 熔断批 M 文件+2 份未提交报告）：开发实例管理页时**不要**混入这些文件（文件级提交纪律）。
