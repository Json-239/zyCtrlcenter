# 事故记录：机器人冷启动崩溃 → 面板「机器人通道未连接」（2026-09-23）

## 现象

- 面板/中控报「机器人通道未连接」「上线下发失败」
- 中控日志反复出现：`[PROC] 机器人已启动 pid=xxxx` → **`[PROC] 机器人进程退出: <nil>`**（启动即退出）
- 在线 0；水位器报「补号失败：上线下发失败：机器人通道未连接或池里没密码」

## 根因

`quest_engine.py` 模块级代码 `_PAID_JUMP_RE = re.compile(...)`（2026-09-22 加「传送选项优先免费」
时引入）**但整个文件没有 `import re`** → 冷启动即 `NameError` → 连锁 ImportError →
机器人进程启动即退出（exe 前台实跑可见完整 traceback）。

## 为什么被掩盖了一整天（关键教训）

9-22 当晚是**热更**（reload_scripts）上线的：Python reload 在**同一个模块字典**里重新执行模块代码，
执行到 679 行抛 NameError 中断 —— 679 行**之前**的定义（"乐观过图回滚"）已生效、
679 行**之后**的（"优先免费"）没生效。生产表现是"部分生效"：回滚逻辑工作正常
（当晚验证"号到达图 612"），刚好掩盖了「re 未导入」这一冷启动致命错误。

两个检测手段都抓不到它：
- `python -m py_compile` 只查语法，查不出 NameError；
- 当晚自检是文本静态检查（读文件内容），不是真实 import。

## 触发链（今早）

1. 10:46 中控启动（旧脚本不带 `--auto-robot`）→ 启动时 `killOrphansInDeployDir`
   清掉昨晚仍在运行的机器人进程（**设计行为**：防双进程抢控制通道）
2. 10:47/10:48 中控带 `--auto-robot` 拉起机器人 → **撞上冷启动崩溃** → 启动即退出
3. 面板持续报「通道未连接」

## 修复

1. `quest_engine.py` 头部加 `import re`（双副本同步；冷启动实跑验证：
   `cnetwork.connect returned`、状态统计正常）
2. 重新拉起机器人（`POST /api/robot/restart`）→ **通道已连接** → 在线 8 → 118 → 128+（水位器补号中）

## 固化（防再犯）

- 新增 `tools/cold_start_selftest.py`：mock `cnetwork` 后**真实 import** 11 个核心模块 +
  静态扫描「用了 `X.` 但未 import X」+ 双副本一致性（13 项）；
  已做**负向验证**（临时去掉 `import re` → 6 项 FAIL，正是事故形态）
- **流程约定**：改任何 `script/*.py` 后，除热更外**必须跑一次 `tools/cold_start_selftest.py`**
  —— 它能抓 NameError，这是 `py_compile` 与热更都抓不到的盲区
