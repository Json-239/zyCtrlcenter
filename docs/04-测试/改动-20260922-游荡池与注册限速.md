## 一、口径（用户已拍板，勿改）

| 项 | 口径 | 说明 |
|---|---|---|
| 在线总数 | **200** | 由「在线水位保持器」维持（本改动不碰它） |
| 抓鬼池 | **100** | `autotask` 的 `ghost.target_online`（现已设） |
| 新手池 | **0** | 池里可能已经没有新手号 |
| 游荡池 | **剩余（目标 100 左右）** | 任务池用不上的余量号去游荡打野 |
| 分布 | **均匀** | 别让某一张图机器人过多（按各图在线数从少到多轮流派） |
| 回收时机 | **立刻** | 任务池缺人马上回收游荡号（不等它这轮游荡走完；用户已接受路程损耗） |
| 生效范围 | 只对**当前区** | 机器人快照按 `robot.zone == 当前区` 过滤 |
| 时间口径 | 不抢时间 | 机器人端已有「空闲 90s 自动游荡」兜底 → keeper 只保证**名额与分布**，每 60s 一轮、单轮最多 5 个 |

三层互不打架：`水位（总数 200） ≥ 抓鬼池 100 + 新手池 0 + 游荡池（余量）`。
任务链路优先：**任务池缺人时游荡池不补位**（把名额让给任务池）。

## 二、游荡池 keeper（`internal/services/roampool`）

### 一轮判决（`Keeper.Tick`）

```
running = 在游荡的号数（机器人上报 walk.enabled=true，且**不在孵化**）
idle    = 在线且"不忙"的号（无任务态/无活跃抓鬼/未游荡/非战斗——判据复用 waterline.Busy，同一口径）
deficit = 抓鬼池 deficit + 新手池 deficit（正=缺人，负=超编；直接读 autotask.States()，不走 HTTP）

① 回收优先：deficit > 0 且 reclaim_on_deficit
   n = min(deficit, max_step, running)
   → PickReclaim（按"所在图人数从多到少"挑，顺带纠偏分布）→ StopRoam(n 个) → **本轮结束**
   （没有可回收的游荡号时也不补位：名额要留给任务池）

② 补位：running < target
   want = min(target - running, max_step, 空闲数)
   → PickIdle(want 个空闲号)
   → balance=true：BalanceAssign 按图均匀分成若干组 → 每张图一条 DispatchRoam(accounts, 图号)
      balance=false：一条 DispatchRoam(全部, "random")（机器人端每号自抽）
```

日志形如：

```
[ROAMPOOL] 回收 3 个游荡号给任务池（缺口 3，按图人数从多到少）：a1,a2,a3
[ROAMPOOL] 补位 5 个 → 图10×2 图24×1 图26×2（在游荡 47 / 目标 100）
[ROAMPOOL] 任务池缺口 2，但没有可回收的游荡号（在游荡 0）
[ROAMPOOL] 游荡池达标（在游荡 100 / 目标 100，空闲 3，缺口 0）
```

### 纯函数（可直接单测）

| 函数 | 行为 |
|---|---|
| `Roaming(r)` | 是否在游荡：`walk.enabled=true` **且不在孵化**（孵化是自动任务自己拉起的有时长会话，回收会打断它） |
| `Idle(r)` | 是否空闲：在线 且 `!waterline.Busy(r)`（任务态/抓鬼/战斗/游荡/孵化都算"在忙"） |
| `PickReclaim(robots, n)` | 从游荡号里挑 n 个：**按所在图人数降序**（并列按账号升序，结果稳定）；不足 n 有几个给几个 |
| `PickIdle(robots, n)` | 挑 n 个空闲号（保序；不足就有几个给几个） |
| `BalanceAssign(accs, mapsByLoad, n)` | 把号轮流派给"当前人最少"的图（每派一个就 +1，所以并列会轮流占位）；余数给并列中图号小的图；图比号多时只占前几张图 |
| `MapLoads(robots, maps)` | 各候选图当前在线号数（图号升序；没人的图 0 → 优先被派到） |

## 三、接口（面板/运维用）

### `GET /api/roampool`（只读）

```json
{"ok":true,"path":"<数据目录>/roampool.json",
 "enabled":false,"target":100,"interval_sec":60,"max_step":5,"minutes":0,
 "balance":true,"reclaim_on_deficit":true,"maps":null,"mode":"",
 "running":47,"idle":3,"deficit":0,"map_count":11,
 "env_pinned":[],"last_action":"补位 5 个 → 图10×2 图26×3","last_run_ts":1758528000,"last_err":""}
```

| 字段 | 含义 |
|---|---|
| `running` / `target` | 当前在游荡 / 目标（面板「在游荡 47/100」） |
| `idle` | 当前空闲（可派游荡）的号数 |
| `deficit` | 任务池缺口（**正 = 下一轮会回收游荡号**） |
| `map_count` | 可用游荡图张数（白名单 ∩ 链数据里有网格的图） |
| `env_pinned` | 被环境变量固定的字段（面板提示"这些改了也不生效"） |
| `last_action` / `last_run_ts` / `last_err` | 最近一次判决/动作、时间、失败原因 |

### `POST /api/roampool`（写接口，可选鉴权；未给的字段保持原值）

```json
{"enabled":true,"target":100,"interval_sec":60,"max_step":5,"minutes":0,
 "balance":true,"reclaim_on_deficit":true,"maps":[6,17],"mode":"dense"}
```

- `maps` 给 `[]` / `""` / `null` = **清空白名单**（回到"链数据里有网格的图"）；
- 校验：`target` 0~10000、`interval_sec` 10~3600、`max_step` 1~50、`minutes` 0~1440（0=不限）、图号须为正整数；
- 参数校验通过才落盘（`data/roampool.json`，原子写 tmp+rename）；**运行期面板改动直接生效并落盘**
  （环境变量只在**启动读盘时**覆盖，见下表说明）。

### 配置（`data/roampool.json`，环境变量可覆盖，**默认 `enabled=false`**）

| 字段 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `enabled` | **false** | — | 总开关；`false` 时**什么都不做**（必须人工开） |
| `target` | **100** | 0~10000 | 游荡池目标（在游荡的号数）；**0 = 不补位**（仍可回收） |
| `interval_sec` | **60** | 10~3600 | 每轮间隔（1 秒粒度轮询，改小下一轮立刻生效） |
| `max_step` | **5** | 1~50 | 单轮最多调整（回收/补位各自限幅） |
| `minutes` | **0** | 0~1440 | 游荡限时（分钟）；0=不限（机器人端不自动收工） |
| `balance` | **true** | — | true=按图均匀；false=每号自抽随机图（`mapid="random"`） |
| `reclaim_on_deficit` | **true** | — | 任务池缺人时立刻回收游荡号 |
| `maps` | 空 | 正整数数组 | 可选白名单；空 = 用链数据里**有网格**的图；白名单里没网格的图会跳过并记日志 |
| `mode` | 空 | 字符串 | 游荡档位（机器人端 `ROAM_PROFILES`；空 = 默认档 `default`） |

环境变量（**优先级：env > 文件 > 默认**；只在启动 `Load()` 时覆盖，运行期以面板为准）：
`CTRL_ROAMPOOL_ENABLED` / `_TARGET` / `_INTERVAL_SEC` / `_MAX_STEP` / `_MINUTES` / `_BALANCE` /
`_RECLAIM_ON_DEFICIT` / `_MAPS`（逗号串，如 `6,17,34,40`）/ `_MODE`。

## 四、注册自适应限速（`internal/api/handlers_create.go`）

**只改"节奏"，不动协议字段**：`106 取验证码 → 104 注册 → 700 结果` 与 8 个字段（验证码/账号/密码/
确认密码/激活码/姓名/身份证/QQ）保持不变。

| 规则 | 说明 |
|---|---|
| 撞风控 `112` | 有效并发**减半**（下限 `CTRL_CREATE_MIN_CONCURRENCY`，默认 2）、批间隔**加倍**（上限 60s） |
| 连续成功 | 每连续成功 `10` 次 → 并发 **+1**（上限 `CTRL_CREATE_MAX_CONCURRENCY`，默认 8）、批间隔**减半**（回到基准止） |
| 抖动 | 批间隔 `±CTRL_CREATE_JITTER_SEC` 秒（默认 ±2s），避免整齐节拍被风控盯上 |
| 请求只能更保守 | 实际并发 = `min(请求 concurrency, 限速器当前值)`；实际批间隔 = `max(请求 batch_interval_ms, 限速器当前值) + 抖动` |
| 生效时机 | 在途批次不改并发（避免抖动）；降速对**后续请求**生效 |
| 两条建号路径共享 | 面板建号与 `autotask` 的"没号自动注册"都走 `createOrReuse` → 都喂给同一个限速器 |
| 统计回带 | 建号响应 `throttle:{concurrency,batch_interval_sec,streak_112,total_112,total_ok}`；历史日志 `accounts_create` 另带 `concurrency` / `throttle_112` |

| 配置项（env/CLI 同现有风格） | 默认 | 含义 |
|---|---|---|
| `CTRL_CREATE_ADAPTIVE` | **1（开）** | 自适应限速总开关（关 = 只统计不调速） |
| `CTRL_CREATE_MAX_CONCURRENCY` | **8** | 并发上限（替换原硬编码 8） |
| `CTRL_CREATE_MIN_CONCURRENCY` | **2** | 并发下限（降速降到这里为止） |
| `CTRL_CREATE_BATCH_INTERVAL_SEC` | **5** | 批间隔基准（秒）；请求没给/给得更小都以此为准 |
| `CTRL_CREATE_JITTER_SEC` | **2** | 批间隔 ±抖动（秒） |

1. **必须重启**：新增包 + `main.go` 装配 + 新路由 → 只热更脚本无效；由主控在维护窗口替换 exe 后重启。

   未装配时显示"未装配（需重启中控）"）。

   面板「游荡池」卡勾「启用」，或启动前设 `CTRL_ROAMPOOL_ENABLED=1`。
4. 建议开启顺序：先确认水位目标（200）与抓鬼池保持数（100）→ 再开游荡池（目标 100）→ 观察
   `last_action` 与日志 `[ROAMPOOL]`。
5. 限速器随进程启动即为"开"（`CTRL_CREATE_ADAPTIVE` 默认 1）：建号比此前保守（批间隔基准 5s ± 2s、
   并发 8）；**要恢复更快的节奏**把 `CTRL_CREATE_BATCH_INTERVAL_SEC` 设为 0。

## 七、风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 回收打断游荡 | 立刻回收会打断正在走的路程（可能白走一段） | 用户已拍板接受；回收量受 `max_step`（默认 5/轮）限制，不会一次全回收 |
| 限速过保守 → 建号变慢 | 持续撞 112 时会退到 2 并发 / 60s 批间隔，20 个号可能要十几分钟 | 看 `throttle.total_112`；确认风控判据后可调 `CTRL_CREATE_MIN_CONCURRENCY`/`CTRL_CREATE_BATCH_INTERVAL_SEC`；根治仍需服务端内部建号接口（评估见 `分析-20260922-三链路池与注册协议评估.md`） |
| 无在途记账 | 下发后要等机器人上报 `walk.enabled=true`（秒级）才计入 `running` | 60s 一轮远大于上报延迟；机器人端「空闲 90s 自动游荡」兜底，不抢时间 |
| 与机器人端自动游荡叠加 | 机器人自己也会去游荡（非池子派发），这些号同样计入 `running` | 设计如此：池子只管**名额与分布**，达标（running ≥ target）就不再补 |
| 白名单与网格不匹配 | 白名单里的图没有寻路网格 → 该图派不出去（`Payloads.Walk` 硬失败） | keeper 取"白名单 ∩ 有网格"并**记日志**列出被跳过的图；下发失败只记 `last_err`、下一轮再补 |
| 单轮异常 | 任何异常/单张图失败 | `Tick` 的 panic 被 `Start` 兜住；单图失败不影响其它图与下一轮；`enabled=false` 时一次动作都不发 |
