## 1. 机器人端：游荡任务参数化（`random_walk.py`）

### 1.1 分层：档位（profile）× 任务形态（图/时长）

```
游荡任务 = 档位(mode: default | dense | gather占位)
         × 目标图(mapid: 数字 | "random")
         × 白名单(maps: 可选, 如孵化图 [6,17,34,40])
         × 限时(minutes: 分钟; 0/缺省=不限)
```

- **档位注册表** `ROAM_PROFILES`（`random_walk.py:311-327`）：`default`（账号级随机，拟人挂机）、
  `dense`（密集游荡，孵化踩暗雷）、`gather`（**占位**：`placeholder=True` + `fallback="default"` + `desc`）。
  → 以后加"挖宝/打猎"等用途 = 加一个 dict 条目，**不用改游荡主循环**。
- **占位档位不静默**（`apply_roam_profile`，`random_walk.py:329-361`）：请求 `gather` → 回退 `default`，
  写一条 `集合走: 档位 'gather' 尚未实现(占位) → 回退 default` 日志，并在 `w.profile_req` 记录请求值；
  dispatch 的 reply 里带 `profile_req` / `profile_fallback`（中控/日志都能看到）。
- **纯函数（可单测，注入随机）**：
  - `is_random_map(v)`（`random_walk.py:374-379`）：random/rand/any 词识别；
  - `norm_map_list(maps)`（`:382-398`）：白名单解析（数组 / `"6,17"` / 单数字 / 去重 / 非法项忽略）；
  - `pick_random_map(candidates, exclude, rng)`（`:402-433`）：抽签（可注入 rng；尽量避开当前图，候选只剩它时仍返回）；
  - `resolve_roam_target(req_mapid, req_maps, grid_mapids, current_map, rng)`（`:438-492`）：
    **一切参数校验的唯一入口**，返回 `(mapid, maps, err)`；`err` 非空 = 明确拒绝（原因原样回日志/reply）。
- **限时**：`__apply_minutes`（`:870-883`）解析 `minutes` → `w.deadline_ms`；`tick` 入口处到点自动
  `random_walk_stop` 并记日志（`:660-673`）。孵化链路不传 `minutes` → 不受影响（它按 `max_minutes` 自己收工）。
- **范围自动计算**：命令未给 `range` 时按目标图网格算（`__auto_range`，`:843-867`，与
  `mount_egg.__walk_range_for` 同算法，内联一份避免反向依赖）；算不出退回原东海村默认范围。
- **幂等/续约兼容随机图**（`__req_same_map`，`:886-898`）：随机图"抽签只抽一次"——同一号续约/补发不再重抽；
  但用户**又点一次随机图**（上次不是随机）按"重新抽签"处理（允许换图）。
- **解析入口**：`dispatch_cmd` 的 `random_walk` 分支（`:901-1070`，起点 `:908`；解析/拒绝在 `:965-975`；
  启动 reply 在 `:1057-1070`）；孵化图白名单常量 `HATCH_MAPS`（`:309`）。
- **热更兜底**：所有新字段读取一律 `getattr`（`deadline_ms` / `map_req` / `profile` / `maps` / `minutes`），
  旧实例（热更前建的 `CollectWalkState`）不会 AttributeError。

### 1.2 命令契约（向下兼容）

```jsonc
// 中控 → 机器人（random_walk）
{"cmd":"random_walk","accounts":["a@x.com"],
 "mapid": 6,              // 数字=指定图；"random"=随机图（每号抽签）
 "maps": [6,17,34,40],    // 可选白名单：random 时只从这里挑；指定图时必须在内
 "mode": "dense",         // 档位（default/dense/gather…）；"random" 也接受为随机图别名
 "minutes": 30,           // 限时（0=不限）；机器人端到点自动停
 "chain": {...}, "range": [[x1,y1],[x2,y2]], "min_bot_dist": 200}
```

- 机器人端 reply 扩展：`{mapid, profile, maps, random, minutes, deadline_ms}`；
  拒绝时 `{"result":"error","reason":"bad_params","detail":"人话原因"}`（`client.py:356-361` 会把 reply 上报中控）。
- **行为变化（刻意）**：①缺 `mapid` 不再默认图 5，而是**明确拒绝**（宁可失败也不静默改图）；
  ②指定图不在白名单 / 白名单里没有有网格的图 / 目标图没有网格 → 拒绝；
  ③命令里带 `minutes` 键才会刷新倒计时（补发续约不带 = 保持已有倒计时）。

### 1.3 与孵化链路（`mount_egg`）的关系（功能 4 口径）

- `mount_egg.__start` = 放蛋校验 → `random_walk` 命令 `{"mapid":<孵化图>, "mode":"dense"}` → 计数/notice/超时
  （`mount_egg.py:285-303`）。**孵化链路一行未改**（不在本次"只碰"清单里）。
- 本次新增的「孵化图游荡」入口只是把"同一套走法"做成**正式入口**：中控下发 `mapid=孵化图 + mode=dense`，
  **不带 `hatch_start`**，所以不放蛋、不计数 —— 号上有蛋（业务上要求）时才顺带踩暗雷攒灵气；
  无蛋就是纯游荡。白名单 6/17/34/40 来自服务端 `CFG/mount.xml`（只有这 4 张图能孵出坐骑）。
- 现场孵化调度（抓鬼满 → 孵化）**不变**：仍走 autotask `hatch` 策略（中控 `hatch.go`），本次未动 autotask。

## 2. 中控 Go：`/api/random_walk` 参数层与校验层扩展

文件：`internal/api/randomwalk.go`（handler）、`internal/api/chainpayload.go`（载荷）、`internal/api/api.go`（路由注释）。

| 入参 | 说明 |
|---|---|
| `mapid` | 数字图号 或 字符串 `"random"`（随机图）。缺/非法 → 明确拒绝 |
| `maps` | 可选白名单：`[6,17,34,40]` / `"6,17"` / 单数字；任一项非法（非数字/<=0）→ 拒绝；空数组 → 拒绝 |
| `mode` | 档位透传（default/dense/gather…）；**也接受 `"mode":"random"`** 作为随机图等价别名（此时档位用可选 `profile` 字段） |
| `minutes` | 限时（0=不限）：**总是随命令下发**（含 0），机器人端据此刷新/清除倒计时 |
| `range` / `min_bot_dist` | 可选透传（不变） |

校验（全部"明确报错 + 一条命令都不发"）：

- `mapid` 与 `mode=random` 同时给 → 拒绝（冲突）；
- 指定图不在 `maps` 白名单 → 拒绝（不静默换图）；
- 随机图 + 白名单里没有任何一张图有寻路网格 → 拒绝（`Payloads.WalkRandom`，`chainpayload.go`）；
- 链数据缺 `dijkstra` / 缺目标图网格 → 拒绝（沿用既有硬校验；`Walk` 拆出 `walkBase`/`cloneWalkChain`/`gridKeysText`，**语义与报错文案不变**）。

**抽签不在中控做**：随机数由机器人端每号独立抽（避免全号扎堆同一张图），中控只给"白名单 + 候选存在性校验"。

## 5. 风险与残留

| # | 风险/残留 | 说明与缓解 |
|---|---|---|
| R1 | **Go/前端尚未生效** | Go 改动需重启中控（主控安排在维护窗口）；前端产物需部署。重启前「随机图」按钮会收到旧 handler 的"mapid 必填"，属预期 |
| R2 | 机器人端"缺 mapid 不再默认图 5" | 已知下发方（`/api/random_walk`、`mount_egg`）都带 `mapid`；如现场有**手工**命令不带 mapid，会被明确拒绝（日志有原因）。刻意如此：不静默改图 |
| R3 | 未给 `range` 时范围改为"按目标图网格自动算" | 影响"老 API 手工下发且不带 range"的路径（更贴合目标图，减少选点失败）；孵化/抓鬼链路都显式带 range，不受影响。若观感异常，可继续显式传 `range` 覆盖 |
| R4 | `minutes` 落地后的续约语义 | 只有命令**带 `minutes` 键**才刷新倒计时（补发续约不带则保持）；中控新 handler 总是带（0=清除），所以"空时长"= 不限时 |
| R5 | `gather` 只是占位 | 选它必然回退 default（日志 + reply `profile_fallback`）。第三位 agent 的采集模块合入时：去掉 `placeholder/fallback`、按节点间走动节奏填参数即可（不用改主循环） |
| R6 | 随机图抽签在机器人端 | 每号不同 → 号可能散在多张图；`maps` 白名单是唯一收口手段。若要求"全号同图"，用「选图游荡」 |
| R7 | 心跳未扩展档位/剩余时长 | `walk` 上报仍是 `{enabled,mapid,state}`，前端只显示"游荡中 + 目标图"；要显示档位/倒计时需在 `client.py` 的 status 段加字段（**本次未动 `client.py`**，热更会清空其模块级缓存，历史踩过） |
| R8 | 未做采集/挖矿动作、未动 autotask | 本次只在参数层预留；"游荡挖矿"仍待 T1~T7 实测（见 `分析-20260922-游荡功能扩展方案.md` §2.3） |
| R9 | 未做现场试跑 | 建议首次试跑：单号、`default`、`minutes=10`、目标图 6；再看 `walk.enabled`/绿环/`WALK_MOVE`/到点自动停 |
