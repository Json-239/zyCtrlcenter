### 1.3 核心逻辑（关键代码）

**① 偏移兜底纯函数**（`quest_engine.py:2063`）：

```python
STAND_OFFSET_MIN_PX = 32
STAND_OFFSET_MAX_PX = 80
_OFFSET_ROUND_EPS = 0.71   # round 取整误差上限 √2/2，采样半径内缩它保证实际距离不越界

def pick_stand_offset(x, y, min_px=STAND_OFFSET_MIN_PX, max_px=STAND_OFFSET_MAX_PX, rand=None, ang=None):
	# 偏移兜底纯函数：角度随机(可注入 ang)、半径在 [min_px,max_px] 随机，返回 (x+dx, y+dy)。
	_rnd = rand or random.random
	lo = float(min_px) + _OFFSET_ROUND_EPS
	hi = max(lo, float(max_px) - _OFFSET_ROUND_EPS)
	if ang == None:
		ang = _rnd() * 2.0 * math.pi
	r = lo + _rnd() * (hi - lo)
	return (int(round(x + math.cos(ang) * r)), int(round(y + math.sin(ang) * r)))
```

- 半径 [32, 80] 像素（2~5 格）；下限 32 > `walk_synced_skip_dist(20)` → 偏移后一定会真走路，不会被"已在目标附近"捷径跳过。
- 采样半径内缩 `_OFFSET_ROUND_EPS`，保证像素取整后**实际距离仍严格落在 [32,80]**（自检 ⑦ 验证）。

**② `__stand_point` 加固**（`quest_engine.py:2080`）：

```python
def __stand_point(robot_object, quest, pos, npc_id, click_type):
	if click_type != 0 or pos == None:
		return None                      # 战斗类/无坐标：保持原行为且不记日志（避免刷屏）
	mapid = pos[0]
	why = ""
	try:
		grid_data = __chain_grid_for(quest, mapid)
		if grid_data == None:
			why = "无网格"
		else:
			g = robot_path.MapGrid(mapid, grid_data)
			gx0, gy0 = g.to_grid(pos[1], pos[2])
			pt = pick_stand_point(g, gx0, gy0)
			if pt != None:
				return [mapid, int(pt[0]), int(pt[1])]     # 优先路径：网格采样（不变）
			why = "有网格但采样失败"
	except Exception as e:
		why = "网格异常(%s)" % e
	# 兜底：走不通时服务端会拒移动，退化为原地（可接受）
	try:
		ox, oy = pick_stand_offset(pos[1], pos[2])
	except Exception as e:
		__emit(robot_object, {"type": "log", "level": "warn",
			"msg": "对话站位: NPC %s 图%s %s, 偏移兜底也异常(%s) → 保持原目标" % (npc_id, mapid, why, e)})
		return None
	__emit(robot_object, {"type": "log", "level": "warn",
		"msg": "对话站位: NPC %s 图%s %s → 退化偏移兜底 (%d,%d) 距 NPC 约 %dpx（不占 NPC 格）" % (
			npc_id, mapid, why, ox, oy, int(round(math.hypot(ox - pos[1], oy - pos[2]))))})
	return [mapid, ox, oy]
```

要点：

1. **warn 日志可区分**三种失败（`why` 字段）：`无网格` / `有网格但采样失败` / `网格异常(<异常文本>)`，且都带 `npc_id`、`mapid`，写明网格是否拿到 —— 现场看一条日志即可定位。
2. **兜底**：网格不可用时对 NPC 像素坐标加随机偏移，返回 `[map, x+dx, y+dy]`，保证号散开。
3. **战斗类不变**：`click_type != 0` 在函数入口直接 `return None`，不碰任何状态（也不发日志）。
4. `pos == None` 分支不加日志：调用方已有一条明确 warn（"NPC %s 无坐标, 原地点击尝试"），避免重复。

**③ 调用点**（`quest_engine.py:267`）：只增加传入 `robot_object`，其余流程（debug 日志、`quest.click_dbg`、走路/跨图）不变。

### 5.1 Bug 1：站位块被嵌进 `live` 分支（`__teleport_click`，266-275 行）

**原因**：第 1 轮插入的站位块整体缩进比 `if live != None and pos != None:` 深一级，而它前面的
两行说明注释是 1 tab —— 于是 `if pos != None:` / `if _stand != None:` 都落在 **`live` 覆盖块的内部**：

```python
	live = __npc_live_pos(robot_object, npc_id)
	if live != None and pos != None:            # ← live 无实时坐标时整块跳过
		pos = [pos[0], live[1], live[2]]
	# 2026-09-21 对话站位随机化：...（注释是 1 tab，站位块却是 2 tab）
		if pos != None:                          # 2 tab：嵌在上面 if 里
			_stand = __stand_point(...)
		if _stand != None:                       # 2 tab：同上
			__emit(...)
			pos = _stand
```

**后果**：`live == None`（刚登录 / `NPC_LIVE_POS_TTL_MS` 过期 / 刚跨图、`__npc_live_pos` 返回 None 或
坐标过旧）时**完全不站位**，号仍旧叠在 NPC 原格 —— 正是本次要修的问题。
（测试报告里"② `_stand` 可能是上一次调用残留值"这一条**不成立**：`_stand` 是 `__teleport_click` 的
函数局部变量，每次调用都是新栈帧，且 `if _stand != None` 也在 `live` 块内、与赋值同块执行，
不存在跨调用残留（更不会 UnboundLocalError）。真正的 bug 只有一个：**整块被 live 分支劫持**。
该结论已由 5.3 的对照模拟实测确认。）

**修法**：把站位块提回函数体顶层（与 `if live != None ...` 同级），并把这段结论写进代码注释。

### 6.2 口径说明：前端 `enabled` vs 后端"字段非空"（本轮的"差异"是有意的）

**机器人上报结构**（`deploy/zones/prod-240-2300/script/client.py:437`）：
`st["ghost"] = {"state": g.state, "done": …, "limit": …, "role": …, "enabled": g.enabled}`；
`GhostState.__init__`（`daily_ghost.py:277-280`）默认 `enabled=False, state="IDLE"`，
`enabled=True` 仅在收到 `ghost_start` 后置位（`daily_ghost.py:1128`），
停止/移除/跑完时置回 `False`（492 / 510 / 542 / 1124 / 1201）。
→ **字段存在** ≈ "该号上报过 GhostState"（含待命/已停止/已跑完）；**`enabled === true`** = 真有在跑的抓鬼会话。

| 侧 | 判据 | 代码位置 | 面向的用途 |
|---|---|---|---|

| 后端（r4 已改，见 §七） | `!r.GhostActive()`（= `ghost.enabled === true`） | `internal/api/autotask.go:334`（`autotaskOnlineCount`，与保持数 `TargetOnline` 比较） | **调度口径**：只有活跃会话才算"在跑"（字段非空但已停的不算；否则 running 虚高、保持数永久"已达标"不补号） |

| 每日满额（r4 **保留原语义**） | `internal/api/autotask.go:253` `ghostDailyFull` | `Ghost == nil → 不判满` |

`Robot.GhostActive()`（`internal/state/state.go:62`，本轮新增，**单一真相源**）：

- `ghost.enabled === true` → true（有活跃会话）；
- `ghost` 字段存在但 `enabled` 非 true → false（会话已停，IDLE/DONE/卡死残留都算）；
- **老版上报缺 `enabled` 字段 → true**（按"有会话"保守处理，不误伤）。

**`ghostDailyFull` 为什么保留"字段非空"语义**：它回答的不是"这个号此刻是否在跑"，而是
"今天还能不能再派"（候选过滤门槛）：

1. 缺数据（`Ghost == nil`）→ 不判满 = 宁可多派一次、由服务端拒绝 —— 保守不误伤（原有语义，不动）；
2. 现场 43 个停摆号里 **27 个是 DONE** —— DONE 表示今日抓满，必须继续判"今日已满"
   （若改看 `enabled`，这 27 个会被当成"可再派"，与"重登也会被服务端拒"的原意相悖）。

因此该函数明确**不纳入**本轮口径统一。
