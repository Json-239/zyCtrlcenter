## 0. 结论速览

1. **真穷号核实结论**：机器人号全部为 **VIP0**，"每日福利"里的储备金对 VIP0 = **0（服务端直接不发）**——
   即**不存在"补领每日奖励就能变富"的号**，"领完也没钱"对全部 23 个穷号成立。
   按"能否自救"细分：**4 个号连 1 个金创药（211 储备金）都买不起 = 真穷（无自救能力）**；
   其余 19 个 ≥211，修复"按余额降量买药"后即可自愈（买 1 个药→用药→抓鬼赚 6000/轮→滚雪球）。
2. **穷号不派抓鬼**：推荐"**4 道代码闸 + 1 个手动动作**"最小组合（全部旁路，不动抓鬼主流程）：
   - 代码闸：G1 抓鬼候选过滤（autotask.go）/ G2 恢复引擎闸（GhostSkipFunc）/ G3 游荡回收资格闸（roampool.go）
     / R1 机器人端接单闸（daily_ghost）。
   - 手动动作：对处置号下发一次游荡（`POST /api/random_walk`）。
   - 恢复通道：号有钱后（≥ 阈值）自动回到抓鬼候选，无需再操作。
3. **三个买药修复**（P0-2 → P0-1 → P0-3）：落点、伪代码、自检用例点见第 3 节。
4. **与残留任务闸（GHOST_LEFTOVER_TASK）的交叉**（gp2 发现 97~102 号触发；实测两份名单 **0 交集**）：
   A=买药穷号 23 个（穷储备金）；B=残留任务号 97 个（穷现金、reserve 反而富，中位 23 万）——
   **处置名单分开管**；"转游荡"可压住 B 群体复现（前提=本节 G 闸已部署）。详见 §2.6。

func (a *API) ghostReserveFloor() int {
    if a.Cfg != nil && a.Cfg.GhostReserveFloor > 0 { return a.Cfg.GhostReserveFloor }
    return 500
}

// reserveTooLowForGhost 储备金低到"大概率买不起药"（数据缺席时保守放行，由机器人端兜底）
func (a *API) reserveTooLowForGhost(r state.Robot) (bool, string) {

        return true, fmt.Sprintf("储备金不足（%d < %d，防买药空转）", r.Reserve, floor)
    }
    return false, ""
}

### 2.3 为什么"不动抓鬼主流程"

- 全部改动都是**旁路闸**（候选筛选 / 跳过补发 / 回收资格 / 接单拒绝），不触碰
  `ghost_start` 主链路、不触碰导航/商店/战斗逻辑；
- 所有闸都"**条件不满足即放行**"（正常富号行为零变化）；
- 每处都有现成同类先例（等级闸/满额闸/熔断闸），实现风险低、可单测。

### 2.5 恢复通道与风险说明

- **恢复**：号 reserve ≥ 阈值（人工补钱/接任务赚钱后），G1/G2/G3/R1 自动放行；号保持在游荡时需先停游荡
  或等游荡结束后自然回到抓鬼候选（窗口 ≤ 游荡限时）。
- **不做"暂停"的原因**：暂停（IsPaused）会连"游荡派发/回收/补发"全部停掉（`roampool.go:757`），
  号会彻底静止且不自动恢复；而"游荡 + G 闸"方案保留自动恢复通道。
- **风险（reserve 数据缺席=0）**：`state.Robot.Reserve` 缺席时是 0，用 `r.Reserve>0` 才拦的写法会漏
  "真 0"号 → 由 R1/§3 修复兜底（P0-1 可买数 0 短路 + P0-2 552 秒回 + P0-3 冷却升级）。
  若后续要更严，先给心跳加 `reserve_set` 标志（本次不做，避免扩大改动面）。

### 2.6 残留任务闸（GHOST_LEFTOVER_TASK）与转游荡的顺序【2026-09-28 与 gp2 交叉补充 + 实测交集】

**交叉发现**（gp2 只读报告：`docs/04-测试/分析-20260928-卡在NPC附近排查.md`）：
重启后 **97~102 个号**触发 GHOST_LEFTOVER_TASK（放弃被拒≥2 + 连续无鬼 → 停空转），
其中 **96 号 money（银两）< 500**；闭环=抓鬼启动→等刷鬼无鬼→回钟馗放弃→**服务端拒（放弃需扣 500 银两，
号上不足）**→停空转→15~30s 后被重新派发→复现。

**实测交集（本文档编者对两份数据交叉核验，16:1x 口径）**：
- 残留任务号（97 个）特征：**reserve 中位 233,578（富，买得起药）、money 中位 206（穷现金）**；
- 买药穷号（23 个）：reserve 56~34,277（穷储备金），money 亦低；
- **两组交集 = 0**（5253/5097/5243 等均不在残留集合；5199 等残留号不在穷号集合）。
- 结论：**"穷"的两个钱包维度分属两批号**——A 群体穷 reserve（买药循环），B 群体穷 money（残留循环），
  处置名单须**分开管理**（不要合并成一份）。

| 群体 | 号数 | 穷的钱包 | 卡点 | 所需"补钱" |
|---|---|---|---|---|
| A：买药循环 | 23 | 储备金 reserve（56~34,277 < 211×批量） | 药铺"552→超时"循环 | 储备金 ~5000/号（或修 P0-1 降量自愈） |
| B：残留任务循环 | 97 | 现金 money（中位 206 < 500 放弃费） | "放弃被拒→等刷鬼"循环 | 现金 ~1000/号即可清残留 |

**"转游荡"是否能压住残留任务复现？——能，但有前提**：
- 游荡启动会 `ghost_stop`（`daily_ghost.py:1861`：仅 `g.enabled=False` + reset，**不放弃服务端任务**）；
- 游荡中：G1（候选过滤）/G2（restorer 跳过）/isTasking 都会阻止"再次派发 ghost_start"→
  残留任务冻结保持（不再接取→不再复现放弃循环）；任务推送（12054 等）由 daily_ghost 在 enabled 时才消费，
  **不驱动导航**（待部署前复验一遍真实样本）。
- 前提=G1/G2/G3 已部署（否则游荡结束瞬间/任务池缺人回收时会被拉回抓鬼）。
- **顺序建议**：① 部署 P0+G 闸 → ②（可选，推荐）补现金清残留任务 → ③ 下发游荡 → ④ 观察。

**"先清任务"的低成本路径（可选）**：
- 给 B 群体号补 ≥500 现金（money）→ 残留出口的"放弃"路径自然可成功（既有逻辑会自动走；
  或人工让它走一轮"启动→等刷鬼→放弃"）；
- 若不补：保留残留任务 + 游荡（冻结保持）也可以，但任务不清、`task_index≠0` 会持续被
  newbie/分享日常等候选视为"有任务"，压舱到跨日/人工清。
- **注意**：B 群体的"无鬼"根因（服务端刷鬼/等刷鬼超时）与补钱无关——补钱只解开"放弃"闸，
  若服务端持续无鬼，号清完任务再抓鬼仍会进"等刷鬼"；**"转游荡"对 B 群体可能才是主要出路**（gp2 口径）。

### 3.1 P0-2：552 立即失败回传（先做——收益最快、改动最小）
