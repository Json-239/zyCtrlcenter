### 2.1 50 级门槛与其他门槛

**（a）开摊门槛（用户点名的"50 级限制"就这一处）**

- `SV/booth/booth_operator.py:57-60`：
  ```
  limit_level = config.get_int_value(keys.config.BOOTH_LEVLE_LIMIT)
  if role_object.get_role_level() < limit_level:
      role_object.send_notice_message(keys.notice.NOTICE_LEVEL_CAN_NOT_BARGIN, limit_level)

  ```
- 配置实测值：`BOOTH_LEVLE_LIMIT,摆摊时的等级限制,50`（`SVCFG/config/config.csv:73`）。

### 2.2 完整流程

**开摊**：`C2S_SELLER_START_BOOTH(80170)` [booth_name, booth_poster] → `seller_start_booth`（`booth_operator.py:50-82`）→ 通过 5 项检查后创建 BoothObject、`begin_booth()`（进入摆摊状态）、广播 `S2C_SELLER_START_BOOTH(90009)`（含自己）。

**上架**：`C2S_UP_SELLER_ITEM(80236)` [物品实例 id(8字节), price(4字节)] → 检查：物品在背包 / 未锁定 / 可交易（`item_object.get_can_trade()`，默认 True：`SV/item/item_base.py:93`）/ 未在售 / 不超上限 → 记录价格 → 回 `S2C_UP_SELLER_ITEM(90059)`。
- **价格完全自由**（服务端无上下限校验）；物品**仍留在卖家背包**（BoothObject 只登记 item_id→price，`SV/booth/booth_object.py:74-84`），卖不掉可下架（`C2S_DOWN_SELLER_ITEM(80086)`），收摊不丢货。
- 召唤兽上架 `C2S_UP_SELLER_SUMMON(80007)`（≤11 只）。

**被购买**：
- 买家必须**与摊主距离 ≤600**（`booth_operator.py:454` `common.check_two_role_distance(role_object, target_role_object, 600)`）→ 打开摊位（`C2S_ENTER_BOOTH_STORE`）→ 列表（`C2S_LIST_STORE_ITEM`）→ 购买（`C2S_BUY_STORE_ITEM`）。
- 校验链（`booth_operator.py:232-277`）：在售 / 物品存在 / 买家资格 / 数量 / **价格一致性**（`:262` 买家应付 = `int(item_price*(100+3)/100)`）/ 买家背包有格 / **买家钱够**。
- 成交：买家付含税价、**卖家收原价**、税被系统抽走（`:272-285`）；双方 notice；卖家另收 **`S2C_SOLD_BOOTH_ITEM(90147)`** [买家id, 买家名, 单价, 数量, 物品链接]（`:293`）。

**收摊**：`C2S_SELLER_CLOSE_BOOTH(80070)` → `seller_close_booth`（`booth_operator.py:84-96`）→ 结算摆摊时长（见 2.5）→ 删摊位、广播 `S2C_SELLER_CLOSE_BOOTH(90109)`、结束摆摊状态。

### 2.3 摆摊期间的操作限制（在线摆摊 = 纯站桩）

摆摊状态 `BoothRoleStatus`（`SV/restrict/restrict_status.py:153-175`）禁用：
**走路、跑步、战斗、再摆摊、钓鱼、主动交易、物品操作、守护操作、守护跟随、宠物跟随、组队、归队传送、锁操作、点击 NPC、切换地图、寻宝、隐身、筋斗云、前世今生**。

推论（对设计关键）：
- **不能点击 NPC / 不能切图 → 摆摊时不能做任务、不能抓鬼、不能游荡、不能采购**；
- 可做：上下架物品、改摊名/广告、聊天、收摊（这些不在禁用表内）；
- 因此"在线摆摊"只能作为**独立档位**（专职摆摊号），不可能与任务并行——与用户"做完任务的号去摆摊"的口径吻合（填谷，不是并行）。

### 2.4 离线摆摊机制（决定设计方向的核心）

**设置**：`C2S_SAVE_OFFLINE_BOOTH_SETTING(80274)` [booth_time(分), grid_num, stamina_count, is_grid_close, is_stamina_close]（格式 `[2,1,2,1,1]`，`RB/protocol2/c2s_list.py:640`）→ `SV/booth/booth_dispatcher.py:89-118`：
1. 校验：单次时长 ≤ VIP 表 `offline_booth_once_hour`（VIP0=8 小时，`SVCFG/vip.csv` 第 20 列）；本周剩余额度（`840 分钟 - 已用 + (level-50)*30`，`OFFLINE_BOOTH_ONE_WEEK=840` `SVCFG/config/booth.csv:8`）；**现金不得超过本等级携带上限**（超了拒绝，`:110-113`；50 级上限 5 千万，`SVCFG/carry_money.csv` 49/50 行）。
2. 若当前有摊位：加 **buff 4322**（`OFFLINE_BOOTH_BUFF_INDEX`，时长 = booth_time 分钟）+ `set_booth_busy(True)`。
3. **`role.role_operator.close_role_client`（`:118`，无条件）**：下发 `S2C_IMMEDIATE_CLOSE_CLIENT` 关闭客户端（`SV/role/role_operator.py:641-647`）。
   - **坑（高危）**：没有摊位时发这条协议 = 号被白踢下线（不下发摆摊 buff、不进入离线摆摊）。机器人端必须"先开摊成功再发设置"。

**挂摊期间**（角色留在服务器内存）：
- 客户端断开 → 服务端登出流程进入 busy 分支：`is_booth_busy` → `insert_booth_offline` + `set_offline_flag(True)` + 保存数据、**不释放角色**（`SV/login/login_operator.py:227-242`）——摊位继续存在于服务器，可被玩家购买（推论，未实测）。
- **扣体力**：buff 4322 的定时检测每分钟扣 1 点（`OFFLINE_BOOTH_ONE_MINUTE_COST=1` `SVCFG/config/booth.csv:5`；`SV/buff/buff_action.py:1435-1440`）。体力上限 4800（`SVCFG/config/config.csv:46`），在线回复 72 秒/点、离线 120 秒/点（`:44-45`）→ 按离线回复算净消耗约 0.5 点/分钟，**满体力约可撑 160 小时，体力一般不是瓶颈**（除非号已近枯竭）。
- **终止条件**（`buff_action.py:1449-1453`）：buff 时长到 / 体力为 0 / 体力低于设定下限（若勾选）/ 在售件数低于设定下限（若勾选）→ 删 buff → `release_buff_action`：**收摊** + 离线则释放角色（`:1456-1459`）。
- **收益结算**（`booth_operator.py:318-344`）：离线卖出时先填现金至携带上限，**溢出部分自动进存款**，并写**离线留言**（`cache.manager.private_note_message`，上线后可见"离线摆摊卖出物品得现金/存款"提示，文案见 `SVCFG/notice/notice_booth.csv`）。
- **上限**：单次 ≤8 小时（VIP0）、每周 14 小时（=840 分钟，50 级基础值；每高 1 级 +30 分钟；VIP0 摆摊每周领双上限 4 小时另计）。

**终结（重要）**：
- **上线即收摊**：号回到世界（`after_virtual_enter_world`）时会 `seller_close_booth` + `remove_booth_offline` + 删 4322 buff（`SV/role/role_observer.py:113-123`）；顶号同理（`before_role_reenter_world`，`:475-483`）。
- ⇒ **离线摆摊号绝不能重登**（我们机器人端的自动重连/水位拉起/看门狗重启都会"一登收摊"）；要等 buff 自然到期（收摊后角色释放）。
- 正常主动下线路径也会收摊（`before_role_leave_world`，`:486-503`）——但离线摆摊走的是 busy 保留分支，不经过这里（逻辑自洽）。
- Guard：`LOGOUT_BUSY_TIMEOUT=60`（`SV/login/login_operator.py:28,243-258`）——登出 busy 反复重入超 60 秒才强退，防卡死；对正常离线摆摊无影响。

### 2.5 收益与约束概要

- 税 3%（**买家付**：`taxed = price*103/100`；卖家收原价）——`SVCFG/config/booth.csv:11`、`booth_operator.py:262,272-274`。
- 定价自由、无摆摊费、无上架费；**卖不动 = 零收益**。
- 摆摊时长奖励：每满 4 小时摆摊（秒）累计 1 小时双倍经验时间（`BOOTH_EXCHANGE_MULEX=14400` `SVCFG/config/config.csv:29`；`booth_operator.py:434-449`），每周上限 VIP0=4 小时（`SVCFG/vip.csv` 第 19 列）。对刷怪/任务号才有意义（摆摊本身不能战斗）。
- 通知：在线被买 = 游戏内 notice + `S2C_SOLD_BOOTH_ITEM`；离线被买 = 离线留言（上线后可查）+ 现金/存款变动。

## 5. 接入方案（论证与取舍）

### 方案① 离线摆摊档（**推荐试点**，前提是号 ≥50 级）

- 流程：号走到摆摊区 → 开摊（booth_start）→ 上架（读背包缓存筛可卖物品）→ 设置离线摆摊（时长 N 分钟）→ 服务端踢线 → **我们不再重连**，号在服务器内存挂摊 → buff 到期/体力耗尽自动收摊释放 →（下次调度上线时自然恢复，上线动作本身也会兜底收摊）。
- 优点：不占机器人连接与三池在线名额；收益离线入账（现金满溢自动进存款）；可多号并行；被买不会打扰机器人端。
- 缺点：必须先开摊（50 级）；单次 ≤8h、每周 14h/号；每分钟扣 1 体力；**绝不能被重登**（水位器/看门狗/轮换任何"拉起"都会收摊）；货卖不动就是零收益。
- 实现要点：
  - 机器人端补写 `booth.py`（含 offline 分支：设置成功后**主动断开并置"离线摆摊中"禁重连标志**，把号从在线管理摘除）；
  - 中控侧新增"摆摊中"台账（复用既有持久台账模式：`data/state/*.json` 原子写），并把这类号从三池/水位/轮换中排除；
  - 到点回收 = 重新上线（上线即收摊）→ 清台账 → 回池。

### 方案② 在线摆摊档（专职摆摊号，可用但更贵）

- 流程：号保持在线站桩（BoothRoleStatus 限制下不能动/不能点 NPC/不能战斗），机器人端维持连接、定时心跳、被买即补货。
- 优点：被买即时通知（90147）；可随时上下架/收摊；无需重登管理；摆摊时长奖励照算。
- 缺点：**占机器人连接与在线名额**（三池容量被吃掉）；号完全站桩（不填谷、不抓鬼）；同受 50 级门槛限制；真人可见度最高。
- 适用：长期蹲点的"品牌摊位"（像参考实现那样专职卖货），与①并存。

### 方案③ 混合（先①，特定货用②）

- 有 ≥50 级号 → 默认走①；需要频繁补货/高价值货物/需要实时确认成交的，走②。

### 结论：**现况不建议投开发**，"验证优先"

- 理由：**可用号 = 1 个**（机器人端开发 + 中控池管理 + 前端适配的总工作量，与 1 个号的收益极不相称）；且摆摊收益高度依赖真人买家（见 4.4）。
- 但仍值得花小成本做**单号最小验证**（见第 7 节）：确认服务端行为、离线摆摊留存时长、被买结算路径，把"能不能用"变成事实，而不是等有号了再走一遍。

### 中控侧接入点（若日后开发，可直接照此设计）

- **候选条件**：`level>=50`（心跳已有 level）+ 不忙（state 非 SUBMIT/FIGHT 等）+ 有可卖物品（机器人端筛 `bag_ops.is_protected_item` 为假、且 `can_trade` 的物品；建议心跳带 `booth.can_list` 件数）+ 未在摆摊台账中。
- **下发命令**：复用既有命名 `booth_start` / `booth_stop` / `booth_status`（client.py 已支持），新增参数如 `offline_minutes`（>0 走离线摆摊，=0 走在线）。
- **心跳状态块**（已有基础，建议扩）：`booth={enabled,state,sold,income,name,offline_until,listed}`。
- **回收**：`booth_stop`；掉线处理（离线摆摊号不得被"重登拉起"逻辑触碰）；被买空/额度耗尽 → 结束。
- **与三池/水位/孵化池的关系**：摆摊号从三池调度排除（新增 `booth` 池或池内标记）；抓鬼/神捕互斥让路模式（`GhostSkipFunc`）可照搬；孵化/领双等日任务优先于摆摊（摆摊=填谷）。

## 6. 风险与注意事项

1. **50 级门槛是硬约束**：误对 <50 号下发开摊 = 无害拒绝（notice）；但**误发离线摆摊设置 = 直接踢下线**（`booth_dispatcher.py:118` 无条件 `close_role_client`）→ 会打断正在跑的抓鬼/任务，必须"等级 + 已有摊位 + 活跃状态"三重校验后才允许发。
2. **重登即收摊**：离线摆摊号被任何"拉起"（水位器/看门狗/轮换/人工重登）触碰都会立即收摊（`role_observer.py:113-123`）——货不丢（物品一直留在背包），但功能白做、台账污染。必须让"摆摊中"状态对全部编排可见。
3. **暴露面**：摆摊点在人流集中的长安东市集（map11），摊位名默认含角色名；真人可围观/交互/购买。建议正常化摊名与广告文案（参考 onsell_base 的"卖药卖药"），避免"robot"字样；本行为与现有机器人操作同性质（合规口径由用户决策）。
4. **经济风险**：无人买 = 长期空摊；自家号互买净亏 3% 税；定价手误（服务端无二次确认，只有买卖双方价格一致性校验）；**上架必须排除保护集合**（药/助战令/蛋，`RB/bag_ops.py:395-406`），并与 `tidy_bag`/孵化（蛋）流程互斥。
5. **在售物品的状态风险**：上架物品仍在背包（被买才扣），上架期间可能被其他自动化误用/丢弃（tidy_bag 丢弃逻辑、孵化放蛋等）——要么把"在售物品"纳入保护，要么功能上闸。
6. **体力/额度**：离线摆摊 1 点/分钟、周额度 14h（50 级）——低效号可能撑不满时；离线摆摊参数（体力下限/格子下限）若设置不当，第一分钟就触发收摊（`buff_action.py:1449-1451`），建议下限一律关闭（is_*_close=0）。
7. **服务端侧的摆摊内存**：离线摆摊号在服务器端是**常驻角色对象**（`insert_booth_offline` / 保活分支），服务端已有"摆摊对象泄漏"加固（`SV/login/login_operator.py:267-292` `force_logout_offline_role` 注释明确"关闭摆摊(含离线摆摊), 避免摆摊对象泄漏"）——批量使用前先小规模观察残留与内存（摆摊号数量、`get_booth_offline_count`）。
8. **反自动化**：未发现服务端针对摆摊的自动化检测（无验证码/行为分析证据）；摆摊是官方功能、协议合法。风险主要来自"异常账号特征"被人工注意，与现有机器人同类。

## 7. 试点建议（最小验证，1 个号）

**对象**：`robot0001032@xy3.com`（50 级，"令狐代芙"，抓鬼池）——现况全池唯一够资格者。建议验证期把它临时从抓鬼池摘出（1 个号对抓鬼吞吐影响可忽略）。

3. **上架 2-3 件低价值非保护物品**（从背包挑非药/非蛋/非助战令；定价参考 onsell_item 样例的低位 250-800）→ 看 `S2C_UP_SELLER_ITEM(90059)` 回执。

6. **回收**：`booth_stop` 收摊 → 确认物品仍在背包、号恢复可调度、心跳 booth 字段变空（中控自动清残留）。
7. **记录**：开摊成功率（矩形有效性）、被买是否发生（真人样本）、离线摆摊的留存与收摊时序、任何 notice 留档。

- 先查"号池为何集中在 31-49"（练级瓶颈/上限设计），评估 49→50 的练级成本；**50 级问题不解决，摆摊没有规模化价值**（本报告最重要的约束）。
