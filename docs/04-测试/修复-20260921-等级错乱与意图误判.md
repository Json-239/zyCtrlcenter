## 0. 一句话

机器人端偶发上报错等级（rd 侧源头未查），中控**单次错值就立刻覆盖 + 立刻切意图**，把
39 级抓鬼号污染成"新手"；同时抓鬼候选的"未毕业"过滤有个 `level > 0` 前置漏洞，
把等级未知（0）的 1 级新手当抓鬼号下发，被服务端通知码 71 拒绝。
本次在中控侧补两道防御：**大幅回退防抖（连续 3 次才认账）+ 未毕业号（含等级未知）不派抓鬼**。

## 1. 问题 1：39 被单次错成 9，抓鬼号被切成「🆕新手」

### 1.1 中控日志时间线（robot0001028）

```
19:36 ~ 20:20  [RESTORE] 意图=ghost（等级 39 ≥ 31 → 抓鬼）      ← 一直 39，正常抓鬼
20:27:19       [INTENT] 意图切换：ghost → newbie（等级 9 < 31 → 新手链优先）  ← 突然变 9
```

### 1.2 机器人端证据（同一时刻）

- 机器人端 diag / runs 日志：`背包整理: lv=39`（**真实 39 级**）；
- 该号实际在正常抓鬼（`ghost.enabled=true`）；
- 即：某一次上报把 `level` 从 39 错成 9，中控据此切换意图 →
  **大屏「🆕新手」筛选显示了正在抓鬼的号**（用户报的现象）。

### 1.3 根因链

```
① 机器人端某次上报 level 错值（39 → 9；fd 竞态 / 残留等级是怀疑方向，见 §4）
        ↓
② 中控 event.go 无防抖：onRobotOnline `r.Level = level`、onStatusReply `r.Level = toInt(v)`
        —— 任何一次错值都**立刻覆盖**已确认等级
        ↓
③ 覆盖后立刻 decideIntent(account, r.Level, ...) → 9 < 31 → 意图切成 newbie
        ↓
④ 大屏按意图筛选 → 正在抓鬼的号出现在「🆕新手」里
```

旧代码（两处入口，已改）：

```go
// onRobotOnline（约 231-243 行）
r.Level = level
...
h.decideIntent(account, level, chainDone, zone, "decide")

// onStatusReply 心跳（约 319-321 行）
if v, ok := st["level"]; ok {
    r.Level = toInt(v)
}
```

### 1.4 改动 1：等级"大幅回退"防抖

`internal/state/state.go`（`Robot`，紧跟 `Level` 字段）：

```go
Level int `json:"level"`
// LevelPending / LevelPendingN 等级"大幅回退"待确认（连续 LevelPendingN 次上报同一新值才真切换，
// 见 event.applyLevel）：单次错值不覆盖已确认等级、不触发意图切换。
// json:"-"：纯内部防抖状态，不进 status 接口/面板。
LevelPending  int `json:"-"`
LevelPendingN int `json:"-"`
```

`internal/services/event/event.go`（新增防抖核心，约 L220-289）：

```go
const (
	levelRegressThreshold = 10 // 已确认等级 - 新上报 ≥ 10 视为"大幅回退"（可疑）
	levelRegressConfirmN  = 3  // 同一可疑新值连续出现 N 次才切换
)

// applyLevel 等级防抖写入（r 在状态锁内，本函数不加锁）。
//   - 新值 > 0 且 已确认等级 - 新值 ≥ 10 → 大幅回退：**不覆盖**，累计连续次数；
//     同一新值连续 3 次 → 切换并清零待确认态；
//   - 其余（升级 / 小幅回退 <10 / 首次上报 / 与已确认值相同）→ 立即生效并清零待确认态
//     （正确值一回来就清，防"错值闪现"让后续错值凑满连续次数）；
//   - 新值 ≤ 0（未知）→ 不判定、不覆盖已有非零等级（比旧行为更保守：旧代码会用 0 覆盖）。
func applyLevel(r *state.Robot, level int) levelUpdate { ... }
```

两个入口改为"防抖写入 + 用**有效等级**判意图"，并在锁外统一打 warn：

```go
// onRobotOnline（L313 起）
reported, chainDone := toInt(ev["level"]), false
level := 0 // 防抖后的**有效等级**（单次错值不会立刻覆盖，也就不会污染意图判定）
var lv levelUpdate
h.St.Update(account, func(r *state.Robot) {
	...
	lv = applyLevel(r, reported)
	...
	level = r.Level
})
h.logLevelUpdate(account, zone, lv)
h.decideIntent(account, level, chainDone, zone, "decide")

// onStatusReply 心跳（L399）
if v, ok := st["level"]; ok {
	lv = applyLevel(r, toInt(v))
}
...
h.logLevelUpdate(account, zone, lv)
h.decideIntent(account, level, chainDone, zone, "status") // level = r.Level（有效等级）
```

### 1.5 防抖口径表

| 场景 | 行为 |
|---|---|
| 首次上报（0 → 39） | 立即生效（不受防抖影响） |
| 升级（39 → 45） | 立即生效 |
| 小幅回退（39 → 35，差 < 10） | 立即生效（旧行为不变） |
| **大幅回退（39 → 9，差 ≥ 10）** | **不覆盖**；同一新值连续 3 次才切换；单次/断续错值完全无副作用 |
| 错值后正确值插回（9 → 39） | 立即生效并清零待确认计数（"连续"口径，不跨值累计） |
| 上报 0（未知） | 不参与判定、不覆盖已有非零等级 |
| 面板/接口 | `LevelPending*` 带 `json:"-"`，`/api/status`、WS 推送里不可见 |

可诊断日志（应用日志 `logs/ctrlcenter_*.log` + 面板运行历史各一条 warn，含旧值/新值/连续次数）：


## 2. 问题 2：1 级真新手被当抓鬼候选下发（通知码 71）

### 2.1 中控日志时间线（robot0009905，真新手：1 级 / 654 血）

```
20:24:02  账号上线
20:24:04  [INTENT] newbie（等级 1 < 31）
20:24:09  [RESTORE] 补发 start_chain                      ← 到这里都对
20:24:11  [AUTOTASK] 抓鬼 已下发抓鬼任务: ...,robot0009905@xy3.com   ← ✗ 抓鬼池把 1 级号当候选下发
20:24:39  捉鬼接取被拒: 通知码 71(等级不足(要求 ≥13 级))   ← 服务端拒绝（号白跑一趟）
```

### 2.2 根因：`level > 0` 前置漏洞

`autotaskCandidates` 的 `case autotask.KindGhost`（修复前）：

```go
if !chainDone && level > 0 && level < a.newbieMaxLevel() {
	continue // 没毕业的号不抓鬼
}
if ok, _ := a.ghostGate(level, r.GhostRequiredLevel); !ok { continue }
```

- 1 级新手号**刚上线那一瞬**，心跳还没到 / 或字段未上报 → `level == 0`；
- `level > 0` 前置条件让 `level == 0` **穿过**第一道"未毕业不抓鬼"的过滤；
- `ghostGate(0, 0)` 的口径是"等级未知（<=0）不拦"（为兼容重连中的真毕业号）→ 也不拦；
- 结果：未毕业 + 等级未知的号被当抓鬼候选下发 → 服务端按通知码 71 拒绝。

### 2.3 改动 2：去掉 `level > 0` 前置

`internal/api/autotask.go`（L231 起）：

```go
case autotask.KindGhost:
	// 未毕业（新手链未完成）一律不派抓鬼，**含等级未知（<=0）**：
	// 旧判据 `level > 0 &&` 让 level=0 穿过这道过滤，ghostGate 又不拦 0，
	// 于是 1 级新手号在上线瞬间被当抓鬼候选下发，服务端以通知码 71
	// （等级不足，要求 ≥13 级）拒绝，号白跑一趟（2026-09-21 robot0009905）。
	// newbieMaxLevel() 恒 > 0，所以 `level < a.newbieMaxLevel()` 天然覆盖 level<=0。
	// 已毕业但等级未知的仍允许：服务端 gate / 学到的 required_level 兜底，别误伤重连中的号。
	if !chainDone && level < a.newbieMaxLevel() {
		continue // 没毕业 / 等级未知且未毕业 → 不派抓鬼
	}
```

口径（**写清避免误伤**）：

| 状态 | 抓鬼候选 |
|---|---|
| 未毕业 + 等级未知（0） | **不派**（本次修复点） |
| 未毕业 + 1 级 | 不派（原有口径，`< 31`） |
| 未毕业 + 20 级（含 chain_done=true） | 不派（等级门槛 31 / ghostGate 原有口径） |
| **已毕业 + 等级未知（0）** | **允许**（服务端 gate / 学到的 `required_level` 兜底；重连中的真毕业号不误伤） |
| 已毕业 + ≥ 门槛 | 允许 |

## 4. 遗留与建议

1. **错值源头在机器人端（未查，建议单独立项）**：机器人端 diag 显示真实 39，但某次上报
   给出 9 —— 怀疑方向是 **fd/对象竞态或残留等级**（例如换角色/重连时读到旧缓存或半初始化
   数据）。本次中控侧**只做防御**（不让单次错值产生副作用），**没有定位机器人端根因**；
   建议后续单独立项：在机器人端上报路径加"等级来源 + 上报序号"打点，抓到错值样本再修。
2. **防抖只能挡"单次/短暂错值"**：若机器人端**持续**错报同一值 ≥3 次心跳（约 9 秒），
   中控仍会认账并切意图 —— 这是刻意保留的"真降级也要能生效"通道；根治仍要 §4.1。
3. **防抖不跨会话**：账号行被 10 分钟无心跳清理后重登，`r.Level` 从 0 起算 → 首次上报
   直接采信（与旧行为一致）。生产 robot0001028 全程行未消失（39 持续 20+ 分钟），本次修复覆盖。
4. **池内等级未防抖**：`accounts.ZoneState.Level`（`internal/api/handlers_verify.go:344` 等写入口）
   仍是"写多少信多少"；但候选判定优先用运行时 `r.Level`（>0 时），仅运行时无数据才回落到池，
   影响面小，暂不扩大改动面。
5. **reghost 补发不受本次过滤影响**：卡死重登恢复按"意图"直接补发；若某号意图已经是 ghost
   但实际等级不够，仍会下发一次（服务端 gate 会拒）。属既有设计（恢复引擎有 `GhostSkipFunc`
   等级闸，口径同 §2）。
6. **部署后观察口径**（给主控）：
   - `logs/ctrlcenter_*.log` 与面板运行历史里搜 `等级大幅回退待确认` / `等级大幅回退已确认`
     —— 关注出现频率与账号分布，可作为机器人端错值的取证来源；
   - 大屏「🆕新手」筛选不应再出现"正在抓鬼（ghost.enabled=true）"的号；
   - 抓鬼下发日志里不应再出现"未毕业/等级未知"的号（对得上"捉鬼接取被拒: 通知码 71"应消失）。
