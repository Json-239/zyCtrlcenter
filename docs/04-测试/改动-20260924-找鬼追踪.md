## 2. 根因链（daily_ghost.py，改动前行号）

1. **坐标快照永不刷新**：12054 只在 `on_add_task`（1835）/`on_load_task`（1779）/缓存恢复（3482）
   解析一次 → `g.kill_area` 是"接取瞬间的快照"。服务端 TASK_UPDATE（90396）经
   `msghandle.__route_task_event` → `quest_engine.on_event` 会刷新 `quest.tasks[ti]`（含最新 attr），
   但 **daily_ghost 无任何消费点**（grep 全文件：无 update_task 处理、无重解析）→
   即使服务端重推了新坐标也不会追。
2. **换图与 kill_area 互相拉锯（P0）**：`g.rounds >= 3` 时 `__pick_ghost_map` 换图
   （3609，条件只看"当前图 in ghost_maps"，**无视 kill_area 任务图**）→ 挑到 map_skip 直达的
   别的刷鬼图；下一 tick 等鬼分支的 kill_area 导航（3494）又把号拉回任务图 →
   26↔9 往返 5 次/单号（每次 ~80 秒，途经付费跳转 13255）。全场 11160 次/天。
3. **换图对"发现鬼"零帮助**：90351（ADD/MOVE）是**全局推送**（号在图 24 也收到"鬼在图 26"），
   且 99.94% 的鬼就在任务图 → 换去别的图纯浪费（还付费）。
4. **（另案，不在本次改动范围）NAV 追鬼到图瞬间误清鬼**：到达图 26 的同一秒判
   "NAV 超时, 第 3 次重试"（`rounds` 是跨状态共享计数，第 3 次非本 NAV 真实次数，
   与 09-23 SUBMIT 误报同款）→ 本地 pop 鬼（3776–3806）→ 服务端不再推 → 之后 20 分钟无鬼。
   该修复在 NAV 分支，超出本次"只改 WAIT_GHOST 无鬼分支"的约束，**保持不动**（见 §6）。

## 3. 修复（两处，均在 WAIT_GHOST 的"无鬼"分支内）

### A. 追新坐标 `__refresh_hunt_target`（新增，改动后 1416–1490 行区）

等鬼期间**节流 3 秒**重读 `quest.tasks[task_index]` 的 12054（`__parse_task_attr` 复用既有解析）：

- 坐标变化（鬼移动/服务端刷新任务点）→ 更新 `g.kill_area` / `g.target_locs` →
  交给下方既有导航逻辑（跨图 `__goto_xy` / 同图 walk >350px）追过去；
- **坐标未变 / 解析失败 / 任务缺失 / 达上限（4 次/任务）→ 返回 False 且不改任何状态**
  （与修复前逐字节一致，零副作用）；
- 调用点：等鬼分支缓存恢复之后、kill_area 导航之前（改动后 3576 行），
  **唯一一处**，且在"发现鬼 → NAV"（有鬼直接 return）之后 —— 有鬼时永不走到新逻辑；
- 追新计数按任务号重置（`hunt_follow_ti`）；同号重派不重置是保守取舍
  （极端连续重派下额度更早耗尽 → 退回现状，不会更坏）。

### B. 3 轮换图不越任务图（改动后 3688–3708 行区）

`g.rounds >= 3` 的换图条件追加 `and not g.kill_area`：

- 有任务目标坐标时**留在任务图等/巡逻**（鬼 99.94% 在任务图；换图零帮助 + 引发拉锯）；
  日志："等刷鬼 N 轮无鬼, **任务图内**继续等/巡逻(保留任务, 不换图)"；
- `kill_area` 缺失（拿不到坐标）→ 与修复前**逐字节一致**（换图碰运气，旧文案保留，
  统计口径"等刷鬼 N 轮无鬼"前缀不变）；
- 6 轮 → 回钟馗放弃重接、12 轮 → 残留出口等兜底链路全部保留不变。

## 5. 评估

**消减推算（基于 09-24 全量日志）**：

- 换图拉锯：11160 次/天"前往图≠任务图"跨图 → 归零（有 kill_area 时不换图）；
  按每次跨图 30~80 秒、含 13255 付费跳转（5 银）估算，约省 **100+ 小时·号/天**的跨图时间
  与相应银两（411 号 ≈ 每号 15~25 分钟/天）。
- 换图引发/加速的"回钟馗放弃被拒"往返（1443 次 wait_ext + 相关放弃往返）在等鬼链路上
  减少（extend 分支"原地换图再等"实际变为"原地等"）。
- "等刷鬼 N 轮"计数本身**不会**因本修复直接下降（30 秒/轮的计时不变），下降的是
  「等鬼 → 换图 → 跨图往返」的附加动作。
- **对"抢鬼"场景无改善**：鬼被别的号打掉/被本地清掉后服务端不重推，本修复不解决
  （需 NAV 清鬼修复或服务端重刷机制，见 §6）。

**风险面**：

1. 追新上限 4 次/任务 → 坐标高频抖动时最多追 4 次即停（不会无底洞）；
2. 新坐标点在阻挡格/不可达 → 走既有兜底（跨图无路由 → 原地等刷鬼；同图 walk 由
   quest_engine 寻路兜底）；
3. 不换图的最坏结果：若服务端确把鬼刷在非任务图（样本 8/7112 ≈ 0.1%）→ 号在任务图等不到，
   走既有 6 轮 → 回钟馗 → 12 轮 → 残留出口链路（与旧行为同样的终态，但少了跨图浪费）；
4. 观测口径：kill_area 路径的"等刷鬼 N 轮无鬼"文案变为"任务图内继续等/巡逻(保留任务, 不换图)"，
   前缀与"等刷鬼 N 轮无鬼"保持一致，既有 grep 统计不受影响。
