## 0. 结论速览

1. **标记落盘推荐：独立文件 `data/personal_pool.json`（方案 b）**。决定性证据：`tools/import_accounts.py:94-101`
   是**全量重建** accounts.json（"_comment: 可重复导入覆盖"）—— 方案 a（Account 加字段）会在每次重导入时被清掉，
   除非同步给导入工具打"保留字段"补丁（可作后续演进）。
2. **`poolOf` 加 `personal` 分支可顺带解决面板分区与"可用"计数**（`handlers_accounts.go:528`、`autotask.go:880-899`），
   但候选/派发/恢复等**仍需 12+ 处显式闸**（§2 全清单）。
3. **手动入口**：上下线有现成（`/api/robots/batch` force、`/api/robots/manage`）；新手链有现成直发（`/api/start auto:false`）；
   **抓鬼/神捕/烽火没有"指定号直发"入口**（`/api/autotask/run` 是整池跑一轮）→ 建议新增薄端点
   `POST /api/personal/task`，内部复用 `ghostStartCmdOf` / startAuto 的日常构造 / start_chain 构造 + 机器人既有 stop 命令。
4. **MVP**：标记文件与 API + `poolOf` 分区 + §2 全部闸 + 意图作废 + 私号任务 start/stop 四任务 + 前端勾选/标签/私人池卡。

## 1. 标记落盘设计（对比 + 推荐）

**现状**：池分区纯推导 —— `api.poolOf`（`internal/api/handlers_accounts.go:528-559`，按等级/chain_done）；
`Account` 结构（`internal/services/accounts/accounts.go:59-73`）无显式标记；`ZoneState`（`:26-41`）为区维度。

| | 方案 a：Account 加字段 | 方案 b：独立文件（推荐） |
|---|---|---|
| 落点 | `Account.Personal bool`（号级）；**不建议**放 ZoneState（"私号"是账号属性，与区无关；"A 区私有 B 区不私有"无业务诉求） | `data/personal_pool.json`：`{"accounts":["a@x.com", ...]}`；由 accounts 包小注册表（Load/Save/Has/Add/Remove，原子写）或 api 层持有 |
| 持久化 | 随 accounts.json 原子写自动保存 | 独立原子写 |
| **重导入风险** | **会被 `tools/import_accounts.py` 全量重建清掉**（`:94-101` json.dump 全量覆写）——需给导入工具加"读旧文件保留 personal"补丁 | **免疫**（导入只写 accounts.json） |
| 删号清理 | 随记录删除自动清 | 需在 `Pool.Remove`/删号 API 顺带清（或容忍悬垂，`IsPersonal` 前查池存在性即可） |
| 审计/手工操作 | 需翻大 JSON | 一眼可读、可直接编辑 |
| 加号入口 | `handleAccountsAdd`（`handlers_accounts.go:155`）需透传（`Add` 签名扩展或 Add 后 `SetFields`） | 端点加一个 `personal:true` 分支写注册表即可 |

**推荐 b**，并预留 a 的迁移路径（若将来想单文件，先给导入工具补保留逻辑，再做一次性合并）。
**与 poolOf 的优先级**：`poolOf` 首行 `if a.IsPersonal(acc) { return "personal" }` —— personal **覆盖**推导；
这样 `poolUsable`（`autotask.go:880-899`）与面板分区自动排除，前端 `POOL_LABEL`（`AccountsView.vue:46`）加一项即可。
移入/移出 = `POST /api/personal/add|remove {accounts}`；重启不丢（文件加载）。

## 3. 手动执行入口盘点 + 推荐实现路径

**现成通道**：

| 入口 | 语义 | 对私号可用性 |
|---|---|---|
| `POST /api/start {auto:false, accounts, chain_id}`（`handleStart` `handlers.go:332`） | 指定号直发 `start_chain`（导航链拒绝 :359） | ✅ 新手链可直接用（不带配额；但会走队内/暂停等既有前置） |
| `POST /api/start {auto:true}` → `startAuto`（:490） | 按意图分配，**带配额截断**（:581 `cutByPoolQuota manual=true`）与队内剔除 | ⚠ 不适用（配额+意图） |
| `POST /api/autotask/run {kind}`（`autotask.go:1304`） | **整池立即跑一轮**（RunNow+Tick），非定向 | ❌ 不适用 |
| `POST /api/robots/batch {action,accounts,force}`（`handlers_accounts.go:191` → `batchOnline:244`） | 手动上下线（chunk/interval/容量闸+force） | ✅ 上下线现成 |
| `POST /api/robots/manage {action:add|remove}`（:1060 区） | 单号 add/remove（reghost 同款） | ✅ |
| 抓鬼 / 神捕 / 烽火 **单号直发** | **不存在**（只在 startAuto 内部 `toGhost:539`/`toDaily:747`） | ❌ 需新增 |
| 停止命令（机器人协议现成） | `ghost_stop`（daily_ghost.py:2160）、`share_daily_stop`（share_daily.py:1961）、quest `stop`（quest_engine.py:5123） | ✅ 直发即可 |

**推荐（最小新增）**：`POST /api/personal/task {accounts, task:"ghost|shenbu|fenghuo|newbie", action:"start|stop", daily_limit?}`
- start-ghost → `ghostStartCmdOf(accs,"solo",limit)`（`autotask.go:1141`）直发（tag `personal_ghost_start`）；
- start-shenbu/fenghuo → 从 `startAuto` 的 toDaily 发送段（`handlers.go:743-758`）抽出 `shareDailyStartCmdOf(kind, accs)` 直发
  （带 share_key/nav/daily_limit/done；tag `personal_daily_start`）；
- start-newbie → 抽 `newbieStartCmdOf(accs)`（同 `LaunchTask` KindNewbie 构造，`:1060-1076`）直发（tag `personal_start_chain`）；
- stop → 按 task 直发上述 stop 命令（tag `personal_stop`）。
- 原则：**不写任何在途/配额/台账**（dailyInflight/ghostInflight/dailySessions 都不碰），但**不绕机器人协议**
  （仍 `a.Events.SendCmd`；机器人端幂等/互斥规则照旧——手动顺序责任在用户）。
- 上线：建议端点内可选 `ensure_online:true` → `sendOnlineChunks` 后延时（≈8s，参照 RESTORE_DELAY）再发任务；或前端两步走（先用 batch 上线）。

## 5. 语义边界决策点（建议默认口径）

1. **上线/下线命令**：与自动派发同命令（`robot_manage add/remove`），仅绕过编排/配额/台账；不做专用协议。
2. **在线数口径**：**显示**（账号池/大屏在线列仍可见），但**不参与**水位目标、本地兜底读数、池"可用"统计与所有配额口径
   （§2.1-3/5）。livecount（外部全服读数）本就含真人，不区分——不必动。
3. **机器人侧影响**：`auto_relogin`（进程级会话重连）继续作用私号——**建议默认接受**（它不是编排，且防止私号网络抖动即死）；
   机器人自发的 auto_roam（空闲 90s）会游荡私号——**建议默认保留**（"游荡不做"= 中控不派；若要彻底静止，后续可给私号下发一次
   `random_walk` stop 或加"私号免游荡"机器人侧闸，属扩展项）。
4. **意图/台账**：私号不写意图、不写任何派发台账、不入 daily overview 队列（手动跑的心跳明细可见）。
5. **自动下机豁免**：私号即使 chain_done/满额/坏号，也**不自动 remove**（§2.12）；用户手动下机/删号不受限。
6. **组队/团队**：私号不参与建队、不可作为队长/队员（§2.9）；如未来需要"私号组队"，单独立项。
7. **删号**：从池删除时同步清 personal 标记；`personal_pool.json` 不随导入工具重写。
