# 分析-20260930-注册协议与风控（含"中控专用注册通道"服务端实现）

> 任务：测试当前"账号注册协议"→ 判定失败是否由服务端风控引起；若确认风控，在服务端源码实现"中控专用注册协议"。
> **结论先行（重要，与任务假设不同）**：
> 1. **112 不是"同 IP 风控"**。112 在服务端是 `RA_ERRNO_EXECUTE_ERR`（注册数据库执行失败的**通用出口**）；服务端注册链路（game C++ + DM + 存过程）**没有任何 IP/频率/设备风控代码**。"风控"说法只存在于中控注释文案里，本次被实测证伪。
> 2. 当前生产（47.96.8.240 的 2400/2300 两区）：**任何账号注册（新号/已存在号）都快速（~140ms）返回 112**；失败点收敛在 `xy3_game.apply_account` 存过程执行环节，其余全链路（登录 102 / 查询 105 / 验证码 106 / 游戏写库）全部正常。
> 3. 阶段 2 仍交付了服务端**"中控专用注册通道"**实现（复用 104 + "姓名位密钥" + DM 参数化直插 `7y_members`，绕过 apply_account；密钥走配置、与玩家注册隔离）——它既**兜住当前故障**，也能在未来"真加风控"时按密钥放行。**未部署**，部署/回滚清单见 §5。
> 4. 报告落库：`zyCtrlcenter/docs/04-测试/分析-20260930-注册协议与风控.md`；测试工具：`zyCtrlcenter/tools/_tmp_scan/reg_probe_20260930.py`；**apply_account 修复/重建脚本：`2d-xiyou-server/sql/fix_apply_account_20260930.sql`**（§4.2）。

**e) 存过程 `apply_account`（`sql/init_db/init_xy3_game.sql:895-1046`）**

## 3. 风控判定与证据

**判定：当前 112 不是"服务端风控拦截"。**

1. **源码级**：注册全链路（§1.2 a-f）**不存在**任何 IP/频率/设备维度的风控；112 只是"注册数据库执行失败"的通用错误折叠（`client_account_result.cpp:785/:817`）。"同 IP 过频触发风控"是**中控侧的推断注释**（`handlers_create.go:24`、`gameproto/register.go:26`），服务端无对应实现。
2. **行为级（决定性）**：连"**已存在账号**"的注册（本应走存过程最前面的 `select` 命中 → ret=2 → **111**）也返回 **112**。任何"防批量注册风控"都不可能让"已存在检查"失效。→ **请求根本没有被正常执行**，与"频率"无关。
3. **同 IP 对照**：同一出口 IP 下，102 登录、105 查询、106 验证码、机器人游戏写库全部正常——"同 IP 被风控"无法解释这种"只坏注册写路径"的选择性。
4. **时间维度**：15:09→15:21 连续 6 次尝试（跨 12 分钟、3 个账号、2 个区）全部 112，无任何恢复趋势；且问题至少可回溯到 9-05（dm_go 注释）/9-21（中控事件），不是"瞬时风控窗口"。
5. 现有 `CreateThrottle`（中控自适应限速）**无法解决**该问题——它不是风控引起的，降速到极限也是 112。

**为什么用户会"感知失败"**：任何一次面板/接口建号都会全量 112（15:09:50 的现场：请求 5 个号，全 failed）。

### 3.5 影响面：**玩家注册同样失败（P0，全服级）**

**判断：该服"注册新账号"功能对所有调用方都不可用，不只机器人。**
1. **唯一链路、无分叉**：注册只经 `client_packet_dispatcher.cpp:62`（104）→ `client_c2s.cpp:378` → `client_account_request.cpp:208 RegisterAccount`，**代码里没有"机器人/玩家"任何区分**（无 flag、无来源分支；唯一分流 `http_way` 是服务端配置级、对所有 104 一视同仁）。
2. **公共末端**：落库只有 `call apply_account(...)`（:452）一条；本次实测已证明"调用它→失败"（新号 112、**已存在账号也 112**）。
3. **"只拦机器人"假设被反例排除**：若有人为针对机器人做拦截，至少"已存在账号"应正常走完 111 分支——实测没有。
4. **玩家视角复现路径**（客户端注册流程逐段对照实测量）：填名 → 客户端查重 105 **正常**（实测 111/0）→ 提交 104 → **112 失败**。
**证据边界**：机器人/玩家共用链路是源码事实；"玩家此刻点击也会失败"是由此推出的强结论——如需玩家侧直接证据，可在确诊时在 dm 日志里找**非 robot 名**的注册 ret 记录（命令已并入 §4）。

## 4. 根因收敛与确诊所需（服务端只读检查）

**收敛点**：`call apply_account(...)` 这一条 SQL 的执行环节。已排除：网络、握手、验证码、game 侧字段校验、DM 任务链（105/登录均正常）、账号库整体可写（机器人在写游戏库；账号库读正常）。

### 4.1 剩余可能（按概率）
1. **生产 `xy3_game.apply_account` 存过程缺失/签名不符**（历史上有多起"RDS collation 事故（`9fe6140b`）/整合数据库（`fd0b3949`）"提交，重建/迁移库时可能漏建或未同步该存过程）→ `call` 直接失败 → DB 错误码 → default → **112**。
2. 存过程存在但**执行即失败**（权限/SQL mode/collation 混用/表结构漂移如 `invite_code`、`is_used` 新列）→ 返回 3 → **112**。
3. dm 侧其它特定错误（可能性低）。

> 三种从客户端无法彻底区分（错误码被折叠为 112）。**确诊只需在服务器上跑 4 条只读命令**（无需重启任何进程）：
> ```bash
> # 1) 存过程是否存在/何时建的
> mysql -uroot -p'<密码>' xy3_game -e "SHOW PROCEDURE STATUS WHERE Name='apply_account'\G"
> # 2) 直接调用一次（观察返回列 = var_ret；用测试名，验证后 delete）

> # 4) dm 日志里的真实 ret（1/2/3/4/5/6 或负数）
> grep "register account" <部署目录>/log/dm_serv*/**/dm_serv.log | tail -20
> ```
> **若 1) 缺失/2) 报错** → 修复=**重建存过程**（从 `sql/init_db/init_xy3_game.sql` 导入 apply_account），一条 SQL 级修复即可，不必走专用通道；
> **若 2) 正常返回 1** → 说明脚本可写、问题在 game→dm 的该任务细节，届时再按 §5 通道兜底。

## 5. 阶段 2：服务端"中控专用注册通道"实现（方案 b）

### 5.1 设计对比与选择

| 方案 | 内容 | 评估 |
| --- | --- | --- |
| a) 白名单放行 | 按来源 IP/签名对中控注册放宽"风控" | **不选**：当前源码根本没有风控可放宽；按 IP 白名单在公网生产脆弱（出口 IP 变动），且解释不了当前故障 |
| **b) 专用入口 + 共享密钥 + 隔离** | 复用 104、"姓名"位携带配置密钥 → 服务端改走**直插落库（绕过 apply_account）** | **选中**：既绕过当前坏点，又天然"专用/隔离"；中控侧**零代码改动**即可用（既有 `agent_key` 参数）；不新增协议号、不动客户端 |
| c) 配置阈值 | 风控阈值可配 | **不选**：无风控实现，无对象 |

**为什么做成了"复用 104 的密钥位"而不是"新协议号 108"**：①中控无需升级即可使用（把 `agent_key` 填成密钥即可），避免"服务端/中控必须同批升级"的部署耦合；②玩家客户端只发既有协议，密钥即隔离边界；③新增协议号需要动 `client_protocol.h/分发/新返回结构`，风险收益不成比例。如后续确需独立协议号，落点已具备（`RegisterAccount` 前挂新 handler + 复用 700 语义）。

**关键安全设计**：
- SQL 全程**参数化**（账号/密码从 `register_account` 结构体字段取，不经字符串拼接），无注入面；
- 玩家注册（姓名位≠密钥，或未配置密钥）**与既有行为完全一致**；
- 密钥只打日志前 4 位；未配置=功能关闭。

**行为差异（明文列出）**：
1. 专用通道**不做激活码分支**（老存过程 ret 4/5/6 语义）——中控建号本就不带激活码；
2. "姓名位"用作密钥后**不落库到 cnname**（老路径会落），直插写空串；
3. 依赖生产 DM 为 **dm_go**（若仍是 C++ dm_serv，`/*CTRLREG*/` 会语法错误 → 112，**功能不可用但无副作用**）；
4. 新旧版本可**独立部署**：旧 dm + 新 game → 112（同现状）；新 dm + 旧 game → 无行为变化。
