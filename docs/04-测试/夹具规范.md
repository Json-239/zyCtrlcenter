# 夹具规范（test/fixtures）

> 规则来源：[测试规范](测试规范.md) §3.4「必须有实际数据支撑」。
> 本文件说明夹具的**结构、来源标注与获取方式**；夹具目录索引见 `test/fixtures/README.md`。

```

│   └── status_reply.json         构造（real=false，trimmed=true）
├── chains/
│   ├── newbie_full.mini.json    真实导出裁剪（**基座链**：npcs 含钟馗、map_grids 含刷鬼图、dijkstra）

│   └── zhuaogui_nav.sample.json  真实导出裁剪（含未知字段与扁平 npcs 形状）
└── fixtures_test.go              元测试：强制校验 provenance
```

## 2. 报文夹具格式（`fixtures/events/*.json`）

```json
{
  "provenance": {
    "real": true,               // 必填 bool：是否真实抓包
    "trimmed": false,           // 必填 bool：是否裁剪过内容
    "raw": "{\"type\":\"...\"}",// real=true 时必填：原始行（未改动）
    "how": "2026-09-19 从参考项目 data/runs_YYYYMMDD.jsonl 尾部抽取（原样）",
    "source": "<源文件路径或文档>"
  },
  "event": { "type": "task_progress", "done": 1, "account": "robotA" }
}
```

**校验规则**（`fixtures_test.go` 强制，违反即全量失败）：

| 规则 | 说明 |
|---|---|
| `provenance` 必填 | 来源必须可查 |
| `real` / `trimmed` 必须是 bool | 显式声明，不允许省略 |
| `how` 非空 | 说明来源或构造依据 |
| `real=true` ⇒ `raw` 非空且 `event` 与 `raw` **逐字段一致** | 真实数据不得改字段 |
| `real=false` ⇒ `how` 含「构造」或「示例」 | 构造数据必须显式标注 |
| `event.type` 必填 | 未知类型的夹具无意义 |

## 3. 链数据夹具格式（`fixtures/chains/*.json`）

```json
{
  "provenance": { "real": true, "trimmed": true, "how": "...裁剪范围说明...", "source": "..." },
  "chain": { "chain_id": "zhuaogui", "npcs": { "44": [9, 481, 604] }, "ghost_map_pos": {...} }
}
```

校验由 `test/chainlib` 的夹具加载器完成：必须 `real=true` 且 `how` 非空（裁剪需说明范围）。
用途：验证**未知字段与字段形状原样透传**（用真实导出的裁剪样本，而不是凭空构造）。

## 4. 真实夹具怎么获取（可复现）

参考项目（Python 版 ctrlcenter）的运行历史落盘在 `data/runs_YYYYMMDD.jsonl`：

```powershell
# 按事件类型抽取一条真实报文
$src = "F:/ZyBin/xm/2d-xiyou-server/robot/ctrlcenter/data/runs_20260919.jsonl"
Get-Content $src -Tail 20000 -Encoding UTF8 |
    Where-Object { $_ -match '"type":\s*"error"' } | Select-Object -First 1
```

链数据（如新手链/抓鬼导航）：

```powershell
cd F:\ZyBin\xm\2d-xiyou-server\robot\ctrlcenter
& "<python.exe>" -c "import json,sys; sys.path.insert(0,'.'); import chainlib; json.dump(chainlib.build_chain('newbie_full'), open('<本项目>/data/chains/newbie_full.json','w',encoding='utf-8'), ensure_ascii=False)"
```

## 5. 什么时候可以构造（`real=false`）

| 场景 | 处理 |
|---|---|
| 该事件不落运行历史（如 `status_reply` 每 3 秒一条，只更新内存） | 用协议文档示例构造，`how` 写明「取自 docs/03-协议/…示例」 |
| 需要边界值（超大字段、类型不符） | 构造，`how` 写明「按协议表构造 + 故意类型不符」 |
| 链数据过大（2MB 级） | 从真实导出裁剪，`real=true, trimmed=true` 并写清裁剪范围 |

## 6. 新增夹具 checklist

- [ ] 放进 `fixtures/events/`（或 `fixtures/chains/`），文件名用事件类型（如 `error_task_stuck.json`）
- [ ] 带完整 `provenance`（`real`/`trimmed`/`how`，真实数据另带 `raw`）
- [ ] 跑 `go test ./test/fixtures/ ./test/chainlib/ -count=1` 通过
- [ ] 需要时在 `fixtures_test.go::TestRequiredFixtureTypesExist` 的 `want` 列表登记
