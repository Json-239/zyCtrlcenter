# 分析-20260923-战斗模式与技能体系（为"主动技能攻击"方案做底）

> 用户口径：「当前战斗都需要等待 60 秒自动发动工具（攻击）……需要做一个配置映射，
> 人/仙/魔的男女角色有对应的战斗体系，且可以自动选择技能主动攻击，而不是等待超时自动拉起攻击。」
>
> 本报告：① 核实"等 60 秒"是否真实；② 给出攻击指令/技能体系的代码级现状；
> ③ 用户方案的可行性与落地设计。**未改任何代码。**

---

## 一、结论速览

1. **"每场战斗等 60 秒"不成立**：今日 9636 场实测 —— 中位数 **25 秒/场**、91% 落在 10~30 秒、
   ≥60 秒仅 **0.3%**（27 场，最长 185 秒）。战斗节奏稳定，**没有普遍性超时等待**。
   （服务端回合超时 `FIGHT_BOUT_TICK = 30` 秒，只在客户端不发指令时兜底；实测说明机器人指令有效。）
2. **机器人当前每回合"主动发普攻"**（并非被动等超时）：`[bo_role, 1, target, 0, 0]` —— 第 2 参数 `1`
   是"攻击"（服务端解析：`msg_data[1] + FIGHTER_CMD_BEGIN(3592) = 3593 = FIGHTER_CMD_ATTACK`）。
3. **从不发技能**：第 4 参数（技能索引）永远为 0。服务端**支持**技能指令：
   `[1, 4, target_index, skill_index, skill_proficiency]`（`4 = 3596(SKILL) - 3592`）。
4. **技能数据已在服务端配置齐全**（`race.csv` / `school.xml` / `skill/*.xml`），协议也有推送
   （`S2C_ROLE_SHARE_SKILL` 等）——但**机器人端接收接线被注释**（protocol3.py:502），
   现状拿不到角色技能列表（`m_skill` 只存 id，且消息未注册）。
5. **用户方案可行**，建议"**分场景**"落地：抓鬼/野外战斗用技能；**新手链剧情战斗保持普攻**
   （8-26 教训：技能指令曾被服务端结算成无效技能导致回合卡死打不赢）。

## 二、当前战斗模式（代码 + 实测）

### 2.1 回合时序（服务端机制，`script/fight/operator_state.py`）

```
回合开始：服务端 state_start_round → 设 30s 触发时间 + 广播 S2C_FIGHTSTATE_BOUTSTART[wait_tick, bout]
  ↓
机器人（fight_tester.py）每回合做两件事：
  ① 回合确认（ack）：C2S_PREPARE_DRAWDONE / C2S_FDRAWDONE / C2S_FIGHT_CHANGE_PHASE_DONE + ANIM_TIME=0
     —— 2026-08-21 修复：不 ack 时每回合空等 30 秒（服务端等客户端"绘制完成"）
  ② 攻击指令：C2S_FIGHTCMD(pos, 1, target_index, 0, 0)，对 pos=0..5 各发一次（见 2.3）
  ↓
服务端结算 → 下一回合（或结束）
超时：客户端 30 秒不发指令 → 服务端自动推进（兜底，非正常路径）
```

### 2.2 实测数据（今日，`data/bot_logs/*/runs_20260923.log`）

| 指标 | 数值 |
|---|---|
| 样本 | 9636 场（野外遇敌 + 抓鬼战斗，配对"开始/结束"日志） |
| 中位数 / P90 | **25 秒 / 26 秒** |
| 分布 | <10s 4.6% / 10-30s **91.2%** / 30-60s 4.0% / **≥60s 0.3%** |
| 最长 | 185 秒 |

→ **"等 60 秒"应是个别场景**（0.3% 长战斗），需用户确认具体观察（见第六节）。

### 2.3 攻击指令的真相（服务端解析实证，`fight_dispatcher.py:28-54`）

```python
bo_role     = msg_data[0]        # 1=角色出手 / 0=召唤兽出手
fighter     = 角色/召唤兽（由 role_object 决定, 不是 pos！）
msg_data[1] += FIGHTER_CMD_BEGIN # 动作类型（相对值）
fight_state.receive_command(...) # msg_data[1..4] = cmd, target, skill_index, proficiency
```

- 机器人 `[pos, 1, target, 0, 0]` 里 **pos=0..5 的"多位置尝试"是历史误解**：
  `msg_data[0]` 实际是 `bo_role`（0=召唤兽/非0=角色），服务端用 `role_object` 定位出手者 ——
  即**同一条"角色攻击"指令被重复发了 6 次**（1 次有效 + 5 次冗余）。
- 动作类型数值：攻击 3593 / 防御 3594 / 捕捉 3595 / **技能 3596** / 道具 3597 / 召唤 3598 /
  召还 3599 / **逃跑 3600** / 保护 3601 ……（`keys/fight_.py`）

## 三、技能体系（"人/仙/魔 男女 → 战斗体系"的数据源）

| 层 | 配置/协议 | 说明 |
|---|---|---|
| 种族 | `config/race.csv` | 0 人族（控制/封印/昏睡/中毒）· 1 魔族（物理）· 2 仙族（法术多体）· 3 鬼族 |
| 种族技能 | `config/skill/human_skill.xml` / `demon_skill.xml` / `immortal_skill.xml` | 按种族分文件 |
| 门派 | `config/school.xml` | 女儿国(毒系)/方寸山(昏睡系)/折冲府(封印系)/法门寺(混乱系)/东海龙宫(水系)…… 每门派 5 技能 |
| 技能定义 | `config/skill/*.xml` | 每条含 `skill_index/skill_name/skill_type(人物战斗技能)/skill_school/limit_level/base_cost_mp/base_target_num/base_status_hit` 等 |
| 角色已学技能 | 服务端 `S2C_ROLE_SHARE_SKILL`（dump: skill_index + proficiency + …） | **机器人端注册被注释**（`protocol3.py:502`），现状收不到 |
| 技能指令 | `C2S_FIGHTCMD [1, 4, target, skill_index, proficiency]` | 服务端 `SkillCommand(target, skill_index, proficiency, hurt)` |

> 注：门派与"性别"的绑定在服务端创建角色流程中（`school.xml` 无性别字段）；
> 落地时**不需要自己维护"种族×性别→门派"映射** —— 直接用**该号已学技能列表**（服务端权威），
> 按 `school.xml`/技能 xml 的 `skill_type` 过滤"可主动攻击的战斗技能"即可。

## 四、技能选择映射表（按用户口径细化）

### 4.1 技能分类判据（配置字段实证）

| 种族 | 技能区间 | 代表 | `magic_type_name` | `status_index` | `base_hurt_num` | 性质 |
|---|---|---|---|---|---|---|
| **仙族** | 61-95 | 91 沧海龙卷 | 水系/火系/雷系 | **0** | 40 | **纯伤害**（"直接使用"） |
| **人族** | 11-45 | 11 迷魂香 / 21 作茧自缚 / 41 毒蝎心 | 昏睡/封印/毒系 | 11/21/41 | 0~0.1 | **状态控制**（"随机使用"） |
| **魔族** | 101-135 | 101 魔王威力 / 131 护心甲 / 111 幽灵噬骨 | 攻系/防系/震慑 | 101/131/0 | 0~0.15 | **附攻/附防/吸血**（"随机使用"） |

> 用户口径与配置完全吻合：仙族技能 `status=0` 是纯法术伤害 → 直接用；
> 人/魔技能带 `status_index`（附加状态/增益）→ 随机用。
> 每门派 5 技能按 `limit_level` 解锁（0/1/30/50/60）→ **60 级前只有前两个**（用户说的"两个特殊技能"）。

### 4.2 映射表设计（建议）

```
robot.m_skills: {skill_index: proficiency}            ← 来自 S2C_ROLE_SHARE_SKILL(90299, 登录全量)
种族判定: 区间（11-45=人 / 61-95=仙 / 101-135=魔；或 school.xml 反查）
可用技能 = m_skills 中 limit_level <= 角色等级（配置表静态信息）
选技能:
  仙族 → 优先"纯伤害"（status_index==0 且 hurt>0），按目标数/伤害取最优，直接使用
  人族/魔族 → 可用技能里随机（用户口径）
  全部不可用（技能受限/法力不足/剧情战斗）→ 回退普通攻击（现状逻辑）
发指令: C2S_FIGHTCMD = [1, 4, target_index, skill_index, proficiency]
```

### 4.3 数据源缺口（当前卡点）

| 数据 | 服务端 | 机器人现状 |
|---|---|---|
| 已学技能（index+熟练度） | `S2C_ROLE_SHARE_SKILL(90299)` 登录时全量 + `S2C_UPDATE_SHARE_SKILL(90334)` 增量 | **完全未处理**（protocol3/msghandle 里连注释都没有）→ 需新接线 |
| 技能定义（类型/等级/伤害） | `config/skill/{human,demon,immortal}_skill.xml` | 机器人可打包一份静态映射（或从服务端配置导出） |
| 旧注册残留 | — | `S2C_ROLE_SKILL` 的注册被注释（protocol3.py:502），那是另一条消息，与 90299 不同 |

## 五、用户方案落地设计（建议）

**目标**：战斗中主动用"攻击技能"（而不是普攻/等超时），按角色体系自动选技能。

| 步 | 改动 | 说明 |
|---|---|---|
| 1 | 接通技能数据 | 注册 `90299`（登录全量）+ `90334`（增量）→ 解析 `{skill_index: proficiency}` 存 `m_skills` |
| 2 | 打包技能静态表 | 从服务端配置导出"技能 → 种族/门派/等级/是否伤害技"（一次性脚本 + JSON） |
| 3 | 选技能策略 | 映射表：仙=纯伤害最优；人/魔=随机；等级/法力过滤 |
| 4 | 战斗发货 | `fight_tester.__send_bout_commands`：有可用技能且法力够 → 发 `[1, 4, target, skill_index, prof]`；否则回退普攻 |
| 5 | **分场景闸** | 抓鬼/野外用技能；**新手链剧情战斗保持普攻**（8-26 教训），异常自动回退 |
| 6 | 观测 | 用已上线的"战斗统计"对比技能前后的时长/成功率 |

**风险**：
- 技能指令被判无效（法力不足/目标不符）→ 回合可能空过；需"下回合未推进 → 回退普攻"
- 剧情战斗禁技能/技能导致打不赢（8-26 实证）→ 分场景闸 + 快速回退
- 冗余的 `pos 0-5` 全发可顺手收敛为单发（减少 5/6 的无效包）


## 六、待验证 / 待澄清

1. **用户说的"等 60 秒"具体场景**：是某几个号？某个玩法（新手链？组队？）？面板上看到的？—— 需用户提供线索以便复现
2. 服务端"超时自动推进"的具体行为（AI 代打还是默认攻击）：未细读定时器到期逻辑
3. 机器人 `m_skill` 现状是否有残留数据（消息未注册 → 大概率为空）
4. 技能熟练度字段在指令里的作用（prof=0 是否可接受）：需实测
