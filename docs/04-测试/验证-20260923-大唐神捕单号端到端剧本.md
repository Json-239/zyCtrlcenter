## 0. 一分钟速览

**一轮的定义**：点张忍慎接取 → 打怪（服务端随机的 A 或 B 分支）→ **主任务完成（日计数 +1）** → 交付收尾任务 `2028399 回复张忍慎` → 票恢复可接。

**P0 硬指标（详见 §4）**：
1. 自然接取成功且**不误点"还是算了吧"**；
2. A 分支 **≤3 场战斗**内击杀匪首；
3. 主键计数每轮**恰好 +1**（收尾环节不二次计数）；
4. 第 **10/10** 轮的收尾 `2028399` **必须照跑**（次数满 ≠ 立刻收工）；
5. 正常完成**无冷却**可连跑；掉任务后 **600s 冷却**内机器人**等待而非报失败**。

## 2. 逐步执行剧本

> 每步给：**动作** / **期望信号**（服务端消息、任务号流转、状态迁移、日志） / **取证点**。
> A/B 分叉处给出各自的期望；未见分叉的步骤两条分支一致。

### S0 下发（机器人收到启动命令）
- **动作**：中控下发（或机器人端直连命令）。若走中控：`POST /api/autotask/start`（或新命令，以实施为准）。
- **期望信号**：
  - 中控：`/api/autotask` 该池 `running/inflight` +1；`/api/status` 该号 `state` 离开 IDLE/READY；
  - 机器人：日志出现"启动/接取"意图行；**不复用**抓鬼/新手链残留状态（若该号在跑抓鬼，应先停抓鬼）。
- **取证**：命令原文与时间戳、下发回执、下发前后 `/api/status` 快照。

### S1 接取（关键：票不可见 → 必须直点 NPC）
- **动作**：寻路至 **张忍慎（`13297`，图 `12 长安城中`，`2265,1846`）** → 点击 → 弹出接取对话 → 选**含"大唐神捕"**的选项
  （`好的（接受大唐神捕任务）`；**绝不能点第一项惯性**——第二项是"还是算了吧"）→ 服务端组内加权随机下发 A 或 B。
- **期望信号**：
  - `S2C_SHOW_DIALOG(90075)`（`TASK_SHOW_DIALOG`）→ 点击选项 → **`S2C_ADD_TASK(90365)`**，`task_index ∈ {2028301, 2028302}`
    （日志 `TASK_ADD`；心跳 `task_index` 变为该值）；
  - 机器人日志明确记录"接受成功/分支=A|B"；**不得**出现连续点 NPC 无对话的空转。
- **判据**：接取在 **≤ 1 分钟**内完成；未误接其它玩法（任务号必须落在 4 个白名单内）。
- **取证**：`TASK_ADD` 原始行、`/api/status` 的任务号、`/api/tasknames` 翻名结果。

## 3. A/B 双分支覆盖策略

**机制（可执行、有据）**：服务端接取走 `task_group.get_random_task()`，按 `task_weight` 加权；**同一会话内"上次接手的那条"权重降为 1**（`task_mark` 存在 **session** 里，**重登即清**）。
→ **同会话连跑两轮，第二轮几乎必然是另一分支**：3000 : 1 ≈ **99.97%**。

**推荐做法**：
1. **第 1 轮自然接取**（同时验证接取链路）→ 记录分支 X；
2. **同会话立刻第 2 轮** → 期望得到另一分支 Y（99.97%）；
3. 若第 2 轮仍是 X（0.03%）→ 第 3 轮再来（此时 `task_mark=X`，P(Y) 同为 99.97%）；
4. **不要重登来"重掷"**：重登会清 `task_mark`，回到 50/50（不划算）。

**判据（覆盖完成）**：A 与 B **各 ≥1 轮**走完全部步骤（S1→S3）并留下 `TASK_FINISH` 证据；其中 B 分支必须看到
**服务端自动下发 `2028311`**（验证"链式后续环节靠推送、无需接取"）。

**测试服加固（可选，只补执行路径）**：
- 强制 B：`@deltask 2028301`（若身上是 A）→ `@addtask 2028302`；
- 强制 A：`@deltask 2028302` → `@addtask 2028301`；
- ⚠ `@addtask` **绕过票/组随机/条件**，因此**不能替代**"自然接取"那 1 轮；GM 干预必须记入证据。

## 5. 失败面测试

### 5.1 掉任务 + 自动重接（**必做**）
- **造法（优选，等价刺激）**：`@deltask 2028301`（或 `2028302`）——服务端走 `drop_task_object` 路径，
  与"战斗失败/逃跑被 step99 掉任务"**同一条服务端路径**（rear + clean）。
- **期望信号**：
  1. `S2C_DROP_TASK(90413)`（`TASK_DROP`）→ 机器人识别并**不惊慌**（不重登、不误判为脚本异常）；
  2. 服务端加 buff **`2028302 忙碌的张忍慎`（600s）** → 期间接取被**静默拒绝**（不发任务、不回拒绝通知、票撤回）；
  3. 机器人 **600s 内进入"冷却等待"**（日志有等待/冷却字样、周期重试），**不得报"接取失败"并停止**；最多等到 900s 上限；
  4. 冷却结束后（或 GM `@delbuff 2028302` 立即解除后）**自动重接成功**（还有日限时）。
- **可选（真实败战）**：控血制造 A 分支战败——成本高、且与 5.1 同一服务端路径，**不建议列为 P0 必做**。

### 5.2 明雷"点击无响应"（隐藏 NPC）兜底
- **造法**：A 分支第 1 场胜后，该匪徒**立即隐藏（60s 后重生）** → 让机器人按旧坐标再点同一只（或人工在同一点连点）。
- **期望信号**：服务端**静默无响应** → 机器人**换下一只可点匪徒**（`18140/18141/18142` 轮换）或等待重生；
  60s 内继续推进（或被"换点"策略消化）；**不得原地死等、不得报 STUCK**。

### 5.3 连点节流（不炸）
- **动作**：在 60s 窗口内对同一 NPC/同一接取 NPC 连续点击。
- **期望信号**：机器人侧有**点击间隔/退避**（不刷包、不刷屏）；无重登、`stuck_count` 不涨、无服务端对话卡死。

### 5.4（可选）包满交付
- **动作**：把包裹填满后再交付 `2028399`。
- **期望信号**：服务端发"包裹满"类通知（`360/415/418/528/1295` 之一）→ 机器人**明确报"包裹已满"并停**，
