# 分析-20260922：捉鬼前「薛仁贵领双」可行性 + 实施方案

## 一、结论（先说结果）

**可行，成本很低**：服务端领双链路完整（NPC 对话 → 领取动作 → 双倍 buff），机器人端**唯一缺的**是
"走到薛仁贵 + 点两下对话选项"这段**业务规则**（点击 NPC 与对话处理能力都已有）。

## 四、实施方案（P0，最小可用）

**放置位置**：抓鬼启动前（`daily_ghost` 的 `ghost_start` 处理链）或"每日首次空闲"——建议做成
**一次性前置步骤**（每天最多一次，失败不阻塞抓鬼）。

1. **机器人端新增 `claim_double_exp(robot_object)`**（建议放 `quest_engine.py` 或新模块 `pre_daily.py`）：
   - 判据：今天没领过（`g.claimed_double_day != 今日`）→ 走流程；
   - 导航到图 12（3931,882）→ 点薛仁贵 → 等对话；
   - 对话里**按文本匹配**依次点：「直接领取（双倍）」→「领取一小时双倍」（文本命中失败则记 warn 并放弃）；
   - 成功判据：收到对话/notice 变化或"剩余小时数"文本变化；写 `g.claimed_double_day = 今日`；
   - 失败处理：**不阻塞抓鬼**（最多重试 1 次，然后放弃并记日志）。
2. **中控**：无需新接口（可作为 `ghost_start` 的前置自动行为）；如需人工触发，可加
   `POST /api/double_exp/claim {accounts}`（复用 `quest_engine.dispatch_cmd` 发一条自定义命令）。
3. **前端**（可选 P1）：大屏行内展示"今日已领双"标记（机器人上报一个布尔字段即可）。

## 五、测试方案（先在测试服单号验证）

1. 挑 1 个号（建议 `robot0001000`）→ 下发"领双"命令；
2. 观测（机器人 diag / 中控 runs）：
   - 是否出现"前往薛仁贵 / 点击 NPC 13035 / 对话打开（选项含『直接领取（双倍）』）"；
   - 是否点中「直接领取（双倍）」→ 二级对话出现「领取一小时双倍」；
   - 点击后是否出现**领取成功**（对话文案变化 / 剩余小时数减少 / buff 提示）；
3. 交叉验证：让该号打一场怪，比较经验数值（或看对话重进的"剩余小时"是否 -1）——**验收判据**；
4. 失败分支：双倍额度为 0 时，对话应给"额度不足"提示 → 代码需识别并停止（不刷屏）。

## 六、风险与未知

- **每周额度**：我们号是否有剩余？未知（要进对话看"剩余 N 小时"）——测试第一步就能看到；
- **重复领取/续领**：若同一小时重复点「领取一小时双倍」，会连续扣额度（多领多占）→ P0 只领**1 小时**并当日只做一次；
- **图 12 是否有 PK/风险区**：长安城中为城市场景，风险低；若号在图 12 有传送限制需实测；
- **交互时长**：一次领双约 20~40 秒（跨图 + 对话），对抓鬼节奏影响可忽略（每天一次）。
