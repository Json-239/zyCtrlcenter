# 测试基座（test/testsupport）

> 基座是**唯一允许被各模块共同依赖**的测试代码。新用例先看这里有没有现成能力，禁止重复造轮子。
> 规范见 [测试规范](测试规范.md)；源码 `test/testsupport/testsupport.go`。

## 1. 能力总览

| 分类 | API | 说明 |
|---|---|---|
| 夹具 | `LoadFixture(t, name)` | 读 `fixtures/events/<name>` → `{Path, Provenance, Event}`；缺 `event` 直接失败 |
| 夹具 | `FixtureFiles(t)` | 枚举全部报文夹具（元测试用） |
| 夹具 | `TestRoot(t)` | 返回 `test/` 绝对路径（自建夹具目录时用） |
| 数据 | `CloneEvent(t, ev)` | 深拷贝事件（同一夹具多次使用防串改） |
| 环境 | `NewTestStore(t)` | 返回 `(*store.Store, dataDir)`，落 `t.TempDir()` |
| 环境 | `NewTestLogger(t)` | 临时目录日志器，用例结束自动 `Close`（Windows 句柄） |
| 环境 | `NewTestHandler(t, cfg)` | 组装 `*event.Handler` + `state` + `store` + 未启动的 `ctrl.Server`；`cfg` 可传 nil |
| 机器人 | `ConnectFakeRobot(t, s)` | **真实 TCP** 连到控制通道（`Port=0`），等待服务端接管 |
| 机器人 | `(*FakeRobot) SendEvent / SendRaw / ReadCmd / Close` | 发事件 / 发原始字节（异常报文）/ 读下行命令 / 关连接 |
| 等待 | `Eventually(t, timeout, cond, msg)` | 轮询等待条件成立，超时失败 |
| 等待 | `WaitEvent(t, s, timeout)` | 从控制通道事件队列取一条（超时失败） |
| 断言 | `StoreHasType(st, type)` | 运行历史里是否存在该 type 的事件 |

## 2. 典型用法

### 2.1 事件处理（不需要真实 TCP）

```go
func TestTaskProgress(t *testing.T) {
    h, st, runStore, _ := testsupport.NewTestHandler(t, nil)
    fx := testsupport.LoadFixture(t, "task_progress.json")

    h.HandleEvent(fx.Event)

    r, ok := st.Get("robot0001035@xy3.com")           // 状态迁移
    if !ok || r.Done != 1 { t.Fatalf("状态不符: %+v", r) }
    if !testsupport.StoreHasType(runStore, "task_progress") { // 落盘证据
        t.Fatal("必须写运行历史")
    }
}
```

### 2.2 端到端（接口 → 机器人实际收到命令）

```go
rb := testsupport.ConnectFakeRobot(t, cs)   // cs 是真实启动的 ctrl.Server
defer rb.Close()
postJSON(t, srv.URL+"/api/start", map[string]any{"accounts": []string{"robotA"}}, nil)
cmd := rb.ReadCmd(t, 2*time.Second)          // 机器人端实际收到的报文
if cmd["cmd"] != "start_chain" { t.Fatalf("命令不符: %v", cmd) }
```

### 2.3 等待异步动作落盘

事件处理里有少量异步动作（下机通知）。用例结束前要等它的历史落盘，
避免后台写入与 `t.TempDir()` 清理打架：

```go
testsupport.Eventually(t, 2*time.Second,
    func() bool { return testsupport.StoreHasType(runStore, "api") }, "下机历史应落盘")
```

## 3. 基座与铁律的对应

| 铁律 | 基座如何保证 |
|---|---|
| 先隔离后使用 | 所有 `New*` 都用 `t.TempDir()`；Logger 自动 Close |
| 副作用可控 | 不提供进程启动能力；`ctrl.Server` 由用例用 `Port=0` 启动 |
| 结果证据 | `StoreHasType`（落盘）、`state.Get`（状态）、`ReadCmd`（机器人实收） |
| 真实数据支撑 | `LoadFixture` 返回 provenance，元测试强制校验 |
| 状态不泄漏 | 每次 `NewTestHandler` 新建独立 state/store/ctrl |
