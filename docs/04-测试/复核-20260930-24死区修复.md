## 7. 发现清单（P2/P3，均不阻断）

- **P2-1（部署操作注意）**：热更必须 **两文件同批**（同一 `reload_scripts` 请求带 `["quest_engine","daily_ghost"]`）。`daily_ghost` 的调用是运行时属性查找（非 import 时绑定）：若只热更 `daily_ghost` 而 `quest_engine` 未更，跳级悬挂号首次走到 L3553 会 `AttributeError` → 被 `daily_ghost.tick` 外层 try 捕获（`GHOST_TICK_MAIN RAISED`）→ 不崩、一 tick 后恢复（届时 quest_engine 也已更），但中间窗口会刷日志。同批热更即无此窗口。
- **P2-2（验收盲点）**：winnow **正常命中无专属日志**（仅"剥离后不连贯"才 warn）。线上验收以行为差异为准（§8 四条口径）；如需直读命中证据，建议后续（非本次）补一条 info 级"跳级剥离 N 跳"日志。
- **P3-1（理论边界，检出已记录）**：`__winnow_route_by_map` 两处未保护路径（见 §4.5）：① 命中且剩余首元素非 dict 时，告警 msg 内二次 `route[0].get(...)` 抛 AttributeError（前一处 try 只保护了 int 解析）；② route 容器非 list 时 `route.pop` 抛。**真实数据不可达**（route 恒由 `__plan_route/__schedule` 构造为 `list[dict]`；元素 `target_map/_from_map` 均为 int）；即便发生，异常受外层兜底（见 §4.5）不崩进程。建议加固方向：msg 内改 `route[0].get(...) if isinstance(route[0], dict) else route[0]`；pop 循环前 `isinstance(route, list)` 守卫。
- **P3-2（语义差异备忘）**：任务链 winnow 分支不复制原分支的 `m_mapid` 回写/对话残留清理——与 §3.4 互斥性分析一致，两分支无重叠场景，无需补。
