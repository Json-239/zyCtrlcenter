## 0. 结论速览

1. **"队员跟随队长"——源码有、实测未体现，不按它设计（2026-09-29 首队实测修正）**：服务端 C++ 源码里存在"队长移动带队员 / 队员移动被丢"逻辑（`role_object.cpp:516-649`，由 C++ 报文层 `cpy_call_logic.cpp:71-191` 调用，非客户端）；但 16:07 试点队实测：建队/快速归队/整队同秒切图/战斗拉入/克隆共享**都生效**，**唯独位置不趋同**——队员自由移动，20 分钟从未靠近队长。→ 阶段 2 按"**队员待命 + 每轮显式集结（走回/fast）**"设计，**不写跟随逻辑**。详见 §3.2.1。
2. **抓鬼是服务端"克隆共享"任务**：队长接任务 → 队员自动获得克隆任务；队长点鬼触发战斗（**队员不能创建战斗**，`script/fight/operator_scene.py:592-599`）→ 全队参战；队长回钟馗交付 → **全队一起完成**（`script/task/task_action.py:250-293`）。即"1 次击杀 = 全队各 +1 次"，5 人队把服务端战斗量降为单人的 1/5。
3. **组队档真实存在且有文案**：抓鬼任务菜单名即「捉鬼【组队完成，队长有额外加成】」（`config/task/20195.xml:2`）；3-5 人档任务 2019512/2019513（`condition_role_team 3..5`，完成奖励与单人档同楼梯 `reward_task_new_ghost`）。**"队长额外加成"的兑现公式未在奖励配置里直接定位，需实测对比（见 §6 D10）**。
4. **机器人端骨架已就绪但从未跑过**：`team_captain.py`（两份副本 sha1 一致 `bd85f6db…`）、`client.py:574-595` 的 `team_*` 命令分支、`msghandle.py:920-1031` 的 10 个事件 handler、`protocol3.py` 的格式注册全部在位；生产日志（diag/console）**0 条 TEAM 痕迹**。**缺一个模块：`route_walk.py` 全盘不存在**，导致"暂离归队-导航"分支空转。
5. **中控 Go/前端仍为零组队代码**（`internal/**` grep team=0；事件表 13 类无 team_*；`role:"solo"` 硬编码 4 处），所有编排（恢复/水位/游荡/批量）按单号操作，**现在组队必被拆**。
6. **py 参考实现已定位且完整**：`robot/ctrlcenter/routers/team.py`（353 行）、`services/team_follow.py`（108 行）、前端 `robot-ctrl-web/src/views/TeamView.vue`（394 行）；`data/teams.json = {"teams":{}}`（从未使用）。
7. **最高优先级待决**：队伍规模与档位口径（3 人起才有组队档？含不含队长）、队长人选策略、归队成本口径（fast 消耗 vs 免费走）、组队抓鬼实际收益（需小规模实测）、是否恢复队员心跳队伍字段。
8. **组队抓鬼队长要多一步"助战令"（用户 2026-09-29 追加，已调研成文）**：2-5 人战斗的助战者**全部由 buff 1128 门控且只认队长**（单人档免费自带 4 个）→ 队长不备令 = 组队战斗无帮手。购买＝钟馗「领取助战令」→ 商店 3000 扩展储备金/个；**使用＝`C2S_USEITEM [190146]`（旧实现只有"买"没有"用"，本次补"用"）**；免费来源＝每日/登陆鼓励各 ×3。详见 §3.4 与 §5 阶段 2 子项。

### 1.5 "队员跟随队长"语义拆解

- **跟什么**：**没有可依赖的"自动跟随"**。可靠的是两条：① 队长**切图**时活跃队员被 Python 层搬运（试点同秒 11→24 弱证据）；② 显式**归队**（fast 传送 / 走到队长 300px 内发 arrival=1）。同图内位置同步（C++ set_cur_pos）源码有、**实测未体现**（§3.2.1）。**不是**跟"任务/目标"——任务进度由克隆共享完成。
- **跟多久**：只要保持**活跃**就持续跟随；掉成**暂离**（跨图入队、逃跑/死亡强制暂离、主动暂离）即断开。
- **断了怎么办**：① 快速归队（消耗 1 开元通宝或道具，服务端瞬移到队长旁，`team_operator.py:164-200`）；② 普通归队（自己走到队长 300px 内后发送抵达，`team_operator.py:141-162`）；③ 队长召唤（80114 提醒 / 80320 召唤/80367 队长去接，未实现）。

### 1.6 后续链路扩展的预留要求（烽火/神捕/新手链）

- 任务共享有 4 档：0=不共享 / 1=?（各自接取）/ 2=克隆共享（队长驱动）/ 3=队伍共享（`task_operator.py:236-257`）。**扩展任何链路前先查该任务的 `task_share` 值**（在 `config/task/*.xml`）。
- 分享日常（烽火/神捕）是 share_daily 类型，机制与抓鬼不同（次数统计/demand 分型），**是否支持组队共享需单独核实**（`config/task/*.xml` grep `share_daily_key` + `task_share`）。
- 新手链（等级<31）：py 参考口径**不参与组队**（`routers/team.py:27 LEVEL_MIN_TEAM=31`），建议沿用。

### 3.2 关键机制点（逐条给证据）

#### 3.2.1 跟随 / 带队：**源码机制存在，但实测运行版未体现 —— 不可作为设计前提**（2026-09-29 实测修正）

**源码机制（服务端 C++，非客户端）**

- 位置：`server/game/logic/role/role_object.cpp:516-589`（移动）/ `:591-649`（上报）——属**服务端 C++ 逻辑层**（不是 `xiyou3-client`；客户端只有 `S2C_TEAM_FOLLOWER(90067)` 渲染）。
- 调用链：**C++ 报文层**在处理移动报文时直接调用——`server/game/logic/py/cpy_call_logic.cpp:71-147`（C2S_ROLE_MOVE 发路径 → `role_move_in_map`）、`:152-191`（C2S_REPORT_POSITION → `role_report_pos`）。
- 逻辑（若标记生效）：成员（TEAM_MEMBER）**自己的移动被丢弃**（`:527-530 / :593-596`）；队长（TEAM_CAPTION）移动/上报时把成员 `set_cur_pos(队长坐标)` + `map->RoleMoveInMap(...)`（`:573-588 / :633-648`）。
- 标记来源：Python `team_object.py:94-115, 168-193` → `cpy_server.set_team_member/set_team_info`（`cpy_interf.cpp:2044-2078`；队长侧成员表在 `role_object.cpp:467-495`）。**标记挂在角色对象上，切图重建（role_leave_map/role_enter_map）会丢**；`map_operator.py:90-117` 的 `[FIX-2026-08-28]` 只补**队长侧**成员表，**成员侧 TEAM_MEMBER 标记无人补**（其部署状态亦未核实）。
- 该逻辑与"捉鬼任务"无绑定（只要标记在就通用）；也不是"特定队伍模式"。

**实测（2026-09-29 试点队；机器人日志 + 中控高频采样）**

- **① 快速归队 = 生效**：建队瞬间两队员被搬到队长旁——16:07:11 三号同图：队长(232,2744) / 队员1166(307,2736) / 队员5044(592,2721)。
- **② 切图搬运 = 生效（一等证据，定向实测）**：停住两队员 + 队长跨图 → **16:37:51 队员5044 从 图11(149,145) 被搬到 图24(109,64) = 队长同位置**（更早 16:16:57 整队同秒 11→24 同型）。实现走 Python `map_operator.__role_change_map`（对活跃成员生效、不依赖 C++ 标记）。
- **③ 同图逐移动同步 = 不生效**：跨图后队长停在 (109,64)，队员 5044 随后自行 NAV 移动（(42,31)→(10,32)→(74,52)→(132,36)…），位置不再重合；队伍机制其余部分（战斗拉入、克隆共享、交付）正常。
- 归因（三选一或叠加，**不影响设计结论**）：① 部署的 game_serv 二进制与源码版本不一致（远端，本机无法验证）；② 切图重建丢标记（成员侧无人补）；③ 成员自身持续发移动——即使被拉也立刻走开。
- **距离的准确影响（代码层，实施勿加错误前提）**：是否暂离**没有距离判据**（§3.2.3 四触发）；**参战与交付共享也不看距离**（`__get_team_role_list`/`__submit_share_task` 只按"活跃"名单）→ 距离>300px **不会**导致"暂离/不参战"；`≤300px` 只与"**自行归队**动作"门槛有关。

**设计结论（阶段 2 必须按此走）**

- **不依赖"自动跟随"**：队员在队期间**必须待命不动**（不接任务 / 不找鬼 / 不发移动）——既避免"永远不齐"，也避免与（若生效的）拉拽互相打架。
- **集结 = 显式动作**：每轮开抓前检查"队员距队长 ≤300px"；未到位 → ① 队员自己走回来（免费，**route_walk / 导航必要性确认**）或 ② fast 传送（1 开元/道具）→ ③ 再让队长接任务。
- 切图搬运（Python）可期望生效（试点弱证据），但**每轮开始仍要重新集结检查**。
- "别掉暂离"依然重要：暂离 = 不参战 / 不被队长交付覆盖（见 §3.2.3、§3.2.4）。

#### 3.2.2 战斗权限与全队参战

- `__get_team_role_list`（`script/fight/operator_scene.py:592-599`）：`队伍成员不能创建战斗`（返回空）；队长创建时 `+= get_active_member_role_object_list()`（全队入场）。该函数被全部 6 条战斗创建路径复用（`:61/94/113/136/174/613`）。
- 归队/暂离中的队员（parted）不在此列，仍可自建战斗（单人打怪）。
- 抓鬼战斗为定制战斗 `new_ghost_003`（`config/fight/tailor/tailor_ghost.xml:4735`），1/2/3/4/5 人档齐全；怪物等级取队伍平均等级或记录等级（`tailor_module.py:681-686`；`task_ruler.py:114-127` 记录 `mark_team_average_level`）。
- 逃跑/死亡强制暂离：`script/fight/response_action.py:731-752 ForceRoleTeamAwayAction`（队长死亡/逃跑先转让队长再暂离；`team_operator.py:68-81`）。

#### 3.2.4 抓鬼的"克隆共享"细节

- 任务共享模型（`task_operator.py:224-264`）：`task_share>0` 且队长接取时——3=队伍共享（每个队员各自 add，需各自能接）；**2=克隆共享（抓鬼）→ 为每个活跃队员 `share_task_object` 克隆**。

- 交付：队员点交付动作被跳过（`task_action.py:250-252`）；队长交付时 `__submit_share_task:266-293` 对每名活跃队员 `finish_task_object(index, bo_check_can_finish_task=False)`。
- 胜利后任务链：`action_submit` → `action_add_next 2019511`（**`<team_add_task>是</team_add_task>`，2026-08-24 注释明确"组队抓鬼胜利后队员也要收到 2019511"**，`config/task/task_element.xml:6670-6676`）→ 2 秒后**全队自动筋斗云回钟馗**（§1.2 B3c）。
- 完成计数：`finish_task_object` 内 `task_index == episode_root` 时 `increase_finish_task_meter + __update_finish_task_limited`（`task_ruler.py:184-188`）→ **每名队员自己的每日计数 +1**（`episode_count_alias="捉鬼任务次数统计"`, `daily_limit=50`）。
- 奖励（三条线）：
  ① 战斗经验 `role_count_mul`（§1.2 B2，`fight_operator.py:364-370`）；
  ② **完成奖励**统一 `reward_task_new_ghost`（共享元素 `task_element.xml:6665`；组队档 `20195.xml:501,595` 内联同款）；**轮数经验加成** `reward_strategy.py:78`（第 10 环约 +48%，"完成第十环额外奖励"）；

## 4. 方案设计

### 4.1 设计原则

1. **服务端跟随优先**：不实现"跟随调度"，只做"保活跃 + 归队"。
2. **队长驱动一切**：接任务/点鬼/交付/带队只由队长做；队员端只做"不发无效命令 + 参战 + 归队"。
3. **机器人最小改动**：优先复用现有链路（`team_*` 命令分支、BUILD_TEAM 对账、暂离状态机）。
4. **编排按队成组**：中控把"队"当调度单位（水箱/游荡/恢复/批量都最小化改动、加过滤即可）。
5. **灰度**：先 1 队 2 号手动，再 5 号，再多队；每阶段可一键散队回滚。

### 4.2 队长机器人行为状态机（目标）

```
IDLE ──team_setup_captain──▶ CREATE(建队) ──S2C_BUILD_TEAM──▶ INVITE(邀请成员)
   └─ 成员到齐/超时确认 ──▶ READY ──next_action=start_ghost──▶ GHOST(现有 daily_ghost 循环, role=captain)
GHOST 内：
   ├─ 接任务(点钟馗) → 鬼刷新 → 走到目标点 → 点鬼(触发全队战斗) → 战毕 → 回钟馗交付 → 循环
   ├─ 队员暂离通知(S2C_APPEND_PARTED) → 可选：召唤(80320)/提醒(80114) → 等归队
   ├─ 成员离线(S2C_REMOVE_TEAM_MEMBER) → 记事件上报中控（由中控决定补人/继续）
   └─ 自身逃跑/死亡 → 服务端自动移交队长 → 本号需按新状态处理（重新入队或转队员）
```

- 队长**不要**做多余动作：不踢人、不主动暂离（保持位置稳定）。
- 满额/收工：默认**继续带队**直到中控下发整队停止（D5）。

### 4.3 队员机器人跟随逻辑（目标）

| 状态 | 行为 |
|---|---|
| 被邀请 | 自动同意（现有 `on_team_invite`） |
| 活跃（Active） | **零操作**：不发移动、不接任务、不点鬼；收到战斗协议正常出招（`fight_tester` 协议驱动）；心跳上报队伍角色 |
| 暂离（Parted） | 归队状态机（现有）：fast（3s 超时→普通）→ 等 `TOO_FAR` 坐标 → 导航/走 → `team_return_arrive` |
| 队长邀请到达 | 同意（现有） |
| 队长掉线/解散 | 收 `S2C_CANCEL_TEAM` → 清状态 → 上报中控 → 转空闲（等恢复编排） |
| 掉线重连 | 上位机重登后：无队 → 上报中控"待归队"；由中控决定重新加入 |
| 自身逃跑/死亡 | 服务端强制暂离 → 走归队流程 |

**注意（阶段 2 前必须解决）**：队员号若仍运行 `daily_ghost` 自主抓鬼循环（G2），会持续发无效动作。最小改法是在 `daily_ghost.dispatch_cmd`/tick 里按 `g.role=="member"` 进入"待命态"（不接任务、不找鬼、保留频道响应与战斗）。

### 4.4 建队 / 维持 / 退出流程

- **谁发起**：中控（`/api/team/setup` 或自动组队）；机器人不自行建队。
- **自动配对（建议）**：从"真正在线（30s 心跳 + role_id）+ 等级≥31 + 非游荡 + 非摆摊 + 非分享日常 + 不在队"的号里，按 `group_size`（3~5）组队，每组第 1 个当队长；队长优先选**等级最高/最稳定**（D1）。
- **掉线恢复**：队长重登 → 中控按台账重建（先 `team_clear` 清残队，再按原 roster 建队，成员不在线则先用在线成员）；队员重登 → 等队长邀请或申请入队。
- **解散条件**：任务完成/满额收工/人工停止/队长连续失败；解散 = 队长 `team_disband` + 队员 `team_clear` 兜底（参照 py `_disband_team`）。
- **一键回滚**：`POST /api/team/disband {accounts}` 立即散队。

### 4.5 编排互斥（按 §3.3 表落地）

- **单一事实源**：中控内存台账 `Teams{captain → {members, mode, next_action, all_present, since, zone}}` + 事件对账（`team_ready/team_disbanded/team_rejoined`）+ 落盘（`data/teams.json` 风格）。
- **候选过滤**：所有"给别人派活"的入口统一走 `IsTeamBusy(account)`（队长/队员都返回 true；队长走专用派发）。
- **状态来源（D6）**：方案 A 自建台账（零机器人改动）；方案 B 恢复 `m_team` 心跳（更准，需重启机器人生效）。建议先 A 后 B。

### 4.6 心跳 / 台账 / 面板契约

**机器人→中控（心跳增量）**：
```json
"team": {"role": "captain|member|applicant", "captain": "<账号>",
         "members": ["<账号>"], "parted": false, "setup_done": true}
```
**中控 API（对照 py 命名，供前端）**：
- `POST /api/team/setup {captain, members[], mode:invite|apply, next_action?, next_action_hint?}`
- `POST /api/team/auto_setup {group_size:3..5, team_count, next_action:"ghost", daily_limit}`
- `POST /api/team/disband {accounts[]|all:true}` / `POST /api/team/clear`
- `GET /api/team/status → {teams:{}, jobs:{}, robots:{}}`（含 parted 标记）
**前端**：
- 大屏/账号池：新增"组队"列/桶（队长👑/队员🔗/暂离⚠），队员折叠到队长行（对照 `RobotTable.vue` 树形）。
- 新页「组队控制」：自动组队卡（每组人数/队伍数/组队后任务/次数）+ 手动组队（队长下拉+队员多选）+ 解散（单队/批量/全部）+ 队伍状态表（对照 `TeamView.vue`）。
- MapView：同队同色/同图提示（P2）。

#### 手动建队试点操作指引（阶段 1 · 用抓鬼号）

> 时序口径（用户 2026-09-29）：**先完成手头工作单元 → 建队集结（人齐）→ 再开接**。阶段 1 只验证组队/跟随/解散，不接任务（`next_action` 不带）。

1. **准备**：选 2-3 个抓鬼号（建议同图、等级接近），等它们自然打完当前一轮、进入空闲/等鬼（避免在下鬼/战斗中建队）。
2. **建队**（HTTP；中控 web 端口，默认无鉴权 token）：
   ```bash
   curl -X POST http://127.0.0.1:<web端口>/api/team/setup \
     -H "Content-Type: application/json" \
     -d '{"captain":"<队长账号>","members":["<队员1>","<队员2>"]}'
   ```
   成功回执含 `ok:true`、`captain_role_id`；失败会给人话原因（不在线 / 无 role_id / 超 4 人 / 通道断开），按提示处理后重试。
3. **集结核对**（约 10-30 秒内完成）：
   ```bash
   curl http://127.0.0.1:<web端口>/api/team/status
   ```
   `jobs` 清空 + `teams` 出现该队（`state:"ready"`）即就绪；`robots` 摘要可看各号 `online/role_id/mapid/pos`。
   机器人侧证据（可选）：`robot/deploy/single_robot_zy/script/diag.log` 出现 `TEAM_SEND … C2S_TEAM_CREATE`、`S2C_BUILD_TEAM`；中控日志出现 `[组队] 队长就绪`。
4. **跟随验证（核心）**：队长走两步（或等下一轮移动）→ 队员 `pos` 被服务端同步跟随（`/api/team/status` 的 `robots.pos` / 面板可见）；跨图：等队长切图后两号 `mapid` 一致（活跃队员被带队）。
5. **解散**：
   ```bash
   curl -X POST http://127.0.0.1:<web端口>/api/team/disband \
     -H "Content-Type: application/json" -d '{"accounts":["<任一队员或队长>"]}'
   # 或 {"all":true}
   ```
   机器人侧应看到 `S2C_CANCEL_TEAM`；`/api/team/status` 台账清空。
6. **回滚**：任一步异常 → 步骤 5 解散；必要时对相关号单独下发 `{"cmd":"team_clear","accounts":[...]}`。
