## 5 风险专查

### 5.1 P1｜`dijkstra` 裁剪会打断跨图多跳寻路（**必须改**）

`__find_dijkstra_route` 只在 **表完全为空** 时回退全局表（1182-1193：`if not table: table = g_chain_dijkstra_cache`），
BFS 扩展只认本表（1221 `entries = table.get(str(cur), [])`）。裁剪后表非空但缺中间图键 →
BFS 从当前图走一跳后立刻断头 → 返回 None → 上层判“无可行路径”停链/转游荡。
真实链 `data/chains/zhongkui_nav.json`：`dijkstra` **89 键**、`map_grids` **83 键**（远超 6，必然触发裁剪）。
沙盒用该表复刻 BFS 规则实测：**1→2 裁剪前 3 跳，裁剪后 None**（保留键 `1,2,653,654,655,669`）。
影响面：任务链跨图段（如新手链 5→9→10→11→612）在裁剪后 5 分钟内即可能断。
**建议**：本轮只裁 `map_grids`（`for _key in ("map_grids",)`）；或把 `table.get(str(from_map))` 缺失也纳入回退（需回归跨图 BFS，不宜本次热更）。

### 5.2 P2｜`quest.chain is g_nav_chain` 时裁剪会**改全局缓存**（实测）

`shop_errand` 直接 `quest.chain = g_nav_chain`（2025，共享全局对象，非副本）。`__mem_trim_grids`
以 `_ch[_key] = _nd` 写回（168），等价于把全局 `g_nav_chain` 永久降到 6 张。
沙盒复刻：**map_grids 83→6、dijkstra 89→6**。后果：后续所有号的采购跨图导航（唯一数据源就是它）
只剩 6 图。**建议**：`if _ch is globals().get("g_nav_chain"): return`（或先 `dict()` 再写回 quest）。

### 5.3 P2｜覆盖缺口：抓鬼 / 分享日常 / 集合走 完全不经过 `__mem_guard`

`main_tester.py`：抓鬼激活 137-138 `continue`、分享日常 155-156 `continue`、集合走 178-187 `continue`，
三条路径都在 191 `quest_engine.tester` 之前返回；`config.robot_task_tester=True`（config.py:326）时也走 191。
即：**抓鬼池、神捕/烽火/私池、集合走的号，其 NPC/grids 永不裁剪**（全局寻路缓存仍能被其它号触发清理）。
**建议**：随下次机器人重启，把该调用提到 `main_tester.tester()` 循环顶部（模块级 `quest_engine.__mem_guard`
无 name-mangling，可直接调用）；本次热更可接受覆盖不全。

### 5.4 P2｜`m_npc_add_logged` 同类无界字典未被治理

`msghandle.py:833-838` 按 npc_id 落 `{id:1}`，与 `m_npc_add_raw` 同源同增长，补丁未覆盖（机器人重启才会随实例销毁）。建议下一批并入 `__mem_trim_robot`。
