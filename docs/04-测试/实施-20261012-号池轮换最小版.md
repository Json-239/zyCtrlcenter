## 五、部署启用步骤建议（主 agent 明日执行）

1. 重建 exe + **温重启中控**（不带 `--auto-robot`；机器人端零改动、无需重启机器人）。
2. env（建议先灰度参数）：`CTRL_ROTATION=1`、`CTRL_ROTATION_PER_HOUR=10`（首日保守，稳后转 30）、
   `CTRL_ROTATION_MIN_RESERVE=50`、`CTRL_ROTATION_KEEP_HOURS=24`。
3. 首日观察（`GET /api/rotation` + 日志 `[ROTATION]`）：
   - `offlined_today` ≤ 速率×小时；`reserve` 不向下穿 50（穿了下线自动暂停）；
   - 水位器 enabled 时：在线数保持 target 附近（轮换号被新号替换）、抓鬼 done 增速不降；
   - 次日：`list_count` 递减（到龄回池日志）→ 水位器把回池号重新拉起（最久未上线优先）。
4. 回滚：`CTRL_ROTATION=0` 温重启（名单保留、仍会到龄回池）；如需立即放回，按 data/rotation.json
   的账号逐个 `POST /api/robots/unremove`（**勿用 clear_removed**——会连带放回其它被移除号）。

## 六、不确定点 / 口径说明

1. "在线 ≥30 分钟"：快照无"在线起始时间"，用进程内"首见在线表"（rotation.go:75）；中控重启
   清零 → 重启后头 30 分钟不轮换（保守）。心跳抖动导致某轮 Online=false 会重置计时（只延后、不误伤）。
2. "今日领双已用"按需求原话实现：`double_claim_date==今日` 或字段缺失 → 放行；有值且非今日 → 拦
   （rotation.go:147）。若业务期望相反方向，改这一处即可。
3. "无队伍"保守实现 = team 块非 nil 即算在队（契约：不在队时机器人省略/置 null）。若机器人端
   会发空 team 块，会导致一直跳过——需机器人端契约确认（不影响首日灰度）。
4. 候选未做"当前区"过滤（同 rescue48 口径；单通道单区部署等价）。
5. 额度按"已尝试"记账（含 sent 失败）：因 MarkRemoved 已本地生效不可逆；通道闸保证正常不出现。
6. 轮换号下线不写 TouchOnline（复用通路本就不写）→ 回池后按"最久未上线优先"优先被水位器选中
   （符合"换班"设计）；若叠加"水位 target 高 + reserve 掉得快"，保护闸会先停轮换（预期）。
