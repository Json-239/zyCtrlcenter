## 5. 风险与裁量（不构成 P0/P1，留档）

- **P2-1（低危，理论窗口极窄）**：abort 守卫为自我标记 `heal_buy_active`，而 `shop_errand.stop → release` 不核对锁 owner（`release(robot_object)` 无条件弹锁）。极端叠加链（非 STUCK 型停摆致标记残留 + 锁 TTL 10min 过期 + 期间同号新会话启动 + 再次 STUCK）时，可能误停/误释放新会话（如抓鬼 owner=drug）。后果：号即将 ERROR、在途会话本需收尾，危害低且可自愈。可选加固（未实施）：abort 内先 `status()` 校验有锁且 `owner=="drug"` 再 stop；当前"无锁也 stop 清残留上下文"为有意取舍（C3 已证无害）。
- **P2-2（提醒级）**：钩子位于 `notify_failed` 之后、`mark_error` 之前；abort→stop 会清 `quest.shop_ctx/active/dialog`。当前无冲突（D1b/D3 实测）。后续若在 `__report_stuck` 内新增依赖 shop_ctx 的逻辑，须放在钩子之前。
- **P3-1（不可达）**：`heal_buy_fails` 为非 int 脏值时，abort 已 stop+清标记但返回 False 且退避未落（字段仅本模块 int 写入，实际不可达）。
- **P3-2（语义说明）**：abort 返回 True 表示"调用时标记在途"，不保证 stop 有实际会话（锁已被清时 no-op 无害，C3 已证）。
