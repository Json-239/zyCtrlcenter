# 实施：机器人内存护栏（2026-10-27）

## 1. 背景（实测）

- 2026-10-27 14:07 生产事故：机器人进程（PID 38124，10-23 10:39 由中控 `--auto-robot` 拉起）
  commit 达 **4.52GB**；同机 msedge 4.41GB、Godot 3.59GB → Windows 提交内存耗尽
  （WER 2004，13:50/14:07 两次告警），中控退出、看门狗 21 秒拉起、全队重登。
- 泄漏速率 **≈1.1GB/天**（本批前记录：10-14 两天 1.1GB；本次 4 天 4.5GB）。
  重启后新进程 415MB。不干预则 4-5 天复发。
- 事故当天产出 -17%（4:30 后半时 520-660 → 400-470，13:30 段 411；重启后 517）。

## 2. 方案

中控侧新增"机器人内存护栏"：按 `max(工作集, 提交量)` 分级，把"4 天必炸"变成
"低峰窗口可控重启"。重启 = 全体账号重登（约 5-15 分钟产出损失），因此阈值取
基线（~415MB）的 5 倍以上，且冷却期内不穿透（防重启风暴）。

| 动作 | 触发 | 影响 |
|---|---|---|
| 告警 | mem ≥ 1800MB | 只记日志（30min 节流） |
| 低峰重启 | 窗口内 && mem ≥ 2200MB | 重启机器人（全体重登） |
| 紧急重启 | mem ≥ 3200MB（任何时段） | 同上 |
| 时长兜底 | 窗口内 && uptime ≥ 96h | 同上（防指标失真） |

## 5. 安全边界

- PowerShell 查询**只按可执行文件路径**过滤（`ExecutablePath -like '<DeployDir>\*'`），
  绝不按镜像名——同机还有 py/测试栈同名 `robot_single_robot.exe`。
- 采样失败/未运行 → 只记日志，**不做任何动作**。
- 重启硬编码 `Restart(true)`：清同部署目录残留（中控重启后 `m.cmd=nil` 的孤儿场景，
  `KillRobots` 默认 false 会漏）。
- `restartMu` 串行化：护栏与手动 `/api/robot/restart` 并发不会双启。
- 不额外发 `add`：依赖机器人 hello 后 `CTRL_RESTART_AUTO_ADD` 自动补号。

## 7. 部署序

1. 备份 `zyctrlcenter.exe` → `.bak_20261027_guard`（记 sha1）。
2. 停看门狗计划任务（`schtasks /end` + taskkill python）。
3. 杀 A → 覆盖 exe → `_restart_warm_20261027.bat`（ASCII+CRLF，**不带** `--auto-robot`，不动机器人）。
4. 起回看门狗。
5. 验收：`/api/status.robot_guard` 的 `pid=42388`、`mem_mb≈415`、`last_sample` 有值；
   5 分钟后第二条采样；Dashboard 策略摘要卡显示"机器人内存"。
