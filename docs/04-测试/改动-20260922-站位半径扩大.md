# 改动说明 2026-09-22：抓鬼/对话站位半径扩大（5 → 7 格）

范围：

- 单文件改动：`quest_engine.py` 的**对话站位随机化半径** `STAND_RADIUS_CELLS` **5 → 7 格**（用户实盘反馈"站位还是过于密集，可以再多两格"），并同步退化兜底像素上限 `STAND_OFFSET_MAX_PX` **80 → 112**（= 7 格 × 16px）。
- 配套：`tools/npc_stand_selftest.py` 硬编码断言同步 + 新增 1 条"多出的两格确实会被用到"用例。
- **未部署**：本次只改文件，**未热更、未重启任何进程**；部署由主控执行。

## 一、用户诉求与结论

> "NPC 站位范围可以再大一些，当前站位还是过于密集，可以再多两格。"

- 2026-09-21 已上线"对话站位随机化"：对话类点击（`click_type==0`）不再走到 NPC 坐标本身，而是走到 NPC 周围 **1~5 格**内的随机可走格中心（见 [`改动-20260921-站位与大屏筛选.md`](改动-20260921-站位与大屏筛选.md)、[`验收-20260921-站位与大屏筛选.md`](验收-20260921-站位与大屏筛选.md)：生产 1621 次落点 100% 合规、73 个不同格）。
- 用户现场反馈**仍偏密集** → 本次把半径**再放宽 2 格**：`[1,5]` → `[1,7]` 格。
- 算法未变（仍是极坐标随机采样 + 严格卡半径 + 只取可走格 + 不占 NPC 格），**只动常量与其对应注释**，属最小改动。

### 2.3 `tools/npc_stand_selftest.py`（断言同步）

| 用例 | 改前 | 改后 |
|---|---|---|
| ① 常量口径 | `(RADIUS, MINC, TRIES) == (5, 1, 24)`，标题"半径 5 格" | `== (7, 1, 24)`，标题"半径 7 格" |
| ② 网格采样范围 | 注释/标题 `[1, 5]`、`1~5 格` | `[1, 7]`、`1~7 格`（判据仍用 `MINC <= d <= RADIUS`，自动跟随常量） |
| ③b **新增** | — | "半径 +2 有效：300 次采样有落点落在 6~7 格（固定种子，可复现）" |
| ④ 只落可走格 | 阻挡盒 ±6 格 | 阻挡盒 ±8 格（见下"为什么要动"） |
| ⑦ 兜底范围 | 注释/标题 `[32, 80]px` | `[32, 112]px`（判据用 `OFF_MIN/OFF_MAX`，自动跟随常量） |
| ⑨b **新增** | — | "兜底上限 == 半径格数 × 16px"（`OFF_MAX == RADIUS * CELL`） |
| ⑪ 网格优先 | `1 <= d <= 5`、文案"1~5 格中心" | `1 <= d <= 7`、文案"1~7 格中心" |

**④ 为什么要动阻挡盒（不是放宽断言，是让用例继续成立）**：该用例把 NPC 周边一整块设为阻挡、只留 3 个可走格，断言"落点必在这 3 格内"。原来的阻挡盒只覆盖 ±6 格；半径扩到 7 后，盒外（`FakeGrid` 默认可走）的格子会被合法采到（实测落点 `(23,30)`，距 NPC 恰 7 格），用例会**误报 FAIL**。把盒扩到 ±8 格后，整个采样范围都被覆盖，断言口径不变、且更严格。此现象在改后首次运行时真实出现并被这条修复闭合（见 §3.2）。

**③b 新增用例的做法（稳定性）**：不依赖全局随机，注入固定种子 `random.Random(20260922)`，连续采样 300 次统计落在 6~7 格的次数（理论占比 ≈ (7-6)/(7-1) = 1/6），断言 `>= 1`。固定种子 → 结果逐字节可复现，不存在"某次跑挂"的偶发不稳定。实测该用例取到 **50 次**（远超阈值 1）。

## 六、部署后验证建议（热更 `quest_engine.py` 之后）

### 6.1 主验证：图 24 钟馗格中心落点应"扩到 6~7 格"

**判据（只看网格采样路径）**：热更后新产生的「对话站位」日志中，图 24 / NPC 10146（钟馗，`1728,1056`，格 `(108,66)`）的**格中心落点**（`x%16==8 且 y%16==8`，即走网格采样那条路），格距分布应从**只有 1~5 格**变成**出现 6 格、7 格**（经验占比 ~16%），且**无一条 >7 格**。

> ⚠ 为什么必须区分两条路径：**兜底偏移**路径的落点是任意像素（不是格中心、日志文案是"退化偏移兜底 … 距 NPC 约 Npx"），把像素折算成格距会因 `x//16` 取整 + NPC 像素(1728,1056) 正好压在格左上角而**虚高约 1 格**（实测旧半径 80px 兜底样本里就有 20 条读作"6 格"，其实像素距仅 74.8px，完全合法）。所以兜底样本只用 `[32,112]px` 校验，不参与格距判越界。

取样命令思路（机器人运行日志为 JSON Lines，落在中控仓库 `data/bot_logs/<账号>/runs_YYYYMMDD.log`，字段 `msg`）：

```bash

#    "对话站位: NPC 10146 (图24,1728,1056) → 站到 (1704,1048)（7 格内随机，不占 NPC 格）"）
grep -h "对话站位: NPC 10146 (图24,1728,1056)" \
     f:/ZyBin/zyCtrlcenter/data/bot_logs/*/runs_2026092*.log > "$TEMP/stand24.txt"

# ② 分开统计"格中心(网格采样)"与"非格中心(兜底偏移)"，只对前者判 1~7 格
python - <<'PY'
import re, math, collections
pat = re.compile(r'站到 \((\d+),(\d+)\)')
gc, fb, bad = collections.Counter(), collections.Counter(), []
for line in open(r'C:/Users/Administrator/AppData/Local/Temp/stand24.txt',
                 encoding='utf-8', errors='ignore'):
    m = pat.search(line)
    if not m: continue
    x, y = int(m.group(1)), int(m.group(2))
    d = math.hypot(x // 16 - 108, y // 16 - 66)     # 钟馗格 (108,66)
    if x % 16 == 8 and y % 16 == 8:                 # 网格采样 → 格中心，判据成立
        gc[round(d)] += 1
        if not (1 <= d <= 7): bad.append(round(d, 2))
    else:                                           # 兜底偏移 → 任意像素，只看计数
        fb[round(d)] += 1
print('格中心(网格采样):', dict(sorted(gc.items())), '越界=<1或>7 =', len(bad))
print('非格中心(兜底):', dict(sorted(fb.items())))
print('6~7 格合计 =', gc.get(6, 0) + gc.get(7, 0))

```
