# 实施：中控静默死亡取证加固（2026-10-28）

## 1. 背景

2026-10-28 14:13 A 中控（PID 75912，10-27 16:58 启动）静默死亡：

| 时间 | 事件 |
|---|---|
| 14:12:54 | 看门狗 HTTP 探测无响应（8s 超时） |
| 14:12:56 | 日志仍正常写最后 19 行 |
| 14:13:02 | 看门狗「进程存在但 HTTP 无响应 1/3」 |
| 14:13:17 | 进程消失（procs=0）→ `_start_detached.bat` 拉起 |
| 14:13:27 | 恢复（宕机 25 秒），机器人被 `--auto-robot` 冷启（42388→76000），全队重登 |

取证结论：**无 FATAL/panic、`logs/stderr.log` 0 字节、无 WER 2004/系统事件**。
stderr 重定向链已确认有效（`_start_detached.bat` → `_run_ctrl_console.bat` → `2>> logs/stderr.log`），
说明不是 Go panic/deadlock（会打印栈），而是被强制终止或自行 `ExitProcess`。主机物理可用 0.7GB、
提交余 5.58GB，内存压力是最大嫌疑但无直接证据。

目标：**下次发生时能区分「卡死」vs「被杀」**，并留下退出码与 goroutine 快照。

## 3. 判读口径

| 现象 | 结论 |
|---|---|
| 心跳停在死亡前 + 进程随后消失 | 被强制终止 / 自行退出（看 `exit_codes.log`） |
| 心跳持续更新但 HTTP 不通 | HTTP/handler 层卡死（goroutines 通常同步飙升） |
| goroutines 持续增长 | goroutine 泄漏（非本次形态） |
| `exit_codes.log` 出现 `0xC0000005` 类退出码 | 访问冲突（需 pprof/内存检查） |
