### A. 乐观过图残留 + 图网格越界（硬卡 4+1：5048/5116/5212/5279 + 5323）

## ④ 样本 robot0001032 机制级解释（"启动后静默无动作"）

**结论：15:05:33 起的四次"集合走启动"之所以零动作，不是跨图导航卡，而是摆摊自检（booth WAIT_MAP）接管后 `main_tester` 跳过了 random_walk 的 tick；`dispatch_cmd`（命令处理）仍照常打日志，所以出现"启动有日志、行动零发生"。**

证据与代码：
1. `script/main_tester.py`（sh）：`ret = booth.tick(...)` 之后若 `m_booth.enabled` → `continue`——**跳过其下全部模块（route_walk/daily_ghost/share_daily/mount_egg/random_walk/quest_engine）**。摆摊"站桩"设计如此。
2. `script/booth.py`：`_activate` 时若游荡仍 enabled → 只记 `ACTIVATE_WARN`（"建议先 random_walk_stop"）**但不接管/不停止游荡**；状态进 `WAIT_MAP`，`_st_wait_map` 只等 `robot_object.m_mapid==b.mapid`，**不自作主张跨图**（schema 注释"等到达目标图"），超时 `map_wait_sec=1800`。
3. `diag.log` 行序证据：`BOOTH_SELFTEST ACTIVATE…(WAIT_MAP cur=42 target=11)` 紧挨在 15:05:33 那次 `CTRL_CMD→集合走启动(目标图10)` **之前**（diag 行号 1193668/1193671 < 1193765）。
4. 时间线：15:02:54 替加 13255 对话过图（乐观→本地 42）；15:05:2x 摆摊激活（此时本地 42、目标 11）；15:05:33 / 15:08:05 / 15:13:33 / 15:17:16 四次集合走启动，全部只有 dispatch 日志、无任何 tick 侧行为（无"跨图…经 N 个跳转点"、无"走路:"）；15:09:44 一次**人工重登**（diag：`CTRL_CMD robot_manage remove/add`，无 [REGHOST] 行）→ 本地图被服务端真值校准为 9（由此也可推断 15:02 的 42 其实**未被服务端接受**）；15:22:00 `[START] 解除人工暂停` + 摆摊计划 enabled=false →`BOOTH_SELFTEST DEACTIVATE reason=PLAN_OFF`→ 号立即恢复（15:33 起正常抓鬼、走路）。
5. 代码级"静默点"补充：`random_walk.__goto_map` 内 `pt = __pick_walk_point(...); if pt is None: return False` **无日志**——本次不是这条（tick 根本没跑），但同一静默风格值得标记。

**给操作层的直接结论**：摆摊自检必须在**机器人已在目标图**时激活才安全；"激活后再用集合走/送图"在现有实现下必然死锁（移动模块全被跳过），只能等 30min 超时或手动撤下。
