## 一、背景问题（依次解决）

1. **面板无法新增服/切换区** → `zones.cloneServers` 把空区列表序列化成 `null`，前端 `s.zones.length` 抛错导致整页崩 → 已修（另：面板 dev server 僵尸进程已重启）
2. **大屏"在线数"虚高**（140+ vs 服务端 64）→ 机器人 `hs` 标志连接死了不清 + 断连扫描不覆盖"连接对象已摘掉"的号 → 已修（`srv_idle_ms` 活性判据 + 兜底重登）
3. **并发填 500 实际只有 16** → `accountverify.MaxConcurrency` 硬编码 16 → 改为可配（默认 512、`CTRL_VERIFY_MAX_CONCURRENCY` 可调）
4. **钟馗扎堆**（峰值 62 个号挤幽冥界，28 个在钟馗 300px 内）→ 两段修复：
   - 任务状态不同步：本地任务表空但服务端仍持有捉鬼任务 → 钟馗不给接取项 → 反复点钟馗。
     修法：**协议放弃**（`C2S_DROP_TASK`，任务号取对话载荷 `data[4]` 或本地缓存；都没有时**盲试**
     2019501~2019513 轮转）+ 清空菜单退避/重登计数。效果：**READY 空转 34 → 8**、钟馗 300px 内 **28 → 5**。
   - **助战令误判**：机器人流程"先领/买助战令再接任务"，买不到就判"接不到捉鬼 → 下线换号"。
     核实服务端 `config/task/20195.xml`：**接取没有任何物品条件**（只要 20 级 + 未持有 2019511）；
     助战令只给抓鬼战斗加 3 个**可选**帮手（`tailor_ghost.xml` 的 助战者 带 `condition_role_buff 1128`）。
     修法：`robot_ghost_use_token = False`（默认）→ 不点领取/不开店/不因无令换号；`__note_no_action`
     的"无可动作项"归因从"没令"改成"空菜单"。效果：`接不到捉鬼` 归零、直接接任务 ✓

**游荡池规则**（`internal/services/roampool` + `GET/POST /api/roampool`）：
- **回收**：任务池（抓鬼+新手）缺口 > 0 时，**立刻**从游荡号里按"所在图人数从多到少"收 `≤max_step` 个

- 默认 `enabled=false`（参数落盘 `data/roampool.json`）。

## 七、追加修复（19:5x）：钟馗"二次堆积"根因 = 每日 50 次上限

**现象**：抓鬼池补到 100 后，幽冥界涨到 87、钟馗 300px 内 26 个，其中 **22 个近 10 分钟零产出**（日志：节流刷屏 31~87 次 + 自愈 + 空菜单）。

**根因（证据链）**：
1. 对比钟馗对话原文（diag）有两种形态：
   - 可接：`'地狱中许多鬼趁机逃出了地狱…'` → `[挑战捉鬼任务, 这太可怕了…]` ✓
   - 卡住：`'对于心术不正之人，鬼无处不在…'` → `[【捉鬼任务】活动说明, 领取助战令, 离开]` ✗（闲聊菜单）
2. 闲聊菜单里**没有「放弃捉鬼任务」** → 服务端**不认为角色持有任务** → 排除"任务不同步"；
3. 服务端 `config/task/20195.xml`：`<daily_limit>50</daily_limit>` —— **当日抓满 50 次后钟馗不再给任务**（只回闲聊菜单）；
4. 控制器**没有"今日已抓满"记录** → `ghost_done` 下线后又被抓鬼池当候选拉起 → 去钟馗 → 空转 → 堆积 ✓

**修复**：
- `state.Robot.GhostDoneDay`（"20060102"）+ `MarkGhostDoneToday/GhostDoneToday`（跨日自动失效，与 `StuckDay` 同款）；
- `onGhostDone` 落标记；`autotaskCandidates(KindGhost)` 跳过"今日已满"的号（当天不再派，跨日自动恢复）。

**验证**：重启后钟馗 300px 内 26 → 21（持续收敛）；满额/空闲号被**游荡池**按 5/分钟收割去游荡
（日志：`集合走启动: 目标图 2(指定)…`、`游荡池 补位 5 个 → 图2/3/8/14/15 …`）。

**顺带对齐口径**：新手池已停（target=0）→ 抓鬼 100 + 游荡 100 = 水位 200 ✓

## 八、追加修复（20:1x）：为什么"重启后又扎堆"—— 标记写错了地方

**现象**：上一节的修复上线后，钟馗 300px 内又回到 26（其中 19 个非游荡在排队）。

**根因（我自己的 bug）**：`MarkGhostDoneToday` 把标记写在了 **robot 状态行**上，而调用方
（`onGhostDone` / `onGhostOffline`）**紧接着就 `removeAccount()` 把这行删掉** → 标记随行丢失
（实测 `/api/status` 的标记数恒为 0）→ 满额/不可用的号**仍被抓鬼池当候选反复拉起**
→ 去钟馗（服务端只回闲聊菜单）→ 排队 → 表现为"重启后又扎堆"。

**修法**：
1. 标记改为 **`State.ghostUnavail`（独立的"账号→日期"表）**，不随行删除；`/api/status` 新增
   `ghost_unavailable_today` 计数供排查；
2. 机器人端"钟馗空菜单退避" **60/120s → 5/10s**（快速二连即判"本号今日抓鬼不可用"→ 下线让位），
   不再长时间占着钟馗排队（自检 `broker_empty_backoff_selftest` 已同步更新，15 项全绿）。

**验证**：标记数 0 → **32**（持续增长）；钟馗 300px 内 20 → **14**（其中非游荡 11）；幽冥界 65 → **44**。

**注意**：标记表在**内存**里，中控重启会清空 → 重启后这些号会被重试一轮（每个约 20 秒）后再次被标记；
如需跨重启保留可落盘（未做，按需再加）。
