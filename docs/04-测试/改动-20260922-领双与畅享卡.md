## 二、流程（每天一次，抓鬼启动前）

```
ghost_start(daily_ghost.dispatch_cmd)
  └─ pre_daily.claim_double_exp(robot)          # 今日未处理才启动(跨日自动重算)
       ↓ tick(daily_ghost.tick 的 pre_daily 段, 导航由 __consume_nav 推进)
  1) 顺带用一张畅享服务卡(auto_summon.use_buff_card; 有卡且非新手才用)
  2) 导航到图12 (3931,882): quest_engine.__teleport_click
     (链 npcs 缺 13035 时注入静态坐标; 跨图前先只读预检路由, 无路径直接放弃,
      避免 __teleport_click 记 NO_LEGAL_ROUTE / 置 ERROR 污染抓鬼)
  3) 走到位自动点薛仁贵 → 等对话(15s; 超时最多再点 2 次)
  4) 按对话文本依次点:「直接领取（双倍）」→「领取一小时双倍」
     (若对话里出现 2.5 倍选项且开关打开 → 优先「领取并开启畅游服务（2.5倍）」→「领取一小时2.5倍」)
  5) 结束: 服务端 CLOSE_DIALOG(成功) / 额度不足提示对话(记 info, 今日不再尝试) /
     文本缺失(记 warn 放弃) / 整体 120s 超时(记 warn 放弃)
```

调用点与"不越界"：

- 只对**抓鬼意图**的号生效——入口只在 `ghost_start` 分支里，新手链阶段的号收不到该命令；
- 失败/异常**一律吞掉**：`tick` 异常返回 `True`（继续抓鬼），`on_dialog`/`on_close_dialog` 异常返回 `False`（交回原链路）；
- 状态存 `robot_object.m_pre_daily`（**Robot 实例属性**，热更 reload 不丢；不存模块级）。

## 三、畅享服务卡门槛口径（用户新口径）

> "畅游卡尽量也要在领双的时候使用；新手的时候先不用，留着抓鬼时用"

两道门槛都收在 `auto_summon.use_buff_card`（空闲整理与领双共用同一条路径）：

| 门槛 | 配置项（默认） | 语义 |
|---|---|---|
| 新手不用卡 | `robot_use_buff_items_min_level = 31` | 等级 < 31（= `start_chain_done_level` 新手链毕业等级同口径；未同步等级按 0 处理）= 新手链阶段 → **绝不用卡**；设 0 = 不启用 |
| 空闲不用卡 | `robot_use_buff_items_idle = False` | 空闲背包整理**默认不再消耗**卡（否则每 3 秒一次整理会快速用光，"卡与领双同时发生"无从谈起）；卡统一留给 `pre_daily` 在抓鬼启动前领双时用。改 True 恢复旧行为 |

领双时用卡沿用既有逻辑：`C2S_USEITEM`（不新写协议）+ 用后延迟 2s/8s 切回常规称谓（`msghandle.change_to_normal_title`）；领双期间由 `pre_daily.tick` 代为驱动还原（抓鬼启动后 `auto_summon.tick` 不跑 `is_idle=False`），错过的时间点仍留给 `auto_summon` 将来空闲时兜底。

## 七、风险与残余

| 风险 | 影响 | 缓解 |
|---|---|---|
| 对话文案/选项变化（服务端改版） | 按文本匹配失败 → 领不到 | 记 warn 放弃、点关闭项收尾，**不阻塞抓鬼**；下次抓鬼会话自动再试（`done_date` 只在"结束"时写） |
| 2.5 倍路径的静默失败 | 若把 `robot_claim_double_exp_prefer_25` 打开且号 0 余额 → 点了什么也拿不到 | **默认关闭**（见第一节事实）；开关只给有充值/畅游的号 |
| 每周额度 | 默认每天 1 小时 × 7 天 = 7 小时 ≤ 每周 16 小时（对话回显口径），不会撞上限 | 若调整 `robot_claim_double_exp_hours` 为 4 需注意 4×7=28 > 16，本周后几天会收到"额度不足"提示（此时记 info 并停手，不刷屏） |
| 服务端对话状态残留（点了选项但不关对话） | 抓鬼链路被既有兜底拦一下 | 依赖 `daily_ghost` 既有兜底（8 秒点服务端关闭项 / 30 秒回 READY / 6 轮重登），本次不改动该链路 |
| 领双期间被野怪打断 | 领双延后 | `tick` 在战斗分支之后执行，战斗结束继续领双；整体 120 秒看门狗兜底放弃 |
| 卡的使用时机 | 空闲期不再用卡（默认），卡消耗速度变慢 | 领双时每天最多用 1 张；要恢复空闲用卡把 `robot_use_buff_items_idle` 改 True |

残余（已知未做，按需再议）：领双成功后**没有**二次校验"是否真的拿到多倍 buff"（服务端领取成功不发对话，仅 `add_buff`），判据取"已发领取动作 + 服务端关对话"；如需强校验，可后续在 `msghandle` 里记录 buff 1000/1 的 `S2C_ADD_BUFF` 作为观测点。
