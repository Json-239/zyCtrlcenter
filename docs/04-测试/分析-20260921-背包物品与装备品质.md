## 1. 数据与协议基础（先立地基）

### 1.1 物品实例的字段（`ATTR_DATA` = cookie+session 白名单）

- 服务端下发物品时 `item_data[ATTR_DATA] = attr_data`，来源是**持久 cookie 白名单** + session：`SV/item/item_object.py:565-598`。
- cookie 白名单 `DUMP_KEY_SET`：`SV/item/item_cookie.py:10-79`，其中与本次相关：
  - `ITEM_QUALITY = 5557`（**在册**，第 78 行；注释"饰品品质，决定名字颜色: 1白~6金"）
  - `COOKIE_PW_LOCK=5366`、`COOKIE_TIME_LOCK=5367`（第 18-19 行）→ 机器人 `is_locked` 判定依据
  - `COOKIE_EGG_PNEUMA`（第 29 行，元气蛋元气值）、`COOKIE_PILL_*`（第 34-38 行，内丹等级/经验/元气/转生）
  - **`EQUIP_CLASS(5108)` 不在白名单** → 实例 `ATTR_DATA` 实际拿不到装备类，机器人 `__bag_is_equip` 会回落到模板（见 1.3）
- 数量在 `ATTR_DATA[ITEM_COUNT=5105]`，**不在顶层**：`RB/quest_engine.py:1806-1819`（2026-09-08 修复买药死循环）
- 位置 `ITEM_POSITION=5356`：背包 `0x2000~0x2fff(8192~12287)`、装备栏 `0x1000~0x10ff(4096~4351)`、包裹栏 `0x6410~0x641f(25616~25631)`
  （`SV/item/item_param.py:41-66`）

### 1.2 品质数值链路（权威）

```
模板 XML  <item_quality>N</item_quality>                 (N = 0..10)
   ↓  SV/item/item_parser.py:56-62
   item_quality = N + QUALITY_BEGIN(5558) + 1 = N + QUALITY_WASTE(5559)
   ↓  实例 cookie 落库 / 下发 (DUMP_KEY_SET 含 5557)
   get_item_quality() = ITEM_QUALITY - QUALITY_WASTE = N   ← 客户端/服务端同一口径
```
- 枚举：`SV/keys/item_.py:460-473`（`QUALITY_WASTE=5559` 废品、`QUALITY_NORMAL=5560` … `QUALITY_SIXTH=5565`；`QUALITY_END=5570`）
- 换算函数：`SV/item/item_base.py:150-152`（唯一实现，注释里把旧实现注释掉了）
- 客户端同名函数：`CL/script/item/item_base.py:188`；颜色档位 `CL/script/item/__init__.py:16-22`（白1/绿2/蓝3/紫4/橙5/金6）
- 机器人侧复刻：`RB/quest_engine.py:1743-1764`（`quality = ATTR_DATA[ITEM_QUALITY] - QUALITY_WASTE`，无值回退模板，再没有就 `None` → **不丢**）

**关键数据事实（易踩坑）**：模板里的 `item_quality` 与"好坏"在本服**不一致**：

| item_index | 名称 | 模板 item_quality | related_element_index | 现场角色等级 | 结论 |
|---|---|---|---|---|---|
| 213604 | 螺旋枪 | 4 | `element_weapon_a_lv3` | 31~33 | 好（lv3 武器） |
| 213104/213204/213704/213904 | 惊鸿剑/断玉刀/檀木棍/金蛇鞭 | 4 | `element_weapon_a_lv3` | 31~33 | 好 |
| 223304/223404 | 玄铁盔/蝴蝶花钗 | 4 | `element_head_*_lv3` | 31~33 | 好 |
| 215601/215701 | 破甲长枪/长棒 | **6** | `element_weapon_a_lv0` | 31~33 | **新手白装** |
| 225101/225201/225501/225601 | 粗布衣/长裙/布鞋/贝壳项链 | **6** | `*_lv0` | 31~33 | **新手白装** |

### 1.3 "使用物品"的服务端分发链路（三去向）

```
C2S_USE_ITEM(80218) [item_id(实例)]
  → SV/item/item_dispatcher.py:49-53 dispatch_use_item
  → SV/item/item_operator.py:209-240 dispatch_use_on_role
      - can_use_on_role()=False → 若 can_use_on_summon() 则回 notice 1268，结束（不消耗）
      - 装备栏里的物品：不做条件判断，直接"解下"（pocket_type == POCKET_TYPE_EQUIP）
      - 有吟唱 ENTRI_CHANT_TIME 的走 chant 队列后重发
      - 其它 → item_pocket.use_on_role(item_object)
          · BagItemPocket.use_on_role → item_object.use_on_role → 执行 item_step / handler
             （SV/item/pocket_object.py:256-257、SV/item/item_object.py:410-414）
          · EquipItemPocket.use_on_role → release_equip_item **解下装备**
             （SV/item/pocket_object.py:211-212）
  → 每个 step 执行完，只有 action 主动 `set_consume_sign()` 才真正扣 1 个
     （SV/item/item_object.py:464-472）
```

由此得三条推论（后文反复用到）：
1. **同一个 `C2S_USE_ITEM`，物品在背包=使用/穿戴，在装备栏=脱下**。
2. 只对守护/宠物/坐骑生效的道具，用在人物身上时：执行对应 action 的空实现（`ItemAction._do_use_on_role` 返回 True 但不 set_consume_sign）→ **静默无效果、不消耗**（仙兽丹/亲密丹等会先被 `can_use_on_role()=False` 拦掉并回 notice 1268）。
3. 有"确认对话"的物品（内丹、坐骑蛋）用 `ItemDialogAction` 弹对话，**推进要靠点选项**。

### 3.3 为什么"先留着"（现状归因，非推测）

1. 2026-09-19 之前的点击选项 0 会让号**永久卡 DIALOG**（服务端不关对话，且对话未关时拒绝移动）；
2. 关闭项是当时**唯一安全**的收尾（`RB/quest_engine.py:677-702` 的注释给了生产复盘：26 个非游荡号卡 DIALOG"原地不动"）；
3. 灵气孵化需要"到半月岛打若干场暗雷战斗"——与抓鬼/任务链路是**两套地图目标**，机器人当前没有"为了孵化去某图打怪"的能力（导航由中控链驱动，见 CC `internal/api/chainpayload.go:163-187`），因此即使把蛋放进装备栏，也不会有人去打灵气；
4. 结论：**蛋不是"不能孵"，而是"孵化的后半段（放置→打灵气）从未被接进链路"**，且前半段的选项点击曾造成过卡死，于是被保守放弃。

1. **部位**：取物品模板 `related_element_index`，正则 `element_(.+?)_lv\d+` → 部位名（如 `element_weapon_a_lv3` → `weapon_a`）（`RB/bag_ops.py:119-137`）。
   - 数据来源：RB 自己解析的 `xml/item.xml` + `xml/item_element.xml`（`RB/client.py:837-885`，字段 `related_element_index / element_name / equip_class / item_quality`）。
2. **好坏**：`_get_equip_quality` = 从 `related_element_index` 里抠 `lv(\d+)`，**lv 越大越好**（`RB/bag_ops.py:180-199`）。注释明确写了理由：模板 `item_quality` 不代表品质（223xxx=4 是好装备、225xxx=6 是低级白装）。
3. **位置区分**：背包 `0x2000~0x2fff` 与装备栏 `0x1000~0x10ff` 分开收集（`RB/bag_ops.py:219-237`，`_is_in_bag_pos` `:20-31`；与 `SV/item/item_param.py:41-50` 一致）。
4. **动作**：同部位里背包最优 `best_q > 已穿最优` 才发 `C2S_USE_ITEM(best.item_id)` 穿上；随后把背包里 `quality < keep_q` 的同部位多余件 `C2S_DELITEM` 丢掉（`RB/bag_ops.py:240-264`）。
5. **附带**：先把 `110173 积满灰尘的追捕令` 丢掉（防它引导的对话覆盖钟馗对话，`RB/bag_ops.py:208-218`）。

**问题（现状缺陷，非我推断）**：
- 判据混用两套（本函数 lv / 另一执行点品质），互相打脸（见 §4.3）。
- 丢弃参数用的是**实例 item_id**（`RB/bag_ops.py:259-260` 注释强调），这点是对的。
- 日志量：现场 `背包整理: lv=33 item=36 ... 穿装备=3`（CC `data/runs_20260921.jsonl`），`穿装备=5` 也出现过 → **每天都在穿**，但由于 §4.3 的丢弃，穿上的东西同时在被丢（或被拒）。
- 未比较**属性数值**（攻击/防御/耐久/星级/孔/宝石），只看 lv；同部位同 lv 时"保留最好的、不丢同 lv"（`RB/bag_ops.py:256-257`）。

### 4.3 "丢坏的"现状（阈值口径 + 保护 + 现场实证）

**两个丢弃实现**：

| 实现 | 判据 | 阈值 | 保护 | 位置过滤 | 现状 |
|---|---|---|---|---|---|
| `bag_ops.auto_equip_best_items` | lv（模板元素等级） | "低于本部位最优" | 已穿（按 pos 分组，不参与丢弃循环） | ✅ 只丢背包件 | 生效 |
| `auto_summon._try_bag_cleanup` | 实例品质 | `robot_drop_item_quality=6`（金色以下） | `is_locked`（密码锁/时间锁）+ `quality is None` 跳过 | ❌ **无位置过滤** | **空转 + 误伤** |
| `daily_ghost.__tidy_bag` | 模板 `item_handler`+`item_level` | `角色等级-item_level >= 5` | 助战令/疗伤药/任务物品 | ❌ 无 | 生效（抓鬼期间） |

**阈值口径**：`quality = ATTR_DATA[ITEM_QUALITY] - QUALITY_WASTE(5559)`，0~10（0=废品…6=金）；`RB/config.py:187-190`：`robot_drop_item_quality = 6` → "金色以下都丢"，注释还写"调 0=只丢废品"（**注释有误**：阈值 0 时 `q < 0` 永不成立=不丢；客户端语义是 `q < 1` 才只丢废品）。
**客户端原始语义对照**（配置注释里引用的依据）：`CL/script/item/item_operator.py:529-540` `try_drop_item`：`quality < DROP_ITEM_QUALITY` 时**直接丢**，否则弹"确认丢弃"对话框；而 `CFG/config/item.csv:9: DROP_ITEM_QUALITY,丢弃物品quality配置,1,` → **客户端阈值是 1（只丢废品）**，不是 6。

**保护（已穿戴/锁定）**：
- 锁定保护：有（`RB/quest_engine.py:1784-1803` `__bag_is_locked` 读 `COOKIE_PW_LOCK/COOKIE_TIME_LOCK`；`RB/auto_summon.py:490-491` 跳过）→ 与客户端 `is_item_locked` 语义一致。
- **已穿戴保护：无**。`_try_bag_cleanup` 遍历 `m_bag_cache`（由 `on_bag_full` 从**整份 `S2C_ROLE_ITEM`** 构建，**含装备栏物品**，`RB/quest_engine.py:1822-1855`；对比 `RB/msghandle.py:373-377` 同一份数据里 pos 有 4096/8192 两种）→ 装备栏里的装备也进候选。

**现场实证链（三重证据一致）**：
1. 中控日志：`背包整理: 丢弃低品级装备 213604(品质4<阈值6) ret=16`（`CC/data/runs_20260921.jsonl`，全天 **1453 条**，覆盖 11 个编号：213104/213204/213604/213704/213904、223304/223404/223504/223604、220602、223104）。
2. 同一秒的背包快照：`pos=213704@4098,223304@4096,225101@4097,...` → 被丢的 213704/223304 **正是已穿戴在装备栏 4098/4096 的**。
3. 服务端拒绝：`SV/item/item_pocket.py:291-292`（装备栏不响应丢弃）→ 机器人 diag.log 实测 **294 次** `>>> NOTICE_ARGS fd=... data=[417, []]`（`SV/keys/notice.py:419` = "丢弃物品不在包内"）。
4. 中控日志里"丢弃"后的位置回写：`物品位置: [(17601525091689358, 4098)]` —— 装备**仍在**装备栏。

**副作用**：`_try_bag_cleanup` 每次动作后 `return True`（单件/3 秒），本地缓存 `item[1]-=1` → 弹出该 idx（`RB/auto_summon.py:497-505`），下一份快照又把它加回来 → **死循环占用整理配额**，真正的背包内低质件（例如 215601 破甲长枪 lv0 品质6、215701 长棒）反而**永远不会被丢**（因为它在 `quality<6` 里不成立）。

## 5. C 建议（按优先级）

> 原则：先修"反着丢/空转"（避免继续产生数据污染与日志噪音），再补齐"判据"和"收益"，最后做新增能力。

### P0-1 修复丢弃位置过滤（1 行级改动，收益立竿见影）
- **做什么**：`_try_bag_cleanup` 丢弃前加 `bag_ops._is_in_bag_pos(item)` 判断（`item[2]` 需在 0x2000~0x2fff），并对 `daily_ghost.__tidy_bag` 同样加位置过滤（`quest.bag` 结构里没有 pos，可从 `m_bag_cache` 取）。
- **改哪**：`RB/auto_summon.py:484-492`；`RB/daily_ghost.py:2254-2278`（改用 `m_bag_cache` 的 `[item_id,count,pos]` 或加一个 pos 映射）。
- **预期收益**：消除 417 空转（当前全天 1453 次尝试 → 0）、整理配额回到真正能丢的物品、日志可读。
- **风险**：低。若 `pos` 解析不到（`None`）按现在的保守语义跳过即可（不会误丢）。

### P0-2 统一"好坏"判据，并修正丢弃阈值方向
- **做什么**：定义唯一 `equip_score(slot, item)`：**优先 lv（元素等级）→ 其次模板 item_level → 最后品质**；丢弃条件从"品质 < 6"改为"**比当前已穿/最优差**（同部位）"，与客户端 `DROP_ITEM_QUALITY=1`（只丢废品）保持兼容：默认只丢"废品 + 明显更低 lv"的件。
- **改哪**：抽一个公共函数（建议放 `RB/bag_ops.py`，供 `auto_summon`/`daily_ghost` 共用）；`RB/config.py:187-190` 的注释同步纠正（"调 1=只丢废品"）。
- **预期收益**：不再丢掉 213xxx/223xxx 这类 lv3 好装备；不再保留/穿上 lv0 白装；与用户"用好的丢坏的"目标一致。
- **风险**：中。判据变更会让现场背包构成变化（白装开始被丢），需先跑单号观察 1~2 个 session（`BAG_QUALITY` 诊断行已经在打，可直接对比）。

### P0-3 已穿戴/锁定/条件三重保护
- **做什么**：丢弃前统一走一个 `_can_drop(item, meta)`：① 位置∈背包；② 非锁定（已有）；③ 非当前已穿；④ 满足 `ITEM_CAN_DROP`（`CFG/item/item.xml` 的 `item_can_drop`，可加进 `client.g_item_data_dict`）。
- **改哪**：`RB/bag_ops.py`（新增）+ `RB/auto_summon.py:484` + `RB/daily_ghost.py:2254`。
- **预期收益**：与客户端 `try_drop_item`（先判锁）语义对齐，杜绝无效请求。
- **风险**：低。

### P1-1 用"卖出"替代"丢弃"（有银两收益）
- **做什么**：优先 `C2S_SELL_MALL_ITEM(80180)`（商会出售，需要 NPC/商会面板上下文）或 `C2S_UP_SELLER_ITEM(80236)`（摆摊，需先 `C2S_SELLER_START_BOOTH`）；拿不准时退回丢弃。先做"到商会 NPC 一次性卖掉全部白/废品"的最小闭环。
- **改哪**：新增 `RB/bag_ops.py` 的 `try_sell_junk()`；服务端入口 `SV/item/item_dispatcher.py`（商会）/ `SV/item/item_operator.py`（摆摊上架）。
- **预期收益**：清理背包同时产生银两；避免"丢弃"被误判为破坏性行为（GM/风控视角更自然）。
- **风险**：中高（需要导航到商会/摆摊 NPC + 商店面板对话解析，参考 `daily_ghost` 的药店购买流程 `RB/daily_ghost.py:1512-1550` 的成熟做法）。

### P1-2 内丹线打通（性价比最高的一条"能力线"）
- **做什么**：把背包里的内丹（`related_element_index == summon_innerpill_common` 或 `item_class==内丹`）用 `C2S_SUMMON_USE_ITEM(80098) [summon_id, item_id]` 装给出战守护；把"内丹确认对话"识别为**可推进对话**（选项文本"是的，我确定"→ 应点选项而不是关闭）。
- **改哪**：`RB/auto_summon.py`（新增 `_try_equip_pill`，挂到 tick 第 6 步）；`RB/quest_engine.py:650-676` 的引导关键词表加"确定/是的/服用"。
- **预期收益**：现场号背包里长期躺着的 150401 等内丹开始产生战力；同时消除 1268 提示码循环（3316 次）。
- **风险**：中（要区分"绑定内丹会绑定守护"的分支；建议先只处理非绑定的 step2/step3 路径）。

### P1-3 孵化线打通（分两段，先段后段）
- **做什么**：
  - 段一（低风险，立即可做）：把坐骑蛋对话识别为**可推进**，点"放置到人物装备栏"（step4 = `action_equip_item`），并校验结果（`物品位置` 里蛋进 4108/五行珠位）；**不**要求后续打灵气。
  - 段二（需链路）：把"到半月岛打 N 场暗雷战斗"做成一个**独立小任务**（导航到 `mount_hatch_place` → 触发若干场战斗 → 检查 `COOKIE_EGG_PNEUMA/灵气` 到位 → 自动孵出）；或直接选"花费50金直接孵化"（`MountDirectBirthAction`，代价 500000 金钱、无需打怪），一次性可验证。
- **改哪**：`RB/quest_engine.py:650-702`（对话分支）；新增 `RB/mount_egg.py`（或并入 `auto_summon`）；配置 `RB/config.py` 加开关（如 `robot_hatch_egg_mode = "direct" | "agility" | "off"`）。
- **预期收益**：坐骑可用（`C2S_START_MOUNTED`），且孵化本身是"真实玩家行为"，拟真度更高。
- **风险**：段一中；段二高（跨图 + 暗雷触发不可控）。**建议先做"直接孵化"验证全链路**，再评估灵气路线。

### P2-1 恢复药补"战斗中吃药"
- **做什么**：在 `fight_tester.__send_bout_commands` 里，当自身血/法低于阈值且背包有药时，发 `C2S_FIGHTCMD [1, 5, target_index, item_id, 0]`（指令号 5 = `FIGHTER_CMD_USEITEM`）替代/补充攻击指令。
- **改哪**：`RB/fight_tester.py:36-56`；血量来源已有（`m_cur_hp/m_max_hp`）。
- **预期收益**：抓鬼/剧情战斗死亡率下降（现在只在战斗外补血）。
- **风险**：中（指令参数需实测；建议先用单个号抓包比对）。

### P2-2 整理逻辑分类收敛（消除无效协议）
- **做什么**：`__tidy_bag` 的"其它 → 当消耗品用"改为**白名单制**：只对已知"人物可用"的消耗品（礼包关键词、buff 卡列表、`use_on_role != no`）发 `C2S_USE_ITEM`；对守护/宠物/坐骑专用（`use_on_summon/use_on_role=no`、内丹、技能书、口粮）跳过。
- **改哪**：`RB/daily_ghost.py:2276-2283`。
- **预期收益**：消除 1268/内丹对话等无效往返与对话干扰。
- **风险**：低。

### P3-1 穿衣判据升级为"属性打分"
- **做什么**：在 lv 之后加入 `item_level`、品质、耐久、是否神兵等权重（数据都能从 RB 的 `client.g_item_data_dict` / `xml/item.xml` 拿到，模板里还有 `item_use_condition`）。
- **改哪**：`RB/bag_ops.py:180-199` → `equip_score()`。
- **预期收益**：更接近"用好的"。
- **风险**：中（权重需要现场对照，建议先记录不改变行为，观察一周）。
