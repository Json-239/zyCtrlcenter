# 分析-20260922：采集（挖矿/采集）实测探针

## 一、为什么要探针

服务端**采集链路是完整的**，但**采集点 NPC 的模板号未知**（`config/gather/gather.xml` 只声明了
11 张图 245 个**区域**，采集 NPC 由服务端在区域里动态刷新），并且"点击 → 吟唱 → 完成"的
时序与产出方式必须**实测**才能确认。探针就是把这个未知量用最小代价问出来。

## 二、探针怎么用（已实现，默认关闭）

**文件**：`script/gather_probe.py`（新）+ `main_tester.py` 里一个 additive 钩子（每号每帧调用）

**开关**（`script/config.py`，两份都有；**默认全关**）：

```python
robot_gather_probe_account = ""      # 空=关闭；填一个账号 → 只对该号生效
robot_gather_probe_click   = False   # False=只发现（扫模板号）；True=走去点一次 + 产出对比
```

**生效方式**：热更 `config` + `main_tester` + `gather_probe` 三个模块（**无需重启**）。

**日志关键字**（`script/diag.log`，也可以在中控"运行日志"看该号）：

| 关键字 | 含义 |
|---|---|
| `GATHER_PROBE_SCAN` | 每图一次：当前图是否采集图 + 该号见过的 NPC 模板号 + 可疑候选 |
| `GATHER_PROBE_SKIP` | 非采集图 / 采集图但没刷出可疑采集点 |
| `GATHER_PROBE_CLICK` | 已发起"走去点击"（npc_id / tpl / 坐标 / 点击前背包条目数） |
| `GATHER_PROBE_RESULT` | **结论行**：背包 前/后/增量 → 产出入包 ✓ 或 无产出（需继续排查） |

**安全边界**：只对指定号生效；抓鬼/游荡激活时**不抢操作**；单次触发不循环；异常只记日志。

## 三、实测步骤（主控执行）

1. 挑一个在**采集图**上的号（图 10 大唐东-野林 / 6 半月岛 / 17 女儿国 等都行）；
2. 停掉它的抓鬼（`POST /api/robots/batch {"action":"stop"}` 或面板"停止"）→ 让它空闲；
3. 填 `robot_gather_probe_account=<该号>`、`robot_gather_probe_click=True` → 热更 `config/main_tester/gather_probe`；
4. 观察 5~10 分钟：
   - 先看 `GATHER_PROBE_SCAN`：**该图有哪些 NPC 模板号**（这是要抓的第一手数据）；
   - 若出现 `GATHER_PROBE_CLICK` → 看 6 秒后的 `GATHER_PROBE_RESULT`；
5. 拿到结论后**把两个 config 项清空/关掉**并热更（保持默认关闭）。

## 五、已知风险与回退

- **抢操作**：探针会让该号走去点 NPC（`click=True` 时）→ 只用于**单个号**的实验窗口，验证完立即关闭；
- **跨图导航**：复用 `pre_daily` 的导航封装（`_ensure_npc_pos` + `_route_precheck`），无路径时记 `GATHER_PROBE_CLICK 无路径` 并放弃；
- **看不到报文序列**：探针以"背包增量"为判据（不碰 `client.py`/`msghandle.py`）；若"无产出"，需要再用别的手段抓报文（另开任务）；
- **回退**：`robot_gather_probe_account=""` 即完全停用（热更 config 即可）。
