## 2. 根因链（daily_ghost.py，改动前行号）

1. **判据"任务可能已过期"** → 决定去放弃：`WAIT_GHOST` 等刷鬼 30s/轮，`g.rounds >= 6`（约 3 分钟无鬼）
   且本地有打鬼任务 → `g.abandon_task = True` + 回钟馗（原 3471–3481）。
2. **被拒只降频、无出口**：点"放弃捉鬼任务"后 60s 无 `S2C_DROP_TASK` → `__note_abandon_nodrop`
   记 `abandon_fail_seen += 1`（694 附近）；`__should_skip_broker_abandon`（710）只让它
   "原地换图再等"最多 2 次（`ghost_wait_extend < 2`），**用满后每次 6 轮必然再回钟馗 → 又被拒**，
   无限循环。
3. **缓存恢复把同一任务反复装回**：`abandon_tries >= ABANDON_FAIL_LIMIT(2)` 后，
   `on_show_dialog` 的"已有任务菜单"分支改走 `__recover_task_from_cache`（1077），
   而 `_TASK_CACHE` 有效期 30 分钟、每轮循环仅 5~8 分钟 → 缓存总是"新鲜"，
   **同一个不可完成的任务在本地↔缓存间来回装**，永不释放。
4. **服务端为什么不刷鬼**：任务目标图（如 25）多轮无鬼（日志中"等刷鬼"期间从未出现
   "发现鬼 NPC"），而"放弃"又被服务端按 `20195.xml: action_ticket_drop_task.money_count=500`
   拒（号上银两只几十~几百）→ 该任务在本会话内**不可完成**。

**收敛点**：既然"放弃被拒"与"目标图无鬼"都是既成事实，应在**本地判该任务不可完成并停止空转**，
而不是无限重试两条都走不通的路。

## 3. 出口设计（最小改动、幂等、有观测）

### 3.1 判据 `__should_leftover_stop`（718）

```
放弃被拒已成事实: 本会话 abandon_fail_seen >= GHOST_LEFTOVER_FAIL_MIN(2)
  且 连续无鬼够久:  本会话 no_ghost_rounds   >= GHOST_LEFTOVER_ROUNDS(12 轮 ≈ 6 分钟)
  且 未冻结过:      not leftover_stop（幂等）
```

### 3.2 出口 `__enter_leftover_stop`（728，幂等只做一次）

- **保留**本地任务与 `_TASK_CACHE`（与服务端状态一致，不制造"本地无记录"→ 点放弃/缓存恢复的新循环）；
- 清动态导航/对话（不再巡逻/换图/回钟馗往返）；
- 置 `DONE` 停状态机推进（tick 顶部 `DONE` 直接 return）；
- 上报一次 `{"type":"error","code":"GHOST_LEFTOVER_TASK", task_index, abandon_fail_seen,
  no_ghost_rounds, done, limit, msg}` + 明确 warn 日志（含"停止空转"）；
- 解除方式：重登 / 中控重新下发 `ghost_start`（`reset()` 清标记）；服务端清了任务也一样。

### 3.3 计数与清零

- 累计：`no_ghost_rounds += 1` 在等刷鬼超时处（3510，独立于会回退/清零的 `g.rounds`）；
- 清零：发现鬼（3417）/ 换新打鬼任务、交付任务到达（`on_add_task` 1794）/ 抓鬼完成（`on_finish_task` 1852）/
  放弃成功（`on_drop_task` 1921）；
- **缓存恢复处不清零**（同一任务装回 = 无进展，否则出口永不触发）。

### 3.4 与既有路径的关系

出口位于 `WAIT_GHOST` 的 `rounds>=6` + `_has_hunt` 分支内、**降频闸之前**（3533 < 3541）：
先判出口 → 否则走既有"降频闸（不回 24）→ 回落（回 24 放弃）"路径，原逻辑逐字保留。
被拒记忆清理（`on_drop/on_finish`）原文保留，正常号行为不变。

## 5. 评估

- **收益**：两天 **207 个号**将在第二圈（第 2 次被拒后）停止空转；省下 **1123 次被拒**
  及其伴随的"回 24 往返"（约半数，≈560 次 × 5 银 ≈ 2800 银 + 8 分钟/次）与"换图巡逻"空转；
  被命中号的"等刷鬼 6 轮"检查点合计 6432 次（旧逻辑的循环量）。
- **对新手链**：<31 级号（如 robot0005232，等级 30、意图 newbie）不再被残留抓鬼任务占住；
  出口停抓鬼后，中控可将其派往新手链。
- **≥31 级号**：停止空转（不再"有任务在跑"的假象），等中控按事件处置（停链/换号/重登）。
- **风险面**：
  1. 阈值误伤：需要"被拒 ≥2 次"（服务端明确拒绝，重试同样失败）叠加"连续无鬼 ≥6 分钟"，
     且发现鬼/换新任务/交付完成即清零 —— 正常号不受影响（反例回归）。
  2. 冻结后号"趴着不动"：若中控完全不处理，号停在 DONE（但比现状的空转/烧钱/刷屏好）；
     重登/重新下发即恢复。
  3. 中控若反复拉起：每轮约 6 分钟后再次冻结+上报（1 事件/轮），噪声可控。
