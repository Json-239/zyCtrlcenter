## 1. 服务端机制（源码级）

- 开摊 `C2S_SELLER_START_BOOTH(80170)` → `seller_start_booth`（`script/booth/booth_operator.py:50`）：
  1) 自己已有摊位 → `NOTICE_ALREADY_IN_BARGIN`；2) `can_operate_booth` 为假 → **静默 return（无 notice）**；
  3) 等级 < `BOOTH_LEVLE_LIMIT`(50) → 等级 notice；4) **色块判定失败 → 1191**。
- 上架 `C2S_UP_SELLER_ITEM(80236)`（`:159`）：查物品在背包/未锁/可交易/未重复/≤20 件，成功回 `90059`。
- 收摊 `C2S_SELLER_CLOSE_BOOTH(80070)` → 广播 `90109`；上架**不消耗物品**，收摊不消耗。
- 移动/位置协议在 C++ 层：`C2S_ROLE_MOVE(80301)`（存路径+按首点定位）、`C2S_REPORT_POSITION(80360)`
  （`server/game/logic/py/cpy_call_logic.cpp:71,150` → `role_object.cpp:591` `role_report_pos`）——
  只做地图边界检查（越界丢弃），**不校验阻挡**，位置=客户端上报（client-authoritative）。

## 4. 操作要点与坑（复现用）

1. **计划热切换，无需 reload**：booth.py 已加载时，改写 `script/booth_selftest.json`（新签名）即触发
   下一轮激活；`run` 序号建议递增。停用=置 `enabled:false` 或删文件。仅当机器人进程重启后
   需 `POST /api/robot/reload_scripts {"modules":["booth"]}` 复位 `main_tester._BOOTH_MISSING`。
2. **起点阻挡格缺陷（本次踩坑）**：`(3864,2647)` 等"真人摆摊点"常标在阻挡格；机器人停在该处后，
   下一段 GOTO 由阻挡格起步 → `find_path` 返回 None → 直接 `GOTO_no_path` 失败（**无起点侧兜底**）。
   规避：先用一个"可走格"计划跳一步（直线兜底 ≤800px 可走），再执行长走。建议后续给 `_walk_step`
   加起点侧兜底（对齐 `quest_engine.__walk_start_connect_fix_cell`）。
3. **水位保持器会压"游荡中"的号**（`prefer_idle` 口径只压 `Pressable`=游荡中；实测 18:27:52 把
   roaming 的 1032 连同 3 个号一起压下线）。**paused(人工暂停) 豁免**——实验顺序必须是
   `robots/manage add`（上线，会清 paused）→ 再 `POST /api/stop`（打 paused 标）。
4. 落点精度：A* 落点=**格中心**（±8 游戏单位），选点需按格心核算颜色并留 ≥2px（20 单位）边距。

## 5. 可摆点清单与生成方法

实测已接受点（map11）：
- **(1385,1545)**（落点 1384,1544）—— 全流程已验证
- **(3155,1555)**（落点 3160,1560）—— 全流程已验证

生成更多点（工具已入库）：
```
python tools/booth_candidates.py --bmp "<...>/config/map_file/boothfile/cad_booth.bmp" \
    --margin 2 --grid-json grid11.json --limit 50
# grid11.json = GET http://127.0.0.1:28082/api/map/grid?mapid=11
```
口径：遍历寻路格心 → 要求格心像素非白且 ≥margin 边距 → 可选只保留可走格。
map11 当前（walkable+margin≥2、排除真人点 600px 内）候选 **1977 个**；输出中已包含上述两个实测点、
且不含已否定的白点。
其他地图同理（`caz_booth.bmp`=map12 长安中、`dhyc_booth.bmp` 等，见 `config/map.csv` 第 10 列）。

## 6. 遗留问题与建议

1. **真人点 (3864,2647) 异常**：同一坐标生产对 1032 判白（两次 1191），但真人当日在此开摊成功
   （90009 广播 4 条，无 90109 收摊）。本地/客户端两副本该点均为白。启用在规模化之前，建议把
   **服务端在用的摆摊色块图重新导出并与本地副本核对**（本机副本可能滞后于此前的配置变更）。
2. **(1416,1112) 复测**：历史两轮"静默无 notice"拒绝（发生在 notice 记录修复前，见 6fc1e23），
   但该点本地为**非白**。修复后未复测；建议上线批量摆摊前用一次实证确认其为非色块原因（restrict 等）。
3. **booth.py 起点侧兜底**（§4.2）建议补齐；另建议给 `GOTO_no_path` 场景加"自动先跳到最近可走格"
   的一次性重试。
4. 摆摊经济/离线摆摊/50 级门槛等背景见《分析-20260924-机器人摆摊实现方向.md》。
