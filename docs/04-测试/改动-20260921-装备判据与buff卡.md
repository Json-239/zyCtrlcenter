## 一、现场证据：本服品质号与装备好坏反向

模板口径（`item.xml`）：`related_element_index` 里的 `lvN` 是**装备等级**，`item_quality` 是**品质号**。

| item_index | 名称 | related_element_index | lv | item_quality(品质号) | 实物 |
|---|---|---|---|---|---|
| 213604 | 螺旋枪 | `element_weapon_a_lv3` | **3** | 4 | 好武器 |
| 223304 | 玄铁盔 | `element_head_a_lv3`(同类) | 3 | 4 | 好防具 |
| 225101 | 粗布衣 | `element_body_a_lv0`(同类) | **0** | 6 | 新手白装 |
| 225601 | 贝壳项链 | `element_neck_a_lv0` | **0** | 6 | 新手白装 |

生产日志（`single_robot_zy/script/diag.log`）：
`BAG_QUALITY ... [(213604, 4), (223304, 4), (225101, 6), (225601, 6)]`
—— 品质号 6 的是白装、品质号 4 的是好装，**"品质号高 = 好"在本服不成立**。

### 旧判据的三重伤害（本次修复对象）

1. **反着丢**：`auto_summon._try_bag_cleanup` 按 `quality < 6` 丢 → 好装备（q=4）全中招，
   白装（q=6）反而留着。现场日志：`丢弃低品级装备 213904(品质4<阈值6) ret=16`。
2. **丢到已穿戴**：丢弃遍历 `m_bag_cache`（含**装备栏**物品）且未过滤 `pos`，命中的往往是
   身上正穿的 → 服务端一律回 `ret=16 / notice 417「丢弃物品不在包内」`。
   中控日志全天 **1453 条**"丢弃低品级装备"尝试，全是无效请求。
3. **穿/丢两套判据打架**：穿装备走 `bag_ops` 的 lv 判据（正确），丢弃走品质判据（错误）→
   "穿上 → 被丢（或被拒）→ 下一轮快照再穿"。
   另发现：`bag_ops.auto_equip_best_items` 的旧丢弃行参数写成 `_it[1][0]`（`_it` 是 item 列表，
   `[1]` 已是数量），**TypeError 被 `except` 静默吞掉，这条丢弃路径其实从未生效过**
   —— 本次一并修正为 `_it[0]`（实例 item_id）。

## 二、统一方案：判据只有一份，在 `bag_ops.py`

### 2.1 打分与比较（唯一实现）

| 函数（`bag_ops.py`） | 作用 |
|---|---|
| `parse_equip_lv(rel)` L204 | 从 `related_element_index` 抽 `lvN`（纯函数，可自检），抽不到=0 |
| `_get_equip_lv(item_index)` L219 | 从模板 `client.g_item_data_dict` 查 lv |
| `meta_quality(meta_entry)` L232 | 取实例品质（`m_bag_meta['quality']` = `ATTR_DATA[ITEM_QUALITY]-QUALITY_WASTE`），未知=None |
| `equip_score(item_index, meta) -> (lv, quality)` L244 | **统一打分**（穿/丢/比较都走它） |
| `score_gt(a, b)` / `score_lt(a, b)` L249/L259 | 比较：lv 大者优；lv 相同且双方 quality 已知时比 quality；**quality 未知不优也不劣**（保守） |
| `collect_best_equipped(...)` L273 | 已穿戴（装备栏 `0x1000~0x1100`）每部位最优 → 换装/丢弃的比较基准 |
| `should_drop_equip(...)` L304 | "丢坏的"判据（不含 pos/锁定/白名单过滤，调用方先做） |

### 2.2 规则表

| 动作 | 规则 | 位置 |
|---|---|---|
| **穿** | 同部位"背包里最好的"**严格优于**"已穿的最好的"（lv 高；或 lv 同 quality 高）才穿；只发背包物品，**绝不对已穿戴(装备栏)物品发任何消息** | `bag_ops.auto_equip_best_items` L348 |
| **丢** | ① 只丢"确定在背包里"（`pos ∈ 8192~12288`）的；装备栏/包裹栏/pos 未知一律不丢；② 同部位有在穿：比在穿的差（lv 更低；或 lv 相同且 quality 更低且 `< robot_drop_item_quality`）才丢；③ 同部位没穿：只丢 `lv==0` 白装；④ 锁定 / 助战令(190146) / 金创药(102007) / 昙花霜(102010) 不丢 | `bag_ops.should_drop_equip` + `auto_summon._try_bag_cleanup` L493 / `bag_ops.auto_equip_best_items` |

`robot_drop_item_quality`（config，默认 6）语义更新：**只作"同等级下的品质下限"辅助**
（同 lv 时 `quality < 对方 and quality < 本值` 才丢），不再单独决定丢弃。

### 2.3 新旧判据对比（用现场四个样本）

| 场景（背包中该件） | 旧判据 | 新判据 |
|---|---|---|
| 213604 螺旋枪 lv3/q4，同部位在穿 lv0 白装 | 丢（q4<6）**丢好装** | 换装（穿上），不丢 |
| 213604 螺旋枪 lv3/q4，同部位在穿 lv3/q6 | 丢（q4<6）**丢好装** | 不换装、不丢（比在穿差才丢，q4<q6 且 <6 → 丢；见注） |
| 225601 贝壳项链 lv0/q6，同部位在穿 lv3 | 留（q6≥6）**留着垃圾** | 丢（lv 0<3） |
| 225601 贝壳项链 lv0/q6，同部位没穿 | 留 | 丢（lv==0，白装） |
| 身上正穿的任意装备 | 可能被丢 → 服务端 ret=16 | **一律不丢**（pos 过滤） |

注：同 lv 比 quality 是用户口径；若现场发现"同 lv 下 quality 反向"（未观察到），把
`robot_drop_item_quality` 调 0 可退化为"只按 lv"。

### 2.4 数据链路补齐（pos）

`m_bag_cache` 之前只有 `[item_id, count]`（无位置），丢弃无法区分背包/装备栏。
现改为 `[item_id, count, pos]`（`quest_engine.__item_pos` L1822，`on_bag_full` L1854 /
`on_bag_add` 同步），丢弃判定以条目第 3 元素为准；取不到 pos → 不丢（保守）。

### 2.5 日志（便于现场核对，带 lv/quality）

- `穿装备 213604(lv=3 quality=4, 部位=weapon_a)(替换原 lv=0 quality=6)`
- `丢弃多余装备 225601(lv=0 quality=6, 部位=neck_a)`（bag_ops 路径）
- `背包整理: 丢弃多余低等级装备 225601(lv=0 quality=6) ret=0`（auto_summon 路径）

## 三、buff 卡（畅享服务卡）恢复 + 称谓处理

1. **config 恢复**：`robot_use_buff_items = [190016, 190018, 190033, 190039]`（原清单，2026-09-03
   停用注释保留，并追加 2026-09-21 恢复说明）。
2. **称谓问题复用既有机制**：用卡后角色显示称谓会被卡 buff 顶成 9008"畅享尊贵"。既有的
   `msghandle.title_load_handle`（登录切常规等级称谓）本次抽成公共函数
   **`msghandle.change_to_normal_title(robot_object, pairs, owned)`**（L424），登录路径改调它，
   行为不变（候选=已拥有里 `0<idx<1000` 且名称不含 `$` 的，按账号 md5 哈希固定选一个；
   没有候选不发）。
3. **用卡后延迟切回**：`auto_summon._try_bag_cleanup` 用卡成功后调用
   `_schedule_title_restore`（L461）安排 **2s / 8s 各一次**，由 `_try_title_restore`（L470）
   在空闲 tick 到点执行 `change_to_normal_title`（复用登录时缓存的已拥有称谓）。
   失败（无候选/异常）只记 warn，不阻塞任何链路；时间点用完即清空。
4. 若服务端在用卡后**重发** `S2C_LOAD_TITLE`，登录路径会再切一次常规称谓（双保险）。

## 五、测试与回归

### 5.1 新增源码级自检 `tools/equip_criteria_selftest.py`（54 项，两份副本各跑一次全 PASS）

- 打分/比较：`lv3q4 > lv0q6`（品质反向不误判）；同 lv 比 quality；quality 未知不优不劣。

  反证：已穿戴 lv0 白装若无 pos 过滤会被判丢（证明过滤是必要闸门）。
- 动态（提取真实函数执行 + fake 运行时）：
  A 在穿 lv3 + 背包 lv0 → 只丢白装、不换装、在穿件零消息；
  B 在穿 lv0 + 背包 lv3 → 换装（USEITEM 背包 item_id）；
  C 同 lv 在穿 quality 更高 → 不换装、丢低品质件；
  D 只含装备栏物品 → 零发包；E 追捕令 110173 仍丢（旧行为保留）；
  F/G/H auto_summon 路径：背包白装丢 / 装备栏白装不丢 / 助战令·药品·锁定全不丢；
  I 用卡 → USEITEM + 安排 2 次称谓还原；J 到点各执行一次、执行后清空；
  称谓：排除 9008 选常规；只有 9008 不发；用卡后不传参复用缓存。

## 六、部署后须知（主控热更口径）

1. **热更必须带 `config.py`** —— buff 卡恢复（`robot_use_buff_items`）在 config 里；其余 4 个文件
   至少带 `bag_ops.py` + `auto_summon.py`（判据与丢弃过滤），`msghandle.py` + `quest_engine.py`
   是同批依赖（称谓函数、pos 缓存）。
2. **"丢弃低品级装备"日志应从 1453/天 大幅下降**：新判据只丢"确定在背包里且确实比在穿差/无在穿 lv0"
   的多余装备；正确丢弃会打 `丢弃多余装备 ...(lv=.. quality=..)` 或
   `背包整理: 丢弃多余低等级装备 ...(lv=.. quality=..)`，不再有 `ret=16`（因为不再对已穿戴物品发包）。
3. **首次热更后可能集中补丢一批历史白装**（lv0 且无更好在穿）：每次 tick 只丢 1 件、冷却 3s，
   速率有限，属预期；可看日志逐件核对 lv/quality。
4. **穿戴回归观察点**：出现 `穿装备 xxx(lv=.. quality=..)` 即换装生效；若某部位反复穿同一件
   （服务端拒绝或部位不符），看服务端 notice（417/16）与 `pos` 值。
5. **buff 卡**：热更后空闲号会用卡（每号背包里的 190016/190018/190033/190039 各用一次），
   日志 `背包整理: 使用buff道具 190016(畅享服务卡等) ret=0`；2s/8s 后应看到
   `buff卡称谓还原: 显示称谓 -> 3(常规等级称谓)`。若服务端把显示顶回 9008 的时间晚于 8s，
   会把该号定格成 9008 —— 届时把 `_TITLE_RESTORE_DELAYS_MS`（auto_summon.py）再加一档即可。
6. **回滚**：直接用两份副本的 `*.bak_20260921l` 覆盖回去（config 需按环境差异单独处理）。

### 已知边界 / 未做

- **未改** `daily_ghost.__tidy_bag`（抓鬼腾格子链路，按 item meta 的 level 判断）：其白名单
  （助战令/金创药/昙花霜）本次在新判据里同样保留；两条链路互不冲突。

- quality 未知的装备：不换、不丢（保守）；`pos` 取不到的：不丢。
- 同 lv 下 quality 的比较依据用户口径（本服未观察到同 lv 品质反向的样本）；如需更保守可把
  `robot_drop_item_quality` 调 0（退化为只按 lv）或调高（收紧同等级丢弃）。
- 孵化/内丹/卖出等其它背包业务未动，见 [分析-20260921-背包物品与装备品质.md](分析-20260921-背包物品与装备品质.md) 第 0 节结论速览。
