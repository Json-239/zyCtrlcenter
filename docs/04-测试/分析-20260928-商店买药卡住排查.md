### 1.3 C 类细节（最大量级，00:00-10:00 为主）

**典型一轮（robot0005072，每 ~65 秒重复；全天 557 轮）：**

```
血量过低 1362/12840 且无背包疗伤道具, 走 shop_errand 买药        ← daily_ghost 认为没药
商店采购: 去NPC 13011 买 item_index=102007 ×13(空闲自动补食物)
买药启动: item_index=102007 ×13(现有 187), 走 shop_errand        ← 同一秒，另一函数读到 187 个！
点击NPC → 对话 → 商店数据到达
商店采购: 已满足, 未购买(item_index=102007 背包已有 ×187 ≥ 请求 ×13)   ← 执行器认为有药，跳过购买
买药完成但背包无药(延迟/其它流程), 60秒冷却                        ← 复查又"没药"，冷却 60s
```

**同一秒内两个函数的判定互相矛盾**（"现有 187" vs "无背包疗伤道具"），根因在两条读取实现不一致：

| 函数 | 位置 | 回退逻辑 | 结果 |
|---|---|---|---|
| `daily_ghost.__bag_item` | daily_ghost.py:1166 | **仅当 m_bag_cache 整体为空**才回退 quest.bag | m_bag_cache 非空但缺 102007 → 返回 None（"无药"） |
| `shop_errand.bag_count` | shop_errand.py:358 | m_bag_cache **缺该键即回退** quest.bag | 读到 quest.bag[102007]=187（"有药"） |

后果链：血低 → `__need_heal_item` → `__bag_item` → None → 发起买药 → 执行器 `__bag_count_of` → 187 ≥ 13
→ 报"已满足"（notify_done(skipped=True)，quest_engine.py:2288-2296）→ daily_ghost 复查（还是 `__bag_item`）仍 None
→ 打"买药完成但背包无药"（daily_ghost.py:1296）→ **60 秒冷却后重来**。
**用药也走 `__bag_item`（daily_ghost.py:1180 `__use_heal_item`）→ 有药也用不上 → 血全天停在低位（1362/12840）**。

**自愈方式**：重新上线/缓存重建后恢复。robot0005072 在 11:24:30 重新上线，11:26-12:01 出现 7 次
"用背包道具疗伤"（用药成功），随后脱离循环进入正常 NAV——**非修复，只是状态重置**。

| 类型 | 卡点 | 证据 |

## 6. 修复建议（按优先级）

### P0-0 统一背包读取（修 C 类，收益最大）
- 方案：删除 `daily_ghost.__bag_item` 的独立实现，全模块改调 `shop_errand.bag_count`（或抽公共函数），
  保证"是否有药/用药/已满足判定"永远同源同值；
- 最小改动版：`__bag_item` 的 miss 回退逻辑对齐 `bag_count`（**m_bag_cache 缺该键 → 也回退 quest.bag**）；
- 加固：当出现"执行器已满足（有药）×N" 而 `__need_heal_item` 仍说无药时，**直接上报 ERROR（数据不一致）**，
  不得进入 60s 冷却循环；并打印两处读数以便定位。

### P0-1 买前余额闸 + 按余额降量（修 A 类）
- 落点：`shop_errand.start()`：读 `robot_object.m_reserve`；`reserve < price×count` 时
  `count = min(count, max(0, reserve//price - 1))`；`count < 1` → 返回 `{"ok": False, "result":"no_money"}`（不占锁）；
- daily_ghost 收 `no_money` → 长冷却（30 分钟）而非 60 秒。

### P0-2 552 即时失败回传（修 A 类空等）
- 落点：`quest_engine.on_shop_notice_args` 失败分支补 `shop_errand.notify_rejected(...)` +
  `notify_failed(robot_object, "被拒:%s" % _why)`；daily_ghost 1 秒内即可结束本轮。

### P0-3 失败升级/节流（与 P0-2 必须同批，否则循环只会变快）
- C/A 同因连续 ≥2 次失败 → 冷却指数升级 60s→300s→1800s；或"仅当 m_reserve/背包数变化才允许重试"。

### P1 穷号治理（需用户决策）
- 23 个穷号（附录 A）：发储备金 / 移出抓鬼池 / 改派能赚钱的日常，三选一。

### P1 B 类超时
- 买药超时改动态（按跨图跳数/距离），或超时后**保留导航进度**（不清上下文，下一轮就地继续）。

### P2 数量策略
- 单批 ≤20~50 或"首单 1 个探活再补量"（呼应 09-23 调研）；水位 200 意图保留（多次累计）。

### 验证方法
1. **自检脚本**（新增 `tools/shop_afford_selftest.py`）：
   - `reserve=31167, price=211, want=200` → 断言降量 147 且发起；
   - `reserve=100` → 断言 `no_money` 不占锁、不产生重试循环；
   - 桩对象模拟"m_bag_cache 缺键 + quest.bag 有货 + 552/已满足" → 断言两函数同值、fail-loud 上报；
2. **现场锚点**：`tools/shop_stuck_scan.py` 复跑，关注"无药空转"与"552"两列停增；
   新日志"储备金不足，暂缓买药(30分钟)"、"已按余额降量买 N 个"；
3. **冒烟**：`POST /api/shop_errand`（已存在）对 5243 下 50 个（10550<31167）应成功；对 5097 下 50 个应**快速失败不循环**；
