## 〇、结论速览

- hqm 拿在线人数的方式：**PHP 后台直接 HTTP GET 游戏服的 `/gm/online?serverId=<区号>`**
  （`GMApi::onlineCount`），返回 `{"online_count":N,"success":true,"serverId":1000}`。
  **无任何鉴权头**——不需要 `admin_license` 的 GM 授权；实测本机测试服 `192.168.0.201:8080`
  裸 GET 即可拿到（见第三节原文）。
- 同族接口：`/gm/robotOnline`（机器人数，90 秒心跳且账号名 `robot` 前缀）、`/gm/onlineList`
  （在线玩家列表，含 uid/username/last_heartbeat），用于"净真人"与名单同步。
- **已落地**：中控新增直连数据源 `internal/services/livecount/`（默认关闭），启用后写进
  `/api/status.svr_online`（`source=svr_provider`），水位保持器**零改动**即可用；
  失败/过期自动回落 `@online` 回执 → 本地握手数。
- **需要用户配合**：生产服该 HTTP 端口当前**不可达**（`47.96.8.240:8080` 超时；
  `gateway.sanfenqiu.cn:8080` 同样超时），必须先确认/开通一条可达链路——见第七节（含可复制命令）。
- 改动**需重启中控生效**（本次未替换 exe、未重启任何进程）。

## 一、hqm 里"在线人数"的实现（文件:行证据）

### 1.1 取数库：GMApi（`app/admin/library/GMApi.php`）

```php
// L18：基地址，可被环境变量覆盖；默认指向游戏服 HTTP 服务
$this->baseUrl = rtrim($baseUrl ?: (string)env('GAME_SERVER_HOST', 'http://192.168.0.120:8080'), '/');

// L22-57 request()：拼 URL → CurlRequest::get(url, query) → json_decode
//   - **不附带任何鉴权头/签名**（只有 URL + query）
//   - 解析 {success, message} 包装（把 data 里的 JSON 拿出来）

// L136-143 在线人数
public function onlineCount(?string $serverId = null): array {
    $query = [];
    if ($serverId !== null) { $query['serverId'] = $serverId; }
    return $this->request('/gm/online', $query);
}

// L145-155 在线玩家列表（分页）
public function onlineList(int $page = 1, int $pageSize = 100, ?string $serverId = null): array {
    $query = ['page' => $page, 'pageSize' => $pageSize];
    if ($serverId !== null) { $query['serverId'] = $serverId; }
    return $this->request('/gm/onlineList', $query);
}

// L157-163 机器人数
public function robotOnline(?string $serverId = null): array {
    return $this->request('/gm/robotOnline', $query);
}
```

- HTTP 由 `app/common/library/CurlRequest.php` 发出（`get()` L82-88）：**空 headers**，
  超时 10s，跟随跳转，无鉴权。
- 同类库 `AgentApi.php:18`、`GameLogApi.php:27` 用同一个 `GAME_SERVER_HOST` —— 说明这是
  **整个后台访问游戏服的统一通道**。

### 1.2 接口定义（`api-docs.json`，项目自带的接口文档）

| 路径 | 摘要 | 返回示例（文档原文） |
|---|---|---|
| `/gm/online` | 在线玩家数量；参数 `serverId`（默认 1000，"统计该服 online_status"） | `{"online_count": 32}` |
| `/gm/robotOnline` | 查询该服机器人当前在线数量（最近 90 秒有心跳且账号名以 robot 开头的账号数） | `{"success":true,"serverId":1000,"robot_online_count":12}` |
| `/gm/onlineList` | 在线玩家列表（账号名取自共用账号库） | `[{"uid":10001,"username":"player1","last_heartbeat":"2026-08-05 10:00:00"}]`（新版为 `{total,page,pageSize,list}`） |
| `/gm/clearOnline` | 清空在线表（一般不需要） | — |

- 口径落点：`online_count` 统计的是**服务端在线表（online_status）**里该服的全部在线角色
  —— 含真实玩家也含我们/他们的机器人；机器人单独由 `/gm/robotOnline` 统计。
  **净真人 ≈ online_count − robot_online_count**（若将来要"纯真人"指标）。
- 多区：`serverId` 默认 1000（一区），1001=二区；未登记的 serverId **直接报错、不回落默认服**
  （`serverId后端接入修改文档.md` 第 3 条：游戏库按 `servers.<id>.game-db` 分服，防串数据）。

### 1.5 hqm 有没有"水位/保持人数"逻辑？

**没有自动化**。它能碰到的相关动作只有：
- `/gm/kick`（`GMApi::kick` → `GET /gm/kick?uid=`）——后台手工"踢人下线"，用于 GM 操作；
- `/gm/clearOnline`——清空在线表（"一般不需要"）。

**没有**"低于目标就补号/高于目标就压号"的闭环。对比我们：
| 能力 | hqm | 我们（zyCtrlcenter） |
|---|---|---|
| 读全服在线 | ✅ `/gm/online` | 现状 `@online` 回执；本次新增直连 provider |
| 读机器人数 | ✅ `/gm/robotOnline` | ❌（本次顺带解析字段，未用） |
| 在线名单 | ✅ `/gm/onlineList` + 定时同步 is_online | ❌（不需要） |
| 在线上/下线控制 | ❌（只有手工 kick 玩家） | ✅ 批量上下线 + 水位保持器（自动补号/压空闲号） |

结论：水位保持器是**我们自研的增强**，参考项目没有可直接抄的对照实现；本次只借用它的"取数通道"。

## 二、我们的现状（对照基线）

- 机器人端每 2 分钟用 `robot0001000` 发管理命令 `@online` → 服务端回"当前(<在线角色数>, 帧率, 战斗数)…"
  → 解析后随心跳上报 → 中控 `/api/status.svr_online = {count, ts, age_sec}`。
- 痛点：该命令需要服务端 `profile/admin_license.csv` 的 **DEPLOY/WIZARD 授权**
  （`GM指令文档.md:578`：`online` / `frame` ｜ DEPLOY/WIZARD ｜ `show_role_count`），
  **生产服还没授权** → 拿不到数（水位保持器只有本地握手数兜底）。
- 水位保持器（`internal/services/waterline/`）：默认关；数据源优先 `svr_online`（新鲜 ≤180s），
  过期用本地握手数；超目标优先断空闲号。

## 三、实测（2026-09-22，本机）

接口本身**不需要授权**（以下为原样返回）：

```bash
# ① 在线人数（标准形态；serverId 缺省=1000）
$ curl -s -m 5 "http://192.168.0.201:8080/gm/online"
{"online_count":0,"success":true,"serverId":1000}

# ② 机器人数
$ curl -s -m 5 "http://192.168.0.201:8080/gm/robotOnline?serverId=1000"
{"robot_online_count":0,"success":true,"serverId":1000}

# ③ 在线列表（分页；pageSize 服务端会回显实际值）
$ curl -s -m 5 "http://192.168.0.201:8080/gm/onlineList?serverId=1000&page=1&pageSize=5"
{"total":0,"success":true,"pageSize":100,"page":1,"list":[],"serverId":1000}

# ④ 旁证：同族 GM 接口同样裸 GET 可用
$ curl -s -m 5 "http://192.168.0.201:8080/gm/banned"
[]
```

- `192.168.0.201` = 同事本地服务器（测试服，见机器人 `config.py:13` 注释）；`online_count=0`
  因为该服当前没有在线角色（不是接口坏了——`success:true` 且列表结构正确）。
- **生产不可达**（本次未做任何写操作，均为只读 GET 探测）：
  - `http://47.96.8.240:8080/gm/online` → 超时（curl exit 28）
  - `http://gateway.sanfenqiu.cn:8080/gm/online` → 超时
  - `http://192.168.0.120:8080/gm/online` → 空响应（内网开发服，注释说"管理命令无响应，待排查"）

## 四、方案对比与推荐

| 维度 | 机器人 `@online`（现状） | 中控直连 `/gm/online`（本方案） |
|---|---|---|
| 授权 | **需要** admin_license 的 DEPLOY/WIZARD（生产未授权 → 拿不到） | **不需要**（实测裸 GET；IP/网络可达即可） |
| 资源占用 | 占用 1 个机器人号在游戏内发命令；该号必须在线、不卡 | 中控自身 HTTP，**不占任何游戏在线** |
| 时效 | 2 分钟一次（还有回执解析、上报链路） | 按配置轮询（默认 60s），读数自带 ts |
| 抗故障 | 号掉线/卡死/回执格式变化都会断 | 只依赖网络与服务端 HTTP；失败自动回落上一路 |
| 口径 | 全部在线角色（含真人） | 同口径 `online_count`（含机器人）；另有机器人数可拆 |
| 生产可用性 | 生产未授权 → 不可用 | **接口已存在**，只差网络可达（需用户配合，见第七节） |

**推荐**：两条链路都保留，**provider 优先、`@online` 兜底、本地握手数最后兜底**——已按此落地。

### 5.3 兜底顺序与 source 语义（`/api/status.svr_online`）

1. **provider**（启用且拉到数、且 age ≤ StaleSec[=3×间隔，最少 90s]）→
   `{count, ts, age_sec, source:"svr_provider"}`；
2. provider 未启用/失败/过期 → **机器人 `@online` 回执**（有读数）→ `{..., source:"svr"}`；
3. 两路都没有 → `{"source":"local"}`（不带 count；面板与水位保持器用本地握手数兜底）。

水位保持器内部再做一次新鲜度判断（180s，`SvrStaleSec`），与旧行为完全兼容。
全程 try/panic 兜底 + 只记日志（`[LIVECOUNT]` 前缀），任何异常不影响主链路。

## 七、需要用户配合（**必须**，按顺序）

> 服务端**不需要改任何代码/配置**（`/gm/*` 接口已存在），只差"中控 → 生产游戏服 HTTP"的网络可达。

1. **确认生产服 /gm HTTP 服务地址与端口**（在游戏服本机或能访问它的机器上跑）：
   ```bash
   curl -s -m 5 "http://127.0.0.1:8080/gm/online?serverId=1000"
   # 期望：{"online_count":N,"success":true,"serverId":1000}
   ```
2. **从中控所在机器验证同一地址可达**（把 <游戏服IP> 换成实际）：
   ```bash
   curl -s -m 5 "http://<游戏服IP>:8080/gm/online?serverId=1000"
   ```
   - 通 → 直接进第 4 步。
   - 不通（当前 `47.96.8.240:8080` 即此情况）→ 第 3 步。
3. **开通链路（任一即可）**：
   - 安全组/防火墙放行中控出口 → 游戏服 `8080/tcp`（只读 GET，建议按源 IP 加白名单）；
   - 或走内网地址（中控与游戏服同内网时用内网 IP）；
   - 或 SSH 隧道（临时验证用）：
     ```bash
     ssh -L 18080:127.0.0.1:8080 <游戏服登录用户>@<游戏服IP> -N
     # 然后中控配 http://127.0.0.1:18080
     ```
   - 若 PHP 后台（game_admin_web）能拿到数而中控不能：看它部署机的 `.env` 里
     `GAME_SERVER_HOST=` 的值（那就是我们要的可达地址）：
     ```bash
     grep -n "GAME_SERVER_HOST" .env    # 在 game_admin_web 部署目录执行
     ```
4. **配置中控并重启**（Windows，批处理/命令行示例）：
   ```bat
   set CTRL_LIVECOUNT_ENABLED=1
   set CTRL_LIVECOUNT_URL=http://<可达地址>:8080
   set CTRL_LIVECOUNT_SERVER_ID=1000
   :: 如需其它区：CTRL_LIVECOUNT_SERVER_ID=1001
   run_ctrlcenter.bat
   ```
   （环境变量方式最简单；也可后续做一个落盘配置项，本次未做。）
   面板来源文案同步可见的前端步骤：`cd web && npm run build`（生成 `web/dist`）。
5. **验证（重启后）**：
   ```bash
   curl -s http://127.0.0.1:28082/api/status | grep -o '"svr_online":{[^}]*}'
   # 期望出现 "source":"svr_provider" 与真实 count；同时看 "livecount":{...} 的 ok=true/age_sec
   ```
   - 面板大屏"🌐 全服在线（含真人）"随之为服务端口径；
