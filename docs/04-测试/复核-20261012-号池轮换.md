## 3. 三个问题的明确结论

### 3.1 领双口径（e）—— **P1：该判据在任何真实数据下恒放行**
- 生产链核实：机器人 `pre_daily.double_claim_date()`（pre_daily.py:428-439）**只在今日成功
  领双时返回 `YYYYMMDD`，其余一律返回空串**（含"从未领/跨天未刷新/异常"）；经 client.py:687
  上报 → event.go:896 全量覆盖 `r.DoubleClaimDate`。
- rotation 判据（rotation.go:147）：`!= "" && != today → 拦`。因机器人端**永不产出"有值且非今日"**，
  该分支不可达 → 实际效果 = **有值（今日已领）放行 + 空（未领）放行 = 恒放行**。
- 实际影响评估：轮换候选=**今日抓鬼已满**号；双倍增益作用于抓鬼，对"已满额转游荡"的号无产出
  价值 → 损失≈0。次生：(i) 当日未领双的号被换下后当天不再补领（若产品认为双倍对隔日的抓鬼
  窗口仍有价值，需另行评估）；(ii) 判据与注释声称的意图（"今日流程没走完先不换"）不符，属
  **无效护栏**（照注释理解会低估实际轮换面）。
- 结论/建议（二选一，推荐 A）：
  - **A（推荐，本期）**：接受现状 + 修订 rotation.go:113-116/147 注释，明说"真实上报下该条件
    等价恒放行；如需拦'未领'需机器人端三态上报"。零代价、不缩轮换面。
  - B：改机器人端上报为三态（已领/未领/未知）→ 中控拦"未领"——跨端改动、当期不建议。
  - **不要**把口径反转为"空也拦"：会把旧版上报/未领全拦下，首日轮换面骤减。

### 3.2 selfOff 交互（d）—— **不会把 rotation 移除的号当天拉回**
见 §2.d。另确认两条配套链路：
- rotation 压号时 `cancelRegHost`（sendOfflineChunks 内，handlers_accounts.go:525）——在 reghost
  队列中的号被取消，不会"刚下线就被重登补发"；
- 反向（reghost 复活 removed 号）：正常路径不可能（remove 送达后机器人端已摘号，不再发事件）；
  异常路径（remove 未送达 + 号卡死上报 task_error）存在理论复活链——onError 处理无 IsRemoved
  过滤（event.go:1133-1180），reghost 重登后 `onRobotOnline` 会 `UnmarkRemoved`
  （event.go:672，2026-09-22 起的既有"上线清标"设计）。已知既有行为、概率低、可自愈
  （复活号>30min 后若再满额游荡会被再次轮换、upsert 续期），列 P2 观察项（§6.3）。

### 3.3 预备队语义（c）—— 语义正确；**发现口径不一致（P2）**
- 语义正确："剔除已移除"使阈值对**新鲜**预备队生效（刚被轮换下线的号不计入，避免"自欺"）；
  在线/暂停/未毕业同样剔除（这些"水位器拉不动"，计入会虚高保护闸）。
- **P2：未剔除私人池号**（api/rotation.go:135-148 无 `IsPersonal` 检查）。私号不参与自动编排
  （waterline.go:128、autotask.go:739 均剔除）→ 水位器**拉不动**私号，但 rotation 把
  "私号且可用且离线且≥31"计入预备队 → 预备队**虚高** → 保护闸偏松（更容易继续下线）。
  影响量=私池中满足条件的号数（通常较小），但方向性错误、与同族口径不一致。
  建议一行修正：`if a.St != nil && (…|| a.IsPersonal(pa.Name)) { continue }`（部署前顺手做，
  或在首日启用前明确接受）。
