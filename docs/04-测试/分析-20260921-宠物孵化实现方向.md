## A. 孵化机制与协议（服务端侧，权威）

### A.1 暗雷怪是什么（触发机制）

```
[角色移动一步] → C 层回调 pymain.meet_monster(role_id, map_id, x, y)   (SV/pymain.py:287)
   ├─ random.random() > MEET_MONSTER_RATE(0.25) → 不遇怪        (SV/const.py:85-86: 70*16 移动步数遇敌)
   ├─ 需 can_meet_monster / must_meet_monster(摄妖香等 buff 可改) (pymain.py:293-297; SV/buff/buff_action.py:328-332)
   ├─ map_object.can_meet_monster(bo_fly)                        (SV/maps/map_entry.py:57-61)
   ├─ 该坐标在"怪物分布 bmp"上的颜色 → 取怪物列表                  (map_entry.py:135-141; CFG/map.csv 第5列 *_mon.bmp)
   ├─ 跳转点落点和平区不遇怪                                       (pymain.py:318)
   └─ fight.tailor.create_base_fight(...)  → 战斗场景 = tailor_base 的 compose
        attach_response = "response_hide"（暗雷怪(附带响应)）        (CFG/fight/tailor/tailor_base.xml:4…; response_base.xml:325)
```

- **"明雷"**（地图上可见、点击进入的怪）走 `tailor_visible.xml`，**也挂了 `response_hide`**（`CFG/fight/tailor/tailor_visible.xml` 内含 attach_response）→ 明雷战斗胜利同样加灵气（可作为备选路径）。
- **世界 BOSS** 同样（`tailor_worldboss.xml`）。
- **抓鬼/点鬼战斗**走 `tailor_ghost.xml`（`tailor_index="ghost_..."`，`related_response="response_revive"`），**没有 attach_response** → 不加灵气（全 tailor 目录仅 base/visible/worldboss 三处含 attach_response，grep 实测）。
- 任务 NPC"前置战斗"（如新手链 7001025 打紫金蛟王 13098）走 `create_tailor_reserve`（`SV/npc/npc_operator.py:718-726`）→ 任务专属 tailor → 不加灵气。

### A.2 孵化动作（MountEggHatch）细节

`SV/fight/response_action.py:585-644`（挂在 response_hide 的"时间点-人物战斗胜利"）：

| 步骤 | 逻辑 | 行号 |
|---|---|---|
| 前置 1 | `role_session.get_mount_egg_sign()==False` → 直接返回（蛋没放装备栏就不给灵气） | :598-599 |
| 前置 2 | `random.random() > action_value(0.8)` → 这场不加（**每场胜利 80% 概率 +1**） | :591,600-601; response_base.xml:331 |
| 前置 3 | 取装备栏五行珠位的蛋（`get_mount_egg`），蛋里已有坐骑（related_mount_id≠0）→ 返回 | :602-607; `SV/item/item_ruler.py:700-708` |
| 前置 4 | `mount_entry.is_hatch_place(map_index)` → **必须在孵化白名单地图** | :615-616; `SV/mount/mount_base.py:56-58` |
| 加灵气 | `increase_egg_agility()`：`COOKIE_EGG_AGILITY(5382) = 旧值+1` | :617; `SV/item/item_cookie.py:263-266` |
| 进度提示 | 未达阈值时：`per==20%` 必发 notice 820，`>20%` 且每 4 点 `p<0.8` 概率发 notice 820 | :619-626 |
| 完成 | 灵气 ≥ `MOUNT_EGG_HATCH_NEED_AGILITY=30` → 建坐骑：坐骑槽未满 → **入槽 + `consume_item_once(蛋)`** + notice 818；槽满 → 蛋内绑定 `related_mount_id` + notice 819（蛋留包内，之后右键用 step5"放置到坐骑槽"） | :627-644; `CFG/config/config.csv:218`; `CFG/notice/notice.csv:823-824` |

**直觉换算**：30 点灵气 × 平均 1/0.8 = **约 38 场暗雷战斗胜利**孵出一只（全在半月岛内打）。

### A.3 "把蛋放到人物装备栏"（`mount_egg_sign` 怎么来）

- 蛋模板（`CFG/item/item_element.xml:2801-2840`，`mount_birth_element_00001`）：
  - `item_class=坐骑蛋`、`equip_class=五行珠`（装备栏专用槽，实例位置 4108）
  - step1 → `action_switch_forward` → step2 小三藏对话 3 选项：
    - "放置到人物装备栏（之后自行到指定地点进行孵化）" = **option_step 4 → `action_equip_item`**
    - "花费50金直接孵化" = option_step 6 → `action_mount_direct_birth`
    - "先留着" = option_step **0 = 关闭对话**（当前机器人就点这个）
  - step5 → "放置到坐骑槽"（孵化后蛋里绑了坐骑时用）；step3 `action_mount_birth`
- **两条"放蛋"路径（都验证过会触发 sign）**：
  1. **对话选项 #0** → `EquipItemAction._do_use_on_role`（`SV/item/item_action.py:714-724`）→ `put_on_weapon_item`（`SV/item/pocket_operator.py:431-457`）→ `__put_on_equip_item` → `__put_in_pocket_position`（:236-249）→ `target.append_item_object`（`SV/item/item_pocket.py:90-95`）→ `EquipItemPocket.add_item_object`（`SV/item/pocket_object.py:58-67`）→ `item_observer.after_put_on_equip`（`SV/item/item_observer.py:68-71`）→ `__check_equip_5elem_head → __check_mount_egg`（:290-302）→ **`session.set_mount_egg_sign()`**
  2. **`C2S_CHANGE_ITEM_POCKET(80032)`**（换包裹：背包→装备栏）→ `SV/item/item_dispatcher.py:108-114` → `item_operator.dispatch_change_item_pocket`（`SV/item/item_operator.py:361-381`）→ `pocket.change_item_pocket` → `change_item_pocket_direct` → `change_item_position_direct`（`SV/item/pocket_operator.py:383-387`）→ `__move_item_position_direct` → `__put_in_pocket_position` → **同一条 append 链** → 同样 set sign ✅
     - ⚠️ 路径 2 **不弹对话**（`put_on_weapon_item`/`EquipItemAction` 才弹），机器人侧已有封装 `RB/bag_ops.py:34-46` `_send_change_pocket`（参数 `[item_id,1,5158(BAG),5170(EQUIP),0]`，**当前是死代码**）。
- **脱下路径**：装备栏内物品 `C2S_USE_ITEM` = 解下（`SV/item/item_operator.py:209-240` / `pocket_object.py:211-212`），`after_put_off_equip` 会 `clear_mount_egg_sign`（`item_observer.py:77-80,296-302`）。

### A.4 "花费50金直接孵化"（不推荐路径，但要先说清）

- `MountDirectBirthAction`（`SV/item/item_action.py:1813-1845`；NPC 版 `SV/npc/npc_action.py:2299-2335`）：
  - **前提：蛋必须在装备栏**，否则 notice 823「未装备坐骑蛋，不能直接孵化」（`CFG/notice/notice.csv:825`）
  - 扣 `MOUNT_EGG_HATCH_NEED_MONEY = 500000` 金（`CFG/config/config.csv:229`）——注意对话文案写"50金"，**配置实际是 500000 金钱**（差 1 万倍，以配置为准）

## B. 现有代码现状（机器人端 / 中控）

### B.1 蛋对话的当前处理（"先留着"）与触发源

- **触发源**：背包整理 `daily_ghost.__tidy_bag`（`RB/daily_ghost.py:2231-2299`）→ 对"非任务物品、非装备、非白名单"的物品一律发 `C2S_USE_ITEM`（:2276-2283）→ 服务端弹孵化对话（蛋 step2 = `action_item_dialog`）。
  - **现场实录**（`robot0001001@xy3.com/runs_20260921.jsonl:16-19`）：
    ```
    背包整理: 处理 25 个物品(用消耗品25 丢装备0 穿装备0)
    对话打开: 任务 0, npc=0, 选项 3 个 ['放置到人物装备栏（之后自行到', '花费50金直接孵化', '先留着']
    系统对话: 无推进项, 点关闭 #2(先留着) 收尾
    ```
    即：**每个整理周期都发一次蛋的使用、弹一次对话、点一次"先留着"**。
- **处理代码**：`RB/quest_engine.py:640-719`（`__handle_dialog` 的 `npc_id==0` 分支）
  - 引导关键词表（"续领/接受/领取/双赢/确认"等，:650-676）**不含**孵化选项 → 落到关闭分支点 `close_flag!=0` 的项（:683-702）→ 即"先留着"。

### C.5 编排建议（孵化放在哪条通道）

**建议：孵化作为"独立低优先任务"，专门挑少量号走"游荡通道"，不进抓鬼状态机。**

理由：
1. 抓鬼是主线（用户硬约束：两条链路 100% 无报错）；孵化要"跨图到半月岛 + 长时间随机走 + 打 38 场野怪"，与抓鬼地图/时长强冲突；
2. 游荡模式（random_walk）天然是"空闲号"的通道（`dispatch_cmd` 会自动停任务链与抓鬼，:623-638），孵化塞进游荡只增加"停走游荡的时机 + 完成判定"两个钩子；
3. 完成一只后即可停游荡（或留号继续游荡），对主线零干扰；
4. 现场只需要**极少量号**做孵化（8 个带蛋号，甚至先拿 1 个号验证），不需要全量。

**操作时序（建议）**：空闲 → 检测到"背包含坐骑蛋" → 放蛋(S1) → 下发 random_walk(map6) → 打满 30 灵气（约 38 场；按现场踩雷速率估算，一个号走 2~4 小时可完成，取决于半月岛怪区密度）→ notice 818 → 收工。
