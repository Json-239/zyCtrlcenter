## 一、根因链（现场铁证）

**现象**：8 个新手号卡在任务 `7001115「寻找草船」`，每个 `跨图跳转被拒绝` 重试 **30+ 次**（≈75 分钟）→ `STUCK_NAV`。

**现场日志（robot0003001@xy3.com，22:11）**：
```
22:11:42 点击跳转NPC 13003
22:11:43 对话打开: npc=13003, 选项 ['请送我去大唐东-码头', '请送我去烟云港',
           '请送我去长安东市集广场（3银…', '请送我去长安城中擂台（4银）', '离开']
22:11:44 [w] 商店流程收到未识别通知(码 1116)        ← 储备金不足，传送被服务端拒
22:11:43 [i] 跳转NPC过图成功 → 地图 11 (主动同步)     ← 但脚本"点中目的地即乐观改图"！
   …随后…
22:50+ [i] 跨图 11→612 经 1 个跳转点
        到达跳转点(3912,648), 发 C2S_DIJKSTRA_DESTINATION 83
        [w] 跨图跳转被拒绝(destination 83), 重走跳转点重试(第 29/30/31 次)
```

**机制**：
1. 号实际在**图 5**，点 NPC 13003 想回图 11 —— 选项"长安东市集广场（3银"**要储备金**，
   服务端回通知 `1116`（储备金不足）→ **传送未执行**；
2. 但 `quest_engine` 的"**点中跳转NPC目的地即乐观改 m_mapid**"（为修"服务端换图推送滞后/丢失"而加，
   见 quest_engine.py 的 2026-08-26 注释）**把本地 m_mapid 改成了 11**；
3. 之后以"图 11"身份发 `destination 83`（11→612），**服务端认为它还在图 5** →
   `start_index` 不匹配 → **全拒**；换目的地（11→5/10/12…）同样全拒 → 重试到超限。

> **初版判断修正**：此前以为"新手任务锁图"（`task_story.can_change_map`）是主因 ——
> 那是**下游现象**：服务端确实会因"身上有新手任务"禁止换图，但本例的拒绝是**图不同步**
> （本地以为 11 / 服务端还在 5）。py 参考实现与我们**同源同服务端**（两条跨图路径都检查
> `can_change_map`），它 09-19 在 11 图用 dest 83 **成功过图** → 证明 11→612 本身可行。

## 二、改动（4 处 + 1 个后备）

| # | 位置 | 改动 |
|---|---|---|
| 1 | `robot_operator.handle_change_map` | 服务端推 `S2C_CHANGE_MAP` 时记录 **`m_srv_mapid`（服务端确认图）** 并清 `m_mapid_optimistic` |
| 2 | `quest_engine` 乐观改图处 | 改 `m_mapid` 同时置 **`m_mapid_optimistic = 目标图`**（标记"待服务端确认"） |
| 3 | `quest_engine` 跳转被拒分支 | 若在乐观态 → **回滚 `m_mapid = m_srv_mapid`** + 清标记（再走原重试/重规划），日志 `跨图失败回滚乐观过图: A → B(服务端确认图)` |
| 4 | `quest_engine` 目的地匹配 | 新增 `_is_paid_jump_option()`（正则 `[（(]\s*\d+\s*(银\|两\|金)`）→ **优先选免费选项**；付费项仅作后备（`_paid_best`） |

**为什么保留"乐观改图"**：它是为修另一个回归（服务端换图推送滞后/丢失 → 号卡在等换图）而加的；
现在改成"**乐观 + 失败回滚**"，两个方向都不丢。

## 三、自检（`tools/cross_map_rollback_selftest.py`，11 项）

静态 6 项（4 处改动的关键语句与顺序：回滚在 retry 递增之前）+ 动态 5 项：
- D1 价格识别（含边界："请送我去金沙湾（免费）"不误判）
- D2 乐观态被拒 → **回滚到服务端确认图** + 清标记 + 发一条日志
- D2b 非乐观态被拒 → 不动（保持旧行为）
- D2c 乐观但已与服务端一致 → 不回退、仅清标记
- D3 `S2C_CHANGE_MAP` → 确认图落地 + 清标记

**全绿**（本地 11 项；另跑 8 套既有自检 + `pos_report`（含双副本一致）全 PASS）。

## 五、遗留

1. **`1116` 在 quest_engine 里仍是"未识别通知"**（`商店流程收到未识别通知(码 1116)`）——
   daily_ghost 侧已识别为"储备金不足"（`_NOTICE_NO_MONEY=(1115,1116)`）；quest_engine 侧可后续补识别，
   让"NPC 传送付费失败"更快反馈（当前靠"下一跳被拒 → 回滚"兜底，会慢一拍）。
2. **付费传送仍可能被选**（目标目的地只有付费选项时，如"长安城中擂台（4银）"）——
   属于正常设计（有意愿付费），失败由回滚兜底；若储备金普遍不足，可考虑给 5→11 加**免费绕路**
   （analysis 文档提到：5→(13003免费"大唐东-码头")→9→10→11，链路数据已具备）。
3. 图 11 上 dest 11/13 被拒的真实原因（是否真"锁"）需服务端 `[DIJKSTRA-REJECT]` 日志原文复核。
