# 账号库（复制自 Python 中控 / ps 侧）

> 本文件记录**账号数据的来源、结构与查法**。账号库是数据资产，不参与中控运行（本骨架不读它），
> 供选号、排查"登录失败"等操作使用。

## 1. 来源

| 项 | 值 |
|---|---|
| Python 中控（ps 侧）的库 | `E:\robot_accounts\robot_accounts.db`（SQLite，活库，Python 中控在写） |
| 本项目副本 | `data/robot_accounts.db`（**用 SQLite 在线备份 API 复制**，非直接拷文件，避免半截事务） |
| 复制时间 | 2026-09-19（后续如需刷新，重跑下面的命令） |

```powershell
# 刷新副本（Python 3 标准库即可，无需装 sqlite3 CLI）
& "<python.exe>" -c "import sqlite3; s=sqlite3.connect(r'E:\robot_accounts\robot_accounts.db'); d=sqlite3.connect(r'<本项目>\data\robot_accounts.db'); s.backup(d); d.close(); s.close(); print('backup ok')"
```

> 注意：**不要**直接 `copy` 活库文件（可能拷到写事务中途）；也不要在中控运行中删它。

## 2. 表结构（Python 中控维护，本骨架只读）

| 表 | 说明 |
|---|---|
| `servers` | 服/区列表：`host_port`（如 `47.96.8.240:2300`）、`name`、`is_current` |
| `accounts` | 账号账本：`account`（如 `robot0001000@xy3.com`）、`password`、`level`、`role_name`、`chain_done`、`fpp`、`done`、`note`… |
| `account_server_state` | **账号 × 服/区** 的可用性：`verified`（是否验证过）、`usable`（该服可用=账号存在）、`verify_msg` |
| `account_servers` | 账号与服/区的绑定关系 |

> ⚠️ **账号是按区用的**：同一个账号可能在 `47.96.8.240:2400` 存在、在 `:2300` 不存在。
> 登录时报 `errno=100(账号可能未建号)` 通常就是"该号在该区没有"——换一个在该区 `usable=1` 的号即可。

## 3. 查询工具（本项目自带）

```powershell
# 概览：服列表 + 账号总数 + 前几条
& "<python.exe>" tools\inspect_accounts.py

# 某服的可用账号（account_server_state.usable=1）
& "<python.exe>" tools\inspect_accounts.py data\robot_accounts.db --usable "47.96.8.240:2300" 20

# 单账号全字段（含密码，供启动机器人用）
& "<python.exe>" tools\inspect_accounts.py data\robot_accounts.db --account robot0001000@xy3.com
```

## 4. 选号要点（启动机器人前必看）

1. **该区可用**：`--usable <host:port>` 里要有它（否则 `errno=100`）；
2. **不要与生产在线号冲突**：同一账号两个进程登录会互踢 —— 拿 `GET /api/status`（Python 中控）的
   `robots[].account` 与候选求差集；
3. **机器人端账号段**：`script/config.py` 的 `robot_account = ["robot000", (起点, 终点), 密码]`
   —— 机器人启动只登录**起点**那个号；要换号就改起点：
   ```powershell
   & "<python.exe>" tools\patch_robot_config.py <部署目录> <起始序号>
   ```
   （只改数字字面量，注释行不动，可重复执行）

## 5. 与中控的关系

账号池由 `internal/services/accounts` 提供（落盘 `<数据目录>/accounts.json`，面板「账号池」页与
`/api/accounts*` 直接使用）。状态按 `(账号, 区)` 维度记录——**区的键是 `host:port`**，因此不会跨区串口径；
密码不下发到前端，批量上线/验证时由服务端从池里取。

## 6. 可用性验证（直连游戏服）

"这个号在某区到底存不存在、能不能用"用**登录协议探测**回答（不进入游戏、无副作用）：

| 操作 | 入口 | 说明 |
|---|---|---|
| **批量验证当前区（默认）** | 面板「账号池」→ 选范围 → 「批量验证当前区」 | 从**本地库该区**选一批（默认"待验证"）→ 后台跑 |
| 手输单个/几个（次要） | 同卡片「手输账号单独验」 | 同步返回，结果同样写回池 |
| **建号 / 校验（按编号）** | 「建号」卡片：填 **前缀 + 起始序号 + 数量 + 后缀**（可勾"自动接续"）→ 建号 | **先验证再注册**：已存在且密码对 → 跳过（标可用+角色）；密码不符 → 标不可用并提示；不存在 → 注册（106→104→700）。新号密码 16 位随机、写入库，面板可点复制；每批/并发可调 |
| 范围（默认**本区全部**） | `zone`（面板默认：该区**有记录**的全部账号，含已验过/不可用）/ `unverified` / `unusable` / `unknown` / `all`，数量预览在卡片上（本区全部 N / 待验证 / 已知不可用 / 该区无记录 / 池内共） | 个数填 **0 = 不限**（任务带进度、可随时「停止」）；并发 2（上限 16）；默认跳过正在线的号 |
| 接口 | `POST /api/accounts/verify` | 带 `accounts`=同步；不带=批量（返回 `job`）；进度 `GET /api/accounts/verify/job`，停止 `POST /api/accounts/verify/cancel` |
| 结果检索 | `GET /api/accounts?zone=<host:port>&usable=1&keyword=&limit=&offset=` | 按区可用性 + 关键词（账号/角色）**分页**检索 |
| **上线 / 下线（点选即可）** | 单个：表格行内「上线」/「下线」（在线行显示"下线"）；批量：勾选（可跨页）→「上线勾选的 N 个」；快捷：全选本页 / 选本页可用 / 选本页未上线 / 选本页在线 / 清空；大屏右上角「选号上线」= 搜索+勾选或「自动挑号上线」 | **不用输账号**：点行内按钮立刻下发（无弹窗），批量确认一次。已在线的自动跳过、库里没密码的会在结果里单独列出；`accounts` 由服务端自动去空白/空串/保序去重 |

**密码来源（没有统一密码；同一个服内通用）**：一切登录/验证的密码都从库里取——优先精确区
`zones["<host:port>"].password`，其次**同服（同 host）其它区**的密码，最后账号级 `password`（导入的老数据）；
取不到就明确报错，**不会**拿某个"默认密码"去试。

判定口径：`100`=不存在；`200 密码错 / 300 冻结` → **存在但不可用**（算可用会被定时上线反复拉起）；
网络/超时/编码错误**不改动**池里已有的 `usable` 结论，只记一条 `验证失败：…`。
协议细节（帧格式/消息号/角色表/编码）见 [游戏服探测协议](../03-协议/游戏服探测协议.md)。
