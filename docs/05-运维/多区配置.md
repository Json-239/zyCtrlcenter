# 多区配置（服 → 区，单进程切换式）

> 目标：在**一个机器人进程**的前提下，能方便地在多个游戏区之间切换。
> 「1 服多区」= 同一个游戏服 IP 的多个端口（如 `47.96.8.240:2400` / `:2300`）。
>
> 事实协议：相关接口见 [HTTP-API](../03-协议/HTTP-API.md)；配置文件落盘 `data/zones.json`。

## 1. 模型

```
服 Server（游戏部署入口：IP + 默认编码=UTF-8）
  └ 区 Zone（入口端口 + 可选编码覆盖）
```

| 层级 | 字段 | 说明 |
|---|---|---|
| 服 | `key` / `name` | 稳定标识（如 `prod-240`）与展示名（如 `生产网关`） |
| 服 | `host` / `coding` | 游戏服 IP（**机器人端不支持域名，只能 IP**）与默认编码（**默认 `UTF-8`**；个别区确需 `GBK` 时在区级覆盖） |
| 区 | `key` / `name` | 区内标识（缺省=端口字符串，如 `2400`）与展示名（如 `1区`） |
| 区 | `port` | 游戏服端口（host 继承所属服） |
| 区 | `coding` | 可选覆盖服级编码（服务端编码不同的区要各自设对） |
| 区 | `note` | 说明（可选） |

区的**全局 key** = `<服key>/<区key>`（如 `prod-240/2400`）——接口、日志、事件里的 `zone` 字段都用它。

## 2. 运行时拓扑（单进程）

```
中控（单进程）
├── HTTP API :28082 + WS
└── 控制通道 :27200 ← robot_single_robot.exe（唯一一个进程）
                       └── 登录哪个区 = 它的 config.py 里 ip/port 指向谁
```

- **控制通道**：只有一条（`--ctrl-port`，默认 27200）；事件会带上 `_zone` = **当前区**。
- **机器人进程**：只有一个（部署目录 `--deploy`，默认自动探测）；同一时刻只能登录一个区。
- **切区 = 改配置 + 重启**：`config.py` 是进程级配置，所以切换区必须
  ①切当前区 → ②「应用到机器人」（改 `ip/port/PROTOCOL_CODING`）→ ③重启机器人进程。

## 3. 「切换当前区」与「应用到机器人」的区别（关键）

| 动作 | 影响 | 接口 | 风险 |
|---|---|---|---|
| **切换当前区** | 只改"当前选择"（面板上下文 + 事件标记），**不碰机器人** | `POST /api/config/switch` | 低（无需鉴权） |
| **应用到机器人** | 把该区 `ip/port/PROTOCOL_CODING` 写进机器人 `script/config.py`，可选顺带重启机器人进程 | `POST /api/config/apply` | 中（改生产配置文件，需鉴权 + 面板二次确认） |

「应用」的实现约束（`internal/services/zones/robotcfg.go`）：

1. **只改三个键**：`ip` / `port` / `PROTOCOL_CODING`；其余内容、注释、行尾注释原样保留；
2. **只改字面量**：值必须是 `"1.2.3.4"` / `2300` / `"UTF-8"` 这种直接量。
   若某键的值是**表达式**（例如现场配置常见的 `ip = _os.environ.get("ROBOT_ZONE_IP") or "47.96.8.240"`），
   **一律跳过不改**并在结果里回 `skipped`（接口 msg 与面板会提示"需人工处理"）——
   强行替换会把表达式改坏（括号不配对等）；
3. 文件里缺键时追加到末尾（带 `# === 由 zyctrlcenter 自动补充 ===` 标记）；
4. 写前**自动备份** `config.py.bak_YYYYMMDD_HHMMSS`；内容无变化则**不写盘、不备份**；
5. 文件不存在直接报错（不新建，避免写错位置）。

> 对指定别的区「应用」时会**顺便把该区设为当前区**，保证"当前区 = 机器人登录的区"一致。

## 4. 首次启动：默认种子

`data/zones.json` 不存在时写入种子（可在面板改/删）：

```jsonc
{
  "current": { "server": "prod-240", "zone": "2400" },
  "servers": [{
    "key": "prod-240", "name": "生产网关", "host": "47.96.8.240", "coding": "UTF-8",
    "zones": [
      { "key": "2400", "name": "1区", "port": 2400 },
      { "key": "2300", "name": "2区", "port": 2300 }
    ]
  }]
}
```

## 5. 常用操作（面板 / 接口）

| 操作 | 面板 | 接口 |
|---|---|---|
| 新增服 | 系统信息 → 新增服 | `POST /api/config/servers` |
| 新增/更新区 | 系统信息 → 新增/更新区 | `POST /api/config/zones` |
| 切换当前区 | 顶栏区下拉 / 区表「切到此区」 | `POST /api/config/switch` |
| 应用到机器人 | 区表「应用到机器人」（可勾选自动重启） | `POST /api/config/apply` |
| 删除服/区 | 区表「删除」/ 服列表「删」 | `POST /api/config/servers|zones/delete` |

> ⚠️ 一个区正在被机器人登录时，删掉它的**配置**不会影响运行中的机器人；
> 但下次「应用」就没有它可选了，所以删前确认当前区不是它（或先切走）。

## 6. 编码口径（2026-09-19 更新）

- 当前环境统一 **UTF-8**：服/区未显式指定时按 UTF-8 处理，种子区默认 UTF-8，
  「应用到机器人」写进 `config.py` 的也是 UTF-8；
- `GBK` 仅作为**个别区的可选覆盖值**保留（`NormalizeZone` 仍接受 `GBK`/`UTF-8`）。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板「通道未连接」 | 还没有机器人连到中控的控制端口 | 启动机器人（自行启动或 `--auto-robot`），并确认它 `ctrl_server_port` 指向本中控 |
| 切了区但机器人还在旧区 | 切换只是"当前选择" | 点「应用到机器人」（改 config.py）→ 重启机器人进程 |
| 机器人乱码 | `coding` 与目标区服务端不一致 | 当前环境用默认 UTF-8；若某个区服务端仍是 GBK，把该区 `coding` 改成 `GBK` 后重新「应用」 |
| 「应用」报 config.py 不存在 | 部署目录不对 | 用 `--deploy` 指定机器人部署目录（或面板看"机器人 config.py"路径） |
| 应用结果里出现 `skipped: ip,port` | 该键的值是环境变量表达式（非字面量） | 属**保护行为**（不会改坏表达式）：若要切区，用启动时的环境变量（`ROBOT_ZONE_IP/PORT`）或手工调整该行 |
| 想同时跑多个区 | 本版本按**单进程**设计 | 需要并行多区时再评估"每区一进程 + 多控制端口"方案 |

## 8. 旁路验证：不动生产进程，起一个连本中控的机器人

想验证「本中控 + 目标区」能跑通，又不想影响生产的那一个机器人进程时：

```powershell
# 1) 复制一份干净部署目录（排除日志；真正的程序文件只有 ~14MB）
robocopy <生产部署目录> F:\ZyBin\zyCtrlcenter\deploy\zones\<区名> /E /XF "diag*.log*" "console*.log*"

# 2) 换一个"该区可用 + 生产未在线"的账号（改副本 config.py 的账号段起点，注释行不动）
& "<python.exe>" tools\inspect_accounts.py data\robot_accounts.db --usable "47.96.8.240:2300" 20
& "<python.exe>" tools\patch_robot_config.py F:\ZyBin\zyCtrlcenter\deploy\zones\<区名> <起始序号>

# 3) 用环境变量把副本进程指向"本中控 + 目标区"（副本 config.py 支持这些变量，无需改文件）
$env:ROBOT_ZONE_IP="47.96.8.240"; $env:ROBOT_ZONE_PORT="2300"
$env:ROBOT_ZONE_KEY="47.96.8.240:2300"
$env:ROBOT_CTRL_HOST="127.0.0.1"; $env:ROBOT_CTRL_PORT="27200"
$env:ROBOT_DEFAULT_PWD="123456"
Start-Process -FilePath "F:\ZyBin\zyCtrlcenter\deploy\zones\<区名>\robot_single_robot.exe" `
              -WorkingDirectory "F:\ZyBin\zyCtrlcenter\deploy\zones\<区名>" -WindowStyle Hidden
```

验证：`GET /api/status` 应出现 `robot_connected=true`，且该账号 `zone=<区 key>`、`online=true`、`hs=true`。

要点：
- **副本目录独立**：日志（`console*/diag*`）、`config.py` 都落在副本里，不碰生产文件；
- **别开 `--kill-robots`**：同名 exe 会让 taskkill 误杀生产进程；
- 停止验证进程：`Get-CimInstance Win32_Process -Filter "Name='robot_single_robot.exe'"` 按 **ExecutablePath** 区分后 `Stop-Process`；
- 账号要按区挑（见 [账号库](账号库.md) §4），否则登录报 `errno=100`。
