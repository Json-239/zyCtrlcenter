# 日志与排障

## 1. 日志位置（日期级）

| 日志 | 路径 | 内容 | 清理 / 熔断 |
|---|---|---|---|
| 运行历史（面板日志页数据源） | `data/runs_YYYYMMDD.jsonl` | 事件 JSONL（含中控自己写的 `api`/`log` 事件） | 保留 30 天；单文件超 500MB 归档 `.over_<ts>`（只留最新一份） |
| 单机器人日志 | `data/bot_logs/<账号>/runs_YYYYMMDD.log` | 该账号相关事件（带 `account` 的事件同时写这里） | 同上 |
| 应用日志 | `logs/ctrlcenter_YYYYMMDD.log` | 启动/运行诊断（与 stdout 同源） | 保留 30 天 |

面板路径：
- 「运行日志」页 = 当天 `runs_YYYYMMDD.jsonl` 尾部 + WS 实时事件（可按类型/级别筛选、暂停、清空）；
- 「监控大屏」的「任务失败待处理」= 出错重复 ≥2 次的账号（来自 `error` 事件记账）。

调整保留/熔断：见 [配置说明](配置说明.md) §3。

## 3. 常见故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板「控制通道未连接」 | 机器人没连上 27200 | 检查机器人 `config.py` 的 ctrl 端口；或 `--auto-robot` 让中控拉起机器人 |
| 操作返回「下发失败：机器人通道未连接」 | 无活跃机器人连接 | 同上；先用 `/api/status` 的 `robot_connected` 确认 |
| 启动即退出，日志有 `[FATAL] HTTP API 端口无法监听` | 28082 被占用 | 换 `--web-port`；或停掉占用进程 |
| 启动日志有「控制通道启动失败」但进程还在 | 27200 被占用（多半已有中控在跑） | 换 `--ctrl-port`；确认是否重复启动 |
| 面板打不开 5273 | 前端没起 / 端口被占 | `cd web && npm run dev`；Vite 会自动换端口，看终端输出的实际地址 |
| 面板日志不刷新 | WS 断开（慢客户端被踢会断开） | 前端每 3 秒自动重连；查应用日志里的 WS 接入/断开记录 |
| 「任务失败待处理」出现条目 | 机器人上报 `error` 且重复 ≥2 | 看 `code`/`msg`，停链排查根因（骨架层不自动跳过掩盖问题） |
| 账号行莫名消失 | 心跳超 10 分钟被清理 / 收到下机类事件被移除 | 看运行历史里的 `api`（`robots_manage/remove`）与 `chain_done`/`ghost_*` |
| 日志文件特别大 | 机器人侧死循环刷日志 | 已内置 500MB 熔断；可调小 `CTRL_RUNS_MAX_MB`，或面板「清空日志」 |
| 面板操作后机器人没反应 | 命令未送达 / 机器人未处理 | 用假客户端 `nc 127.0.0.1 27200` 观察？→ 更推荐看运行历史里的 `api` 事件 `sent` 字段 |

## 4. 冒烟自检（不依赖真实机器人）

```powershell
# 启动中控（新端口，避免与生产冲突）
run_ctrlcenter.bat --web-port 28099 --ctrl-port 27299 --data-dir data_smoke

# 另开一个 PowerShell 冒充机器人发一条事件，然后看状态
$c = New-Object System.Net.Sockets.TcpClient("127.0.0.1", 27299)
$w = New-Object System.IO.StreamWriter($c.GetStream(), (New-Object System.Text.UTF8Encoding $false)); $w.AutoFlush = $true
$w.WriteLine('{"type":"robot_online","account":"smoke001","role_name":"冒烟","level":21,"mapid":5}')
$c.Close()
(Invoke-RestMethod http://127.0.0.1:28099/api/status).robots | Format-Table account, state, role_name, level
```

预期：`robots` 出现 `smoke001`，状态 `ONLINE`，`data/runs_YYYYMMDD.jsonl` 里能看到对应的 log 事件。

## 4.1 「钟馗对话卡死」怎么排（2026-09-21 专项）

**三种形态**（都在运行日志里搜 `STUCK`）：

| 形态 | 日志特征 | 根因 | 处置 |
|---|---|---|---|
| 点钟馗**开不出**对话 | `error: GHOST_DIALOG_STUCK 点钟馗连续 N 次无对话` | 协议只有 `S2C_CLOSE_DIALOG`（服务端推），**没有 C2S 可主动关** → 本地与服务端对话态一旦不同步，客户端再也点不开，只能重登（实测空点 2.4 万次/天） | 机器人连续 8 次无对话 → 上报 → **中控自动下线重登 + 8 秒后重新下发**（reghost） |
| 对话**开着关不掉** | `钟馗对话 N 轮超 30 秒未关闭` | 服务端漏推 CLOSE_DIALOG；旧兜底是"死等 30 秒 + 本地清 dialog_open"（本地清无效） | 机器人侧新增：**8 秒内若该对话不是抓鬼业务对话，就点服务端自己给的关闭项**（如"我什么都不想做"）收尾；点不动才走 30 秒/重登 |
| 交付阶段开不出对话 | `交付捉鬼任务连续 N 次无进展(点钟馗无交付对话)` | 同上（对话态不同步），叠加"服务端主动弹的引导对话（npc=0，如领双/追捕令）与钟馗对话同层、互相覆盖" | 保留任务不清（清掉会走"放弃→扣钱失败→死循环"），连续 3 次 → 重登恢复 |
| **零选项空对话**（2026-09-21） | `对话打开: 任务 0, npc=0, 选项 0 个 []` 之后**再无日志**（号一动不动） | 服务端在"领双引导对话"点掉后推一个**没有按钮的确认框**；机器人端没有任何可点项 → 旧逻辑"稍候点 NPC 0"无效，`dialog_open` 挂着把状态机钉死（`quest_engine` 主循环 `if quest.dialog_open: return 0`）。**抓鬼未启用时（g.enabled=false）daily_ghost 的 30 秒兜底也不跑**，无人处理 | 机器人侧：`__handle_dialog` 对空对话**主动清对话态**恢复（同 09-11 引导对话口径）；中控侧：恢复引擎把"抓鬼意图 + DIALOG + 无抓鬼会话 + task_index=0"算作可补发（补发后 30 秒兜底会接管） |

**两侧各自的职责**

- **机器人端**（`deploy/zones/<区>/script/daily_ghost.py`）：判死阈值 `BROKER_NODLG_LIMIT=8`；`DIALOG_CLOSE_AFTER_MS=8000` + `DIALOG_CLOSE_TRIES=2`（点关闭项收尾）。
- **中控端**：收到 `GHOST_DIALOG_STUCK` / `TASK_STUCK` → `reghost`：下线 → 重登 → 8 秒后按意图补发（带组装载荷）；用户手动「停止/移除」会取消待恢复。
- **中控端（2026-09-21 起）**：恢复引擎把"抓鬼意图 + `DIALOG` + **无活跃抓鬼会话**（`ghost` 字段为空）+ `task_index=0`"也算"没在跑" → 补发 `ghost_start`（机器人端 30 秒兜底随后接管；重复下发幂等）。修这道是因为：会话在重连时丢了、抓鬼未启用 → 机器人端所有卡死侦测（都在 `daily_ghost.tick` 里）都不跑，只有中控能救。
- **防 churn**：同一号**当日**卡死 ≥3 次 → 当天不再被：自动任务拉起 / **自动补发（恢复引擎 Skip）** / **自动重登（reghost）**（`stuck_count`，跨日自动归零；面板 `reghost` 名单里显示"当日卡死已达上限"）。

**自检（改完必跑）**：

```bash
# 验"要不要点关闭项"的判据 + 阈值；两份副本（线上/仓库）都跑一遍
python tools/dialog_selftest.py F:/ZyBin/xm/2d-xiyou-server/robot/deploy/single_robot_zy/script/daily_ghost.py
python tools/dialog_selftest.py deploy/zones/prod-240-2300/script/daily_ghost.py
```

**为什么不能 100% 消灭**：关对话的能力在协议里缺失、钟馗对话态由服务端掌管 —— 客户端只能"重登把状态洗掉"。中控已把恢复链路自动化（8 秒级），业务上表现为"偶尔重登一次，不卡死"。
